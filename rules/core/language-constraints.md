# 語言約束規則

本文件定義專案中所有文字輸出的語言規範。

---

## 強制規則

### 規則 1：使用繁體中文

**所有回應必須使用繁體中文 (zh-TW)**

| 適用範圍 | 說明 |
|---------|------|
| 對話回應 | 所有與用戶的對話 |
| 文件撰寫 | 所有交接文件、工作日誌、Ticket |
| 程式碼註解 | 所有原始碼檔案中的中文註解 |
| Commit 訊息 | Git commit 的描述部分 |

### 規則 2：禁用詞彙

以下詞彙**禁止使用**，必須替換為對應的正確用語：

| 禁用詞彙 | 正確用語 | 說明 |
|---------|---------|------|
| 智能 | Hook 系統、規則比對 | 避免過度擬人化 |
| 文檔 | 文件 | 臺灣用語 |
| 數據 | 資料 | 臺灣用語 |
| 默認 | 預設 | 臺灣用語 |
| 代碼 | 程式碼 | 臺灣用語 |
| 視頻 | 影片 | 臺灣用語 |
| 軟件 | 軟體 | 臺灣用語 |
| 硬件 | 硬體 | 臺灣用語 |
| 信息 | 資訊 | 臺灣用語 |
| 優化 | 最佳化 | 臺灣用語（程式碼品質上下文可用「優化」） |

### 規則 3：禁止使用 Emoji

**所有文字輸出禁止使用 emoji 符號**，適用範圍包括所有文件、對話和程式碼中的文字。

| 情境 | 禁止（用 emoji） | 替代方式 |
|------|----------------|---------|
| 標題/章節標記 | 標題開頭加裝飾 emoji（如目標符號 U+1F3AF） | `## Title` |
| 完成項目 | 列表項加完成 emoji（勾選符號 U+2705） | `- [x] done` |
| 未完成項目 | 列表項加未完成 emoji（叉號 U+274C） | `- [ ] pending` |
| 警告提示 | 文字前加警示 emoji（警示燈 U+1F6A8） | `[WARNING] 注意` |
| 狀態標示 | 狀態用色彩 emoji（紅綠圓 U+1F534/U+1F7E2） | `[高]` `[低]` |
| 程式碼正確示範 | 註解內加肯定 emoji（U+2705） | `// 正確：` |
| 程式碼錯誤示範 | 註解內加否定 emoji（U+274C） | `// 錯誤：` |

> **本表設計原則**：禁止欄不直接展示 emoji 字元，改用「裝飾類別 + Unicode codepoint」描述，避免本檔自動載入時汙染 PM token attention pool（源於 PC-072 診斷，改版經驗另沉澱為 PC-080）。

**理由**：確保跨平台渲染一致性與文件專業性；CLI 環境處理 emoji 可能產生對齊問題與不同系統顯示差異。

#### 規則 3 豁免條款（按需讀取）

規格文件（`docs/spec/**/*.md`）對 src code log 字面的機械引用有限定豁免（三條件 AND：檔案位置 + 結構化前綴對應表引用語意 + 字面一致性）。編輯 spec 文件含 emoji log 字面前，讀取 `.claude/references/language-constraints-exemption-rules.md`。非結構化散落 emoji 仍適用規則 3 絕對禁令。

### 規則 4：技術術語保留原文

以下情況**保留英文原文**：

| 類型 | 範例 |
|------|------|
| 程式碼識別符 | `BookRepository`, `useCase`, `Widget` |
| 技術專有名詞 | Flutter, Dart, LSP, MCP, TDD |
| 指令和命令 | `/ticket create`, `git commit` |
| 檔案名稱 | `CLAUDE.md`, `pubspec.yaml` |
| API 和協定名稱 | REST API, WebSocket, JSON |

### 規則 5：字元集子集清單必須動態驗證

**維護任何「字元集子集」清單（簡體字黑名單、日漢字清單、異體字白名單等）時，禁止僅依人工判斷，必須用工具動態驗證清單純度。**

> **與規則 1-4 邊界**：規則 1-4 處理「輸出語言選擇」（寫什麼語言、用哪些詞、是否保留原文）；規則 5 處理「字元集清單維護品質」（如何維護字元辨識工具本身），聚焦不同。

**Why/Consequence**：人工無法可靠區分繁簡共用字與簡體專屬字（PC-074 二度自證），靜態清單必然累積誤差；共用字混入黑名單產生 false positive 打斷正常繁體文本，一次誤判即讓維護者繞過防護使守衛失效。

**Action**：「動態驗證」不等於「引入外部轉換函式庫」，可用清單間交叉比對取代——靜態清單本身仍是 frozenset，但清單之間、清單與對照表之間的一致性須由程式規則檢查，而非人工目視。

| 場景 | 反模式 | 正確做法 |
|------|-------|---------|
| 簡體字黑名單 | 人工列簡體字清單，無交叉驗證 | 建 codepoint 對照表（繁/簡/日新字體並列），啟動時比對黑名單與對照表一致性 |
| 日漢字黑名單 | 人工列日漢字清單，無交叉驗證 | 同上，額外檢查繁日共用字未誤入日漢字清單 |
| 異體字白名單 | 人工列異體字，無交叉驗證 | 同上機制延伸套用 |
| 任何字元集子集 | 靜態維護且無驗證 | 靜態清單（frozenset）+ 啟動時 self-check 交叉驗證規則一致性 |

實作參考：`.claude/hooks/askuserquestion-charset-guard-hook.py`（`SIMPLIFIED_CHARS`、`JAPANESE_ONLY` 兩個 frozenset 清單，搭配 `CONFUSABLE_PAIRS` 繁/簡/日新字體 codepoint 對照表；啟動時執行 self-check，交叉驗證「繁體字未誤入簡體黑名單」「日文新字體未誤入簡體黑名單」「繁日共用字未誤入日漢字清單」等一致性規則，任一規則違反即拋錯阻擋啟動）。

> **不採 OpenCC 的技術理由**：本規則原文（PC-074 v1.2.0）曾要求以 OpenCC `s2t(X) != X` / round-trip 動態過濾清單。PC-131 實證 OpenCC 對臺灣標準字有 30% 偏差，不適合作為清單純度的判準來源；後續查證亦確認該 hook 實作中 OpenCC 引用數為 0、PEP 723 dependencies 為空、環境未安裝此套件，規則文字與實作已脫節多時。此處改寫為上述靜態清單 + self-check 機制，此為實際運作中的動態驗證手段，「禁止僅依人工判斷」的核心主張不變，變更的僅是驗證手段。

> **來源**：PC-074（動態驗證主張起源，含完整案例、已知共用字清單、擴充流程）；PC-084（繁日共用字維度詳細案例）；PC-131（否定 OpenCC 作為驗證手段的技術理由，30% 偏差實證）；後續查證確認規則與實作脫節，定案改寫為靜態清單 + self-check 機制。
