# IMP-BAL-012: 合併標記語彙的正則抹除來源，清理任務據此靜默破壞另一機制

## 症狀

一個偵測工具以 `|` 把多套來源不同的標記語彙併入單一正則：

```python
EXEMPT_MARKER = re.compile(r"<!--\s*broken-link-exempt\b.*?-->|portability-allow")
```

下游任何複用該正則的分析，其產出的分類清單會把兩套機制的標記混為一談。當該清單被用來
驅動「清理多餘標記」類任務時，屬於另一套機制、功能完全正常的標記會被列為清理對象。

辨識訊號（依出現順序）：

1. 清理任務的命中清單裡出現「不該有這種問題的檔案」——例如失效連結清理命中了一批與連結
   無關的 skill 說明文件
2. 命中項的共同特徵是「該標記所在行的引用**都是活的**」——這正是另一套機制的正常狀態
3. 執行後偵測工具的輸出**完全不變**，沒有任何檢查會紅燈

第 3 點是本模式的核心危險：破壞完成後所有指標正常。

---

## 根因

正則的 `|` 是語法層的併集，不是語意層的併集。工具作者合併它們是為了「這兩種標記都讓我
跳過這一行」，這在**該工具自身的職責範圍內**完全正確；但正則一旦被下游複用，下游繼承的
是合併後的結果，而非合併時的那個理由。

來源資訊在合併當下就已遺失，且無法從匹配結果反推——`EXEMPT_MARKER.search(line)` 回傳
的 match 物件不告訴你命中的是哪一支。下游若要區分，必須自己重新拆開，但下游通常不知道
需要拆，因為正則名稱（`EXEMPT_MARKER`）表達的是用途不是組成。

實例中的兩套機制：

| 標記 | 所屬機制 | 語意 |
|------|---------|------|
| `broken-link-exempt` | 失效連結偵測 | 這個死引用是刻意保留的，別報 |
| `portability-allow` | skill 可攜性檢查 | 這個跨界引用是刻意的，非違規 |

第二種標記的引用**本來就是活的**（那正是它的用途），故在「有標記但該行沒有死引用」這個
判準下必然被歸為多餘標記。判準本身沒錯，錯在它作用的集合已經被污染。

---

## 案例

失效連結存量清理批次中，一張 ANA 量測「行級豁免標記連帶遮蔽同行有效引用」的範圍，正確
複用了偵測工具自身的 `extract_refs()` / `resolve_path()`（刻意避免自寫近似邏輯），但沿用
`EXEMPT_MARKER` 時未區分兩支語彙，得出「58 行中 28 行是零成本可刪的多餘標記」。

該數字直接支撐了兩項判定：選定「拆行」方向（理由是「近半免費」），以及否決「標記改引用級」
方向（理由是「只有 30 個真實案例，占全庫 0.7%，重寫核心邏輯不成比例」）。

驗收時以「僅 `broken-link-exempt`、排除備份目錄與歷史紀錄」重新統計，得多餘標記 7 檔 8 行、
混合行 52 檔 127 行。原判定的兩項成本論證前提皆不成立。

若未在派發前攔下，落地票會依「刪除多餘標記」的指示，把 `compositional-writing`、`spec`、
`tdd`、`saas-tech-selection`、`wrap-decision`、`5w1h-decision` 等 skill 的可攜性標記整批刪除，
而失效連結掃描輸出零變化。

值得注意的是，該 ANA 的方案評估表其實已列出 `portability-allow` 的存在（作為「標記出現形式
多樣」的風險項），但該認知未回頭套用到自己的分類定義上——**知道有兩支，仍用了合併後的那一支**。

---

## 解決方案

已發生時，以「只認一支語彙」重跑分類，並逐一比對新舊清單的差集；差集中的每一項都要能說出
它屬於哪一支。既有已執行的清理若已誤刪，從 git 歷史還原被誤刪的標記，不要憑記憶重建。

判定所依據的成本論證若引用了受污染的數字，該論證須重算——判定方向可能仍成立，但不能以
「結論沒變」為由略過重算，因為那等於用錯誤前提為正確結論背書。

---

## 預防措施

**複用他人的正則時，先看它的組成不只看它的名稱。** 正則名稱表達用途（`EXEMPT_MARKER` =
「該跳過的」），組成才表達來源。名稱不會告訴你它併了幾套東西。

具體檢查：複用的正則模式字串中若含頂層 `|`，逐一確認每個分支的來源機制，並判斷本次分析
是否需要區分它們。需要區分時，自行拆成獨立正則，不要傳整個 `EXEMPT_MARKER` 進分類邏輯。

**工具側的預防**：合併語彙時在常數旁註明每支的來源與用途，並提供拆分後的個別常數供下游
選用：

```python
BROKEN_LINK_EXEMPT = re.compile(r"<!--\s*broken-link-exempt\b.*?-->")
PORTABILITY_ALLOW = re.compile(r"portability-allow")
# 本工具自身跳過任一種；下游若需區分來源，請用上面兩個個別常數
EXEMPT_MARKER = re.compile(f"{BROKEN_LINK_EXEMPT.pattern}|{PORTABILITY_ALLOW.pattern}")
```

**驗收側的預防**：清理類任務若預期「執行後偵測輸出不變」，該預期本身就是訊號——輸出不變
代表偵測工具無法驗證這次清理，驗收必須改用其他手段（凍結快照的 before/after 逐項比對，
或刻意破壞後確認會被回報）。**不要把「數字沒變」當成「做對了」。**
