# IMP-GPD-022: 父容器的固定高度乘了等比縮放係數，子件高度契約寫的是未縮放 token，小視窗下子件被壓扁，內容被靜默裁切

## 基本資訊

| 項目 | 值 |
|------|-----|
| 分類 | implementation |
| 來源版本 | 0.5.0 |
| 風險等級 | 中 |
| 首次觀察 | 2026-10-31 |

## 症狀

固定高度的容器（工具列之類）把高度與內距寫成「token 乘縮放係數」，例如 `flutter_screenutil` 的 `(token).h`；容器裡的子件（下拉觸發器之類）依自己的契約寫固定高度 token，不乘係數。

在設計基準尺寸下，縮放係數是 1，兩邊一樣高，看不出問題。視窗縮小時係數小於 1，父容器變矮，子件的固定高度被父容器的緊約束壓小。扣掉子件自己的內距與邊框後，內容高度低於內容的固有高度，超出的部分被靜默裁切，不會拋 overflow 錯誤。

## 根因

**同一條高度鏈混用兩種單位**。父容器用的是「縮放後的設計單位」，子件用的是「固定的邏輯像素 token」。規格把兩者都寫成同一組 token（父容器高 = 子件高 + 2 × 內距），實作時只在父容器乘上係數，鏈的兩端就不再相等。

**測試字型遮蔽**。widget test 的測試字型，每個字符的高度恰好等於字級；實機字型的中文字形較高。被壓小的內容在測試字型下剛好放得下，換成實機字型才裁切。因此只有「最小視窗 × 實機字型」這一格會紅燈。

**overflow 斷言沒有鑑別力**。緊約束下子件只會照做並裁切，不拋錯。只檢查「沒有例外」的版面測試，對這類缺陷恆真（PC-BAL-010）。

## 解決方案

- 一條固定高度鏈（父容器高、內距、子件契約高）統一使用同一種單位：規格寫成固定 token 時，整條鏈都不乘縮放係數。
- 修在父容器，不修子件：子件的契約高是規格值，修法是讓父容器回到規格寫定的固定值，不是把子件調小到剛好塞得進去（TEST-GPD-1006）。
- 檢查方式：用「實得高度 >= 內容固有高度」的斷言（`getMaxIntrinsicHeight`），以實機字型在最小視窗尺寸跑一次。

## 預防措施

- code review 時，看到固定高度容器的高度帶縮放係數，就追問其子件的契約高有沒有帶同一個係數。
- 版面測試至少涵蓋「最小視窗尺寸 × 實機字型」這一格，並在檢查元件前先斷言畫面已到達就緒狀態，避免元件不存在時靜默跳過。
