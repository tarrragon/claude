# IMP-GPD-027: 紀錄端以比產生端窄的規則抽出衍生欄位，欄位外觀正常而下游聚合失真

## 基本資訊

| 項目 | 內容 |
|------|------|
| 風險等級 | 中 |
| 首次發現 | 2026-11-05 |
| 來源版本 | 0.6.0 |
| 適用範圍 | 從原始內容（prompt、訊息、路徑）以正則或解析器抽出識別碼並另存為欄位的日誌、索引、快取 |
| 偵測成本 | 低（對同一批資料以原始內容重新解析，計算與衍生欄位不一致的比例） |

## 摘要

**日誌裡的衍生欄位，是用紀錄當時的解析規則抽出來的。如果這個規則比識別碼的產生規則窄，欄位會靜默記成錯的值。** 值的格式仍然合法，不會報錯，而下游把它當聚合鍵時，不同實體會被併在一起，計數與比率同時失真。

## 症狀

- 衍生欄位的值都符合識別碼格式，看不出異常。
- 以該欄聚合時，少數鍵的計數特別高。例：一張父票看起來被派發十幾次，實際上是多張子票各派一次。
- 分母（實體數）偏低、每實體事件數偏高，比率偏向「重複發生」。

## 根因

產生端（例：建子票的 CLI）後來擴充了識別碼形態（多層後綴），紀錄端仍用舊的窄規則（單層後綴）抽取。兩端各自維護規則，沒有共用同一個定義，也沒有測試覆蓋新形態。

## 解決方案

1. 聚合前，先用原始內容對衍生欄位做一次全量比對，報出不一致筆數；不一致時改以原始內容重新解析作為聚合鍵。
2. 紀錄端改用與產生端相同的識別碼定義（共用模組中最寬、與產生端一致的變體），並補一筆產生端最新形態的測試。
3. 存量資料不回寫時，在讀取端註明哪一段期間的欄位不可信。

## 預防措施

- 共用的識別碼模組若同時提供多個寬窄不同的變體，標明各變體的使用者與限制；產生端擴充形態時，一併盤點窄變體的使用者。
- 依日誌做量測的票，口徑中寫明聚合鍵的來源（原始內容或衍生欄位）。

## 實例

派發日誌 hook 以單層後綴正則抽票號，ticket CLI 產生的多層子票號被截成上一層；一段期間的 687 筆實作層派發中有 98 筆不一致。重派率量測改從 prompt 的 `Ticket:` 行重新解析，才避開失真。觀測寫在 tarrragon/claude#54。
