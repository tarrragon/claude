# IMP-BAL-015: 子行程繼承環境變數使 cwd 隔離失效，且僅在呼叫端處於該環境時重現

## 基本資訊

| 項目 | 內容 |
|------|------|
| 風險等級 | 高 |
| 首次發現 | 2026-08-26 |
| 來源版本 | v0.2.1 |
| 適用範圍 | 任何以 `cwd=` 隔離子行程做驗證，而被測程式碼的路徑或設定解析會讀環境變數的情境 |
| 偵測成本 | 中（互動式重跑必過，需在真實呼叫環境下加診斷才能定位） |

## 摘要

**以 `cwd=` 啟動子行程做隔離驗證時，若被測程式碼的路徑解析優先讀環境變數，而子行程又繼承了呼叫端的環境，隔離就在解析的第一步失效——子行程會寫到環境變數指向的位置，不是 `cwd` 指向的位置。**

驗證邏輯因此比對錯了對象：它在隔離目錄檢查副作用，副作用卻發生在真實目錄。結論可能是任意方向的假訊號——被測對象健康卻被判為失敗，或反過來。

這個缺陷的診斷成本高於一般環境問題，因為**它只在「呼叫端本身處於帶有該環境變數的執行環境」時發生**。開發者在互動式 shell 手動重跑時，該變數通常不存在，路徑解析正確落到 `cwd`，測試通過。於是症狀表現為「自動執行時失敗、手動重跑必過」，這個形狀強烈暗示時序或負載問題，把調查引向錯誤方向。

## 症狀

- 同一段驗證邏輯在自動執行環境下失敗、在互動式 shell 手動重跑必定通過
- 失敗率與系統負載看似相關，實際上與「由誰啟動」相關
- 隔離目錄（`tmp_path` 等）在驗證結束後是空的或不含預期產物
- 真實工作目錄出現了本應寫進隔離目錄的檔案或紀錄
- 初步歸因傾向於逾時、競態、負載——因為「時好時壞」是這些問題的典型形狀

## 根因

| 環節 | 事實 | 後果 |
|------|------|------|
| 路徑解析的判準優先序 | 環境變數排在 `cwd` 之前 | `cwd=` 對解析結果沒有決定權 |
| 子行程環境來源 | `os.environ.copy()` 或預設繼承 | 呼叫端的變數原封不動傳入 |
| 呼叫端的執行身份 | 由自動化框架啟動時帶有該變數，互動式 shell 沒有 | 同一段程式碼在兩種環境下解析出不同路徑 |
| 驗證方式 | 在隔離目錄比對副作用有無 | 副作用寫到別處，比對對象與實際作用對象不一致 |

判準優先序本身通常是刻意設計——讓程式無論從哪個目錄被呼叫都能找到專案根，是合理需求。缺陷不在該設計，而在**驗證方需要的隔離語意與該設計直接衝突，且衝突不會報錯**。

## 最小重現

三個條件同時成立即可重現，與語言無關：

1. 被測程式碼的路徑（或設定）解析為多來源，環境變數優先於 `cwd`
2. 驗證方以 `cwd=<隔離目錄>` 啟動子行程，環境採繼承
3. 驗證方自身在帶有該環境變數的環境下執行

驗證方式：在隔離目錄與環境變數指向的目錄各檢查一次副作用。副作用出現在後者即命中。若手動重跑無法重現，改以「顯式設定該環境變數為不相關路徑」的方式模擬呼叫端環境。

## 案例：健康的元件被驗證機制判為崩潰（2026-08-26）

一個 SessionStart 期間執行的自檢機制，以 `uv run` 搭配 `cwd=<暫存目錄>` 逐一啟動各元件，比對啟動前後暫存目錄內索引檔的行數增減，判定元件是否可執行。

子行程以繼承方式取得環境，而該環境在自檢機制由框架以真實身份啟動時，帶有指向真實專案根的路徑變數。被啟動的元件因此把索引條目寫進真實專案，暫存目錄始終沒有新增行——所有健康元件一律被判為崩潰。

執行者最初將此歸因為系統負載造成的逾時，並據此加入三態逾時設計。以診斷探針定位後才確認真正成因，並在票面更正該誤診。三態設計本身作為系統過載防呆保留，但與本次問題無關。

值得記的是誤診的合理性：「自動執行必失敗、手動重跑必通過」在絕大多數情況下確實是負載或競態的徵狀。這個形狀本身沒有指向環境變數的訊號。

## 防護

| 時機 | 動作 |
|------|------|
| 以 `cwd=` 啟動子行程做隔離驗證時 | **明確設定**該環境變數為隔離目錄，不依賴繼承（`env[VAR] = str(isolated_root)`）。凡被測程式碼會讀的環境變數，驗證方都應顯式賦值而非放任繼承 |
| 撰寫多來源的路徑或設定解析函式時 | 在 docstring 明列判準優先序，並標明「以 `cwd` 隔離的驗證方需顯式覆寫優先來源」——解析的設計者知道優先序，驗證方通常不知道 |
| 遇到「自動執行失敗、手動重跑通過」的形狀時 | 在歸因為負載或競態**之前**，先比對兩種執行環境的環境變數差異。該形狀對環境差異與時序問題同樣相容，而環境差異的排查成本低得多 |
| 驗證邏輯依賴「某目錄內的副作用」時 | 加一道反向檢查：確認副作用**沒有**出現在非預期位置。只檢查預期位置無法區分「沒發生」與「發生在別處」 |
