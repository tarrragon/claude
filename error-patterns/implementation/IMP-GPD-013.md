# IMP-GPD-013: 分檔遷移的過渡路徑只要求編譯通過，舊入口的執行期行為卻跟著新政策一起改變

## 基本資訊

- **Pattern ID**: IMP-GPD-013
- **分類**: 實作（implementation）
- **風險等級**: 中（尚未遷移的呼叫端在遷移票合併前就先改變畫面行為；編譯與多數單元測試不會翻紅，只有版面高度類斷言或實機才看得到）
- **來源版本**: 0.5.0
- **相關 Pattern**: IMP-GPD-012（同屬「向後相容」判斷只看一個面向）

---

## 問題描述

### 症狀

- API 改版拆成「先上新入口、保留舊入口，呼叫端分檔遷移，最後移除舊入口」三段
- 派發時只寫了「遷移期間每張票合併後編譯通過、測試全綠」
- 實作者把新政策的判斷式寫在共用的 build 路徑，舊入口也走同一條判斷式：舊入口的預設值（例如行數上限為 null）在新判斷式下被解讀成新語意，執行期行為隨之改變
- 尚未遷移的呼叫端全部受影響，而它們的遷移票還沒開始

### 根因

「過渡路徑」有兩個不變式：編譯期相容（舊寫法還能編譯）與執行期相容（舊寫法的行為不變）。派發與驗收只寫了前者。新政策通常就是要改掉舊預設值的語意，共用判斷式時舊入口一定會被波及，除非明確把舊入口的行為凍結。

---

## 防護措施

| 時點 | 動作 |
|------|------|
| 派發過渡 API 票時 | acceptance 明寫「舊入口的執行期行為與改版前完全相同」，並要求一個針對舊入口、以舊預設值呼叫的行為測試（斷言舊結果） |
| 實作時 | 新政策的判斷只綁新入口；舊入口保留原分支，不與新入口共用帶新語意的條件式 |
| PM 驗收時 | 讀 diff 中被改動的共用條件式，代入舊入口的預設值手算一次結果，再看測試 |

## 觸發案例

AppText 行數政策改版（拆單行／多行兩個具名建構子，預設建構子留作過渡）：`overflow` 條件改為「無行數上限時 clip」，預設建構子 body 未傳行數上限即落入此分支，由單行省略號變成換行。PM 驗收時讀 diff 發現，合併前退回修正。
