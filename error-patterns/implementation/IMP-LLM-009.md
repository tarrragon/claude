# IMP-LLM-009: 識別符規則式以 \b 收尾，帶點號後綴或緊接中文字時回溯成較短的前綴

## 基本資訊

| 項目 | 內容 |
|------|------|
| 風險等級 | 中 |
| 首次發現 | 2026-11-13 |
| 來源版本 | 3.3.0 |
| 適用範圍 | 以 Python `re` 從自由文字擷取「主幹 + 可選點號後綴」形態識別符（子票號、版本號、章節編號）的程式，且規則式結尾加了 `\b` |

以下以 `<父票號>` 表示主幹、`<父票號>.2` 表示其子票號。

## 症狀

- 擷取 `<父票號>.2` 得到 `<父票號>`：子項被歸到父項判定，結果看似正常，只是對象錯了
- 識別符後面緊接中文字（`<父票號>.2的修正`、`<父票號>的`）時擷取結果同樣變短，或完全擷取不到
- 測試多半以空白或行尾結束識別符，兩種失效都不會出現

## 根因

1. **`.` 不屬 `\w`**：主幹結尾的數字與後綴的 `.` 之間本身就是字邊界。規則式沒有寫後綴（或後綴可選）時，結尾的 `\b` 在主幹結尾即成立，比對停在後綴之前。
2. **Python 3 的 `\w` 預設含中日韓文字**：`2的` 中兩個字元都屬 `\w`，之間沒有字邊界。結尾 `\b` 不成立時，引擎回溯縮短可變長度的部分（`\d+`、`(?:\.\d+)*`），直到找到成立的邊界——落在主幹與 `.` 之間，於是得到父項。
3. **與 PC-113 方向相反**：PC-113 的修法是「加 `\b` 防子字串誤判」。對帶點號後綴的識別符照做，子字串誤判換成了截短；截短的結果仍是合法識別符，下游查得到檔案，不會報錯。

## 案例

- UserPromptSubmit 的開發命令閘門以「兩側 `\b`、無後綴」的樣式擷取 prompt 中的票號。prompt 引用子票時被判成父票，父票缺必填欄位時整則 prompt 被丟棄（2026-11-13 修正，改用多層後綴且結尾不加 `\b` 的樣式）。

## 修復方式

- 規則式明寫後綴：`{主幹}(?:\.\d+)*`，結尾不加 `\b`。貪婪比對會吃完全部後綴，不需要結尾錨點。
- 確實需要結尾邊界時，用只排除「會延續識別符的字元」的前瞻，例如 `(?![\d.]*\d)`，不用 `\b`。
- 要防的是開頭被嵌進更長字串時，只在開頭加邊界（`(?<![\w.])`），結尾交給貪婪後綴。

## 防護

- 擷取識別符的測試至少含三種收尾：空白、緊接中文字、多層後綴（`.1.3.1`），三者都斷言擷取到完整識別符。
- 審查時看到識別符規則式以 `\b` 收尾且含可變長度部分，問：「後面接 `.數字` 或中文字時，回溯會停在哪？」
