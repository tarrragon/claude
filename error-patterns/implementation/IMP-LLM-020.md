# IMP-LLM-020: 白名單前綴比對前未收斂 `..` 路徑段

## 基本資訊

- **風險等級**: 中
- **發現**: 新增一個白名單前綴的審查中，在主線實測發現缺口早於該次變更

## 症狀

路徑權限檢查（允許清單優先、再比對禁止清單）對「允許前綴 + `../../` + 受限路徑」判為放行：
穿越寫法判允許，直接寫受限路徑則判拒絕。測試只用乾淨路徑時全綠。

## 根因

1. 允許清單以正則前綴比對字串，字串層的前綴不等於檔案系統解析後的位置。
2. 正規化函式只處理分隔符、根前綴、`./`，未收斂 `..`。
3. 允許清單先於禁止清單檢查，穿越路徑在第一關即放行。
4. 呼叫端另有「窄化門檻」（以正規化後字串判斷是否進入檢查）時，未收斂的字串會在門檻處被略過，連權限函式都沒呼叫。

## 解決方案

在所有前綴比對之前收斂 `.` 與 `..`（`posixpath.normpath`），再剝根前綴；收斂後仍以 `..` 開頭（跳出作用根）一律拒絕，不進入允許清單。收斂放在共用正規化函式而非單一判定函式，使呼叫端的門檻判斷也看到收斂後的路徑。

## 防護措施

1. 任何「字串前綴 / glob 白名單」在比對前先收斂路徑（`normpath` 或 `resolve`），跳出根者拒絕。
2. 測試必含穿越輸入（已知該拒絕的「前綴 + `../../` + 受限路徑」）與乾淨路徑對照。
3. 審查白名單時一併檢查呼叫端的前置門檻是否使用同一份正規化結果。
