# IMP-GPD-010: 專案以工具釘選語言版本，代理人直接呼叫 PATH 上的指令，產物落在全域版本

## 基本資訊

| 項目 | 值 |
|------|------|
| 編號 | IMP-GPD-010 |
| 類別 | implementation |
| 風險等級 | 中 |
| 發現日期 | 2026-10-20 |
| 來源版本 | 0.5.0 |

## 症狀

專案以 `.fvmrc` 把 Flutter 釘在某個版本。代理人在 worktree 裡直接執行 `flutter gen-l10n`、`flutter test`，沒有經過 `fvm`。PATH 上的 `flutter` 是本機全域預設版，與釘選版不同，所以：

- 舊版 gen-l10n 少產出一個空行，這個差異被提交進主幹。之後只要用釘選版重新產生，這個檔就會出現差異，各線合併前都得手動還原。
- 代理人回報的本機測試與分析綠燈，都是在全域版上跑出來的，不代表釘選版也是綠燈。

排查走了兩次錯誤歸因：先懷疑依賴重新解析，再懷疑 dart format。直到用拋棄式 worktree 對照「經 fvm」與「不經 fvm」兩種產出，才確認根因。

## 根因

| 層 | 原因 |
|----|------|
| 執行方式未宣告 | 專案文件記載了「版本由 FVM 釘選」，卻沒有規定「指令必須經 fvm 呼叫」。代理人看到 `flutter` 可以執行，就直接用了 |
| 無強制層 | 沒有任何守衛檢查 flutter／dart 呼叫是否經過釘選工具 |
| 結果同形 | 用全域版跑出的綠燈，和用釘選版跑出的綠燈，輸出看起來一樣；生成檔的差異也小到只有一個空行，不會引起注意 |

同類風險不限 Flutter，凡以工具管理版本的專案都有：Python 的 uv、Node／Vue 的 nvm、volta 或宣告的 package manager、PHP 的 composer 與版本管理器、多語言的 asdf／mise。

## 解決方案

1. 建立或接手專案時，先找出工具鏈的識別檔，確認實際的執行寫法。確認方式是用該寫法跑一次版本查詢，與釘選值比對。
2. 把確認後的寫法寫進 CLAUDE.md §1 的「執行方式」列。代理人會載入 CLAUDE.md，寫在那裡才能送達每個執行者。
3. 合併閘門與 CI 的指令也用同一個寫法，例如 `fvm flutter test`、`uv run pytest`。這樣即使代理人在本機用錯版本，閘門的結果仍然有效。

## 預防措施

- `CLAUDE-template.md` 的 §1 表格有「執行方式」列，並附常見工具鏈的識別檔與寫法提示。
- `project-init` skill 的〈建立或接手專案：確認執行方式〉一節列出確認步驟。
- 強制層（Bash 守衛：專案有釘選檔時，擋下未經工具的直接呼叫）尚未實作，追蹤於框架 issue。

## 實例

2026-10-20，一個以 FVM 釘選 Flutter 的專案，在多線並行開發時發生 l10n 生成檔漂移，影響多條線的合併。調查確認根因是代理人未經 fvm 呼叫 flutter。之後專案在 CLAUDE.md 規定一律經 fvm 執行，並由用戶要求把這項確認列為框架的注意事項。
