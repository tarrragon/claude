# IMP-BAL-017：訊息指名的抽象層與判準實際讀取的層不同

## 基本資訊

- **Pattern ID**: IMP-BAL-017
- **分類**: implementation（訊息與判準的層次一致性）
- **風險等級**: 高
- **關聯**: [[IMP-BAL-016]]（兩種成因壓成同一回傳值；彼處落差在同一層內的成因合併，此處在跨層改寫）、[[PC-GPD-001]]（追加型載體凍結未量測的宣稱；同屬載體承諾強於實際擔保，落差種類為時間軸而非抽象層）、[[ARCH-BAL-011]]（名稱造成職責已涵蓋的假象）、[[PC-BAL-036]]（規格宣稱與實作機制脫節）、[[IMP-BAL-010]]（空值表示判定失敗致守衛語意反轉）

一個判準讀取層 A（如 git tracked 樹、索引、快取）求值，但對外訊息以層 B 的語言陳述結論（如檔案系統、原始檔、真實狀態）。同一個述詞在兩層有不同答案時，訊息宣稱的事實與讀者所在層的觀察直接矛盾，而讀者無從得知該用哪一層驗證。

**Why**：判準與訊息通常由不同人在不同時間撰寫，且判準的層次選擇多為實作便利（tracked 樹比檔案系統好取、索引比原始檔便宜）。撰寫訊息的人以「這個判準想表達什麼」下筆，而非「這個判準實際讀了什麼」——兩者在多數情況下答案相同，落差只在兩層分歧時浮現，故不會在開發與測試期被觸發。函式 docstring 常保有精確措辭（撰寫者當下清楚判準來源），落差只出現在對外訊息，使程式碼審查讀 docstring 時看不出問題。

**Consequence**：

| 層級 | 影響 |
|------|------|
| 否證能力 | 讀者在自己所在的層查驗，得到與訊息相反的結果，卻無法判斷是訊息錯還是自己看錯層。此時多數人傾向相信訊息 |
| 破壞性 | 訊息若附帶操作建議（刪除、回退、清理），該建議依錯誤前提產生，且執行後果落在建議所指的層——最常見是刪掉實際存在的內容 |
| 傳播 | 分散式或多消費端場景中，訊息的接收者往往不是判準的擁有者，無權也無資訊修正它；錯誤結論因此在各節點各自成立 |
| 偵測 | 兩層答案一致時訊息正確，測試若只覆蓋一致情境則永遠綠燈；分歧情境通常由環境差異（本地設定、排除規則）產生，不在測試矩陣內 |

**Action**：

| 情境 | 做法 |
|------|------|
| 撰寫判準的對外訊息 | 措辭直接複述判準讀的東西，不複述它想代表的東西。「本地 tracked 樹中無此檔」而非「本地已刪除」 |
| 判準讀取層與陳述層必然不同（如讀索引陳述真實狀態） | 訊息並列兩種可能成因，不擇一斷言。「可能為已刪除，或被排除規則過濾」 |
| 訊息附帶破壞性操作建議 | 建議前加上該操作在另一層的後果，或要求接收者先在判準所在層複驗 |
| 收到與自身觀察矛盾的訊息 | 先問「這個判準讀的是哪一層」，再在該層複驗，不在自己習慣的層反覆確認 |
| 程式碼審查 | docstring 精確不代表訊息精確，兩者須分別讀。落差多半只在對外訊息 |

**識別訊號**：docstring 與使用者可見訊息對同一判定使用不同層次的詞彙；訊息描述的狀態可被讀者直接查驗且查驗為否；跨節點回報的問題在來源端無法重現；訊息用「已刪除」「不存在」「未設定」等終態詞，而判準實際只讀了某個衍生視圖。

**邊界**：與 `PC-GPD-001`（追加型載體凍結未量測的宣稱）同屬「載體承諾的語意強於它實際擔保的語意」家族，但落差的種類不同——該模式的落差在**時間軸**（記錄寫於某時點，讀者取得的是現況宣稱，載體不強制呈現時間），且其最深一層指出風險最高者非過期的量測而是**從未量測過的宣稱**（無時間可標、無命令可重跑，故無法被低成本推翻）；本模式的落差在**抽象層**（判準讀某層、訊息述另一層）。兩者的處置同構：先問載體攜帶了什麼把手（量測時間與命令／判準所在層），再問內容對不對。

該家族另有一個轉述方向的變體：把某次量測得出的結論搬給他人時只搬結論、不搬產生它的量測，則成立條件隨量測一併脫落，接收方拿到的是無適用域的斷言。此變體的實證為一句「那則缺漏提醒是誤報，可直接忽略」——說話者的依據是自身環境（兩側檔名大小寫一致）下該提醒確為誤報，但條件未隨結論送出，接收方所處環境（索引與磁碟認知不一致）下該提醒為真，照該建議行動會留下三個無入口檔的 skill。**三者的補救動作同一個：把量測命令與它跑的環境隨結論一起送出，接收方即可自行重跑判斷適用與否。**與 `IMP-BAL-016`（兩種成因壓成同一回傳值，訊息指名其中一種）的差別在落差的軸向——那是同一層內多個成因被壓縮，本模式是單一成因跨層被改寫。與 `PC-BAL-036`（規格宣稱與實作機制脫節）的差別：那是規格與實作兩份文件的落差，本模式的判準與訊息在同一份程式碼內且彼此相鄰。與 `ARCH-BAL-011`（名稱造成職責已涵蓋的假象）同屬「名稱承諾與實際語意差一層」家族，但那作用於架構命名，本模式作用於單次判定的輸出。

**實證來源**：`sync-claude-push.py` 的 `detect_stale_remote_files` 以 `git archive HEAD` 解出的 tracked 樹為 `reference_dir` 求值，docstring 精確寫「本地 git tracked 樹已無」；使用者可見訊息（第 2624 行）寫「本地已刪除但遠端殘留的 tracked .claude/ 檔（孤兒）」，並建議跑 `--clean` 傳播刪除。

某消費專案的 `.gitignore` 含 `*.js` 通配（原意排除前端建置產物，副作用波及 skill 隨附腳本），使某 skill 的 4 個 `.js` 全數 untracked。該端 push 時四檔被列為孤兒並附 `--clean` 建議。上游複驗：四檔在上游本地與 canonical 皆存在且 tracked，執行該建議會從共用 repo 刪除四個正常檔案，破壞所有消費端的該 skill。

該消費端在檔案系統層查驗得到「四檔都在」，與訊息的「本地已刪除」直接矛盾，但因無從得知判準讀的是 tracked 樹，該矛盾無法在本地解釋。**訊息的層次錯置使矛盾看起來像自己的觀察有誤**——這是本模式與單純措辭不精確的關鍵差異：它不只是說得不夠清楚，而是主動把讀者的正確觀察推翻。

同期在同一組對話中另有兩例同族落差：一個以 `carrier` 命名的欄位被讀為目錄（實為含檔名的路徑模式），一組以 `*_REQUIRED_FIELDS` 命名的常數被讀為規範（實為觀察記錄，且無任何 validator 消費）。三例的共同形狀是名稱或措辭承諾的語意比實際語意高一層，而讀者依承諾行動。
