# IMP-LLM-010: 以 str.lstrip("./") 去路徑前綴，會連 .claude/ 開頭的點一起剝掉，框架路徑比對永不命中

## 基本資訊

| 項目 | 內容 |
|------|------|
| 風險等級 | 中 |
| 分類 | implementation（路徑正規化） |
| 來源版本 | 3.3.0 |
| 首次觀測 | 2026-11-13 |

## 症狀

以 where.files 等清單比對目標路徑的檢查，對 `lib/`、`src/` 開頭的路徑正常命中，對 `.claude/` 開頭的路徑一律回報「命中 0」。沒有錯誤、沒有例外，只是提醒或判定從不發生。單元測試全綠，因為測資只用不以點開頭的路徑。

同一寫法在同一程式庫重複出現：一處已在先前修過並在 docstring 註明禁用，之後新寫的程式碼與既有的另外兩處仍沿用。

## 根因

`str.lstrip(chars)` 的引數是**字元集合**，不是前綴字串。`".claude/hooks/x.py".lstrip("./")` 會逐字剝掉開頭所有屬於 `{'.', '/'}` 的字元，得到 `"claude/hooks/x.py"`。作者的意圖是「去掉 `./` 前綴」，讀起來也像，但語意不同。

失效只在路徑以點開頭時出現，而框架自己的檔案正好都以點開頭；以一般產品路徑寫的測資剛好避開唯一會出錯的輸入。

## 解決方案

只去字面前綴：

```python
rel = path.strip().removeprefix("./")          # Python 3.9+
# 需處理 "././foo" 這類重複前綴時
while rel.startswith("./"):
    rel = rel[2:]
```

## 預防措施

- 路徑比對的測試至少含一筆以點開頭的路徑（`.claude/...`、`./.claude/...`）作為正向對照，斷言它命中。
- 看到 `lstrip("...")` 引數長度大於 1 時，確認作者要的是字元集合還是前綴；要前綴就改 `removeprefix`。
- 修一處時全庫 grep 同一寫法（非測試碼），其餘命中一併建票。
