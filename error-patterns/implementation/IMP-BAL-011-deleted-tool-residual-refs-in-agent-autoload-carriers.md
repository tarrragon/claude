# IMP-BAL-011: 刪除工具後的殘留引用在代理人自動載入載體上是行為缺陷，且被刪工具承擔的職責未隨引用一併交接

## 基本資訊

| 項目 | 說明 |
|------|------|
| 分類 | Implementation |
| 風險等級 | 高 |
| 來源版本 | v0.2.1 |
| 發現日期 | 2026-08-22 |
| 與 IMP-042 關係 | IMP-042 是本模式的基底（刪除後殘留引用未同步清理）；本模式補其未涵蓋的三個維度 |

## 症狀

刪除一個工具腳本（實例為某測試摘要 shell 腳本）後，`grep` 全庫仍命中大量引用，且呈現四種彼此無法互相推斷的形態：

| 形態 | 判別方式 | 實測數 | 正確處置 |
|------|---------|-------|---------|
| 真失蹤 | 同名檔搜尋不到，且反向搜尋層確認無接手者 | 4 個 | 判定廢止則改寫為現行慣例並加註；判定應存在則屬功能缺口另案 |
| 合併型遷移 | 同名檔搜尋不到，但反向搜尋在某現役元件內找到原名的併入紀錄 | 2 個 | 改為接手者路徑；此類最易被誤判為真失蹤，見 PC-BAL-053 |
| 路徑漂移 | 檔案存在但已遷入子目錄，引用仍寫舊扁平路徑 | 6 個 | 改路徑即解，不改內容 |
| 示例佔位符 | 名稱本身即示例（`foo.py` / `a.py` / `guard.py` / `hook-name.py`） | 11 個 | 不動，改寫反而破壞示例 |

四者在 `grep` 輸出中形態完全相同，必須逐一查證才能分流，且查證需做滿「修復既有殘留時的分流順序」全部四步——省略最後的反向搜尋層會把合併型遷移併入真失蹤。把四者當同一批處理，會對示例佔位符做出破壞性改寫，並對合併型遷移得出「功能缺口」的假結論。

## 根因

### 根因一：殘留引用的嚴重性由載體決定，不由引用本身決定

IMP-042 把殘留引用定性為「語義矛盾，不影響功能但誤導讀者」（Medium）。此定性只在**人工閱讀載體**成立。當殘留引用位於**代理人自動載入載體**且形態是**可執行指令**時，讀者不是人而是代理人：

| 載體 | 載入時機 | 殘留可執行指令的後果 |
|------|---------|-------------------|
| `.claude/agents/*.md` | 派發時載入代理人 context | 代理人照做，得到 No such file |
| `.claude/skills/*/SKILL.md` | skill 呼叫時載入 | 同上 |
| `.claude/references/**`、`.claude/error-patterns/**` | 人工按需閱讀 | 讀者察覺路徑失效並自行判斷 |

代理人不會「察覺後自行判斷」——它可能誤判執行環境損壞而中止，或自行改用未受約束的替代指令（實例中即為裸的全量測試命令，正是周圍禁令要防的行為）。這是行為缺陷，不是文字矛盾。

### 根因二：被刪工具承擔的職責沒有隨引用一併交接

被刪的測試摘要腳本同時承擔兩件事：執行測試，以及把輸出截斷到可用大小。文件中它出現的位置，周圍恆有「禁止裸執行全量測試（輸出數 MB，會耗盡 context）」的禁令——該腳本是這條禁令唯一的替代方案。

刪除者的心智模型是「移除這個檔案」，不是「這個檔案在幫誰承擔什麼」。因此單純移除引用行會讓禁令變成沒有替代方案的空禁令，讀者（代理人）為了完成測試只能違反禁令。**刪除工具時真正要交接的是該工具承擔的職責，不是引用字串。**

### 根因三：刪除者與引用者資訊不對稱

刪除 `.claude/hooks/` 下某腳本的人，不會知道某個 agent 定義檔有 4 處在教代理人跑它。反向索引不存在，且刪除操作沒有任何機制強制建立它。

## 防護措施

### 刪除任何可執行工具前的三步檢查

| 步驟 | 動作 | 判準 |
|------|------|------|
| 1 | `grep -rn "<檔名>" .claude/ docs/` 取得全部引用 | 命中即需分流，不可假設「只有我在用」 |
| 2 | 對每個命中判定載體等級 | 命中落在 `.claude/agents/` 或 `.claude/skills/*/SKILL.md` 且形態為可執行指令者，優先級高於其餘 |
| 3 | 列出被刪工具承擔的職責，逐項指定接手者 | 職責無接手者時，刪除即製造空禁令，應先建立替代方案再刪 |

### 修復既有殘留時的分流順序

先 `ls` 驗證再改寫，順序不可顛倒：

```bash
# 1. 抽出全部引用路徑
grep -rhoE '\.claude/hooks/[A-Za-z0-9_./-]+\.(sh|py)' .claude/agents/ .claude/skills/ | sort -u

# 2. 逐一驗證存在性（分出真失蹤）
for f in $(上一步輸出); do [ -e "$f" ] || echo "MISSING: $f"; done

# 3. 對 MISSING 者全庫搜尋同名檔（分出路徑漂移）
find .claude -name "<basename>" -not -path "*/archived/*"

# 4. 反向搜尋層：前一步仍無命中時反轉搜尋方向，找「提到這個名字」的現役元件（分出合併型遷移）
grep -rn "<basename>" .claude/hooks/ .claude/skills/*/hooks/
```

**反向搜尋層不可省略**：前三步全部以檔名為鍵；接手者取新的上位語意名時（合併型遷移的常見形態，與原名無共同詞根），這三步必然為盲。省略反向搜尋層會把運作中的功能誤判為缺口，據此建票、寫 error-pattern、甚至重建已存在的能力。完整論證與實例見 `PC-BAL-053`（該檔以「反向搜尋層」指同一動作，其內部序號為第 3 層）。

### 改寫時同時交接職責並留下更正說明

改寫格式：

```markdown
> `<被刪路徑>` 已刪除，現行慣例改為<替代做法>（見 `<權威規則路徑>`），<日期> 文件複查更正。
```

替代做法本身若承擔了原工具的某項職責，需在該處點明承擔關係，否則後續維護者會把它當成可省略的修飾。實例中的補述：「管道是輸出限制的承擔者，省略截斷管道會使全量測試輸出重新耗盡 context，即本節禁令要防的失效。」

## 與 IMP-042 的邊界

| 維度 | IMP-042 | IMP-BAL-011 |
|------|---------|-------------|
| 對象 | 刪除章節／概念後的文字殘留 | 刪除可執行工具後的指令殘留 |
| 嚴重性定性 | Medium（誤導讀者） | 高（代理人照做即失敗） |
| 防護重點 | 刪除後全檔 grep 搜尋 | 載體分級 + 職責交接 + 四分類分流 |
| 讀者 | 人 | 代理人（不會自行察覺並修正） |

遇到殘留引用時先套 IMP-042 的全檔搜尋，再以本模式判定載體等級與職責交接需求。

## 學習要點

- 同一個 `grep` 命中集合可能混雜四類語意（真失蹤／路徑漂移／合併型遷移／示例佔位符），逐一查證是分流的唯一手段，不能靠檔名形態猜測
- `ls` 與同名搜尋只能分出前兩類與最後一類；合併型遷移須以**反向搜尋層**（找提到原名的現役元件）才能分出，遺漏這一步即得出功能缺口假結論
- 判斷殘留引用的嚴重性時，先問「誰會讀到這行」而非「這行寫錯了什麼」
- 刪除工具是職責移轉事件，不是檔案移除事件；沒有接手者的刪除會把周圍的禁令變成無解禁令
