# IMP-LLM-012: 拿 git 狀態當「兩個檔案仍一致」的證據

## 基本資訊

| 項目 | 內容 |
|------|------|
| 風險等級 | 中 |
| 分類 | implementation（以版本控制狀態推論檔案一致性） |
| 來源版本 | 3.3.0 |
| 首次觀測 | 2026-11-13 |

## 症狀

一個檢查器原本用 mtime 判斷「設定檔比衍生檔新，衍生檔可能過期」，誤報偏多。為了少誤報，改成「衍生檔在工作區未改動，且設定檔的相關區段與 HEAD 相同，就視為一致」。測試全綠，正向對照（改相關區段仍提示）也通過；但審查者用臨時 repo 找到兩個情境，修改前會提示、修改後卻不提示：

1. 設定檔的相關變更已提交，但產生衍生檔的命令沒跑，衍生檔沒動。例如拉到別人只提交了設定檔的變更。
2. 衍生檔被 `.gitignore` 忽略。`git status --porcelain -- <衍生檔>` 對被忽略的檔沒有輸出，輸出為空被讀成「未改動」。

兩個情境都是漏報：放寬改動讓檢查器少提示了一則本該提示的訊息，測試沒有任何一則轉紅。

## 根因

推論把兩個 git 事實當成一致性的證據，但它們回答的是別的問題：

| 拿來用的事實 | 它真正回答的問題 | 被當成的意思 |
|------|------|------|
| 設定檔與 HEAD 相同 | 這份內容是否已提交 | 衍生檔是依這份內容產生的 |
| `git status` 對衍生檔無輸出 | 該檔沒有「已追蹤且被修改」或「未追蹤且未忽略」的狀態 | 該檔與提交版本相同 |

「已提交」只保證兩個檔案各自進了版本歷史，不保證它們是同一次產生的一對；在不同 commit 分別提交、或只提交其中一個都很常見。`git status` 的空輸出則同時涵蓋「乾淨」與「被忽略」兩種狀態，無法區分。

測試抓不到的原因：測試 fixture 都在同一個 commit 一起提交兩個檔案，也沒有建立 `.gitignore`。fixture 剛好落在「兩個假設都成立」的情境，正向對照只檢查了「改相關區段會提示」，沒有涵蓋「基準本身已失效」。

## 解決方案

比對基準改為「衍生檔最後一次改動的那個 commit 裡的設定檔」：

1. `git log -1 --format=%H -- <衍生檔>` 取衍生檔最後一次提交的 commit。
2. `git show <該 commit>:./<設定檔>` 取當時的設定檔，與目前內容比對相關區段。
3. 查不到該 commit（衍生檔未追蹤、被忽略）時視為無法判定，回到原本的保守判定。
4. 衍生檔在工作區已改動的檢查保留：它的內容已不是該 commit 的版本。

`git log -- <path>` 對被忽略、從未提交的檔沒有輸出，自然落入「無法判定」，不需另外判斷忽略狀態。

## 預防措施

- 用 git 狀態推論「A 與 B 一致」前，先寫出「這個 git 事實真正保證什麼」，再對照要推論的命題；兩者不同就換一個能直接回答的事實（例如「B 最後一次改動時的 A」）。
- `git status --porcelain -- <path>` 的空輸出不可單獨解讀為「未改動」。需要區分時，加 `--ignored`，或改問 `git ls-files --error-unmatch <path>`（是否被追蹤）。
- 放寬類修改的反向測試，除了「目標情境不再觸發」與「原觸發條件仍觸發」，還要列出放寬判準依賴的每個前提，並為每個前提各建一個前提不成立的 fixture，斷言仍觸發。本例的前提有兩個：兩檔在同一次提交、衍生檔被追蹤。
- 同一 fixture 對修改前版本跑一次：前提不成立的情境中，修改前與修改後的結果應相同。
