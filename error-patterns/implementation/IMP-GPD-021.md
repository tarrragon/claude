# IMP-GPD-021: 刪檔或搬檔前以完整路徑字串搜尋引用端，同目錄的相對 import 只寫檔名、不含目錄段，盤點清單漏列

## 基本資訊

| 項目 | 值 |
|------|-----|
| 分類 | implementation |
| 來源版本 | 0.5.0 |
| 風險等級 | 低 |
| 首次觀察 | 2026-10-30 |

## 症狀

一張票要刪除 `<dir>/<name>` 這個轉接檔，引用端改指向新位置。派發前，PM 以 `grep "<dir>/<name>"` 盤點引用端，把命中的檔案全部寫進票的改動範圍。代理人刪檔後跑靜態分析，發現 `<dir>/` 底下還有一個檔案以 `import '<name>'` 引用它，這個檔不在改動範圍內，提交被範圍守衛拒絕，只好回頭補宣告。

## 根因

**同目錄引用不寫目錄段**。相對 import 在同目錄時只寫檔名，路徑字串中沒有 `<dir>/`。以完整路徑搜尋，只抓得到從其他目錄引用的寫法。

**搜尋字串被當成語意查詢**。「誰引用這個檔」是語意問題，答案取決於語言的路徑解析規則；字串搜尋只能找到其中一種寫法。命中清單看起來完整，漏掉的部分沒有任何訊號。

## 解決方案

- 盤點引用端時，以檔名本身搜尋（`grep "<name>"`），再逐筆排除同名但不同目錄的命中。
- 或在 worktree 內先刪檔，以靜態分析／編譯器列出所有斷掉的引用，用這份清單作為改動範圍；這是語言解析規則本身給出的答案。

## 預防措施

- 派發刪檔或搬檔票時，改動範圍的來源寫成「檔名搜尋」或「刪檔後的分析結果」，不寫「完整路徑搜尋」。
- 驗收時對舊位置做兩種查核：完整路徑字串 0 筆，且舊目錄內以檔名相對引用的寫法也 0 筆。
