# IMP-LLM-006: 模板標記圈出的跳過區塊在內容寫入後仍生效 → 實質內容永久不被掃描

## 基本資訊

- **Pattern ID**: IMP-LLM-006
- **分類**: 實作 bug（implementation）
- **來源版本**: 3.2.0
- **發現日期**: 2026-11-11
- **風險等級**: 中
- **影響範圍**: 任何「掃描文件內容、但要略過模板說明文字」的檢查器（hook、validator、lint），且以一個會留在文件裡的標記（註解、Schema 行、哨兵字串）作為略過區塊的起點，到下一個結構邊界才結束

---

## 問題描述

### 症狀

檢查器在某些章節完全失效，但沒有任何錯誤或警告：章節裡明明寫了該被攔下的內容，檢查照樣放行。檢查器自己的測試全綠，因為測試只餵了「模板原樣、尚未填寫」的章節。

實例：`phase4-decision-enforcement-hook.py` 原本以 `<!-- Schema[<type>/<section>]: ... -->` 這一行為起點，一路略過到下一個 `## ` 或 `---`。建票模板在每個章節開頭寫入 Schema 行，填寫者把內容寫在 Schema 行下方，Schema 行不會被刪。結果全部票檔中，凡是有 Schema 行的章節，填入的內容都被整段略過，延後話術的掃描在這些章節從未生效。實測一張票的 Solution 有 21 行被略過，另一張票有 764 行被略過。

### 根因

略過區塊的設計前提是「標記出現 = 這段還是模板」。但標記的生命週期與模板內容不同：

| 物件 | 何時消失 |
|------|---------|
| 模板說明文字（佔位符） | 填寫者覆寫或刪除時 |
| 標記本身（Schema 行） | 永不消失，它是章節的結構描述 |

標記的存在只能證明「這個章節曾經是模板」，不能證明「這段現在還是模板」。以標記為起點、以結構邊界為終點的區塊，在內容寫入後仍然涵蓋整個章節。

這和章節錯位（PC-110：內容寫進錯的章節）不同：這裡內容寫在正確的位置，是檢查器的略過範圍錯了。

### 為什麼測試抓不到

測試資料取自模板，略過區塊內只有說明文字，「略過」與「沒有東西可攔」在輸出上無法區分。這是 `test-assertion-design-rules` E2 描述的形態：守衛的測試缺少「已知該紅」的正向對照輸入。

---

## 解決方案

略過範圍改為「以行為單位、依行本身的形態判定」，不從標記推論一個區塊：

1. 只略過本身就是模板說明的行：剝掉 HTML 註解片段後沒有剩下文字的行，以及多行註解的內部行。模板佔位符也改為註解形態（`<!-- 必填：… -->`），讓「是不是模板」可以從單行判定。
2. 會被寫在註解裡的有效宣告要排除在略過範圍外。例如整行只有 `<!-- PC-093-exempt: … -->` 的豁免宣告，必須照常蒐集；格式錯誤的宣告也要蒐集，才能回報錯誤。
3. 未關閉的註解只算開頭那一行。檢查器屬於強制閘門，寧可多掃，也不讓一個漏掉的 `-->` 使檔案其餘內容靜默放行。
4. 改動前後用全部現存文件比對命中結果：新增的命中應全部是過去被藏起來的實質內容，既有命中不應消失。

---

## 預防措施

- 設計略過規則時先問：「這個起點標記在內容寫入後會不會消失？」不會消失的標記，不能當區塊起點。
- 略過規則的測試必須包含「模板標記仍在、下方已有實質違規內容」的輸入，並斷言它被攔下（`test-assertion-design-rules` E2）。
- 模板說明文字用可單行判定的形態（HTML 註解）書寫，讓下游檢查器不需要區塊推論。
- 修改略過規則後，以全部現存文件比對新舊命中，作為影響範圍的證據。
