# ARCH-PM-001: 邊緣觸發的衍生資料在多裝置合併下逐輪補規則，審查不收斂

## 基本資訊

| 項目 | 內容 |
|------|------|
| 風險等級 | high |
| 來源版本 | PM v0.1.0（規格與用例的四輪多輪審查之後，2026-11-05） |
| 情境 | 離線優先、多裝置同步、合併時不重播事件的個人應用；規格階段的文字審查 |

## 症狀

- 由其他資料自動產生的「衍生資料」（例：由處方產生的領藥任務、由完成產生的下一次重複任務、前置全部結束後自動完成的收尾步驟），規格寫成「某事件發生時當下做什麼」。
- 同步只搬資料、不重播事件。每一輪審查都找到「某種交錯順序下事件效果遺失」，修法是再加一條「在某時點重新檢查」的規則。
- 下一輪審查在新規則之間又找到缺口：兩條規則互相打架（一條重開、一條結束），或判斷只拿到「目前狀態」，拿不到「是誰、為什麼造成這個狀態」。
- 停止訊號遲遲不成立：每一輪都產生下一輪的待驗結構。

## 根因

1. **邊緣觸發不能跨合併存活**：事件反應只在產生事件的那台裝置執行一次；合併後的狀態組合沒有對應的事件，效果就遺失。補「重新檢查」等於把邊緣觸發一條條改成水平觸發，但只改了審查者想到的那幾條。
2. **狀態的來源被折疊**：判斷標準只收「目前是 done」，不收「是使用者完成的，還是系統因來源而結束的」，重開條件只能靠痕跡推測（例如比對時間戳是否相等）。
3. **文字審查覆蓋的是審查者想到的順序，不是順序空間**：交錯組合呈指數成長，逐輪個案實跑永遠只覆蓋一部分。

## 解決方案

1. 每種衍生資料只定義一個**期望狀態函式**：輸入只有來源資料，輸出「應未結束／應完成／應放棄／不表態」。
2. 一張**通用套用表**依目前狀態與期望執行：只建立、結束、重開；不改寫使用者可改的欄位（避免以較新的時鐘蓋掉另一台裝置上使用者同時的修改）。
3. 把使用者意圖存成**明確欄位**（例：最後一次狀態寫入者是使用者或系統），重開只作用於系統結束的列；合併規則讓「使用者最後一次結束」勝過系統寫入。
4. 在固定時點**冪等對帳**（本機命令後、拉取完成後、開始一天、啟動），時點與順序只寫在一個住址；同步只套用一部分時不對帳。
5. 驗證從文字審查換成**可執行模型的性質測試**：隨機交錯兩台裝置的操作，斷言兩邊業務資料逐列相同、對帳執行兩次第二次不產生變更。

## 預防措施

- 設計多裝置同步的衍生資料時，先問「合併後沒有事件，它怎麼知道要變？」答不出來就是邊緣觸發，直接改成期望狀態函式。
- 審查中同一類缺口（事件遺失、規則互斥）連續兩輪出現時，停止補規則，換驗證方法（可執行模型）或換機制。
- 冷讀新機制時特別檢查兩種邊界：一列同時被兩個函式管（需要「一列只歸一個函式」的優先規則）；對帳跑在只套用一半的同步資料上。
- 「記下某件事」若是來源事實（例：記下一次就醫連到某任務），不要記成使用者對任務的意圖，否則來源被刪除後衍生資料不會回復。
