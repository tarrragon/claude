# ARCH-BAL-006：宣告層枚舉窄於執行層判準，讀者據宣告自我豁免

## 摘要

**一項機制的適用範圍在文件中以枚舉清單表述，在程式中以通用判準執行；枚舉少於判準涵蓋範圍時，讀者查表得到「此處不適用」的結論而停止檢查。** 未被枚舉但實際受管轄的區域因此成為無人自查的死角，違規在該區累積。

與 ARCH-BAL-003 的差別在失敗的**音量**。ARCH-BAL-003 是宣告寬於執行（判準完整、名單缺項），使用者符合判準卻被擋住，會撞牆、會抱怨、會找繞道——問題吵，因此會被發現。本 pattern 是宣告窄於執行，讀者得到的是「不用管」而非「被擋住」，沒有任何摩擦訊號，因此可以潛伏到有人為了別的目的去比對兩層時才暴露。

## 症狀

- 文件的「適用範圍」「支援清單」「允許路徑」以目錄或項目枚舉呈現，程式端則以前綴、正則或通用條件判定
- 某區域實際受機制管轄，但不在文件枚舉內；該區域的違規累積且無人自查
- 讀者依文件做出比實際更保守或更寬鬆的錯誤結論，且該結論不會被任何回饋修正
- 兩層的落差不是靠使用者回報暴露，而是靠一次無關的比對偶然發現
- 枚舉清單的最後更新時間遠早於程式端的最後更新時間

## 根因

| 環節 | 事實 | 後果 |
|------|------|------|
| 兩層表述形態不同 | 文件用枚舉（可讀性佳），程式用判準（可執行） | 兩者無法逐字比對，同步只能靠人記得 |
| 新增區域的路徑不經過文件 | 建立新目錄或新檔案類型時，作者不會想到有一份文件在枚舉範圍 | 落差單向擴大 |
| 落差方向決定是否有回饋 | 宣告窄於執行時，讀者的結論是「不適用」，不會撞牆 | 沒有摩擦即沒有訊號，落差無法自我暴露 |
| 執行層通常只管新寫入 | PreToolUse 類守衛攔截寫入，不掃既有內容 | 落差期間寫入的違規內容永久留存，之後也不會被回頭檢查 |

**為何「不會撞牆」比「會撞牆」更危險**：撞牆會產生使用者行為（回報、繞道、質疑清單），這些行為本身是偵測訊號。自我豁免不產生任何行為——讀者做完查表就離開了，系統中沒有任何地方記錄「有人以為這裡不適用」。缺乏訊號的錯誤只能靠主動稽核發現，而主動稽核的觸發條件通常是別的事情。

## 案例一：規則 8 適用範圍表窄於守衛掃描前綴（2026-07-27）

`.claude/references/reference-stability-rules.md` 規則 8 的「適用範圍」表枚舉 9 個目錄（`rules` / `pm-rules` / `references` / `methodologies` / `error-patterns` / `agents` / `skills` / `hooks` / `best-practices`），不含 `.claude/config/` 與 `.claude/lib/`。

執行層 `reference-stability-rule8-guard-hook.py` 的 `SCAN_PREFIX = ".claude/"` 為全域，僅豁免 `.claude/handoff/archive/`。

後果：`.claude/config/` 累積 17 處 ticket ID 引用，其中 3 處為依賴型（`來源：Ticket <id>`、`相關 Ticket：<id>`、`<id> acceptance #4/#8 已明示`），sync 至其他專案後皆為死連結。守衛在寫入時本會告警，但既有內容從未被掃描；而任何查表的維護者都會得到「config 不適用規則 8」的結論。落差由一次無關的白名單擴充作業偶然揭露。

## 案例二：權限拒絕訊息枚舉窄於允許清單（2026-07-27）

`.claude/lib/path_permission.py` 的 `ALLOWED_PATTERNS` 含 18 條 `.claude` 項目；拒絕訊息（`.claude/lib/hook_messages.py`）列出 11 個允許子目錄，缺 `scripts` / `analyses` / `templates` / `lib`（md） / `output-styles` 與兩條根目錄檔案模式。

後果：主線程嘗試寫入 `.claude/templates/` 前先讀拒絕訊息，據該清單判定該目錄不可寫，差點把一項本可執行的變更誤報為受阻。此處的錯誤方向是「過度保守」——與案例一的「自我豁免」相反，但成因相同：讀者信任枚舉，枚舉不完整。

兩個案例的落差方向相反（一個少列受管轄區、一個少列可用區），共同結構是**人讀的枚舉與機器執行的判準各自維護**。

## 防護

| 層 | 措施 |
|----|------|
| 設計層 | 人讀的枚舉由執行層判準**生成**，不平行維護。訊息文字從 pattern 清單動態組出，文件表格改為描述判準本身（「`.claude/` 全域，豁免 X」）而非列舉成員 |
| 檢查層 | 生成不可行時，加啟動期 self-test：比對兩層並在不一致時輸出具體差異項。此檢查成本低於任何一次落差造成的誤判 |
| 表述層 | 枚舉若保留供閱讀，明文標注「以程式端 X 為準，本表為說明性質」，使讀者知道枚舉不是權威 |
| 稽核層 | 執行層若只管新寫入（PreToolUse 類），落差修正後須對既有內容補一次全量掃描——守衛從那一刻才開始管的區域，之前的內容不會自己合規 |

**方向判準**：不確定誰是權威時，以「誰決定實際行為」為建立端。文件描述行為，程式產生行為；兩者衝突時改文件，不改程式來遷就文件。

## 與其他 pattern 的邊界

| Pattern | 聚焦 | 差異 |
|---------|------|------|
| ARCH-BAL-003（白名單判準與成員脫節） | 宣告**寬**於執行：判準完整、名單缺項 | 失敗會撞牆，使用者產生可觀測行為。本 pattern 宣告**窄**於執行，失敗是靜默的自我豁免 |
| ARCH-BAL-002（識別符雙載體，工具只讀一側） | 同一識別符存在兩處，工具只認一處 | 該 pattern 兩側都參與資料流；本 pattern 一側純供人閱讀，不參與執行 |
| ARCH-BAL-005（自證式豁免理由無消費端） | 理由欄位無任何程式讀取 | 該 pattern 的宣告從不影響行為；本 pattern 的宣告影響**人的行為**（是否自查），只是不影響程式行為 |
| IMP-BAL-003（稽核器與消費端解析器嚴格度落差） | 兩層都在執行，嚴格度不同 | 本 pattern 一層是文字宣告 |

## 驗證方式

- 對每份「適用範圍 / 支援清單 / 允許路徑」文件，找出對應的執行層判準，逐項比對涵蓋範圍
- 落差修正後，對「新納入宣告的區域」執行一次全量內容掃描，不假設守衛已經管過
- 新增此類清單時，在同一位置寫下權威方（哪一層說了算）與同步機制（生成 / self-test / 人工）
