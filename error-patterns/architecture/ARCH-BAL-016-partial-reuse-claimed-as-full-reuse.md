# ARCH-BAL-016: 宣稱重用他處實作，實際只重用中段，頭尾各自重寫成第二套

## 摘要

**當某段流程因「維護第二套實作導致漂移」而被移除，後續恢復時若只重用流程中段而自行重寫頭尾，重複並未消失，只是換了漂移軸。** 重用宣告寫在 commit message 與 docstring 裡並被審查接受，因為中段確實重用了；頭（取得輸入、解析設定）與尾（輸出格式、後續指引）各自重寫的部分不在宣告的檢視範圍內。

原本的漂移軸（例如資料 schema）被封住了，新的漂移軸（例如來源設定、環境變數覆寫、輸出契約）開著。下一次上游變更時，失效形態與被移除的那一版完全相同。

## 症狀

- commit message 或 ticket 出現「重用而非重寫」「不維護第二套實作」這類宣告
- 該宣告在審查中未被逐段核對，因為存在一個真實的重用點可指
- 上游模組已有函式承擔完整流程（取得輸入 → 處理 → 輸出），消費端卻只取用中間的處理函式
- 消費端出現與上游逐字同構的片段：同一組字串轉換、同一個常數、同一份預設值
- 上游的設定機制（環境變數、設定檔、參數覆寫）在消費端失效，且兩端對同一輸入給出互相矛盾的判定
- 取用的是上游的私有名稱（底線開頭），沒有任何契約測試保護

## 根因

| 環節 | 事實 | 後果 |
|------|------|------|
| 上游 public 介面顆粒度過細 | 上游只導出處理函式，完整流程封裝在 `cmd_*` 這類與 CLI 輸出綁定的函式內 | 消費端無法整段重用，只能取中段 |
| 中段可重用而頭尾不可 | 頭（設定解析）與尾（輸出）與上游的 CLI 呈現耦合 | 消費端自行重寫頭尾，形成第二套 |
| 宣告的檢驗粒度是「有無重用」 | 審查問「是否重用」而非「重用覆蓋了流程的哪幾段」 | 有一個真實重用點即通過 |
| 重寫的頭尾看似瑣碎 | 一行字串轉換、一個常數，單看無足輕重 | 不觸發「這是第二套實作」的警覺 |
| 私有名稱耦合無契約 | 消費端取用底線開頭的名稱，上游測試對此無感 | 上游重命名時消費端 runtime 才失效 |

**與一般程式碼重複的差別**：一般重複沒有宣告，發現即可合併；本 pattern 帶著「已經重用了」的宣告，該宣告會讓後續審查跳過這一段，重複因此獲得豁免。

**與「移除第二套實作」決策的關係**：本 pattern 常出現在「因重複而移除」之後的恢復階段。移除的決策正確，恢復的方向也正確，失誤發生在恢復的執行粒度——恢復者記得「不要重寫」這條約束，但把它套用在最顯眼的那一段（通常是核心演算法），而非整條流程。

## 案例：sync-push 的 skill 庫漂移檢查（2026-08-08）

### 事件鏈

1. 某腳本自行實作「比對本地與遠端資產版本」的檢查
2. 遠端 manifest 的 schema 由扁平字串改為巢狀結構，該腳本的比對未同步，字串比 dict 永遠不相等 → 全數誤判為漂移，且比較本身不拋例外故外層 `except` 攔不到
3. 處置為移除該實作，改印一行提示引導使用者執行上游 CLI；理由記為「不重複維護第二套比對邏輯」
4. 該提示引用的子命令不存在（上游 CLI 從未有此子命令），無任何測試驗證其可執行性，失效潛伏
5. 恢復檢查時，以 `importlib` 載入上游模組並取用其分類函式，commit message 記「重用即同時滿足兩者」
6. 多視角審查發現：分類確實重用，但取得遠端 manifest 的 URL 拼裝、來源常數、輸出格式與後續指引全部重寫

### 實證

恢復後的實作硬編碼來源 URL，繞過上游 `get_repo_url()` 的環境變數覆寫：

```
設 SKILL_SYNC_REPO=https://github.com/example/other-skills.git 後
  上游 CLI 使用:      https://github.com/example/other-skills.git
  腳本漂移檢查使用:    https://github.com/tarrragon/claude-skills.git
  一致: False
```

在有設定該環境變數的環境中，兩端會對同一批資產比對不同來源，輸出滿螢幕假分歧——與步驟 2 被移除的那一版失效形態相同，只是漂移軸從 schema 換成來源設定。

### 審查為何能發現而 commit 時沒有

審查者的提問是「重用覆蓋了流程的哪幾段」，而非「有沒有重用」。逐段核對後，頭尾兩段的重寫立刻顯形。commit 階段的自檢問的是前者的反面——「我有沒有重寫核心邏輯」——答案為否，因此通過。

## 防護

| 時機 | 動作 |
|------|------|
| 寫下「重用而非重寫」類宣告時 | 逐段列出流程的每一段（取得輸入 / 處理 / 輸出 / 後續指引），標明每段是重用還是自寫；任一段自寫即不可宣告整體重用 |
| 消費端取用上游私有名稱（底線開頭）時 | 要求上游提供 public 介面，或在上游測試套件加對外契約斷言，讓破壞在改動發生的那一側現形 |
| 上游已有涵蓋完整流程的函式時 | 優先要求上游把該流程拆出 public 版本，而非在消費端重組中段 |
| 審查含重用宣告的變更時 | 對消費端 grep 上游的常數字面值與字串轉換片段，逐字同構者即為第二套 |
| 消費端複述上游的操作指引時 | 檢查上游是否已輸出更精確的指引（帶參數、帶對象名）；若是，消費端的複述應刪除而非加護欄 |
