# PC-GPD-067：接手續作只處理最後一段範圍補充

## 基本資訊

| 項目 | 內容 |
|------|------|
| Pattern ID | PC-GPD-067 |
| 分類 | process-compliance（接手續作的範圍核對） |
| 風險等級 | 中 |
| 來源版本 | 0.5.0 |
| 首次觀測 | 2026-10-13 |
| 關聯 | [[PC-APP-007]]（多來源併入一張票時驗收項遺失；本模式的範圍連 acceptance 都沒進）、[[IMP-031]]（部分完成報成全部完成）、[[PC-BAL-019]]（交接內容完整被誤讀為交接已建立） |

## 摘要

**一張票的範圍若是以多段「範圍補充」陸續追加在票面，而不是寫進 acceptance，接手續作的人只會處理最近、最顯眼的那一段。** 完成自檢只對照 acceptance，acceptance 不含任何一段補充，所以自檢全數通過，「無遺留項」的宣稱讀起來像已經核對過。

## 症狀

- 票面有兩段以上標題相近的範圍補充（例如「PM 範圍補充：併入某審查的發現」），分屬不同時間、不同來源。
- acceptance 沒有隨補充增列，仍是建票時的條目。
- 接手者的 Solution 只逐項回應其中一段，結尾寫「上列各項皆已完成或查明，無遺留項」。
- 稽核者把各段補充逐項對照產出時，才發現前面幾段沒有被核對過。

實例（2026-10-13）：一張腳本修正票的票面有三段範圍補充：併入一次審查的第 1 至 6 項、併入另一次審查的第 7 至 10 項、以及一段訊息用詞的修正。原執行者暫停後，另一個 session 接手續作，只處理了最後一段（用詞修正），收尾寫「無遺留項」。事後驗收稽核逐項查證前十項：五項已因其他變更不成立，五項仍為原狀，票面沒有標註也沒有票承接。稽核結論為不通過，遺漏的五項另建兩張票。

## 根因

- **Why**：範圍補充以追加段落的形式存在，寫的人省掉了「同步改 acceptance」這一步，範圍與驗收從此分離。接手者讀票時，最後一段離暫停紀錄最近，標題又和前面幾段相近，容易被當成「目前的待辦」；前面幾段讀起來像已被處理過的歷史。
- **Consequence**：

| 層級 | 影響 |
|------|------|
| 範圍履行 | 前幾段補充的項目靜默遺漏；票照常完成，遺漏要到稽核才出現 |
| 宣稱可信度 | 「無遺留項」以只核對一段的結果宣稱全部；讀者無從分辨核對了哪幾段 |
| 自檢失效 | 完成閘門與自檢都對照 acceptance，範圍不在 acceptance 內，兩者都抓不到 |

## 解決方案

- **Action**：

| 時點 | 做法 |
|------|------|
| 追加範圍補充時 | 同步以 acceptance 指令增列一條，指向該段補充的標題與項數（如「範圍補充〈併入某審查〉第 1 至 6 項逐項有處置」） |
| 接手續作時 | 先列出票面所有範圍補充段落與各段項數，寫進接手紀錄，再開工 |
| 宣稱無遺留前 | 逐段逐項列出處置（完成／已不成立／另建票），以表格呈現；只核對部分段落時，寫明核對了哪幾段 |

事後發現遺漏時：依稽核的逐項處置表補建票或標註已不成立，並更正原「無遺留項」的宣稱，不刪除原句。

## 預防措施

- 範圍補充的寫入改由票務指令完成，指令同時增列 acceptance，讓補充無法只停在票面文字。
- 接手流程的檢查清單加一項：「票面範圍補充段落數與 acceptance 涵蓋的段落數是否相等」。
