# PC-GPD-054: 主控以口頭核准的「獨占時段」給負載實驗，但合併閘門只認機械名額，看不到口頭時段；主控同時放行閘門送出，兩者重疊而互相污染

## 基本資訊

| 項目 | 值 |
|------|-----|
| 分類 | process-compliance |
| 來源版本 | 0.5.0 |
| 風險等級 | 中 |
| 首次觀察 | 2026-10-30 |

## 症狀

並行 session 協作時，重度測試的互斥有兩套機制：
- 機械名額：合併閘門與包裝過的測試指令，啟動前要先以檔案鎖取得名額。
- 口頭時段：主控在訊息裡核准某條線「現在可以跑」。

研究線申請一段 CPU 滿載的負載實驗，主控以口頭時段核准。實驗本身沒有透過名額機制啟動。接著主控在同一輪放行另一條線送合併閘門，以為「時段」已經把兩者錯開。

閘門取名額時，看不到任何持有者，就直接開跑。兩者重疊的後果有兩個：閘門可能在滿載下出現與程式碼無關的逾時紅燈，實驗量到的耗時也會被閘門的負載拉高。

實證（2026-10-30）：主控核准負載實驗後放行閘門，幾秒後才發現重疊並發出更正。更正送達時閘門已經啟動，只能中止；中止又在快照清理途中打斷，殘留了一個快照 worktree。

## 根因

**口頭時段與機械名額是兩套互不相通的互斥**。主控心中的「時段」只存在於訊息裡，閘門的判斷只看鎖檔。主控以為一套機制管住了全部，實際上只管住了會讀訊息的那一方。

**「放行閘門」和「核准實驗」在主控端是兩個獨立決定**。分開處理時，各自看都合理，但沒有人檢查兩者是否搶同一份資源。

## 解決方案

- 核准會占滿 CPU 的實驗時，同時凍結所有線的閘門送出，並明確通知各線：「實驗結束前不得送閘門」。
- 或者讓實驗透過名額機制啟動（例如以包裝指令執行整段實驗），讓閘門取名額時能看到持有者並排隊。

## 預防措施

- 放行任何閘門前，先查目前是否有已核准、還沒結束的口頭時段。
- 時段核准寫進協調票，並寫明會被凍結的動作（閘門送出、其他測試）。
- 長期改善方向：口頭時段一律落到名額鎖上，讓機械層成為唯一的互斥來源。
