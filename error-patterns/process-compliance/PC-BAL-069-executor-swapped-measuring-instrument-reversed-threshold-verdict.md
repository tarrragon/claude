# PC-BAL-069: 執行者換了量尺量門檻，得出與規範相反的結論而報告外觀相同

## 基本資訊

| 項目 | 內容 |
|------|------|
| 風險等級 | medium |
| 發現途徑 | skill 拆分修票的 acceptance 寫「分段估算 < 5,000 tokens」，執行者改用 tiktoken cl100k 實測得 7,730，判未達成並登記 spawn request |
| 復發次數 | 一次；同日另一執行者對同一檔用規範公式得 4,770 |
| 來源版本 | v0.2.1 |

## 摘要

**規範對一個門檻給了自己的量測方法（含校準依據），執行者改用另一種看起來更權威的儀器量同一對象，得到方向相反的結論；兩份報告在文字上都是「量了、數字、判定」，讀者無從分辨儀器不同。**

門檻是「數字 + 儀器」的組合，不是數字本身。換儀器等於換門檻，而換的人以為自己只是量得更準。

## 症狀

- 同一份檔案兩位執行者量出相差 60% 的 token 數，判定一過一不過
- 執行者以「規範的估算是近似，我用實測更準」為由替換方法，未查規範的公式是否有校準依據
- 報告寫「實測 N tokens」而不寫用哪個分詞器，下游把它當成與規範同一量尺
- 未達成的 acceptance 被登記為 spawn request，實際是儀器不同

## 根因

| 環節 | 事實 | 後果 |
|------|------|------|
| 規範只寫門檻與公式，沒寫「不可換儀器」 | 公式看起來是近似值，執行者合理地認為實測優於估算 | 替換儀器不被視為違規 |
| 校準依據住在公式旁的一句話 | 「以 /context 實測校準」這句說明公式是對目標 tokenizer 的校準，讀者跳過它 | 執行者不知道公式已是實測代理 |
| 不同分詞器對 CJK 粒度差異大 | cl100k 對繁中約 1 token/字，目標 tokenizer 約 1.3 字/token | 同一檔差 60% |
| 報告欄位只有數字沒有儀器 | acceptance 表與 Test Results 記「N tokens」 | 讀者無法察覺儀器已換 |

## 案例：tiktoken 7,730 vs 規範公式 4,770（2026-09-08，skill 拆分修票）

1. 修票 acceptance：「SKILL.md body 分段估算 < 5,000」（規範：skill-design-guide〈Progressive Disclosure〉公式）
2. 執行者以 tiktoken cl100k_base 量 body 得 7,263（改前）→ 7,730（改後），判「超標在本票開始前就存在，非本票能解」，登記 spawn request 建議另開瘦身票
3. PM 以規範公式量同一 HEAD 得 5,059，指出儀器不同；執行者重量得 4,770（改前）→ 5,059 → 精簡後 4,966，通過
4. 儀器差異回饋至框架 issue（規範應明寫量尺不可替換）

## 第二條路徑：量尺在別處被汰換，票面不留任何痕跡

前述案例是執行者主動換儀器。同一族還有一條相反的路徑——**執行者忠實沿用票面寫的量尺，而那把量尺早已在規範側被換掉**。

| 環節 | 事實 |
|------|------|
| 舊量尺 | 全檔字元數比單一門檻（門檻 = 目標 token 數 × 單一 CJK 係數） |
| 新量尺 | 分段加總（ASCII 與非 ASCII 各用各的係數）後直接比 token 門檻 |
| 汰換發生的位置 | 規範檔的某一次改版，**票面與被量對象都不會有任何變化** |
| 誤差方向 | 單向：舊法只多抓不漏抓，ASCII 佔比越高偏得越多 |

一次跨專案交叉核對的實測：同一批 skill，舊字元法判 27 支超標，現行分段法判 10 支，**17 支為偽陽性、零漏網**。偽陽性名單依 ASCII 佔比排，最前面幾支是全英文內容；其中一支正是**寫下現行判準的那份規範自己**——被它自己汰換掉的舊判準判為超標。另有一張票記載某 skill「46,270 字元、7.12 倍」，實際在現行判準下是 4,933 tokens 未超標，該數字同時錯在方法與時效。

**為何難以察覺**：票面數字、被量對象、執行者的操作三者都沒有變，變的是規範。復核時若只問「這個結論是否已被推翻」，答案是否；要問的是「這個結論所依據的量尺是否仍是現行的」，而那個答案住在另一個檔案裡。

**Action**：任何引用門檻判定的票，在其被消費（收束、驗收、據以排序）時，先回建立端確認量尺版本，再看數字。跨專案共用資產尤其如此——一端更新規範，另一端的存量票會靜默地全部過期。記錄量測結果時同時記下所用公式與該公式的來源版本，使後續讀者能判斷是否需重量。

## 共同結構：拿低維表徵當高維事實的代理

下列三種偏誤是同一個結構在不同載體上的實例——都以一個便宜取得的表徵代替昂貴的事實比對，而該表徵在關鍵情況下鑑別力正好為零：

| 代理 | 真正的事實 | 鑑別力為零的情況 |
|------|-----------|-----------------|
| 計數 | 集合成員 | 方向相反的兩個錯誤數量相抵 |
| 版號 | 內容雜湊 | 內容變更而版號未動（同號異容） |
| 字元數／行數 | 分段 token 估算 | ASCII 佔比高的檔案 |

**實測**：一次跨專案同步比對中，以 `metadata.version` 判定分歧得 2 支，以內容雜湊判定得 8 支，其中三支正是同號異容。同一次流程裡，同號異容在兩個不同的 skill 上各發生一次且都推了才發現。

**判別問句**：這個判準讀到的是事實本身，還是事實的一個投影？投影相等不蘊涵事實相等——凡是「便宜、可直接讀、單一純量」的判準，都要先問它在什麼情況下會與事實脫鉤。

**版號比計數更危險**，因為它額外帶有「較大者較新」的語意，讓讀者以為它不只是標籤而是可排序的事實。同號異容時那個語意正是誤導的來源——它讓人連「要不要比對內容」這個問題都不會問。計數至少不宣稱自己蘊涵順序。

**Action**：以版號判斷是否需同步時，同時取內容雜湊；工具若提供內容比對就以其為準，版號只作為人類可讀的標籤。

## 交叉核對要比對成員，不能只比對計數

發現量尺問題最有效的手段是兩方各自獨立量同一批對象再交換結果。但**交換的必須是成員清單，不能只是總數**——計數是集合的有損投影，方向相反的兩個錯誤會在投影上互相抵銷，呈現為完美吻合。

同一次交叉核對的兩組對照說明了差別：

| 對照組 | 兩方數字 | 交換的內容 | 結果 |
|--------|---------|-----------|------|
| 檔案體量 | 10 對 10 | 數量**加上**「17 偽陽性、0 漏網」的成員分解 | 一致為真證據 |
| description 長度 | 22 對 22 | 只有數量 | 兩個相反的錯誤同時存活 |

description 那組的真相是：正解量法與舊量法都得 22，但**成員不同**——舊法漏抓一支用 YAML 折疊純量寫的（`description: >` 後接多行縮排，單行 regex 只讀到分隔符，636 字元被算成 1），又多抓另一支。一漏一多恰好抵銷。若當時只交換數字，雙方會同時確認「22，一致」，然後兩個缺陷都留下。

**兩種偏誤的方向相反且各自單向**：字元法只多抓不漏抓（ASCII 佔比越高偏越多），單行 regex 只漏抓不多抓（讀到容器而非內容）。共同的判別問句是「**這個量法讀到的是內容本身，還是內容的容器**」。

**Action**：交叉核對時交換超標成員清單而非總數；兩方數字相同但未比對成員時，不得視為已互相印證。最低成本的做法是兩邊各交出超標清單、取差集，**差集為空才算一致**——前述 22 對 22 那組若交的是清單，一眼就看得出兩支各在一邊。

## 副本分歧使「超標」失去共同指稱

共用資產（多消費端同步的 skill、規範、設定）的體量判定量的是**各自的本地副本**。副本已分歧時，兩方報出的倍數指的不是同一份內容，交叉核對會把分歧誤讀為量法差異。

一次實測：兩方報同一支共用 skill 為 1.09 倍與 0.63 倍，跨越門檻兩側。查三方（發佈庫、我方、對方）後確認是對方副本落後約 9,000 字元，量法無誤。

**風險不對稱且不可自我判定**：收斂者若持有較新副本，收斂結果正確；持有較舊副本則會把回退固化進收斂成果並推給全體消費端。而收斂者從自己這一側看不出是哪一種——本地副本永遠自洽。

**Action**：對共用資產做體量收斂前，先與其他消費端交換該資產的版號與字元數確認量的是同一份內容；發佈庫版本為第三方基準。對齊是收斂的前置條件，不是禮貌。

## 解決方案

1. **門檻條文明寫儀器**：「以本公式為準；tiktoken 或其他分詞器的結果不進判定」，並把校準依據放在門檻同一行
2. **報告欄位帶儀器名**：Test Results 記「4,966 tokens（skill-design-guide 分段估算公式）」，不記裸數字
3. **判未達成前先核對量尺**：acceptance 引用的量測方法與自己用的是否同一個；不同即先換回再判
4. **儀器差異回饋規範層**：差距大到翻轉判定時，把兩個數字與儀器名附到規範的 issue，讓規範決定要不要換權威儀器

## 預防措施

| 層級 | 措施 |
|------|------|
| 規範撰寫 | 量測指令旁一句「不可用其他儀器替代」與校準依據 |
| 派發 prompt | acceptance 引用門檻時附量測指令原文或路徑 |
| 驗收 | PM 驗收用規範指令重量，不採信報告裸數字 |
| 報告契約 | 數字欄位強制帶儀器名 |
