# PC-GPD-071：了結寫成敘事，沒寫配對行

## 基本資訊

| 項目 | 內容 |
|------|------|
| Pattern ID | PC-GPD-071 |
| 分類 | process-compliance（交接文件的機器可讀狀態） |
| 風險等級 | 中 |
| 來源版本 | 0.6.0 |
| 首次觀測 | 2026-11-02（同一主控 session 第二次發生） |
| 關聯 | [[PC-GPD-070]]（同屬交接文件的狀態宣告與實際狀態不一致） |

## 摘要

**待辦由一行固定格式開啟、由另一行同鍵的固定格式關閉時，以敘事段落（查證段、裁定紀錄）寫下「此事已了結」，不會關閉該待辦。** 看板、狀態列等讀取端只認配對行，敘事段對它們不可見；待辦因此一直掛著，直到用戶發現並提問。

## 症狀

- 協調票有一行 `**用戶待辦**（鍵）`。用戶裁定後，主控寫了「主控查證：… 經用戶授權 …」，沒有寫 `**用戶待辦完成**（鍵）`。
- 看板持續列出這項待辦。協調票結案、換版後，殘留仍留在舊票上。
- 主控每輪檢查的工具只回報各線狀態，不回報未配對的待辦，所以主控看不到殘留。

## 根因

- 敘事記錄和配對行服務的讀者不同：前者給人讀，後者給工具讀。寫完前者，作者會覺得「已經記錄了」。
- 規則文字已規定「條件成立時同一輪寫完成行」，但沒有工具在寫敘事時提醒，也沒有工具在每輪檢查或結案時列出未配對項。

## 防護

| 情境 | 做法 |
|------|------|
| 記錄某項待辦的裁定或結果 | 同一筆 append 先寫配對行（完成行），再寫敘事；不要只寫敘事 |
| 讀取端只認固定格式 | 主控的例行檢查工具要列出未配對的開啟行，不只看各線狀態 |
| 承載待辦的票要結案或換版 | 結案前檢查開啟行是否全部配對；未配對的阻擋結案，或轉移到新票 |

## 檢查問句

寫「已裁定」「已處理」之前問：這件事在票上有沒有一行開啟它的固定格式？有的話，這次 append 是否也包含關閉它的那一行？
