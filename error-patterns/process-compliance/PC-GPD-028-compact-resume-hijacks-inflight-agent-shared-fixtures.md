# PC-GPD-028: context 壓縮後以工作區空目錄推斷在飛代理人已停擺，接手並污染其共用器材

## 基本資訊

| 項目 | 內容 |
|------|------|
| 風險等級 | 高 |
| 分類 | process-compliance |
| 來源版本 | 0.1.0 |
| 來源事件 | 一次探針回歸輪的並行接手 |
| 首次觀測 | 2026-09-18 |

## 症狀

context 壓縮（compact）後，主線程讀到某票狀態為進行中、其產出目錄為空、派發腳本就緒，於是接手執行該票的下一步。實際上原代理人仍在執行，只是停在兩個步驟之間。兩個執行體同時操作同一批共用器材。

進一步的症狀是**主線程在代理人的實驗材料上做了修改**（該次為採納複核建議、收緊五份題目檔的共用尾綴），而該材料位於共用暫存目錄、不受版控、無 diff 可查。

## 根因

三個條件疊加：

1. **壓縮摘要記錄的是「當時在跑」，不是「現在在跑」**。摘要是記錄平面，而代理人的執行進度在世界平面；兩者在壓縮的時間差內必然漂移。
2. **產出目錄為空被讀成「尚未開始」**。工作區狀態屬瞬時，空目錄同時相容於「尚未開始」與「正在準備」兩種狀態，而接手者只會看到前者——因為那是接手所需的前提。
3. **代理人清單未被查詢**。`ListAgents` 可分辨 idle 與 busy，但接手者在已形成「它停了」這個判斷之後，不會再去查一個自認已知的事實。

第 2 點是本模式的核心：**「可以接手」與「需要接手」在可觀測面同形**。空目錄不提供區分這兩者的資訊，而接手的動機會把歧義解讀為有利的那一支。

## 後果

| 層面 | 後果 |
|---|---|
| 實驗完整性 | 在飛實驗的輸入被中途更換。若原代理人未察覺，其全部機械檢查的綠燈都建立在已不存在的輸入上 |
| 記錄一致性 | 同一張票被兩個執行體各寫一套記錄。該次是主線程先 complete，代理人隨後追加數節；acceptance 勾選被 CLI 擋下（代理人未用逃生閥，處置正確） |
| 判讀可比性 | 兩組判定者讀同一批作答，一組零分歧、一組有分歧。結論的差異無法歸因於方法或材料，因為兩者都不是控制變數 |
| 訊號缺失 | 共用暫存目錄非版控，被他方寫入時無 diff、無時間戳比對、無任何訊號 |
| **誤歸因** | 原代理人循線詢問時，首先被懷疑的是提出該修改建議的複核者——因為**改法與它的建議逐字相同**。若非該複核者能舉證自己全程未呼叫寫入工具，帳會算到它頭上 |

該次未造成錯誤結論——原代理人偵測到材料被改，在改後內容上重跑全部機械檢查與洩題複核並全綠。**偵測成功屬該代理人的謹慎，不屬流程保證。**

## 解決方案

接手任何進行中的票之前，依序執行：

1. **查代理人清單**：`ListAgents` 讀該票對應代理人的列，確認是 idle 還是 busy。停止不是終態——idle 的代理人可被 `SendMessage` 喚起並帶原 transcript 續行。
2. **不以工作區空目錄作為「已停擺」的依據**。空目錄是瞬時狀態，對「是否在飛」零鑑別力。
3. **確認在飛時，改為喚起而非接手**：`SendMessage` 到其名稱問進度，不要並行執行同一批步驟。
4. **必須動其器材時，先取雜湊**：修改前後各記一次材料雜湊並寫入票面，使被改事件在事後可查。
5. **事後歸因先查自己**：材料被改而作者不明時，第一個排除的對象應是「提出該修改建議者」——建議與實作逐字相同正是誤歸因的放大因子，不是證據。

## 預防措施

| 機制 | 內容 |
|---|---|
| 器材側 | 共用暫存目錄的實驗材料，在材料定稿與派發當下各記一次檔案雜湊並比對；不一致即停手 |
| 流程側 | 壓縮後恢復的第一個動作是代理人清單查詢，先於任何票務判斷 |
| 條文側 | 「產出目錄為空」不得作為接手的充分條件，須與代理人狀態合取 |

## 邊界

本模式**不涵蓋**前 session 遺留的未完成工作（該情形代理人確實已不存在，接手是正確動作）。判別點是代理人清單：列存在且 busy 屬本模式；列不存在或已完成屬遺留接手。兩者症狀同形而處置相反。
