# PC-BAL-032：以單一環境的證據推翻另一環境的記錄

**分類**: process-compliance
**嚴重度**: 高（結論指向另一個 session 的誠實性，且會寫進框架資產）
**首次捕獲**: 2026-08-12

---

## 一句話

手上的證據為真、推理形式有效，結論仍然錯誤——因為證據只覆蓋自己所在的環境，而被審查的記錄產生於另一個環境。

## 觸發條件（三者同時成立）

1. 存在兩個以上並行的執行環境（多台機器、多個 working copy、容器與宿主、CI 與本機）
2. 各環境的觀測會寫進**同一份共用記錄**（ticket、worklog、框架文件）
3. 審查者只能取得**自己這一側**的旁證（本機日誌、本機檔案系統、本機環境變數）

第 3 點是關鍵：旁證越硬，越容易被當成足以定案。程式產生的日誌不會說謊，但它也不會說「我只記錄了這一台」。

## 失效形態

| 階段 | 發生的事 |
|------|---------|
| 1 | 環境 A 的 session 觀測自身環境，把結果寫進共用記錄 |
| 2 | 環境 B 的接手者讀到該記錄，在自己這側複驗，得到相反結果 |
| 3 | 接手者尋找旁證，找到程式產生的硬證據（日誌計數、目錄列表），全部支持自己這側 |
| 4 | 接手者下結論：原記錄是虛構的 |
| 5 | 該結論被寫進共用記錄與框架資產，成為後續讀者的既定事實 |

第 4 步的推理在單一環境假設下完全正確。錯的不是推理，是那個未被說出口的假設。

## 為何難以自我察覺

- **證據品質給出錯誤的信心**：`grep -c` 於本機日誌得到 12084 比 0 這種懸殊比數，直覺上不留任何懷疑空間。但比數大小與「證據涵蓋範圍是否足夠」無關。
- **虛構假說有現成的解釋框架**：LLM confabulation 是已知現象且有既有 error-pattern 可援引。有名字的假說比「可能有另一台機器」這種無名假說更容易被選中。
- **並行環境不會自我宣告**：每一側各自運作都正常，記錄裡也不會寫「本記錄僅在環境 A 成立」。缺席的限定詞不產生任何訊號。

## 判別協議

宣稱另一份記錄「不實」之前，先回答：

| 問題 | 若答不出 |
|------|---------|
| 我的旁證涵蓋哪些執行環境？ | 不能用它反證任何事，只能說「在我這側不成立」 |
| 那份記錄是在哪裡產生的？ | 先查，別先判 |
| 有沒有非模型產生的痕跡能定位它的執行環境？ | 見下方判別手段 |

**可用的判別手段**（皆非模型可自由書寫的內容）：

| 手段 | 讀法 |
|------|------|
| gitignored 的本機日誌時段分布 | 日誌不隨 commit 移動，故「某時段本地無日誌」等於「該時段的 session 不在本地執行」 |
| harness 依 cwd 編碼的暫存目錄名 | 目錄名由執行環境產生，其中的路徑片段可反推當時的 cwd |
| git author / committer 身份與時段分布 | 同一 email 下的不同 author name 常對應不同機器的 git config |
| 檔案 inode 建立時間與 commit 時間的落差 | 落差過大暗示檔案由他處產生後同步而來 |

## 結論的措辭

即使查證後確認記錄有誤，措辭仍應描述**失效範圍**而非**產生原因**：

| 避免 | 改為 |
|------|------|
| 「該記錄是虛構的」 | 「該記錄在環境 B 不成立」 |
| 「未執行命令而以預期填補」 | 「未標註量測環境，讀者無法判斷適用範圍」 |

**Why**：前者是對產生過程的斷言，需要證明「命令沒被執行」——那是負面證明，通常做不到。後者只斷言可觀測的事實，且已足以驅動修正動作。**Consequence**：把適用範圍問題誤述為誠實性問題，會使後續讀者對整份記錄失去信任並重做已經正確的工作。**Action**：先寫失效範圍，確有產生過程的直接證據時才追加原因判定。

## 與相關 pattern 的邊界

- `PC-BAL-029`（機器專屬絕對路徑屬環境事實）處理**路徑值**在環境間的可解析性；本 pattern 處理**判定行為**在環境間的有效性。前者的修法是改寫路徑，後者的修法是限定結論範圍。兩者常同時出現：路徑不相容引發複驗，複驗結果引發誤判。
- `PC-166`（幻覺工具結果）是本 pattern 最容易被誤用的解釋框架。差別在於 confabulation 的記錄無論在哪個環境都無法重現，本 pattern 的記錄在其產生環境可完整重現。判別方式是先定位產生環境再複驗，不是比對本地證據的懸殊程度。
- `tool-output-trust-rules` 規則 3（關鍵事實用固定值交叉驗證）給出固定值的可信性；本 pattern 補上其邊界——**固定值只在產生它的環境內有效**，跨環境引用時必須帶量測環境標註。

## 案例

一份跨 repo 路徑記錄在環境 A 寫成 `~/Projects/<repo>/...`。環境 B 的接手者複驗，該路徑 MISSING、另一形式 `~/project/<repo>/...` EXISTS。接手者查本機 hook 日誌：記錄當日 12084 筆環境 B 的家目錄、0 筆環境 A 的，遂判定原記錄為虛構，並把該判定寫進兩份框架資產作為反面舉證。

後續鑑識推翻此判定：本機 hook 日誌屬 gitignore 範圍（`git ls-files` 計數為 0），只涵蓋本機；當日日誌時段為 09-18 時，而原記錄由另一 git author 身份於 21:44-22:12 寫成，該時段本機零日誌。另有更早的記錄含 harness 依 cwd 編碼的暫存目錄名，其中的路徑片段直接對應環境 A。環境 A 為真實並行的 working copy，原記錄對自身環境的觀測正確。

原記錄真正的失誤是把環境相對的事實寫成跨環境通用的絕對指引；接手者的失誤與之同型且成本更高——在單一環境的證據上下了跨環境的結論，且結論的對象是另一個 session 是否誠實。
