# PC-GPD-024: 變更記錄照修改計畫寫而非照 diff 寫，同輪的無關改善為不存在的修法背書

**類別**: process-compliance

**來源版本**: 0.1.0

## 症狀

一次修改批次的變更記錄逐條列出了處置，其中一條的目標檔案**在該次 commit 裡完全沒有被觸及**。記錄本身讀起來完全正常——有問題描述、有歸因、有修法、有理由，只是那個修法不存在於任何檔案。

單有這一項還只是記錄失準。**真正讓它存活的是第二個條件：同一批的量測剛好顯示該項目改善了。** 於是「宣稱」與「數據」互相背書，中間缺的那一步——修法有沒有真的寫進檔案——沒有人查。

**本案實例**：一份 skill 連續四輪派低階 model 讀者探針量測可用性。第二輪發現一個受管詞的指路不清（讀者判不出那張表住在哪個檔），處置寫成「把代稱『入口檔』改為明寫檔名」，並記進變更記錄。第三輪量測該項 0/3（前輪 2/3 判不清楚），判定生效、結案。

第四輪同一位置又被 1/3 判為不清楚、另 1/3 指到錯誤的章節。回查 git：

```
git show --stat <該次 commit>
  CHANGELOG.md | 20 +++++
  SKILL.md     | 30 ++++-----
```

目標檔 `references/splitting-an-existing-skill.md` 不在 diff 中，「入口檔」三字原封不動。第三輪的 0/3 來自**上一版**新增的一張三欄定義表，與這條宣稱無關——那次改善替一個不存在的修法簽了名。

**識別特徵**：

- 某個項目在量測中「已解決」，之後又以相同形態重新出現
- 變更記錄該條處置的目標檔案，不在該次 commit 的 `--stat` 清單裡
- 同一批有其他改動命中同一個量測項，使該項的數字看起來改善

---

## 根因

**變更記錄的寫作時點與寫作依據都錯了。**

寫記錄時作者手上有的是**修改計畫**（我打算改哪幾處、為什麼），不是 **diff**（我實際改了哪幾處）。多處批次修改時，計畫上的某一項因為在別的檔案、因為被別的編輯打斷、因為字串比對失敗而靜默沒有套用，而寫記錄的人是照計畫逐條謄的。

字串比對失敗這一路徑特別安靜：批次套用腳本對每一處回報命中與否，作者看到一行 `[SKIP n=0]` 的當下判斷「稍後處理」，然後在寫記錄時已經不記得它。

**同輪量測的改善是最後一道假背書。** 一批修改通常包含多項處置，而量測項與處置項不是一對一。任一項處置讓數字改善，整批的每一條宣稱都會共享那個「已驗證」的外觀。這使得「修法是否落地」這個問題在流程中沒有任何一處被問到——量測驗的是結果，記錄寫的是意圖，兩者之間沒有橋。

---

## 解決方案

**變更記錄的每一條處置，都要對得上該次 commit 的 diff。**

寫完記錄後、commit 之前，跑一次對照：

```bash
git diff --cached --name-only     # 這次實際動了哪些檔
```

把記錄裡每一條處置提到的目標檔，逐條在這份清單裡找。找不到的那一條，只有兩種可能——修法沒套用，或記錄寫錯了目標。兩種都要當場處理，不可留到下次。

**批次套用腳本的 `[SKIP n=0]` 要當成阻擋，不是提示。** 命中數不等於預期時停下處理，不要繼續往下跑；跑完再回頭補，那一項會與記錄脫節。

---

## 預防措施

- **記錄照 diff 寫，不照計畫寫。** 計畫是輸入，diff 是事實；兩者不一致時以 diff 為準並回頭補修法。
- **量測改善不構成「該修法生效」的證據**，除非該量測項與該修法是一對一。一批多項處置時，改善只能歸給整批，不能歸給其中任一條。
- **已判定生效而後續又復發的項目，第一件事是回查 diff**，不是重新設計修法。復發的常見成因是原修法從未存在，而不是原修法不夠好。

---

## 與相關模式的關係

- 與「對表述歧義加警告而非改結構」（`DOC-GPD-009`）互補：該模式是修法落地了但層級選錯；本模式是修法根本沒落地。兩者的外觀相同——記錄上都有一條看似合理的處置，而問題在下一輪重現。
- 與工具輸出信任規則的「記錄平面不是 ground truth」同源：變更記錄屬記錄平面，diff 屬世界平面，兩者會漂移，重大判定要以世界平面為準。

---

## 行為模式分析

這個模式在**有量測的流程裡比沒量測的更危險**。沒有量測時，記錄失準只是記錄失準；有量測時，一個無關的改善會把失準的記錄升格為「已驗證的事實」，而後續的人會拿那條記錄當既成結論來規劃下一步。

它也解釋了為什麼「已解決的項目重新出現」值得當成獨立訊號來查。復發的直覺歸因是「修法不夠好」，於是下一輪投入的是更用力的修法——而真正該做的是先確認上一次到底改了什麼。
