# PC-BAL-073：以專案名索引行為，把並行 session 併成一個行動者

## 基本資訊

- **Pattern ID**: PC-BAL-073
- **分類**: process-compliance（跨 session 協作的歸因）
- **風險等級**: 中
- **關聯**: [[PC-BAL-023]]（計數相等不蘊含集合相等；本模式是歸納樣本未逐一核實的行為面對應）、[[PC-BAL-056]]（缺陷發現率取決於操作多樣性）、[[PC-166]] 防護 D 延伸（同 prompt 異執行體；彼處問「這件事是不是我做的」，此處問「這些事是不是同一個做的」）

跨專案協作中，同一個專案常同時存在多個 session。以專案名稱指稱對方時，多個 session 的言行會被記在同一個名下；當其中若干則出現相似的自我更正或相似的失誤，讀者會歸納出「該行動者反覆犯同一種錯」的形態，而實際上那是不同執行體各犯一次。

**Why**：專案名在協作訊息裡是最順手的稱呼，但它不是行為的主鍵。session 才是持有 context、做出判斷、犯下該次錯誤的單位。以專案名索引等於對「誰做的」這一維做了有損投影，而投影後的樣本看起來比原像更集中——三個執行體各一次，投影成一個執行體三次。

**Consequence**：

| 層級 | 影響 |
|------|------|
| 歸納品質 | 以 N 實例支撐的形態，實際可能只有 1 實例；形態被寫進規則或 pattern 後，其實證基礎不成立 |
| 對人的判斷 | 「這個對象反覆犯錯」的印象由投影產生而非由事實產生，後續互動據此調整（加驗證、降信任）而該調整無依據 |
| 修法方向 | 針對「單一行動者的習慣」設計的防護，對「多個執行體各犯一次」無效——後者要修的是共用的判準或流程，不是某個執行體 |
| 發現難度 | 錯誤的外觀比事實更像一個形態，因此比隨機錯誤更不容易引起懷疑 |

**Action**：

| 情境 | 做法 |
|------|------|
| 歸納對方的行為形態 | 以執行體（session 名稱／id）而非專案名索引；同專案不同 session 視為不同行動者 |
| 引用他方的自我更正或失誤 | 逐則回查該則出自哪個 session；訊息的 `from-name` 是主鍵，專案名不是 |
| 寫下「某方三次都…」之類的句子前 | 對每一則問「這一則確實是它嗎」，而不是只確認「這三則相似嗎」 |
| 對方指出歸屬有誤 | 撤回以該樣本支撐的形態，不保留「雖然實例數少但結論仍成立」的折衷版本——實例數是該形態成立的唯一依據時，實例減少即結論失效 |

**識別訊號**：用專案名而非 session 名稱指稱對方；同一段落內混用「你方」「該專案」「那個 session」；歸納句的實例來自不同時段而未回查來源；對方回覆「那不是我做的」。

**邊界**：本模式處理行為歸因的索引鍵，與 [[PC-BAL-023]] 的差別在維度——該模式的樣本成員是集合元素（計數相等掩蓋集合相異），本模式的樣本成員是行為事件（來源相異被投影成同一來源）。兩者的共同上游是「在樣本裡挑出一致的部分而未逐一核實每一項是否成立」，判別問句：對不上的是元素還是行動者。

**實證來源**：一次跨專案協作中，本側對某專案指出「你今天三次自我更正都是同一形態」，對方逐則回查後回覆其中兩則不屬該 session——一則是另一個 session 的自我更正，一則該 session 從未處理過該主題。以三實例支撐的形態實際只有一個實例，形態撤回。

該次歸納發生在本側剛剛糾正對方「以七支相同推出機制、未查對不上的那一支」之後：糾正者與被糾正者在同一輪內犯了同一個結構的錯，差別只在樣本成員是 skill 還是行為事件。這也說明本模式不因「知道這個道理」而免疫——它的觸發點在歸納當下是否逐項核實，不在事後是否能說出判準。
