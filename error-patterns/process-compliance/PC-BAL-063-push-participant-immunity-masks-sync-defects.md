# PC-BAL-063: 雙向同步中推送參與者對自己推送過的內容天然免疫，缺陷只咬純消費者

## 基本資訊

| 項目 | 說明 |
|------|------|
| 分類 | Process Compliance |
| 風險等級 | 中 |
| 來源版本 | v0.2.1 |
| 發現日期 | 2026-09-03 |
| 發現途徑 | 修復 sync-claude-pull.py 衝突處置缺陷（P0 IMP 票）時，另一 consumer session 對其全樹做上游/本地比對，追問「為何這個缺陷能存活這麼久」而發現 |

## 症狀

一個雙向同步機制（consumer 拉取 canonical、也會把本地修改推送回 canonical）存在缺陷：三方合併衝突時，upstream 對該檔的非衝突變更被靜默丟棄，只保留本地版本。該缺陷理論上每次拉取遇到衝突就會發生，但實際上：

- 某 consumer 長期使用該機制、經歷多輪拉取，全樹比對後「上游有而本地無」的缺漏僅一行。
- 另一參與雙向同步（會推送）的 consumer，兩輪拉取中各有衝突檔案被判為「保留本地」，但比對後這些本地版本**正是 canonical 後續收下的版本**——即該內容由它自己推送、canonical 收下、它再拉回，形成往返閉合，故不存在「upstream 獨有內容被丟棄」的情形。

兩案例合起來指向同一結構：**參與推送的一方對自己推送過的內容天然免疫於此類缺陷**，缺陷因此在多輪實際使用中幾乎不外顯，直到一個純消費、從不推送的節點才踩到。

## 根因

雙向同步的拓撲中，一個節點對某段內容的「新舊」判斷有兩種來源：自己曾經推送過的版本（該節點知道、且該版本已被 canonical 採納），或完全來自 canonical 單方演進、自己從未持有過的版本。三方合併衝突發生時，若處置邏輯是「衝突則保留本地版本」，這兩種來源的後果截然不同：

- 若衝突區塊的本地版本恰好是「自己曾推送、canonical 已採納」的內容，保留本地即等同於保留 canonical 現況（因為兩者是同一份內容的兩個副本）——**衝突被誤判為已解決，缺陷不外顯**。
- 若衝突區塊是 canonical 單方新增、本地從未持有的內容，保留本地會真正丟棄這段新內容——**缺陷外顯，但只對從未推送過相關內容的節點成立**。

推送行為本身不是缺陷的觸發條件，卻是缺陷「是否可觀測」的決定因素。一個節點推送得越頻繁、覆蓋面越廣，它踩到「本地版本恰好不是 canonical 已採納版本」這種真衝突的機率就越低；反之，純消費節點的每一次衝突都是真衝突。

## 為何純消費節點最不會被保護

純消費節點是最不可能主動做逐項核對的族群——它沒有「自己的內容是否被正確帶回」這種天然的核對誘因（因為它從不推送，不存在「帶回自己東西」的期待），而參與推送的節點反而會在下次拉取時順帶注意到自己推送的內容是否完整（哪怕只是無意識地掃過）。這使得風險承受者（純消費節點）與缺陷發現者（參與推送、進行核對的節點）系統性錯位：真正被咬的一方最不會去發現，而發現的一方往往（因為往返閉合）根本沒被咬到。

## 防護措施

- **不能靠「使用者會注意到」評估缺陷影響範圍**：影響評估時若參考「目前有反映此問題的使用者比例」，需先確認該比例的分母是否混雜了推送參與者（天然免疫、不會反映）與純消費者（會被咬但不會主動反映）；僅以「至今無人回報」判斷缺陷不嚴重，在雙向同步拓撲下會系統性低估。
- **測試/驗證 fixture 需覆蓋純消費情境**：驗證雙向同步機制時，構造的 local/upstream 差異不應恰好是「本地曾推送過的內容」，否則測出的是「往返閉合」的假陽性安全，未覆蓋純消費節點的真實風險面。
- **修復後的回歸驗證優先找純消費節點的樣本**：若需要外部 consumer 提供 repro 樣本驗證修復，優先選擇不參與推送（或推送覆蓋面小）的節點，其歷史更可能保留未被往返閉合掩蓋的真實衝突案例。

## 與相關模式的邊界

| 模式 | 對象 | 與本模式的關係 |
|------|------|--------------|
| PC-165 | 修復訊息/日誌/跨模組整合類 bug 時單元測試綠燈但 runtime 仍失效（mock 遮蔽 + 斷言不檢查文字 + 動態語言靜默忽略多餘參數三層共振） | 同屬「表面訊號正常、實際缺陷仍在」家族，但遮蔽機制不同：PC-165 是測試環境的替身與斷言設計造成的假陽性；本模式是雙向同步拓撲本身的結構性性質（往返閉合）造成部分參與者對缺陷天然免疫，不是測試設計問題，是誰在觀察、觀察者處於拓撲中哪個位置決定了缺陷是否可見 |

## 學習要點

- 「多輪實際使用未暴露問題」在單向消費拓撲下是有效訊號，在雙向同步（含推送）拓撲下不是——推送參與者的往返閉合會系統性掩蓋缺陷。
- 評估某類同步/合併缺陷的影響範圍時，需先問「回報者/核對者的拓撲位置是什麼」，而非只看「有多少人用了多久沒回報」。
- 風險承受者與缺陷發現者的系統性錯位，本身就是一種需要在防護措施設計時主動補償的偏差來源，不能假設兩者重合。
