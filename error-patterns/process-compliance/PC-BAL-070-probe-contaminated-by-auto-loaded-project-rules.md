# PC-BAL-070: 探針執行體自動載入專案規則，術語探針量到的是詞頻不是語域

## 基本資訊

| 項目 | 內容 |
|------|------|
| 風險等級 | medium |
| 發現途徑 | multi-round-review 術語探針：五份低階模型探針對「世界平面」「隔離索引」「幽靈」等詞全數答得出，一份自陳「根據前文 tool-output-trust-rules.md 的脈絡」 |
| 復發次數 | 一次（同批五詞作廢，四詞乾淨） |
| 來源版本 | v0.2.1 |

## 摘要

**術語探針的設計條件是「探針只拿得到測試詞」，而在專案目錄內派出的探針執行體會自動載入 `rules/core/` 全部規則；測試詞若已在那些規則裡被定義，探針量到的是「規則裡出現過」不是「領域裡通用」。控制詞照常收斂，報告外觀完全正常。**

汙染來自執行環境而不是 prompt。prompt 寫得再乾淨，系統提示先於它注入。

## 症狀

- 自造詞（框架內部定義的術語）在探針裡被多份「有把握」地正確定義，與其非通用的實際地位相反
- 探針自陳「根據前文某規則檔的脈絡」——這句是唯一的外顯訊號，不是每份都會寫
- 控制詞正常收斂，因此該批不會被整批作廢，汙染詞混在乾淨詞之間
- 汙染只影響「恰好被自動載入規則定義」的詞，其餘測試詞結果仍有效，判讀者容易整批採信

## 根因

| 環節 | 事實 | 後果 |
|------|------|------|
| 派發環境自動載入 `rules/core/` | Claude Code 對專案內每個 session（含子代理人）注入 CLAUDE.md 與 rules/core | 探針拿到的不只是測試詞 |
| 探針設計以「無脈絡」為前提 | round-2-probes.md 明列「測試詞若出現在探針讀得到的系統提示裡，量到的是詞頻」 | 條件已寫在規範，但派發時未核對測試詞是否在自動載入層 |
| 汙染詞與乾淨詞同批 | 控制詞收斂使該批被判有效 | 汙染結果混入判讀 |

## 案例：九個測試詞中五個在 rules/core 有定義（2026-09-07）

1. 測試詞：落票、票面、鑑識三查、幽靈票、隔離索引、派發骨架、世界平面、接手、lease；控制詞：issue tracker、git index、worktree
2. 五份 Haiku 探針回報：控制詞 5/5 收斂；「世界平面」「隔離索引」「幽靈」被多份正確定義；一份寫「根據前文 tool-output-trust-rules.md 的脈絡」
3. PM 對照 rules/core：tool-output-trust-rules 定義世界平面、bash-tool-usage-rules 定義隔離索引與幽靈、pm-role 含落票與票面——五詞結果作廢
4. 乾淨訊號：鑑識三查、lease 5/5 沒把握（非通用）；接手一名多義；派發骨架邊緣

## 解決方案

1. **派探針前 grep 測試詞於自動載入層**：`grep -l <詞> .claude/rules/core/*.md CLAUDE.md`，命中者不進本批，或改在無專案 cwd 的環境派（純 API、空目錄 session）
2. **探針回報加「你從哪裡知道的」欄**：讓「前文脈絡」這類自陳成為必填，而不是偶然出現
3. **判讀時逐詞標來源可能性**：自造詞若在框架內有定義位置，先假設汙染再看回報
4. **規範側**：round-2-probes.md 的條件句升級為派發前檢查步驟（附 grep 指令）

## 預防措施

| 層級 | 措施 |
|------|------|
| 派發前 | 測試詞對自動載入層 grep，命中即排除或換環境 |
| 探針指令 | 必填「你從哪裡知道的」 |
| 判讀 | 汙染詞與乾淨詞分表列，作廢的明寫作廢 |
| 規範 | 條件句改為程序步驟 |
