# PC-BAL-039: 清查以符號自身為 grep 錨點，漏掉其他符號的描述中對它的引用

## 基本資訊

| 項目 | 內容 |
|------|------|
| 風險等級 | 中 |
| 發現時機 | 一次「全域清查」任務完成後的獨立複核，複核者以不同錨點重跑而命中增量 |
| 發現日期 | 2026-08-18 |

## 症狀

- 某次清查宣告「全域掃描完成、無遺漏」，且清查表逐項列出並經第二人複核一致
- 事後仍有同族缺陷被發現，位置往往就在已改動行的鄰近數行內
- 遺漏項的共同特徵：它們不含被清查的符號本身，只在**其他符號的說明文字**中描述了該符號的行為
- 清查者與複核者都沒錯——他們用同一個錨點掃描，因此共享同一個盲區

## 根因

清查任務的自然做法是以待清查符號為 grep 錨點（清查 `--all` 就 grep `--all`）。這個錨點涵蓋所有「使用該符號」的位置，但不涵蓋「談論該符號」的位置。

兩類位置的分佈不同：

| 類別 | 特徵 | 錨點是否命中 |
|------|------|-------------|
| 使用位置 | 符號出現在定義、傳遞、判斷中 | 是 |
| 描述位置 | 符號只出現在**別的符號**的說明文字裡（help 字串、docstring、註解、文件表格） | 視描述是否恰好寫出該符號字面而定 |

描述位置之所以危險，在於它承載的是**關於該符號的宣稱**——「與 X 互斥」「預設同 X」「僅在 X 為真時生效」。當 X 的行為改變，這些宣稱就成為錯誤資訊，而它們不在 X 的使用清單上。

第二層原因是複核方式。複核者若以「重跑同一個 grep 並比對清單」的方式驗證，只能確認清查者沒有在同一錨點下漏看，無法發現錨點本身的覆蓋不足。**兩人用同一把尺量，量出的一致不構成正確的證據。**

**家族歸屬**：本模式與 `PC-BAL-028`、`PC-BAL-012` 同屬「查詢定義偵測域，域外在數學上不可見」家族——`PC-BAL-028` 的域外是「從未宣稱的變更」，`PC-BAL-012` 的域外是「加總查詢未拆解的單項」，本模式的域外是「談論該符號但不使用它的描述位置」。三者的防護策略同形：另開一條獨立於原查詢域的驗證軸，而非在同一域內加強力道。

## 解決方案

**清查時**：除了符號自身，另以「符號的行為描述用語」為第二錨點掃描。以旗標為例，除 grep 旗標名外，另 grep 該旗標的鄰近符號說明——實務上最有效的做法是掃描同一檔案中所有 help／docstring 字串，人工讀過一遍是否有提及該符號的句子。

**複核時**：複核者應**自選錨點**而非重跑清查者的指令。若複核者的錨點與清查者相同，該次複核只驗證了執行正確性，未驗證覆蓋完整性——這一點應在複核結論中明說，避免「已複核」被讀成「已確認無遺漏」。

**發現遺漏時**：不將其記為清查者的疏失。錨點覆蓋不足是方法問題，清查者在該方法下的執行可能完全正確。把它記為疏失會使下次清查者傾向擴大 grep 範圍以自保，產出大量雜訊而非提高覆蓋。

**修法須另行判斷**：發現「A 的說明宣稱與 A 的實際行為不符」時，修法有兩個方向——改說明使其符合行為，或改行為使其符合說明。這兩者的破壞面完全不同，不可因為「說明寫了就照做」而預設選後者。若說明描述的行為從未實作、而實作它會破壞既有呼叫方，正解是刪除該說明。

## 預防措施

| 時機 | 檢查 |
|------|------|
| 規劃清查任務 | 明列將使用的錨點，並自問「有沒有位置是談論它但不使用它的」 |
| 撰寫清查表 | 表格標題註明錨點，使讀者知道覆蓋邊界，而非讀成無條件的全域結論 |
| 派發複核 | 要求複核者自選錨點，並在結論中說明所用錨點與清查者是否相同 |
| 撰寫 help／docstring | 避免在 A 的說明中描述 B 的行為；必須描述時，該處是 B 變更時的必檢點 |

## 案例

一次針對某 CLI 旗標的全域清查：該旗標在多個子命令中為無作用的空殼，任務是確認所有出現位置皆已處理。清查者以旗標名為錨點全量 grep，產出十列清查表，逐一讀實作判定語意，結論為「無遺漏」。第二位審查者獨立複核，分割與判定完全一致。

第三位審查者以不同角度切入時發現增量：兩個子命令的**另一個旗標**的 help 字串寫著「與 `<該旗標>` 互斥」。這半句與新文案直接矛盾——一個無作用的旗標不可能與任何東西互斥；而且該互斥從未被實作，全 codebase 零互斥群組定義。兩處都落在已改動行的鄰近數行內。

它同時指出修法必須指定方向：正解是刪掉那半句，不是補實作互斥——真去加互斥群組會讓既有同時帶兩個旗標的呼叫從能跑變成參數錯誤，屬於這批變更一路避開的那類破壞。

值得注意的是清查者與第一位複核者都沒有出錯：在「以旗標名為錨點」的方法下，兩人的執行都正確且完整。遺漏來自方法的覆蓋邊界，不是執行品質。
