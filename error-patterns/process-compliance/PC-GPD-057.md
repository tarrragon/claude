# PC-GPD-057: 以 worktree 隔離派發的代理人停手時若沒有改任何檔，平台會自動移除它的 worktree；PM 依「續用」判準讓同一個代理人接續，代理人找不到工作目錄

## 基本資訊

| 項目 | 值 |
|------|-----|
| 分類 | process-compliance |
| 來源版本 | 0.5.0 |
| 風險等級 | 低 |
| 首次觀察 | 2026-10-30 |

## 症狀

實作代理人以 worktree 隔離派發，開工前發現要改的測試檔不在票的 where.files 內，依派發骨架規定停手回報，沒有改任何檔。PM 補完 where.files 後，以 SendMessage 請同一個代理人接續。代理人回報 worktree 已不存在，並拒絕改用主 checkout（判斷正確），PM 只好另派新代理人、新 worktree。

## 根因

**平台會自動清理沒有變更的隔離 worktree**。Agent 工具的 `isolation: "worktree"` 在代理人結束時，若 worktree 沒有任何變更，就會自動移除。停手而沒有改檔，正好符合這個條件。

**框架的「續用」判準沒有考慮隔離派發**。續用／放生的判準只看同類票與檔案範圍是否重疊，沒有區分代理人是否以 worktree 隔離派發，也沒有考慮它的 worktree 是否還在。依判準選擇續用時，工作目錄可能已經不見。

## 解決方案

- 隔離派發的代理人停手後，若它沒有改任何檔，不要讓它接續，直接派新代理人；context 一律寫在票面，新代理人讀票即可接手。
- 若代理人已改過檔（worktree 有變更、不會被清理），可以續用，但續用前先以 `git worktree list` 確認目錄仍在。

## 預防措施

- 續用判準加一條前提：worktree 隔離派發的代理人，續用前要確認 worktree 仍存在；沒有變更就結束的代理人，一律改為重派。
- 派發骨架的停手規定可以順帶提醒：停手回報後 worktree 可能被清理，接手方應重派。
