# PC-GPD-059: 搬檔重構的引用更正只掃程式碼與規格，未結案票面的 what／why／where 仍指向舊路徑，接手者依票面找錯檔

## 基本資訊

| 項目 | 值 |
|------|-----|
| 分類 | process-compliance |
| 來源版本 | 0.5.0 |
| 風險等級 | 低 |
| 首次觀察 | 2026-10-30 |

## 症狀

一組重構票把某個檔案從 `<old_dir>/` 搬到 `<new_dir>/`，最後一張子票專門更正舊路徑引用，範圍涵蓋程式碼、測試與規格文件，結案時舊路徑在這三處都是 0 筆。

之後主控要派一張早已存在的待處理票，讀票面時發現它的 what、why 仍寫 `<old_dir>/<name>`。若沒注意就派發，接手者會照票面去找一個已不存在的檔案，或把 where.files 宣告成舊路徑，到提交時才被範圍守衛擋下。

## 根因

**引用更正的掃描範圍是「產物」，不含「票面」**。更正票的範圍依 grep 程式碼與規格得出，票庫不在這個範圍裡。待處理票的文字是建票當下的快照，重構不會自動更新它。

**票面看起來是權威來源**。接手者被要求先讀票，票面寫的路徑會被當成事實，不會先懷疑它過期。

## 解決方案

- 搬檔或改名的重構結案前，同時搜尋未結案票（pending、in_progress）的票面，列出仍引用舊路徑的票，逐張更正或在票面補一行「路徑已改為 X」。
- 派發一張建立已久的票前，先確認票面引用的路徑仍存在（`ls` 或 `git cat-file -e HEAD:<path>`）。

## 預防措施

- 引用更正票的 acceptance 加一項：未結案票面的舊路徑引用為 0，或已逐張補註。
- 派發前檢查清單加一項：票面所列路徑在 HEAD 上存在。

## 關聯 Ticket

本地案例票號只記在專案票面（框架檔案依引用穩定性規則 8 不引用專案層級識別符）。
