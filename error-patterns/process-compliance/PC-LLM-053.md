# PC-LLM-053: 以「連續 N 筆零違規」作為收緊條件時，同一批放寬新增的豁免通道讓計數膨脹

## 基本資訊

| 項目 | 值 |
|------|-----|
| 分類 | process-compliance |
| 來源版本 | 3.5.0 |
| 風險等級 | 中 |
| 發現日期 | 2026-11-20 |

## 症狀

一條檢查先以「放寬」上線（只警告、或接受較寬的證據），同時約定一個收緊條件：「放寬版合入後，連續 N 筆樣本零違規，就改為阻擋」。而同一批放寬也新增了豁免通道（例如「證據不適用」「延後取證」之類的標記），走豁免通道的樣本在違規計數上同樣記為零。

**識別特徵**：

- 收緊條件只數「違規行數為零」的樣本，沒有區分「零是因為合規」還是「零是因為走了豁免」
- 豁免通道與收緊條件出自同一次決策或同一批變更，訂條件時豁免標記還不存在於樣本中，所以條件文字看起來完整
- 豁免使用紀錄只寫進日誌，沒有任何人被指定要讀；豁免理由空洞（只有標記、沒有內容）也照樣計為零
- 發現途徑通常是有人把豁免樣本逐筆列成盤點表，看到「理由空洞、只寫日誌」的列，而不是看計數本身

**後果**：計數可能在證據實際不足時達標，檢查在沒有被驗證過的前提下改為阻擋；或反過來，條件一直被當成「已接近成立」，真正的違規率沒有人知道。

## 根因

**計數的單位是「零違規的樣本」，而豁免通道產生的樣本在這個單位上與合規樣本同形。**

| 層 | 機制 |
|----|------|
| 計數定義 | 條件以結果（違規數 = 0）定義，不以「檢查實際被套用並通過」定義；豁免樣本跳過檢查，結果同樣是 0 |
| 決策時序 | 放寬與收緊條件在同一次裁定中訂下，訂條件的人以放寬前的樣本形態想像未來樣本，沒有把新增的豁免通道算進分母 |
| 讀者缺位 | 豁免紀錄沒有指定讀者，沒有人在計數時把它扣掉，也沒有人檢查豁免理由是否成立 |

這與「驗證工具對空輸入集回報通過」（`IMP-APP-005`）同屬一類：通過的判定沒有確認檢查真的作用在樣本上。差別在於本模式的空集合是由同一批變更**主動製造**的。

## 防護（判讀規則）

訂下或判讀「連續 N 筆零違規即收緊」這類條件時，依序執行：

1. **列出同批新增的豁免通道**：訂收緊條件前，盤點同一次放寬引入的所有豁免標記、旗標與例外路徑。有任何一項，下列步驟 2-4 必做。
2. **豁免樣本另計，不進連續計數**：計數只數「檢查實際套用且違規為零」的樣本。走豁免通道的樣本另列一欄，既不算零違規、也不中斷連續（或在條件文字中明定它中斷連續，兩者擇一並寫死）。
3. **豁免比例設上限**：條件文字同時寫明豁免樣本佔總樣本的上限；超過上限時，收緊條件不得判定成立，改為先檢討豁免通道本身。
4. **為豁免紀錄指定讀者**：寫明誰在何時讀豁免紀錄（例如判定收緊條件的人，在判定當下逐筆讀），並檢查每筆豁免理由是否具體；只有標記、沒有理由的豁免，視同違規計入。

判讀既有條件時，若條件文字沒有涵蓋步驟 2-4，先依步驟 2 重算計數，再判斷是否成立；不以原始計數直接宣告達標。

## 案例

一條針對 hook 實作票的檢查，放寬後約定「放寬版合入後，連續 10 張 hook 實作票的違規記錄為 0 行，就改為阻擋」。同一批放寬新增了「證據不適用」「延後取證」兩種標記，帶標記的票同樣產生 0 行違規記錄。訂條件時沒有把這兩種標記扣除，計數會因帶標記的票而膨脹，條件可能在證據實際不足時成立。直到有人把帶標記的票列成盤點表、看到「理由空洞，只寫日誌」的列才發現，之後才補上判讀方式：帶標記的票另計，並指定判定者讀標記理由。
