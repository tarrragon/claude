# PC-GPD-060: 以「先凍結 X 才能開工 Y」設計閘門時，凍結前的查核需要的輸入正是 Y 的產出，兩張票互等；循環直到接手 Y 時才被發現

## 基本資訊

| 項目 | 值 |
|------|-----|
| 分類 | process-compliance |
| 來源版本 | 0.5.0 |
| 風險等級 | 中 |
| 首次觀察 | 2026-10-31 |

## 症狀

一個實驗型父票的 AC 規定：變體目錄要先凍結，之後才能取樣，用來防止看到資料後再改實驗設計。另一張子票負責產生每個變體的注入版本截圖，when 寫「父票的變體目錄已凍結」。

父票的凍結前查核清單又要求：每個變體「注入後」都要跑一次準則檢查、核對可互動元件數。

接手子票的人讀完兩邊才發現：凍結要等查核，查核要等注入版本，注入版本是子票的工作，子票又要等凍結。兩張票各自都寫得合理，合起來誰都不能開工。此時距離建票已經過了十天。

## 根因

**閘門的條件與閘門的查核分開寫**。「凍結後才開工」寫在子票的 when，「凍結前要查核什麼」寫在父票的清單。寫的人各看一邊，沒有人把兩者放在一起檢查查核的輸入從哪裡來。

**凍結的目的被讀成「什麼都不能先做」**。凍結要防的是「看到取樣結果後改設計」，所以真正的界線在取樣，不在產生器材。把界線畫在器材產生之前，比原意更嚴，才造成循環。

**依賴圖只記票，不記輸入**。blockedBy 只表示「這張票要等那張票」，不表示「查核要用哪個產出」。循環藏在 AC 文字裡，依賴圖上看不出來，排程工具也就偵測不到。

## 解決方案

- 把閘門的界線移到它真正要保護的動作之前。以本例而言，凍結只需要早於第一次取樣；產生器材與查核可以在凍結前進行。
- 修改後的 AC 寫明「凍結早於任何取樣」這個不變的約束，讓完整性要求仍可以驗證。

## 預防措施

- 設計「先 X 再 Y」的閘門時，逐項列出 X 的查核需要哪些輸入，確認沒有任何一項是 Y 的產出。
- 閘門的條件寫上它要防什麼（例如「防止看到結果後改設計」），讓後來的人能判斷界線該畫在哪個動作之前。
- 建子票時，若 when 引用父票某項 AC 的完成，回頭讀那項 AC 的查核內容，確認不依賴本子票。
