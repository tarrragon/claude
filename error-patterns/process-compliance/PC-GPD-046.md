# PC-GPD-046: 本機合併閘門與 CI 的執行環境不同，環境相依的斷言只在 CI 紅；CI 失敗只寄信給用戶，沒有進入協調流程，紅燈持續多日

## 基本資訊

| 項目 | 值 |
|------|-----|
| 分類 | process-compliance |
| 來源版本 | 0.5.0 |
| 風險等級 | 中 |
| 首次觀察 | 2026-10-28 |

## 症狀

合併前的全套件在本機閘門執行並全綠，CI 只承接部分套件（例如整合測試）。某個測試的期望值依賴執行環境（語系、時區、字型、路徑分隔符等），本機環境恰好符合，CI 環境不符。結果：每次合併本機都綠，CI 每次 push 都紅。

CI 失敗通知只寄到用戶信箱，沒有任何 session 讀取，也沒有開票。各線持續合併、推送，協調者以本機閘門結果判定「全綠」。紅燈要等用戶受不了通知、主動貼日誌來問，才被診斷。

實證（2026-10-28）：整合測試以寫死的中文頓號組期望值，產品端依語系選分隔符（中文「、」、英文「, 」）。本機為中文語系，閘門通過；CI runner 為英文語系，自該測試加入當天起連續約 400 次 run 全紅，持續 8 天。

## 根因

**兩個綠燈來源的環境差異沒有被列為已知差異**。閘門與 CI 分工時只分了「誰跑哪些套件」，沒有比對兩邊的語系、時區等環境變數；環境相依的斷言因此只在其中一邊可見。

**CI 結果沒有接收方**。CI 被設計成承接者，但失敗訊號的出口只有通知信，沒有路由到協調票或任何 session 的檢查點。協調者的「全綠」判定只讀本機閘門的結束碼。

## 解決方案

- 修測試：期望值以與受測程式相同的環境依據產生，或在測試內固定環境（例如指定語系），不改產品端正確的環境相依行為。
- 開票追蹤，驗收含「修正合併後 CI 轉綠」。

## 預防措施

- 閘門與 CI 分工時，列出兩邊的環境差異（語系、時區、作業系統版本），環境相依的斷言在兩種環境下都要能通過，或在測試內固定環境。
- 協調者在每輪佇列更新或合併回報時，同時檢查 CI 最近一次的結論（例如 `gh run list --limit 1`），紅燈即開票，不以本機閘門綠燈代替。
- 新增環境相依的斷言時，比照不可靠斷言判準自問：「換一台語系不同的機器，這個斷言會翻轉嗎？」
