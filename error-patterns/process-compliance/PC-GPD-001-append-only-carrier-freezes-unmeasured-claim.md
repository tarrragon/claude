# PC-GPD-001：追加型載體凍結未量測的宣稱

| 項目 | 值 |

| 編號 | PC-GPD-001 |

| 風險等級 | 高 |

## 核心主張

追加型（append-only）載體承諾的是「這是當時的記錄」，讀者取得的是「這是現在的狀態」，兩者相差一條時間軸，而載體本身不強制把它呈現出來。

其中風險最高的不是過期的量測，而是**從未量測過的宣稱**——它沒有量測時間可標，也沒有命令可重跑，因此無法被任何後續讀者以低成本推翻。量測與推測寫進追加型載體之後，句式完全相同。

## 症狀

| 表現 | 讀者當下的感受 |
|------|---------------|
| 文件某段以事實語氣陳述一項狀態（數量、範圍、某機制的行為） | 「這是查過的」 |
| 該段無量測時間、無可重跑的命令 | 無異狀可見——缺漏的東西不會自己現身 |
| 後續實測推翻該段，但載體為追加型不回改，原句留存 | 先讀到原句的人取為現況，繼續往下推論 |

## 案例

### 案例一：全稱宣稱從未被量測

一張多輪審查票的問題分析段落寫下「受測的 23 個儲存庫全部由同一作者建立，因此老專案接手情境零命中」。該句無量測時間、無命令。

後續一位審查者實際逐一統計作者分佈，得到 15 個單作者 / 8 個多作者 / 3 個真正多人協作——原句的「全部」與「零命中」皆不成立。因載體為追加型不回改，原句留在票面，且位置早於推翻它的段落，順讀者先遇到的是錯的那一句。

### 案例二：延後的前提從未成立

另一張票的 `when` 欄位寫下「現在寫入框架目錄會擋住取得修復所需的 pull」，整張票據此延後。

執行時實際讀該 pull 腳本的檢查函式，其判斷依據為：

```
git diff --name-only -- .claude
git diff --cached --name-only -- .claude
```

兩者都只列**已追蹤檔案的修改**。新建的未追蹤檔案不在其中——而該票要產出的正是一個新檔。實測（工作區同時存在一個已追蹤修改與兩個未追蹤新檔）：

```
diff(工作區)   : .claude/error-patterns/_project-registry.yaml   [1 行]
diff --cached  :                                                  [0 行]
```

兩個未追蹤新檔落在兩個判斷依據之外。延後的前提從寫下的那一刻就不成立。

### 兩案例的關係本身即證據

記錄案例一的那張票，被案例二延後。本模式的兩個實例在同一天內互相作用：一個未量測的宣稱，阻擋了記錄另一個未量測宣稱的工作。

## 根因

| 層 | 內容 |
|----|------|
| 表層 | 載體不呈現時間軸，讀者無法分辨「當時」與「現在」 |
| 中層 | 事實語氣抹平了量測與推測的差別。量測有時間、有命令、可重跑；推測沒有，但寫下來之後兩者長得一模一樣，載體對它們一視同仁 |
| 深層 | 追加型的不回改保證使錯誤宣稱的存活期等於文件的存活期。該保證本身是對的（回改會破壞順序保證），問題在於缺少與之配套的標記機制 |

**Why**：追加型載體的價值來自「不回改」，而不回改意味著任何寫入都是永久的。永久性放大了寫入品質的差距——量測寫進去是永久的資產，推測寫進去是永久的負債，兩者以同一個動作產生。

**Consequence**：後續讀者沒有理由懷疑一句以事實語氣寫下的話，因此不會去查；查證的成本由第一個湊巧撞上矛盾的人承擔，而在此之前的所有下游推論都建立在該句之上。案例二顯示這個成本可以是一整張票的無謂延後。

**Action**：見下節。

## 判斷標準

對載體中每一句事實宣稱問兩個問題：

1. 它是哪一天量到的？
2. 用什麼命令量的？

兩題都答得出，屬量測，把兩項補進句子即可。
任一題答不出，屬推測，必須改寫為推測語氣（「預期」「推測」「尚未查證」），或當場補做量測再寫。

## 防護措施

| 措施 | 做法 |
|------|------|
| 量測型宣稱攜帶出處 | 固定格式 `（量測於 YYYY-MM-DD，命令：<cmd>）` 附於句尾，使讀者能自行重跑判斷是否仍成立 |
| 推測型宣稱明示語氣 | 未查證者一律用「推測」「預期」而非直述句；延後的前提尤其必須標，因為它會被當成不必再查的既定事實 |
| 撰寫後自檢 | 對含全稱量詞或數字的句子逐句過判斷標準兩問 |
| 機械偵測 | 見下 |

```bash
# 找出含全稱量詞或數字、卻未攜帶量測出處的句子（候選，非結論）
grep -nE '(全部|皆|一律|零|沒有任何|[0-9]+ 個)' <file> | grep -v '量測於'
```

該命令只產出候選——語言形式無法斷定一句話是否查證過，最終仍須由撰寫者對兩問作答。其價值在於把「逐句自檢」的範圍從全文縮到少數幾行。
