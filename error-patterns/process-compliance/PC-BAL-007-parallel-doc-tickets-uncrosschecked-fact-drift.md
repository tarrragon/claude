# PC-BAL-007: 並行文件票各自陳述同一事實時，未實查的一方寫入誤述

## 症狀

- 兩張並行文件票的產出各自涉及同一底層事實（如某 domain 的持久化型態），一票以第一手實查（讀 schema / grep 程式碼）陳述，另一票以推論或 domain-map 既有描述轉述
- 轉述方寫入與事實相反的斷言（實證：W10-006 在 loan domain-map 寫「無獨立持久化（內嵌 VO）」，而 W10-003 同時段實查 schema 確認 `book_loans` 為實表且為雙載體分工）
- 兩票各自驗收都通過（各自 acceptance 不含對方的事實範圍），誤述只有在 PM 合併期交叉比對時才暴露

## 根因

並行票的 context 隔離是設計特性（避免檔案衝突），但同一事實的「陳述權」未指派：兩票都被允許描述該事實，卻只有一票的任務路徑必然經過第一手實查。轉述方的資訊來源是舊文件或自身推論，且其 acceptance 不驗證該斷言——形成無驗證錨點的事實寫入。

PC-162（接手者應獨立重新驗證數量/範圍）針對「同一票的接手鏈」；本模式是其並行變體：橫向並行票之間無接手關係，交叉驗證責任落在 PM 合併期，若 PM 只做檔案級衝突檢查（git 無衝突即過）就會漏掉語意級矛盾。

## 解決方案

- 派發期：並行票 prompt 涉及同一 domain 的事實陳述時，指定單一事實來源（「持久化型態以 schema 實查為準，不確定時標待查」），轉述方禁止下斷言、只准引用或標註待另一票定案
- 合併期：PM 對並行票產出做語意級交叉比對（兩票輸出中重疊主題的斷言逐一對照），不以 git 無衝突為驗收終點（實證：本案即在此步攔截並修正）

## 預防措施

- 並行派發前的 parallel-check 除檔案路徑交集外，對「輸出主題交集」（兩票都會描述的 domain/表/元件）加一行提示：指定事實權威方
- 文件票 prompt 模板加一句：「陳述持久化/schema/接線現況前必須實查（grep/ls/讀 DDL），無法實查則標註來源票」

## 關聯
