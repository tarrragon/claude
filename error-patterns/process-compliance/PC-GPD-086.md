# PC-GPD-086：回報裡的「接下來」不等於已派發

## 基本資訊

| 項目 | 內容 |
|------|------|
| Pattern ID | PC-GPD-086 |
| 分類 | process-compliance（多線協調的進度可觀測性） |
| 風險等級 | 中（不會產生錯誤產出，但產品線會停滯，而且沒有任何訊號） |
| 來源版本 | 0.6.0 |
| 首次觀測 | 2026-11-05 |
| 關聯 | [[PC-GPD-078]]（主控不回覆有背景代理人的線）、[[PC-BAL-015]]（把 idle 讀成代理人沒做事） |

## 摘要

**線 session 的回報以「下一張是 X，我會處理」結尾，不代表 X 已經派發。** 線寫完回報後可能直接結束回合；主控依「有背景代理人在跑時不回覆」的慣例沒有回應，雙方都在等對方，線就停在 idle。主控若只在收到回報時才查看各線，停滯會一直持續，直到用戶主動問進度。

## 症狀

- 線最後一則回報的結尾是預告句（「下一張 X 驗收要求與 Y 同批，我會兩張一起處理」）。
- 數小時後查詢：X 仍是 pending、沒有 worktree、線 session 是 idle、line_status 的 ctx 時間戳停在幾小時前。
- 線事後說明：沒有在等主控，收尾後就停下了，沒有接著派發。

## 根因

1. **預告句和完成句在回報裡長得一樣。** 「已派發 X」和「接下來做 X」都出現在回報的最後一行，主控讀回報時沒有區分兩者。
2. **主控的不回覆慣例讓沉默變成常態。** 有背景代理人時主控不回覆，所以線結束回合後收不到任何推動。
3. **主控只在事件觸發時查看。** 沒有收到新回報，就不會檢查各線的票狀態與 session 狀態。

## 防護

| 情境 | 做法 |
|------|------|
| 線寫回報 | 結尾寫明下一步的狀態：「已派發 X（代理人在跑）」或「停手，等主控 Y」，不寫只有預告的句子 |
| 主控讀到預告句 | 不套用「不回覆」慣例，回一句確認或直接請它派發 |
| 主控每次回應用戶時 | line_status 的 ctx 時間戳超過一小時、而且佇列首張仍是 pending，就視為停滯，查 ListAgents 的 idle／busy 狀態並推動 |

## 檢查問句

主控讀線回報時問：這則回報最後一句說的事，已經發生了嗎？還是只是預告？

## 實例

- 2026-11-05，一個 Flutter 專案的診斷線在兩張子票合併後回報「下一張 169.3 驗收要求跟 169.4 同批，我會兩張一起處理」，然後結束回合。主控照不回覆的慣例只把回報記進協調票。約四小時後，用戶請主控確認各線進度，主控才發現兩張票都還是 pending、線 session 是 idle，推動後線立刻開工。
