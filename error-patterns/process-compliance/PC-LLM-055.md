# PC-LLM-055: 交給用戶執行的長單行指令被終端機折行，複製後語法錯誤或靜默失敗

## 基本資訊

| 項目 | 值 |
|------|-----|
| 分類 | process-compliance |
| 來源版本 | 3.5.0 |
| 風險等級 | 中 |
| 首次觀察 | 2026-11-11 |

## 症狀

模型因工具權限或守衛無法自己執行某個操作，改把一行指令交給用戶，請用戶以 `!` 前綴或貼到終端機執行。指令長度超過終端機寬度時，出現下列任一症狀：

- **語法錯誤出現在第 1 行的關鍵字後**：`python3 -c '...'` 這類內嵌程式碼的指令，回報 `SyntaxError`，位置落在 `import` 之類的關鍵字後方，看起來像程式碼本身寫錯，實際上是複製時多出的換行把一個語句切成兩段
- **指令看似執行完畢，結果沒有發生**：`rm <長路徑>` 這類指令，路徑在折行處被切斷，刪除的對象不存在或不是目標檔，終端機沒有明顯錯誤，目標檔仍在
- **模型把「用戶已回覆」當成「已執行成功」**：用戶回報已經執行，模型據此推進下一步，實際狀態沒有改變，直到後續步驟（例如合併閘門）再次被同一個檔案擋下才發現

### 實例

| 實例 | 指令 | 長度 | 結果 |
|------|------|------|------|
| 寫入用戶層設定 | 一行 `python3 -c` 內嵌腳本 | 約 400 字元 | `SyntaxError`，設定未寫入；改為腳本檔加一行短指令後成功 |
| 刪除 worktree 內的配號佔位檔 | `! rm <絕對路徑>` | 約 95 字元 | 在 80 欄寬下折行，三次都沒有刪成功；改用 glob 縮到 70 字元以內後成功 |
| 同類刪除，三個路徑串在一行 | `! rm <路徑1> <路徑2> <路徑3>` | 約 280 字元 | 同樣超過寬度，屬同一風險 |

## 根因分析

### 行為模式

模型寫指令時看到的是一個沒有寬度限制的字串，不會意識到指令要經過「顯示、複製、貼上」三個步驟才會執行。終端機或聊天介面依寬度把長行折成多行顯示，部分環境複製時會把折行處的換行一起帶走。換行對 shell 而言是指令分隔，對 Python 而言是語句結束，於是同一個字串在模型端與用戶端的意義不同。

### 結構性原因

1. **交付通道不保留字串原樣**：模型與用戶之間隔著顯示層，顯示層會改寫長行，模型無從觀察用戶實際貼上的內容
2. **失敗與成功的回覆外觀相同**：用戶回覆「已執行」時，模型分不出指令是否完整執行；`rm` 對不存在的路徑在部分寫法下沒有明顯錯誤
3. **長度直覺偏高**：以「約 120 字元」為上限仍不夠，實測 95 字元在 80 欄寬下已失敗。實際上限取決於用戶的終端機寬度，模型通常不知道這個值

## 解決方案

### 事後處理

1. 以固定值確認狀態，不依用戶回覆推斷：檔案用 `test -e <路徑> && echo Y || echo N`，工作區用 `git status --porcelain`
2. 確認未生效時，把指令改短後重新交付（做法見下方預防措施），不要原樣再給一次

### 預防措施

| 措施 | 說明 |
|------|------|
| **單行長度判準** | 交給用戶執行的指令，單行不超過終端機寬度；不知道寬度時以 80 字元為上限 |
| **超過上限時改短** | 用 glob 取代長路徑的中段（交付前先以 `ls <glob>` 確認只命中目標檔）、改用相對路徑、拆成多條各自獨立的短指令 |
| **邏輯寫進腳本檔** | 內嵌程式碼（`python3 -c`、多段管線）一律寫進腳本檔，交給用戶的指令只留執行該檔的短路徑；或用 heredoc 寫成檔案再執行 |
| **一行一個操作** | 多個路徑或多個步驟不要串成一行，每條指令各自可以單獨執行並單獨驗證 |
| **交付後以固定值確認** | 用戶回覆已執行之後，模型自己以 `test -e`、`git status --porcelain` 之類的固定值命令確認結果，再推進下一步 |

**檢查問句**：這行指令的長度超過 80 字元了嗎？用戶回覆之後，我用什麼固定值確認它真的生效？
