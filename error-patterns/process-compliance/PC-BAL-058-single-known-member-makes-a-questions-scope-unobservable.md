# PC-BAL-058：唯一已知成員使問題範圍不可觀察

## 基本資訊

- **Pattern ID**: PC-BAL-058
- **分類**: process-compliance（提問前提與結論適用域）
- **風險等級**: 高
- **關聯**: [[PC-GPD-002]]（兩個來源共享抽取方法時一致性不是證據；該模式是「二的退化」——有兩個來源但它們不獨立，本模式是「一的盲區」——只有一個來源故連邊界都看不見）、[[PC-BAL-057]]（安全網與被保護判斷共享輸入）、[[PC-BAL-056]]（潛伏缺陷的發現率取決於操作多樣性；該模式講如何找到未知缺陷，屬搜尋策略，本模式講為何問題邊界本身不可見，屬提問前提）、[[ARCH-BAL-011]]（名稱造成職責已涵蓋的假象）

一個問題若只有一個已知的答案來源，該來源的答案會自動被當成整個問題的答案。此時「這個答案涵蓋多少」不是被誤判，而是**無從判斷**——要看出答案的範圍小於問題，需要至少存在第二個候選來源，而該來源正是尚未被發現的東西。

**Why**：範圍是相對概念，須有比較對象才能被觀察。當某類別只有一個已知成員時，該成員與整個類別在認知上完全重合——不是相似，是無法區分，因為區分所需的第二個成員不存在於視野內。此時任何自我檢查都不會發現問題：檢查者去驗證那個答案，答案本身確實正確，而「它是否回答了整個問題」這一問沒有可用的證據可以回答。

該狀態常伴隨高品質的驗證工作，因而更難察覺。針對唯一已知成員做的實驗越嚴謹、結論越可靠，越容易把該結論當作整個問題的答案——**嚴謹的部分是真的，範圍是被自動繼承的，兩者在同一個結論裡不可分辨**。

**Consequence**：

| 層級 | 影響 |
|------|------|
| 結論適用域 | 針對單一成員的正確結論被用於回答更大的問題，且該誤用不產生任何錯誤訊號 |
| 自檢工具 | 依該結論設計的檢查對其他成員為偽陰性；檢查回報乾淨時，與完整檢查回報乾淨無法區分 |
| 對外建議 | 依該結論給出的安全性判斷會成為通行證，接收者據以行動，代價落在接收者身上 |
| 自律無效 | 「注意不要把結論用出範圍」無法執行——範圍不可觀察，不是被忽略 |
| 修復規劃 | 修復針對唯一已知成員設計，對同類別其他成員無效，且無人知道還有幾個 |

**Action**：

| 情境 | 做法 |
|------|------|
| 某問題只有一個已知答案來源 | 在採用該答案前，先列舉該來源所屬的類別有哪些成員。列舉本身即把範圍從不可觀察變為可觀察 |
| 診斷完一個成因即宣告問題已解 | 問「這個成因是這一類的唯一成員，還是唯一被發現的成員」。答不出即屬本模式 |
| 依單一結論產出對外的安全性建議 | 建議須明示所依據的判準涵蓋什麼、不涵蓋什麼；無法列舉未涵蓋範圍時，不給安全性結論 |
| 設計防護或自檢工具 | 工具的涵蓋範圍須與問題的類別範圍一併宣告；只驗證單一成員者，輸出中明示其餘成員未檢查 |
| 事後檢討「為何把範圍講大了」 | 不以自律為結論。追問當時是否具備第二個候選；不具備者，改善方向是建立列舉機制而非提高警覺 |

**識別訊號**：某問題的所有討論都指向同一個機制或同一段程式碼；「已查明根因」的結論後未接續「是否還有其他路徑」的檢查；針對單一成因設計的自檢工具被用於回答一般性的安全問題；事後發現第二個成因時，第一個成因的分析本身完全正確。

**邊界**：與 `PC-BAL-056`（潛伏缺陷的發現率取決於操作多樣性）分屬不同階段——該模式處理「如何找到未知缺陷」（搜尋策略：執行未執行過的操作），本模式處理「為何連問題的邊界都看不見」（提問前提：類別成員數為一時範圍不可觀察）。兩者可串接：依 `PC-BAL-056` 執行新操作而發現第二個成員，正是本模式的解除條件。與 `PC-GPD-002`（兩個來源共享抽取方法使一致性失效）為對照——該模式是「二的退化」（有兩個來源但不獨立），本模式是「一的盲區」（只有一個來源）。與 `PC-BAL-057`（安全網與被保護判斷共享輸入）的差別：那是兩個機制的獨立性問題，本模式是類別成員數的問題。

**實證來源**：某同步工具出現消費端檔案遭刪除，經八組合受控實驗查明一條刪除路徑的觸發條件，結論在該路徑上完全正確。該結論隨後被用於回答「執行拉取是否安全」，並據以產出提供給消費端的自檢腳本。消費端執行自檢，結果為乾淨，據此拉取，三個檔案再度遭刪除。

事後查明存在第二條刪除路徑：三方合併把上游的純大小寫改名拆為刪除與新增兩個獨立操作，刪除半邊在大小寫不敏感檔案系統上命中本地檔案。該路徑不經過第一條路徑的任何函式，其觸發變數為「同步基準點是否落在改名之前」，與第一條路徑的三個大小寫變數完全無關，故自檢對其為偽陰性。

**第一條路徑的分析無任何錯誤**——八組合實驗、隔離 fixture、以 tree object 而非檔案系統列舉判定大小寫，方法皆正確，觸發式在該路徑上百分之百成立。錯誤只發生在它被用來回答一個更大的問題，而當時第二條路徑尚未被發現，故「這個答案涵蓋多少」沒有任何可用的證據可回答。

同期另一實例形態相同而方向相反：一份為「已卡住的消費端」寫的復原配方，作者僅設想卡住者為讀者，未設想未卡住者也會讀到。配方採清單形式，而清單的形式本身暗示「照做即可」，故對非目標讀者構成通行證。作者自述「配方的讀者範圍比我預設的大，而那個差額我看不見」——同樣是唯一已知成員（目標讀者）與整個類別（所有讀者）在認知上重合。

**修復方向的性質**：該事件的追蹤票要求「盤點所有會呼叫刪除的路徑，逐一標註觸發條件與測試涵蓋，未涵蓋者明列不得省略」。該條的價值不只是防止漏修——**它把「唯一已知成員」變成「已列舉的集合」，使「這個答案涵蓋多少」第一次成為可回答的問題**。列舉是本模式唯一有效的解除手段，提高警覺不是。

**列舉的有效性取決於觀察者的獨立性**：由單一觀察者列出的多個成員，可能是同一個盲區的多次顯現而非彼此獨立的成員——該觀察者看不見的那一類，不會因為他多列幾次而出現在清單上。判別方式：問這些成員各自由誰、在什麼條件下發現；若答案皆為同一人於同一段時間內，該清單證明的是「此觀察角度下可見的範圍」，不是「類別的全集」。故列舉應盡量跨觀察者或跨環境取得，且清單本身須標明其成員的來源，使讀者能判斷它涵蓋的是類別還是視角。此限定同時適用於本模式自身的實證累積——同批對話、同組參與者產出的多個實例，在確認獨立性之前應計為一個。
