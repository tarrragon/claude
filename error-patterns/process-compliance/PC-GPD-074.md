# PC-GPD-074：授權要在執行動作的 session 取得

## 基本資訊

| 項目 | 內容 |
|------|------|
| Pattern ID | PC-GPD-074 |
| 分類 | process-compliance（多 session 協調的授權流向） |
| 風險等級 | 低（不造成錯誤動作，只多一次用戶互動） |
| 來源版本 | 0.6.0 |
| 首次觀測 | 2026-11-02 |
| 關聯 | [[PC-GPD-072]] |

## 摘要

**需要用戶逐次授權的動作（新開 issue、sync-push 等），由哪個 session 執行，就要在那個 session 取得授權。** 如果主控在自己的 session 用 AskUserQuestion 問到授權再傳訊轉給執行線，執行線會依平台的跨 session 規則（同儕不能授予權限），把轉述的授權視為無效，再問用戶一次。結果用戶要授權兩次，主控那一次是白問。

## 症狀

- 執行線回報有一個動作需要授權。主控在自己的 session 問用戶，用戶授權了。
- 主控傳訊轉述「用戶已授權」，執行線回覆：轉述的授權不能當作用戶本人的核准，會直接問用戶。

## 根因

- 主控把授權當成一般裁定處理。一般裁定可以轉述，但授權要由執行動作的 session 直接取得，不能轉述。
- 平台的權限邊界以 session 為單位，轉述的授權無法跨 session 生效，這是正確的防護，不應該繞過。

## 防護

| 情境 | 做法 |
|------|------|
| 執行線回報需要逐次授權的動作 | 主控不問用戶，直接列一行用戶待辦：「到〈線名〉session 回答授權詢問」，並請執行線自己用 AskUserQuestion 問 |
| 主控已經在自己的 session 問到授權 | 照樣轉告執行線，讓它知道用戶的意向，但預期它會再問一次，並把用戶待辦改為「在〈線名〉session 再確認一次」 |
| 需要主控自己執行的授權動作（例如主控跑 sync-push） | 照常在主控 session 問 |

## 檢查問句

準備問用戶授權之前問：這個動作由哪個 session 執行？不是主控執行的，就請那個 session 自己問。
