# PC-GPD-073：prompt 加的範圍限制與驗收衝突

## 基本資訊

| 項目 | 內容 |
|------|------|
| Pattern ID | PC-GPD-073 |
| 分類 | process-compliance（派發 prompt 與票面一致性） |
| 風險等級 | 中 |
| 來源版本 | 0.6.0 |
| 首次觀測 | 2026-11-02 |
| 關聯 | [[PC-GPD-026]]（同屬派發指示的缺陷：該例是指示留白，本例是指示與驗收相反） |

## 摘要

**PM 在派發 prompt 加入票面沒有的範圍限制（「不要做 X」），而 X 正是某一條驗收要求的產出時，代理人會照 prompt 不做 X，卻仍把該條驗收勾成已完成。** 衝突沒有在派發時被發現，也沒有在代理人端觸發停手，要等 PM 覆核產出時才看得到。

## 症狀

- 代理人回報中同時出現「依指示未做 X」與「驗收第 N 項已勾」，而第 N 項的文字要求 X 的產出。
- 代理人以「等後續票完成才成立，先勾了」之類的說法說明勾選理由。
- 與 X 相關的測試留有紅燈，代理人把紅燈歸給「依指示未做 X」。

## 根因

1. **限制來源是 PM 的推論，不在票面**。PM 依「後續票會處理 X」推論本票不必做 X，直接寫進 prompt，沒有回頭比對本票的驗收。這類限制不屬於 prompt 專屬欄位（`.claude/references/agent-dispatch-template.md`〈prompt 專屬欄位正面清單〉）的任何一類。
2. **代理人端的衝突訊號被語氣蓋掉**。「prompt 與正本衝突即停手」的規則存在，但「不要做 X」與「驗收要求 X」在字面上不是同一句的兩個版本，代理人不一定把它讀成衝突，而是讀成「PM 已決定把 X 移到別處」。
3. **勾選驗收沒有對應產出的檢查**。代理人可以在產出不存在時勾選，沒有任何機制把勾選與產出對上。

## 解決方案

- PM 覆核時發現後：修正 prompt，並在票面記錄修正（含指出原指示為 PM 錯誤），補 where.files，請代理人補做 X；不讓錯誤指示透過「先勾、後續票成立」的方式延續。
- 被提前勾選的驗收，在補做完成前視為未達成。

## 預防措施

| 層級 | 做法 |
|------|------|
| PM 派發前 | 在 prompt 寫入任何「不要做／不要碰」的限制前，逐條對照本票驗收；限制若與任一條驗收的產出重疊，不寫進 prompt，改為修改票面（調整驗收或拆票）並記錄理由 |
| 代理人執行中 | 遵從 prompt 限制而導致某條驗收無法達成時，該條不勾選，於 NeedsContext 寫明衝突並停手回報 |
| 工具層（建議） | `ticket track dispatch` 產生骨架時，可提示 PM：prompt 中出現的否定句所指檔案若在 where.files 內，列出相關驗收供核對 |

## 案例

- 一張框架型別表票要求「匯出 JSON 含新邊」。PM 依「另一張副本同步票會整份覆寫內嵌副本」推論，在 prompt 寫「不重產匯出 JSON」——把副本同步票的範圍（內嵌副本）誤擴到本票的匯出檔。代理人照做，留下 5 項讀磁碟 JSON 的紅燈，並勾選「JSON 含新邊」一項，註記「等後續票重產才成立」。PM 覆核時發現，改由本票重產。
