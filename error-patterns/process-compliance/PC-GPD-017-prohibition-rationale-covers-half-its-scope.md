# PC-GPD-017: 規範類文件的禁令只被問效力不被問代價，誤傷的合規設計無 frame 負責

**類別**: process-compliance
**嚴重度**: 高
**發現日期**: 2026-09-09

## 基本資訊

| 項目 | 值 |
|------|-----|
| 風險等級 | 高 |
| 來源版本 | 0.1.0 |
| 偵測時機 | 審查一份含「不得」「禁止」「一律」條款的規範類文件時，finding 清單的方向欄一側全空 |

---

## 症狀

審查一份規範，所有 frame 問的都是「這條規則有沒有漏掉某個情境」。沒有任何 frame 問「這條規則會不會把某個合規的設計判成違規」。finding 清單因此一側全滿、另一側全空，而**空的那一側讀起來像那一側沒有問題**。

規範類文件的禁令特別容易誤傷，因為**禁令的理由句通常只涵蓋禁令範圍的一半**。作者寫禁令時腦中有一個具體的壞例子，理由句描述的是那個壞例子的機制；禁令的字面範圍比那個機制寬，寬出來的部分裡住著該領域的標準正確做法。

## 根因

| 層級 | 機制 |
|------|------|
| L1 frame 清單不成對 | 審查框架的 frame 是為了找缺陷設計的，找到漏抓是產出（多一則 finding），找到誤報是否定產出（少一則，且要撤回別人寫下的） |
| L2 規劃者與執行者的誘因同向 | 規劃者在問「還有什麼沒被檢查」，執行者的價值由 finding 數體現，兩端都不指向「哪些命中其實合規」 |
| L3 禁令的理由句只寫一半 | 作者從一個壞例子歸納出禁令，理由句寫的是那個例子的機制。字面範圍寬出來的部分沒有理由句涵蓋，也就沒有人去檢查那裡有什麼 |

## 實證

一份關於資源仲裁的方法論，三輪審查的前 26 則 finding 全為漏抓、零多抓。在各 frame 的指令加一條反向問句（「哪些判準過度限制，會把合規的設計判成違規」）後，單一輪次產出 12 則多抓，其中兩則高嚴重度：

- 一條禁令寫「仲裁狀態不跨執行緒共享」，理由是「共享狀態需要鎖，鎖本身是另一個通道」。**理由只涵蓋需要鎖的那一半**：無鎖的原子計數沒有等待佇列、不構成第二個通道，而它正是有界資源池的標準實作。照原條文，該實作被判違規。
- 一條禁令寫「級別傳播單調不升，不可升」，理由是「允許升級則任何請求都能自我拔高」。**理由只涵蓋自我拔高那一半**：優先權繼承的級別由等待者給予而非持有者宣稱、且隨資源釋放而終止，它是優先權反轉的標準解。照原條文，不給這個例外反而會製造它要防的問題。

兩則都不會被任何一個「找漏抓」的 frame 命中——它們不是規則漏了什麼，是規則多管了什麼。

## 解決方案

1. **finding 清單加方向欄**，只有兩個值：這一則說規則漏掉了什麼，還是說規則多抓了什麼。一欄全空時，缺的是 frame 不是缺陷。
2. **frame 清單成對排**：判準漏了哪些情境／判準會把哪些合規個案判成違規；這一類還有哪些位置／這一類的命中有哪幾處其實合規。
3. **對每條「不得／禁止／一律／恰有」問一句**：這條的理由句涵蓋它字面範圍的全部嗎；答否時，寬出來的部分裡有什麼。
4. 誤傷的修法是**加例外並寫出例外的判別依據**，不是放寬禁令——放寬會同時放掉禁令原本擋住的東西。

## 預防措施

| 措施 | 落點 |
|------|------|
| 審查規範類文件時，每個 frame 的指令附一條反向問句 | 派發指令範本 |
| 收尾前檢查 finding 方向分佈，一欄全空即判為缺 frame 並補跑 | 收尾清單 |
| 寫禁令時，理由句寫完後回頭問「這個機制涵蓋禁令的全部字面範圍嗎」 | 規範撰寫 |

## 行為模式分析

「找誤報會減少產出」這個估計本身是錯的——實測中撤回之後的替代 finding 都比原本那一則強，因為找誤報要求理解規則的真正機制，而理解機制之後看到的缺陷比表面掃描看到的深。

規範類文件是這個模式的高風險載體，因為它的讀者會照著執行。一條誤傷標準做法的禁令，會讓執行者要嘛違規、要嘛採用較差的設計，而兩種結果都不會回頭報告規則錯了。
