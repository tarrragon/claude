# PC-GPD-064: 分類計數由截斷的頻率表推估，而不是對每一列套用判定規則；推估值被當成精確計數回報，更正時沿用同一方法再錯一次

## 基本資訊

| 項目 | 值 |
|------|-----|
| 分類 | process-compliance |
| 來源版本 | 0.5.0 |
| 風險等級 | 中 |
| 首次觀察 | 2026-10-31 |

## 症狀

一份資料集（例如 90 筆模型回覆）要依預登記的規則分類：哪些是合法答案、哪些無法解析。執行者先跑 `sort | uniq -c | sort -rn | head -20` 看前 20 名的值，再依這張表心算各類的筆數，寫進票面或回報。

實例中連續錯了兩次：

1. 第一次寫「68 筆為合法代碼」。判斷只看值的形狀，沒有對照每一列自己的選項集合。
2. 更正為「65 筆合法、3 筆代碼形狀但不在選項內」。這次對照了選項，但仍從頻率表歸類，沒有逐列套規則。逐列重算後，3 筆其實是中文單字，前一版頻率表沒有列出它們，所以被歸到錯的類別。

兩次的數字都寫得像精確計數，沒有標示是推估。

## 根因

1. **頻率表被截斷，長尾不可見。** `head -20` 只顯示高頻值。低頻值不在表上，但仍會被分進某一類。分類者只能猜那些值屬於哪一類。
2. **判定規則依賴每一列的上下文。** 「合法代碼」是相對於該列的選項集合，同一個值在不同列可能合法也可能不合法。頻率表把列合併成值，列層級的上下文就不見了，所以無論表格多完整都算不對。
3. **更正沿用原方法。** 被指出錯誤後，執行者修正了發現的那一個疏漏（加入選項比對），但沒有換掉推估本身。第二個數字因此帶著同一個缺陷，且因為是「更正後」的版本，可信度更高。

## 解決方案

用一支程式對每一列套用判定規則（最好直接呼叫正式判定用的函式），輸出各類筆數，加總必須等於總列數。回報的數字一律以這份輸出為準。

## 預防措施

| 時機 | 動作 |
|------|------|
| 要回報分類筆數 | 以程式逐列套規則，不從頻率表心算；能呼叫正式判定函式就不要另寫一套 |
| 判定規則依列的上下文而定（選項、所屬題目、狀態） | 不能用 `uniq -c` 合併後的值分類，必須在列層級判定 |
| 回報前 | 檢查各類筆數加總是否等於總列數；不等就是有列沒分到 |
| 只能給推估 | 明寫「推估，依前 N 名頻率表」，不寫成精確數字 |
| 被指出計數錯誤 | 先確認錯誤是否來自方法本身；是的話換方法重算，不只補修被發現的那一處 |
