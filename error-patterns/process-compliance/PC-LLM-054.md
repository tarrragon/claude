# PC-LLM-054: 升級判準指定的資料來源不記錄計算所需欄位，前提永遠無法量測

## 基本資訊

| 項目 | 值 |
|------|-----|
| 分類 | process-compliance |
| 來源版本 | 3.5.0 |
| 風險等級 | 中 |
| 首次觀察 | 2026-11-19 |

## 症狀

- 一個「先不做、之後依資料決定」的決策（守衛由提示升級為阻擋、功能由實驗轉正式、閾值收緊）寫明了可量測的升級前提，例如「新增命中的誤報比例低於某值即升級」
- 前提指名或隱含了資料來源（hook 營運日誌、metrics、事件紀錄），但該來源只記錄事件發生，沒有記錄計算前提所需的欄位（例如只記檔名與工具，不記命中值）
- 到了評估時點，評估者只能從其他平面（git 歷史、事後重現）回推，回推覆蓋率低（實例：14 筆中僅 4 筆可回推），樣本不足以下結論，於是再延後一次
- 延後在外觀上合規：決策有 trigger、有追蹤票、有量化判準；缺的只是「量測得到」這一環，而這一環在寫下判準時沒有人檢查

## 根因分析

### 行為模式

寫下升級前提的人，想的是「什麼數字能證明可以升級」，沒有回頭問「這個數字從哪裡算出來、那裡現在有沒有記」。判準的正確性與判準的可量測性是兩件事，前者在決策當下被審查，後者要等評估時點才第一次被測試。資料來源一旦沒有記錄必要欄位，等待期間累積的每一筆事件都是不可用樣本，等待時間不會換來資料。

### 具體案例：路徑軌守衛的升級判準

| 階段 | 內容 | 前提可量測嗎 |
|------|------|------------|
| 決策 | 引用穩定性守衛的專案路徑軌維持提示、不升級；升級前提寫為「先排除既定路徑以外的誤報來源，再以新增命中的誤報比例為判準」 | 未檢查 |
| 等待期 | 守衛營運日誌每次命中記一行，內容只有檔名與工具，不含命中的路徑值 | 否：缺命中值 |
| 評估 | 評估者以 git 回推命中值：14 筆中 4 筆回推成功（全為誤報），10 筆因後續 commit 已無該新增而無法判定 | 否：樣本不足 |
| 結果 | 結論仍為不升級；另開一張票先讓日誌記錄命中值，再開一張票重新量測後判定 | 升級延後一整輪 |

補記錄的修改本身很小：抽出一個回傳命中值的函式，日誌行多記一個欄位，對模型與用戶可見的輸出與結束碼不變。若在寫下升級前提的同一張票就補上，評估時點即可直接計算比例。

### 結構性原因

1. **判準與資料來源分屬兩個元件**：判準寫在決策紀錄（ticket、規則），欄位定義寫在產生資料的程式（hook 的 logger 呼叫），寫判準時不會一併打開程式確認欄位
2. **資料來源的設計目的不同**：營運日誌原本為除錯而設計，記「發生了」就夠；升級評估需要的是「發生了什麼內容」，用途在事後才加上去
3. **缺欄位的日誌與有欄位的日誌在等待期外觀相同**：每次命中都有一行紀錄，筆數持續增加，看起來資料在累積；只有實際計算時才發現每筆都缺同一欄
4. **合規檢查只看 trigger 存在**：延後決策的檢查（是否綁票、是否有判準）不檢查判準能否從指定來源算出

## 解決方案

### 事後處理

先補資料來源的欄位（同一個修改通常很小），再從補記錄之後的新事件重新量測。補記錄之前的舊紀錄若要使用，回推結果須標明覆蓋率，覆蓋率不足時不以其下結論。

### 預防措施

| 措施 | 說明 |
|------|------|
| **寫判準時同步列出計算式與欄位** | 寫下可量測前提時，把計算式寫成「分子／分母各取自哪個來源的哪個欄位」，逐欄確認該來源現在就有記錄 |
| **欄位缺漏同票補記錄** | 確認發現欄位缺漏時，在寫下判準的同一張票補上記錄（或建一張排在等待期開始之前的票），不把補記錄留到評估時點 |
| **等待期中途抽查一筆** | 等待期內至少一次取一筆實際紀錄，試算一次前提，確認算得出來；算不出來即提前補欄位 |
| **評估時報告覆蓋率** | 評估結論同時寫出「可計算筆數／總筆數」，覆蓋率不足時結論為「補欄位後重量」，而非沿用舊前提再等一輪 |

**檢查問句**：這個數字從哪裡算？我打開過那個來源、確認它現在記了這個欄位嗎？

## 相關模式

- PC-093：無 trigger 延後會累積為死議題。本模式是延後已綁票且有量化判準，形式上符合決策 trigger 綁定規則，但判準依賴的資料不存在，trigger 實質上永遠無法以資料成立，結果與 PC-093 相同：決策停在延後。差別在於 PC-093 的防護（綁 ticket、寫明判準）在本模式中都已做到，需要補的是判準的可量測性檢查
- PC-BAL-067：觀測到零並預設單一成因。兩者都涉及「觀測來源能回答什麼問題」，但軸不同：PC-BAL-067 是對既有觀測下了超出射程的結論；本模式是觀測來源從一開始就沒有記錄判準所需的內容，評估者正確地發現無法下結論
