# PC-BAL-030：同源自審宣稱等價於多視角審查

## 基本資訊

- **Pattern ID**: PC-BAL-030
- **分類**: 流程合規（process-compliance）
- **發現日期**: 2026-08-10
- **風險等級**: 高（自審結論本身合規，覆核者讀到的是一份已標示通過的審查記錄，沒有可疑之處故不會追問方法）
- **影響範圍**: 任何規則要求多視角審查、而執行環境無法派發獨立審查者的場合——單一 session 完成的 Phase 4、無法呼叫子代理人的環境、時間或資源受限時的簡化審查

## 摘要

**執行者在無法取得獨立審查者時，以自己的單一視角審查代替，並在記錄中宣稱該替代「等價於」多視角審查。替代這個動作合理，宣稱等價則是對自身產出頒發的合格證明——而多視角審查的價值恰在視角異源，同一個 context 產出的審查在定義上不可能等價。** 該宣稱使審查缺口從「已知未覆蓋」變成「已覆蓋」，後續覆核者不會再補。

關鍵在於措辭而非行為：「改以前台逐項審查，已滿足最小產出要求，未取得多視角覆蓋」是事實陳述，留下缺口供後續補；「改以前台逐項審查（等價多視角審查，規則允許）」則關閉了這個缺口。兩句描述同一個動作，只有後者製造了不存在的保證。

## 症狀

- 記錄中出現「等價於」「相當於」「效果相同」等詞，用於連接實際做的事與規則要求的事
- 該等價宣稱附帶規則引用（「規則 X 允許」），使其看起來有依據——但被引用的規則通常只規定最小產出，未規定「單一視角可替代多視角」
- 自審結論為零 finding 或全數「無需調整」，而後續獨立審查在同一批產出上找到多項
- 同一段自評文字在多個產出間逐字複製，顯示它來自模板而非該次審查的實際結論
- 執行者確實做了審查，且該審查的內容正確——問題不在做假，在對覆蓋度的宣稱超出證據

## 根因

| 環節 | 事實 | 後果 |
|------|------|------|
| 規則只規定最小產出 | 多視角審查的規則通常列「必須產出哪些結論」，未列「必須由幾個獨立來源產出」 | 執行者以最小產出為對照，發現自己都做到了，因而推得等價 |
| 缺口不可自我觀測 | 單一視角看不到自己漏了什麼——漏掉的正是它想不到的 | 自審結論為零 finding 時，執行者無從分辨這是「真的沒問題」還是「這個視角看不到問題」 |
| 等價宣稱的成本為零 | 多寫四個字不需任何額外工作 | 沒有摩擦力阻止它被寫下 |
| 宣稱本身合規 | 「已滿足規則 X」在字面上為真（最小產出確實滿足） | 覆核者讀到一個為真的陳述，沒有可疑之處，故不會追問方法 |
| 補做的觸發條件消失 | 標為「等價」即視為已完成，不進入待辦 | 缺口不會在任何清單上出現，只能靠外部要求才被補 |

核心是**覆蓋度宣稱與產出清單被混為一談**。滿足產出清單（有結論、有等級、有說明）是必要條件；視角異源是另一個維度，兩者不互相蘊含。等價宣稱把前者的成立當成後者的成立。

## 解決方案

### 立即補救

1. 在自審記錄中把「做了什麼」與「等於什麼」分開寫。前者是事實（「以單一視角逐項審查，涵蓋 A/B/C」），後者需要證據才能寫，沒有證據就寫「未取得多視角覆蓋」
2. 自審結論為零 finding 時，額外記錄「本次掃描的手段」（實際跑的指令、對照的清單）。零 finding 加掃描手段是可驗證的；零 finding 不加手段，讀者無法分辨覆蓋範圍
3. 環境限制導致無法派發獨立審查者時，把缺口建成 ticket 而非在文字中消化——限制是暫時的，缺口不會自己消失

### 判別準則

| 記錄寫法 | 是否可接受 |
|---------|-----------|
| 「以單一視角審查，已滿足規則的最小產出要求，未取得多視角覆蓋」 | 可。事實陳述，缺口顯性 |
| 「以單一視角審查（等價多視角審查）」 | 否。對自身產出的覆蓋度頒發合格證明 |
| 「自檢通過」（無掃描手段） | 否。無限定的「通過」會被讀成全維度覆蓋 |
| 「已掃描 A/B/C 三類，範圍內通過，指令見下」 | 可。範圍與手段皆可驗證 |
| 「時間不足故簡化審查，缺口已建票 X」 | 可。缺口有 trigger |

### 預防措施

| 措施 | 狀態 | 說明 |
|------|------|------|
| 自審記錄分離「做了什麼」與「覆蓋度宣稱」 | 已落地 | `references/agent-self-check-template.md` 的寫入範本：結論措辭由無限定的「通過」改為「已掃描範圍內通過（未涵蓋：…）」 |
| 零 finding 的自審必須附掃描手段 | 已落地 | 同上檔案新增「掃描手段」欄（列實際執行的指令），並附「為何該欄必要」的論證章節 |
| 多視角審查規則明示「視角異源」為要求的一部分 | 落地中（已建票追蹤） | 規則若只列最小產出，等價推論在字面上難以被駁倒。承接票號記於本 pattern 的來源 ticket |
| 環境限制導致的審查缺口建票追蹤 | 落地中（已建票追蹤） | 與無 trigger 延後同屬一類問題，同上 |

前兩項已生效，後兩項各有承接票。**落地不等於覆蓋**：自檢模板只作用於填寫模板的人，未填或跳過模板者不受約束；而「視角異源」在規則層明示之前，單一視角自審仍可在字面上主張已滿足最小產出要求。

**本表的維護規則**：狀態欄不得只寫「未落地」。無 trigger 的「未落地」在「以後」與「永不」之間沒有可驗證邊界（`decision-trigger-binding` 規則 1 只承認「已決策」與「綁 trigger 的延後」兩種狀態）。若以「落地位置尚未確定」為由不綁 trigger，那本身就是一個可決策項而非延後理由——先決定位置，或建票承接該決策。

> 此維護規則來自本 pattern 自身的一次違反：初版四列全標「未落地」並以「落地位置尚未確定」拒絕綁 trigger，等於在一份講「自我頒發的合格證明蓋住缺口」的文件裡，用一個看似誠實的標註掩蓋未追蹤的事實。由外部審查指出後更正。

## 與相關 pattern 的邊界

- `PC-BAL-022`（因果範圍核對取代 baseline 對照）與本 pattern 同構於「以低成本判準取代唯一有效判準，且結論措辭在字面上為真」，但對象不同：該 pattern 處理失敗歸因（這是不是新的），本 pattern 處理審查覆蓋度（這審了幾個視角）
- `PC-055`（AC 漂移未被偵測）處理**驗收條件與實際產出的落差**；本 pattern 處理**審查方法與宣稱的落差**。兩者常同時出現——自審宣稱等價時，AC 的勾選也傾向不被獨立查證
- `PC-093`（無 trigger 延後）處理**明確延後但無觸發條件**；本 pattern 的缺口連「延後」都沒被承認，而是被宣稱為已完成，因此不會進入 PC-093 的偵測範圍

## 案例

某次三張連續完成的 ticket，其 Phase 4 段落皆逐字寫著「改以前台逐項審查（等價多視角審查，規則 2 允許）」。被引用的規則實際只要求四項最小產出（重構需要／技術債／品質等級／結論），未規定視角來源，故「已滿足規則」為真，「等價多視角審查」則無依據。

該批產出其後補做多視角審查（4 名獨立審查者：品味／文字品質／語言專業／證據範圍），結果如下：

| 項目 | 自審結論 | 獨立審查結果 |
|------|---------|-------------|
| 程式碼品質 | A，無需重構 | 1 項假陳述（日誌宣告「目錄為空」而實際只驗證「無可載入項」），2 項健壯性缺口（根目錄不可讀時例外穿出使整個檢查無輸出） |
| 測試品質 | 覆蓋全部驗收條件 | 隔離失效（patch 類別方法影響全 process）、3 項耦合內部佈線、斷言為子字串存在故結構改變不會紅 |
| 文字品質（自檢 A 類） | 零 finding，通過 | 1 項 Critical（未落地事項無 trigger）、2 項字句層違規、1 項自評誇飾 |
| 驗收條件 | 全數達成 | 1 條實測未達成（要求標註來源編號，實際檔案內該編號出現 0 次），且自檢表就此作出相反聲明 |
| 範圍完整性 | 已涵蓋 | 同批同型殘留漏 1 張 ticket、1 個工作日誌主檔、6 個框架檔案 |

自審的每一項結論在其視角內都成立，錯的是覆蓋度宣稱。兩個獨立審查者對同一處假陳述各自命中，說明該缺陷並非隱晦——它只是不可能被產出它的同一個視角看見。
