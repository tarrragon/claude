# DOC-GPD-010: 規範條文的效力取決於讀者是否走到它，不在執行路徑上的條文措辭再清楚也零生效

## 症狀

一份供人或 agent 執行的判準文件（判定程序、檢查清單、評估 skill、審查規範、驗收條件表）中，某一條要件語意明確、措辭無歧義、位置就在該主題的段落裡。獨立讀者依該文件作答後，**該條在產出中從未被援引，或被援引而不進判定**。

作者這一側的可觀測面全部正常：改文的 diff 存在、措辭經過推敲、複核者同意它寫得清楚。唯一缺的東西不在文字裡——讀者沒有走到那裡。

**最強訊號是同文件內的位置對照**：某一句連續多輪零引用，而**同段落僅相距兩句**的另一句被同批讀者全數引用。兩句的措辭品質、可讀性、與題目的相關性皆相近，差別只有位置。「寫在同一段落」本身已被量到讀數為零。

### 三個變體

三者的共同結構是：條文要生效，讀者與條文之間需要一個**到達事件**；三個變體各自缺了到達事件的一個必要條件。

| 變體 | 讀者走不到它的原因 | 最短偵測問句 |
|------|------------------|------------|
| **A：位置在程序之外** | 條文寫成段落中的一句、清單引言、旁註、補充說明；而讀者取用的單位是**程序中的一個步驟與有編號的款次**，不是段落中的一句 | 這句話是讀者執行的第幾步？答不出步號即命中 |
| **B：更早的一格已給出可填的值** | 條文寫在判定表之外，表內某欄已能填出一個值，讀者取到值即停止；表外段落只被當作程序說明，不被當作取值來源 | 表內每個委派型欄位：被委派的段落回傳的，是該欄承諾的型別嗎？ |
| **C：入口被後來的改動堵死** | 既有款次自述其適用前提為 P，新增的定義款使 P 恆不成立。該款**邏輯上不可達**，與讀者的注意力無關 | 新增定義款後，逐一取既有款次自述的適用前提，新款是否使它恆真或恆假？ |

### 變體 A：位置在程序之外

同一形態在單一工作線內量到五次，其中第五次是在明知前三次的情況下批准的：

| 讀數 | 形態 |
|------|------|
| 十五輪合計零引用 | 一款處置側的涵蓋關係陳述——讀者在前一步就收斂，不是措辭壞 |
| 六輪零引用 | 排除句寫在清單引言中段；同段落僅相距兩句的另一句被六輪全引 |
| 三輪 0/3 | 引言句的對應關係要求，未寫成任一步驟 |
| 六輪全引、仍判「無作用」 | **讀到了不綁定**——該款位於判定程序的結尾而非開頭，讀者讀完它時判定已經結束 |
| 排除條件邏輯成立、不生效 | 排除點位於讀者做選擇之後 |

後兩列是本變體最容易被誤診的部分：**被引用不等於生效**。以「該條是否出現在依據句裡」驗收改文，這兩種會判為成功。

**識別特徵**

- 某條文在多輪獨立讀數中取用率為零，或被引用而結論不受其影響
- 該條文的載體是段落、引言、括號補充、粗體提醒，而非編號步驟或編號款次
- 同一份文件中被穩定取用的內容，全部具有步號或款號
- 改文記錄是「新增一句／一段」，讀者執行的那個程序的步驟數未變

### 變體 B：判定表把終值託付給表外段落

表格欄位承諾輸出一個值（判定結果、分類、是否適用），但該欄的內容是「依某某段落判斷」。被委派的段落回傳的是**診斷句、判別問句或程序說明**，不是該欄承諾的那個型別。讀者在表內取到一個可填的值即停止，表外段落被當成程序而不是取值來源。

同一家族的兩個跨檔實例，載體形態是唯一差異：

| 實例 | 讀數 |
|------|------|
| 同型兜底邏輯寫在表格欄內 | 三輪零誤讀 |
| 同一邏輯寫在表外散文 | 一輪誤讀，其餘未被取用 |
| 兜底已進表內，但該欄把終值託付給表外的判別問句段 | 三輪讀者**全數引用該段、全數未轉換為該欄的值** |

第三列是本變體的純形態：委派關係本身被讀者接受了（他引用了被委派段落），失效在**回傳型別不符**——那段給的是一個問題，欄位要的是一個答案。

### 變體 C：新增定義款使既有款次的適用前提恆為空

在一份逐項封閉清單加內涵界定款構成的判準文件中增列某個名詞的界定款時，只檢查該款會不會**改變既有款次的判定結果**，未檢查它會不會使既有款次的**適用前提變成空集合**。

實例中兩道檢查一做一漏，對比清楚：

| 檢查方向 | 本次是否執行 | 結果 |
|---------|------------|------|
| 往回看（外溢／誤傷）：新款是否跑進不該管的地方，改變既有判定結果 | 執行了 | 發現界定款的重合判別法會外溢至另一項，加了射程限制句 |
| 往前看（可達性）：新款是否使既有款次自述的適用前提恆不成立 | **未執行** | 新款使同一項內某款第一句明寫的適用前提恆為空，該款的豁免效果從此走不到 |

被漏掉的是往前看那一道，且漏掉有結構性理由：**外溢有可觀測的失敗訊號，堵死沒有**。外溢會讓某個既有題目的答案翻面，看得見；堵死不翻面任何既有答案——它只是讓一條路再也走不到，所有既有輸出不變。以「既有題目複核無翻面」驗收改文的流程，對本變體完全沒有鑑別力。

**識別特徵**：新款次落檔後，任一既有款次的條文自述其適用前提為 P，而新款次使 P 恆不成立。

## 根因

**讀者走的是最省力的路徑，從第一個能產生所需輸出的位置取值，取到即停。** 文件對讀者的實際介面因此不是全文，而是他實際走過的那條路徑；路徑之外的字，無論寫得多清楚，都在介面之外。這對每一種讀者都成立——低階模型探針取字面可對的一句而非要先分類的抽象規則；代理人取一行就看得到的欄位而非要另開檔案的正確來源；文件作者本人引用手邊方便的計量口徑而不標明。

**作者是全文讀者，不是路徑讀者。** 作者寫下一句時，心裡的模型是「讀者讀到這一段時會知道 X」；但讀者不讀段落，他執行步驟。這使得措辭品質的提升——更精確的用詞、更強的語氣、粗體、驚嘆式提醒——全部作用在「讀到之後」，而失效發生在「讀不讀到」。**兩者不同層，因此措辭改動的預期效果是零，不是小。**

三個變體是到達事件的三種缺法：A 缺步號（不在程序上）、B 缺優先權（更早的一格先給了值）、C 缺可達性（前提恆空）。前兩者的成因在讀者的路徑，第三者的成因在條文之間的邏輯關係，與讀者無關——**C 對任何讀者都不可達，包括逐字讀完全文的讀者**。

---

## 證據：位置判準經過一次可證偽檢驗

> **讀者取用的單位是程序中的一個步驟與有編號的款次，不是段落中的一句。**

| 項目 | 內容 |
|------|------|
| 操作 | 把一款條文由段落移入編號程序，措辭未動 |
| 讀數變化 | 該款取用率由 0/3 升為 3/3 |
| 證偽條件 | 移入後取用率不升 |
| 是否觸發 | 未觸發 |

**射程限制（同批量測寫下，與上述判準同等重要）**：判準只到「編號單位」這一層，不到句。同一編號單位內**末句仍會掉**——實例中該款六輪全數被引用，其末句僅一輪被抄出。

因此正確的改法是「**成為一個步驟**」，不是「搬進某個有編號的段落，放在最後一句」。後者滿足判準的字面而不滿足它的射程。

## 解決方案

| 變體 | 改法 | 禁止的替代 |
|------|------|-----------|
| A | 把要件改寫成讀者執行的程序中的一個編號步驟。無法獨立成步時，**改寫該步驟本身**，使要件成為那一步的產出的一部分 | 加粗、加驚嘆、把句子移到段落開頭、在旁邊補一段說明——這些的預期讀數改變為零 |
| B | 判定表的每一格自己輸出該欄承諾的型別：分支條件與各分支的值寫進欄內，末格直接輸出值。表外段落的角色只能是解釋，不能是取值來源 | 在欄內寫「依某某段落判斷」而該段落回傳的是問句或診斷句 |
| C | 增列定義款後，**兩個方向各跑一次**：往回看（新款是否改變既有判定結果）、往前看（逐一取既有款次自述的適用前提 P，檢查新款是否使 P 恆真或恆假）。恆假者即死條文，當次處理 | 只跑往回看，並以「既有題目複核無翻面」作為改文安全的證據 |

**共同的驗收要求**：改文是否有效，只有另一批獨立讀者能判定。作者與同源審查者讀自己的改法時會自動補完缺的那一步，看不出差別——這正是本模式能在明知前例的情況下第五次發生的原因。

**條文零取用時，先分辨兩種成因**：沒測到（樣本不足，補測即可）與測不到（設計上同形，補測無用）。兩者在紀錄上同形，而每多測一批都會讓人更相信那條路不存在。

## 預防措施

| 時機 | 動作 |
|------|------|
| 寫下一條要件時 | 問「讀者執行到第幾步會用到它」。答不出步號，就不要寫在那裡 |
| 改文修一個缺陷時 | diff 必須落在讀者會走到的那個步驟上。diff 只有新增段落而程序的步驟未變，視為未修 |
| 判定表增欄或改欄 | 逐欄檢查該欄的值是否在欄內產生；委派到表外者列為缺陷，不論被委派段落寫得多清楚 |
| 增列定義款或收窄既有定義 | 兩方向檢查各跑一次並各自記錄結論；只記一個方向視為未做 |
| 宣告改文有效前 | 以獨立讀者重量一次取用率，且驗收標準不可只看「該條是否出現在依據句裡」——被引用而不綁定會通過該標準 |
| 撰寫多輪審查的意見時 | 審查意見必須落在被審查者的執行路徑上，不寫旁註 |

## 與既有模式的分界

| 模式 | 它治的形態 | 與本模式的差別 |
|------|-----------|--------------|
| `DOC-GPD-001` | 並列兩個判準，只有一個綁定可執行動作 | 該模式的條文**結構上沒有入口**（Action 沒綁它）；本模式的條文有入口，讀者的實際路徑不經過 |
| `DOC-GPD-009` | 對表述歧義加警告而非改句子結構 | 該模式的讀者**讀到了但讀錯**；本模式的讀者沒讀到，或讀到了不綁定。兩者的修法層級要求相同：修在缺陷所在的那一層 |
| `DOC-GPD-006` | 帶條件的決策壓進表格欄位，條件掉落 | 該模式是格**內**的值失真；本模式變體 B 是格把取值託付到格**外** |
| `TEST-BAL-005`、`ARCH-BAL-014` | 收窄合法值或修好上游，使既有消費者改走另一分支 | 與變體 C 同構，域在 code；本模式的載體是人或 agent 執行的文字，且無型別檢查與測試作為攔截層 |

## 跨專案可重現性

三個變體的成立條件只有兩項：(1) 存在一份供他人執行的判準文件；(2) 該文件有編號程序或判定表，且會被增補。替換專案名稱、檔案路徑與條文編號後，症狀、根因與偵測問句全數不變。

本模式的量測手段（獨立探針讀者、逐輪取用率）在沒有 agent 探針的環境同樣可用——以任何未參與撰寫的讀者實際執行一次該文件，記錄他援引了哪些條文，即可得到同型讀數。
