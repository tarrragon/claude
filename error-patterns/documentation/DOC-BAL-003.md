# DOC-BAL-003: 表格列的行尾豁免標記被下游格式化工具刪除

## 基本資訊

- **Pattern ID**: DOC-BAL-003
- **分類**: 文件標記慣例
- **來源版本**: v0.2.1
- **發現日期**: 2026-08-18
- **風險等級**: 中

## 症狀

在 markdown 表格列的行尾加上 HTML 註解形式的豁免標記（`broken-link-exempt`、`portability-allow` 等），在本地檢查通過；同一份檔案同步到另一個專案後，檢查器仍回報該行違規。檢視該檔在另一端的內容，標記已不存在，而同一張表中寫在儲存格內文的標記完好。

判別訊號：兩端檔案的同一張表，部分列有標記、部分列沒有，且沒有標記的都是「標記原本寫在行尾」的那些列。

## 根因

markdown 格式化工具（本例為 blog 專案的 `mdtools fmt --fix`，pre-commit 自動執行）重排表格時，把最後一個 `|` 之後的內容視為多餘欄位而移除。標記寫在儲存格**內文**時屬於欄位內容，重排後保留；寫在**行尾**（最後一個 `|` 之外）時被判定為表格語法殘餘，直接刪除。

上游作者看不到這件事，因為刪除發生在下游 consumer 的 commit 流程中，而非上游的檢查中；下游看到的是「標記本來就不存在」，因此會判定為上游漏標而重新補一次——補在行尾，於是下一次 commit 再被刪除一次。同一組標記可因此被反覆補與反覆刪除。

## 解決方案

把標記移進最後一欄的儲存格內文，位於閉合 `|` 之前：

```markdown
錯誤：| 欄一 | 欄二 | 欄三 | <!-- broken-link-exempt: 理由 -->
正確：| 欄一 | 欄二 | 欄三 <!-- broken-link-exempt: 理由 -->|
```

非表格行的行尾標記不受影響——格式化工具只重排表格結構。

## 預防措施

- 在表格列加行內標記時，一律寫進儲存格內文，不寫在閉合 `|` 之外
- 同一張表已有其他列標過標記時，照抄該列的位置寫法而非自行決定
- 補標記後在下游 consumer 端重跑一次檢查，而非只看上游結果——標記是否存活取決於下游的格式化工具，上游看不到

## 判別與相近模式的差異

`PC-146` 記錄的是人把標記放在錯誤的位置（獨立章節、命中行下方），修法是人重新放對。本模式的標記位置對檢查器而言是有效的，失效來自下游工具改寫檔案內容，修法是選一個格式化工具不會動到的位置。兩者的共同前提是行內標記只作用於所在行，一旦標記與命中行分離即失效。
