# DOC-GPD-003: 敘述中實例化可變計數，集合增減一員即全量失效

**類別**: documentation
**嚴重度**: 中
**發現日期**: 2026-09-07
**來源版本**: 0.1.0
**相關 Ticket**: 元件契約新增回饋契約欄時的血緣盤點票（2026-09-07 建立）、可變計數規則固化票（同日建立）；規則落點 `.claude/references/reference-stability-rules.md`

---

## 症狀

文件敘述以數字描述一個會演進的集合大小——「十一欄位契約」「`core/` 共 7 檔」「九欄位」——集合新增或移除一個成員後，所有帶數字的敘述同時變錯，而每一句字面完好、連結有效、grep 不報錯。修正時必須 grep 全量找出每一處數字並逐一改成新數字，下一次集合再變，同一批位置再失效一次。

**本案實例**：元件契約自「九欄位」（doc 範本初版）→「十一欄位」（方法論 1.11.0 加操作機制與無障礙）→ 2026-09-07 加回饋契約。第二次升格時 doc SKILL.md 的模板表仍寫九欄位，落後 15 天才被稽核發現（doc CHANGELOG 1.12.1）；第三次升格前盤點，「十一欄」字面分布 17 檔 60 餘處（方法論 17 處、skill 六檔 29 處、範本 4、專案 spec 4、外圍 7 檔各 1-3），其中 skill 的 description 觸發詞、〈契約齊全的定義〉分母、佔位值「六欄／五欄」分組、「三欄制」皆以計數為結構前提。

**同型前例**：`rules/README.md` 的「`core/` 共 7 檔」在檔數增至 17 後 stale 多版（10.2.0 更正、10.3.0 再確認）——每次確認都是一次人工對帳。

**識別特徵**：

- 句中含「N 欄位」「N 檔」「N 條」「N 項」「N 類」「N 步」且 N 指的是活文件內某張表、某個目錄、某份清單的大小
- 數字出現在權威表以外的位置（description、入口檔、下游 skill、CHANGELOG 以外的敘述）
- 數字被當成名稱使用（「十一欄位」成為觸發詞、章節名、分組名），使改名成本疊加在改數字上

## 根因

集合大小是集合的**衍生值**（derivation），不是穩定事實：權威表加一列，數字就變，但沒有任何機制把權威表的變更推送到寫著舊數字的每個位置。與 DOC-V1-001（位置編號）同源——位置編號是排列的衍生值，計數是大小的衍生值；兩者都在寫入當下正確、在目標後續任一次改版失效、失效時不報錯。計數更難處理的一點：它常被拿來當名稱（「十一欄位表」），名稱一旦成為跨檔錨點（觸發詞、章節名、分組法），改數字等於改名，血緣擴散到所有引用該名稱的檔。

## 解決方案

1. 敘述引用集合大小時**不寫數字，改引用集合的權威名稱**：「〈元件契約判準〉欄位表的全部欄位」「`rules/core/` 全部檔案」；讀者要數字就去權威表數，權威表變了敘述自動正確。
2. 權威表本身也不以數字命名：「元件契約欄位表」而非「十二欄位表」；分組法以成員語意命名（「可填不適用的欄位」而非「六欄」；「最小適用集」而非「三欄制」）。
3. 已成為錨點的數字名稱（description 觸發詞、章節名）改名時走 grep 全量同步，CHANGELOG 記血緣檔數，且改成不帶數字的名稱——只把十一改成十二是把同一筆債換個數字再欠一次。
4. 判準問句：「這個數字在集合增減一個成員後還對嗎？」答否即為衍生值，不得實例化。

## 預防措施

| 時機 | 動作 |
|------|------|
| 寫任何「N 欄／N 檔／N 條／N 類」句時 | 先問判準問句；答否改為引用權威名稱 |
| 為表、分組、章節命名時 | 不以成員數命名，以語意命名 |
| 權威表增減成員的 commit | `rg "[一二三四五六七八九十0-9]+(欄位|檔|條|項|類|步)" .claude/rules .claude/references .claude/methodologies .claude/skills/*/SKILL.md` 掃殘留計數（規則固化與 hook 候選由規則固化票承接） |
| 例外 | 凍結承諾的數字（規則編號、schema 版本、API 常數）與實測記錄（規則 9 量測值，附時點）是 fact 可寫；判準為「數字是否有凍結承諾或量測時點」 |

## 與相關模式的關係

- **DOC-V1-001**（位置編號引用隨目標文件演進靜默失效）：同一根因的兩個方向——DOC-V1-001 是排列的衍生值（位置編號），本案是大小的衍生值（計數）；兩者防護原則相同（引用改用語意標題／權威名稱，不寫死衍生值本身）。
- **規則落點**：`.claude/references/reference-stability-rules.md` 規則 10「可變計數不實例化」——本錯誤模式為該規則的固化來源，判準問句、例外表、偵測 pattern 皆源自本案「解決方案」與「預防措施」章節。

## 行為模式分析

寫作當下數字是對的，且比引用名稱短、比「全部欄位」具體，生成端傾向選它；失效發生在未來別人的 commit 裡，作者永遠看不到自己寫的數字變錯。DOC-V1-001 記錄的是「第 N 點」，本案是「共 N 個」，兩者是同一個 derivation 問題的兩個方向：一個指位置，一個指大小。
