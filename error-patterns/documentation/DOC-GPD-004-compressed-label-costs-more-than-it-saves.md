# DOC-GPD-004: 標籤壓縮省下的字數固定，展開成本乘以讀者數與引用點數

**類別**: documentation
**嚴重度**: 中
**發現日期**: 2026-09-08
**來源版本**: 0.1.0
**相關 Ticket**: 展開壓縮列名並同步錨點的規格票（2026-09-08 建立，用戶裁示）

---

## 症狀

表格列名、欄位標籤、章節標題被壓縮成缺少限定語的短詞，讀者無法就地判定它指涉什麼，須跨節或跨檔查證才能還原。壓縮的載體是**標識符**（會被引用、被 grep、被當錨點），不是散文句子，因此還原成本不是付一次，而是每個讀者各付一次、每個引用點各付一次。

**本案實例**：一份互動規格的動畫提示表有一列名為「格選中態出現」。還原它需要三項外部知識：

| 被省略的限定語 | 讀者須查何處 |
|---------------|-------------|
| 哪一種「格」 | 該表所在的 §3.1 標題（Domain 視圖），再對到元件目錄的矩陣格元件 |
| 「選中態」是一次性回饋還是持續性標記 | 該列「形式」欄的括號說明（讀了列名還不知道要看它） |
| 「出現」指什麼 | 同表其他列的「轉換」欄語意——這一欄問的是狀態從無到有的那一瞬間 |

實測還原一次耗兩次檔案查詢加一段拆解；把限定語寫進列名（「矩陣格的選取標記出現時」）只多六個字。該列名另被下游規格四處逐字引用為跨檔錨點，壓縮成本因此被複製四次，且各引用點無法就地展開——改字即斷開字串比對。

**識別特徵**：

- 列名／標籤的名詞缺限定語（「格」是哪種格）、或動詞缺主詞（「出現」是誰出現）
- 同一份文件的其他列寫得完整（「矩陣 → 泳道的定位」「載入中 → 正常 / 空圖」），可見壓縮非該表慣例而是個案
- 該標籤被其他文件逐字引用為錨點——引用點越多，就地展開越不可行

## 根因

寫作當下作者持有全部限定語，列名只是他腦中概念的提示符，短的讀起來更整齊；讀者沒有那份脈絡，短詞對他是待解的謎。與 `DOC-V1-001`（位置編號當錨點）、`DOC-GPD-003`（計數當字面）同屬「錨點寫法」家族：三者都把「作者側成立、讀者側不成立」的東西寫進了標識符。

**為何既有的用詞檢查全數放行**（來源：並行 session 對同一案例的分析，2026-09-08）：一般的壓縮術語檢查問的是「拿出句子後知不知道這是什麼、能不能放進表格第一欄、讀者能不能用它問問題、能不能跟同類詞並列」——本案四道全過。被砍掉的是**限定語**，而限定語的缺席**在語法上沒有痕跡**：名詞頭健在、語法完整、grep 命中。詞本身讀起來就是完整的，所以檢查者不會停下來。這比「周圍寫法都正確因而不突兀」更根本：不突兀是環境因素，語法無痕是這個詞自身的性質。

**成本結構是不對稱的**，這是它比一般用詞不精確更該處理的理由：壓縮省下的是固定字數（本案六個字，寫一次），展開付出的是查證成本乘以讀者數再乘以引用點數。標籤被引用得越多——正是它被壓縮得越像個「術語」的時候——總成本越高。

## 解決方案

1. **列名與標籤自足**：讀者只看標籤本身（不看同列其他欄、不跳章節）能判定它指涉什麼。判準問句：「這個標籤裡的每個名詞，讀者知道是哪一個嗎？每個動詞，讀者知道主詞是誰嗎？」
2. **省略的限定語補回標籤，不補在鄰欄**：把限定語寫進「形式」「說明」欄不算解決——讀者是先讀標籤決定要不要讀那一列的。
3. **要當跨檔錨點的標籤，自足性要求加倍**：引用點無法就地補充脈絡，只能整串複製；此時標籤是唯一的說明。
4. 既有壓縮標籤要改時，**與其全部引用點同一次改**（改字即斷鏈，見 `DOC-V1-001` 的錨點穩定性要求）。

## 預防措施

| 時機 | 動作 |
|------|------|
| 為表格列、欄位、章節命名時 | 先問判準問句；缺限定語就補進標籤本身 |
| 判定一個標籤是不是錨點（可機械執行） | 拿**定義處的標籤字串**跑 `rg -F -l -- "<標籤>" <根目錄>`，命中兩檔以上即為錨點，自足性要求升級。**代理指標會量錯**：用「這個段標在幾個檔出現過」之類的近似去掃，量到的是模板重複而非引用，而輸出仍是一張看似正常的排行榜（並行 session 實測前幾名為 `YAML`、`Problem`、`Server`） |
| 標籤將被其他文件引用為錨點時 | 自足性從建議升為要求——引用點無法就地展開 |
| 審查文件時遇到讀不懂的短標籤 | 那不是讀者的知識缺口，是標籤的缺陷；記下來，不要私下查完就算了 |
| 例外 | 表頭語境下已自足的通用欄位標籤（「觸發」「反應」在該表結構下無歧義）；領域內有正式定義且該定義可一跳查到的術語 |

## 與相關模式的關係

- **DOC-GPD-006**（帶條件的決策被壓進表格欄位，條件掉落使結論的決策語意改變）：同屬壓縮家族，**失效形態相反**。本模式掉的是限定語，壓縮後的標籤模糊但可還原，讀者知道自己不懂於是去查——傷害是查證成本；該模式掉的是條件，壓縮後的值明確但已改變決策語意（「延後 + 重評條件」寫成「N/A」），讀者沒有任何訊號要去查——傷害是依錯誤的決策行動。**模糊會促使查證，明確不會**，故該模式比本模式更難被攔下。兩者的防線因此不同：本模式的防線是把限定語寫回標籤，該模式的防線是改變欄位的形狀（加寬到裝得下條件，或讓格只放指標）。
- **DOC-V1-001**（位置編號當錨點）、**DOC-GPD-003**（計數當字面）：見根因段所述的「錨點寫法」家族。

## 行為模式分析

壓縮發生在作者剛把一件事想清楚的當下——限定語在腦中太顯然，寫出來像廢話。而「像廢話」正是讀者需要的：他沒有經歷那次想清楚的過程。這也是為什麼審查抓不到——審查者若熟悉該文件，同樣持有那份脈絡；只有真正的新讀者（或另一個 session）才會撞上。

本案的暴露路徑值得記：問題不是由審查發現，而是由一位讀者問「這四個字是什麼意思」，而回答那個問題所花的成本本身就是證據。
