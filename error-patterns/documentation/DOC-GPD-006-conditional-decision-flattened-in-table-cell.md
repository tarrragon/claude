# DOC-GPD-006: 帶條件的決策被壓進表格欄位，條件掉落使結論的決策語意改變

**類別**: documentation
**嚴重度**: 高
**發現日期**: 2026-09-09
**來源版本**: 0.1.0
**相關 Ticket**: driven port 回饋點覆蓋盤點與輸出端 spec 落點裁定的分析票（2026-09-09），其覆蓋表的監控追蹤欄；權威來源為 `docs/tech-decisions.md`「2026-08-27：執行期 log 的裁決」

---

## 症狀

一項記錄為「暫時不做，條件成立時重評」的決策，在被摘要進表格欄位、狀態欄或檢查清單時，寫成一個無條件的值——「N/A」「不適用」「不做」「已完成」。該格讀起來明確、語法完整、沒有任何缺漏的痕跡，因此**沒有任何讀者會被觸發去查來源**。

失真的不是精確度，是決策語意：「延後 + 重評條件 + 觀察者」是已定策略，有觸發條件、有人在看；「N/A」是這件事本來就不適用。前者會醒來，後者不會。

**本案實例（同一決策上第二次發生）**：

專案的 structured log 決策原文為「**維持 structured log 的延後**，重評條件與 tripwire 不變」，且 tripwire 總表有對應一列（「出現無法由破洞報告解釋的故障 → 重評 structured log 的延後決定」）。

| 次數 | 失真形態 | 被記錄於何處 |
|------|---------|------------|
| 第一次 | 摘要寫成「Stage 5 明示不寫」，使一個已處理好的決策在待決清單裡變成擋住整個維度的死結 | 由 `docs/tech-decisions.md`「2026-08-27：執行期 log 的裁決」段落**開頭親自更正**，並寫明「延後與拒絕在決策語意上不同：前者是已定策略、有觸發條件、有觀察者；後者是關門」 |
| 第二次 | 一份 driven port 回饋點覆蓋表把「監控追蹤」整欄判為 `N/A`，並附一個不存在的引用（宣稱某入口文件已定，該文件全檔搜尋 `APM`／`監控`／`Sentry` 為零命中） | 本錯誤模式；PM 覆核時攔下，該表原將被兩份新規格逐字沿用 |

**第二次的關鍵細節**：執行者在同一份報告的另一段寫了「監控 N/A + **tripwire**」——**它知道 tripwire 存在**。失真不發生在認知，發生在把結論濃縮進表格欄位的那一步。

**識別特徵**：

- 表格欄位、狀態欄或檢查清單格內出現絕對值：`N/A`、`不適用`、`無`、`不做`、`已完成`
- 該值的來源是一份帶條件的決策（含「延後」「暫緩」「重評條件」「tripwire」「待……時」等語）
- 該格附帶的引用指向一份摘要文件（入口文件、索引、CLAUDE.md 類），而非決策的原始記錄
- 同一份產出的散文段落提到了條件，表格欄位沒有——認知與記錄不一致，是本模式最強的訊號

## 根因

表格欄位是**定寬單值槽**：它問一個問題，收一個答案。帶條件的決策至少有兩個成分——處置（延後）與條件（何時重評、誰在看）。壓進單值槽必須捨棄其一，而被捨棄的必然是條件，因為欄位問的正是處置。

這使失真具有**方向性**，不是隨機的資訊損失：條件永遠是先掉的那個，且掉了之後剩下的處置看起來仍然是一個完整的答案。

與 `DOC-GPD-004`（標籤壓縮）同屬壓縮家族，但**失效形態相反，這是本模式須獨立記錄的理由**：

| | DOC-GPD-004 | 本模式 |
|---|---|---|
| 掉的是 | 限定語（哪一種格、誰出現） | 條件（何時重評、誰在看） |
| 壓縮後的值 | 模糊但可還原 | **明確但已改變語意** |
| 讀者的處境 | 知道自己不懂，去查，付查證成本 | **不知道自己不懂，不查** |
| 成本落點 | 查證成本 × 讀者數 × 引用點數 | 依錯誤的決策行動 |

`DOC-GPD-004` 的傷害是效率，本模式的傷害是正確性。模糊會促使查證，明確不會——**這正是為何本模式比它更難被攔下**。

與 `DOC-GPD-003`（可變計數實例化）的關係：兩者都是「壓縮產生的衍生值與原始事實分歧」，但該模式掉的是精確度（數字過期），本模式掉的是決策語意（條件消失）。

## 解決方案

1. **條件與處置同格**：欄位寫「延後（重評條件：出現無法由破洞報告解釋的故障）」，不寫「N/A」。多幾個字，換掉一次錯誤行動。
2. **欄位窄到放不下時，該格只放指標**：寫「見〈2026-08-27：執行期 log 的裁決〉」，讓讀者必須跳轉。**一個逼人跳轉的格，優於一個讀起來完整但錯的格。**
3. **引用指向決策的原始記錄，不指向摘要文件**：摘要文件本身可能已經是一次壓縮的產物，引用它等於把失真接力下去。本案第二次失真的引用正是指向入口文件，且該文件根本沒有這項內容。

## 預防措施

| 時機 | 動作 |
|------|------|
| 準備在表格／狀態欄／檢查清單寫下 `N/A`／`不適用`／`不做`／`無` | 問一句：**這是「本來就不適用」，還是「暫時不做」？** 後者不得寫成前者 |
| 摘要一項決策進任何定寬欄位 | 先讀決策的**原始記錄**（非入口文件的轉述），確認它是否帶條件；帶條件者依解決方案 1 或 2 處理 |
| 覆核他人產出的覆蓋表／狀態表 | 對每一個絕對值欄位反查來源，確認**來源本身也是絕對的**；同時比對該產出的散文段落是否提到了欄位裡沒有的條件（認知與記錄不一致是最強訊號） |
| 決策原文本身已記載過同型失真 | 該決策為高風險複發點，其每一次被引用都應覆核。本案的原文親自更正過第一次，仍發生第二次 |

## 與相關模式的關係

- **DOC-GPD-004**（標籤壓縮省下的字數固定，展開成本乘以讀者數與引用點數）：同屬壓縮家族，失效形態相反（模糊可還原 vs 明確已變質），詳見根因段對照表。
- **DOC-GPD-003**（敘述中實例化可變計數）：同為壓縮產生的衍生值與事實分歧，掉的是精確度而非決策語意。
- **規則落點**：`.claude/rules/core/decision-trigger-binding.md` 規則 1 定義兩種合法狀態——(a) 已決策、(b) 明確 trigger 延後。本模式是**狀態 (b) 在被轉述時退化為狀態 (a)**：原本綁了 trigger 的延後，被寫成一個沒有 trigger 的結論。該規則管的是寫入端（不得無 trigger 延後），本模式管的是轉述端（不得使既有的 trigger 在轉述中消失）。

## 行為模式分析

寫的人在壓縮當下持有完整脈絡，「N/A」對他是「那件事我們決定延後所以這欄先不填」的簡寫；讀的人拿到的是一個定論。本案第二次失真的執行者在同一份報告的散文段寫了「監控 N/A + tripwire」——**它並非不知道條件存在，是欄位裝不下**。

因此本模式的防線不能放在「提醒作者記得條件」——作者記得。防線要放在**欄位的形狀**上：定寬單值槽承載帶條件的決策，本身就是形狀不匹配。要嘛把格加寬到裝得下條件，要嘛讓格只放指標。
