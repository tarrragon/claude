# TEST-GPD-1010: 語法層守衛以單一字面子字串偵測一個語法構造，只擋得住撰寫者想到的那一種寫法

## 基本資訊

| 項目 | 內容 |
|------|------|
| 風險等級 | 中 |
| 分類 | test |
| 來源版本 | 0.6.0 |
| 來源事件 | 架構守衛要禁止 lib 重新匯出某個 extension，判定寫成 `source.contains('show X')`；Phase 4 審查列出四種等價寫法全部漏過 |
| 首次觀測 | 2026-11-04 |

## 症狀

守衛要禁止的是一個語法構造（例：「把某符號匯出到模組外」），判定卻寫成比對該構造的一種字面形態。結果：

- 守衛改寫前為紅、改寫後為綠，正向對照輸入也照規則 E2 判為違規，測試鏈看起來完整。
- 但同一語意的其他寫法全部不命中：不帶篩選子句的整體匯出、以排除子句（`hide`）匯出、篩選清單中目標不在第一位、子句內換行或空白數不同。

其中最常見的寫法（不帶篩選子句）往往正好漏過，因為撰寫者是看著現存違規的那一種形態寫判定的。

## 根因分析

1. 判定的對象是「字面形態」，要禁止的卻是「語意」。同一語意在語法上有多種形態，字面比對只覆蓋其一。
2. 正向對照輸入取自現存違規，與判定出自同一個心智模型，兩者一起漏掉同樣的變體。E2 證明守衛會紅，但不證明守衛擋得住該語意的全部寫法。
3. 派發者在紅燈步驟裡直接指定了比對字串，實作者照字面實作，沒有人回頭問「還有哪些寫法表達同一件事」。

## 解決方案

- 判定改為解析語法單元本身（例：抓出整段 export 指令直到 `;`），再對解析結果判斷語意（是否會把目標符號帶出模組），而不是比對某段文字。
- 能直接禁止更上位的構造時，優先禁止上位構造（例：lib 內禁止 export 該檔案的 extension），遞移與變體問題一併消失。

## 預防措施

- 撰寫或派發語法層守衛時，先列出「同一語意的所有寫法」，每一種各給一個正向對照輸入；列不出來就代表判定的對象選錯了層次。
- 派發紅燈步驟時，指定要禁止的語意與至少三種變體輸入，不直接指定比對字串。
- Phase 4 審查語法層守衛時，固定問一句：「不帶任何修飾子句的最常見寫法，擋得住嗎？」

## 觸發案例

- 0.6.0：禁止 lib 重新匯出 `StateHolderOverride` 的架構守衛，判定為 `contains('show StateHolderOverride')`。審查列出裸 export、`hide`、多名 `show`、換行 `show` 四種漏網寫法，改為解析 export 指令並補四個正向對照。
