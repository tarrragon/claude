# TEST-GPD-1001: 以精簡測試輸出中累計計數器的出現位置推定單一測試的結果，歸屬會錯位

## 基本資訊

- **Pattern ID**: TEST-GPD-1001
- **分類**: 測試設計（test）
- **風險等級**: 低（總數正確、結論通常不受影響；但逐測試結果表會寫錯，下一位讀者據此判斷某個測試被停用）
- **來源版本**: 0.5.0
- **相關 Pattern**: TEST-GPD-1000（同一批 integration_test 驗證的前因）

---

## 問題描述

### 症狀

- 測試執行器以精簡格式輸出（例：`flutter test` 預設 reporter 的 `+36 ~2 -0: <測試名>` 形式），只給累計的通過、略過、失敗數
- 回報者要產出逐測試結果表，便以「`~1` 變成 `~2` 那一行附近的測試名」推定哪個測試被略過
- 推定結果與原始碼不符：被列為 skip 的測試其實通過，真正被略過的是另一個

### 根因

| 因素 | 作用 |
|------|------|
| 計數器是累計值，不是逐測試事件 | 一行只說「到目前為止共幾個略過」，不說「這一行的測試被略過」 |
| 計數行附帶的名稱是當下顯示的測試 | 計數變動與名稱更新不保證同一事件，相鄰測試的名稱會出現在計數變動的那一行 |
| 總數守恆 | 歸錯一個時總數仍對，自我核對看不出錯 |

---

## 解決方案

- 逐測試結果改用結構化事件取得：`--reporter json` 的每個 `testDone` 事件帶測試 ID 與 `skipped` 欄位，可直接對應到測試名
- 或從原始碼確認略過條件：搜尋 `skip:` 參數，列出條件為真的測試（例：未設環境變數時預設略過的實機探測）
- 兩者都做不到時，結果表只寫總數，不寫逐測試歸屬

## 預防措施

- 派發驗證票要求逐測試結果時，同時指定取得方式（json reporter 或原始碼對照），不讓回報者從精簡輸出自行推定
- 驗收逐測試結果表時，對每個 skip 或 fail 條目查原始碼的 `skip:` 條件或失敗訊息，數量對得上不算驗證

## 實例

一次 macOS integration_test 全套驗證回報 36 通過、2 略過。回報者依日誌中 `~` 計數出現的位置，把略過歸給「實機探測：開啟真實目錄」與「矩陣三值分布 A1」。原始碼顯示實機探測群組的兩個案例皆標 `skip: !_runProbe`，未帶 `RUN_OPEN_PROBE=true` 時一律略過；兩個略過都是這兩個探測案例，矩陣三值分布 A1 實際通過。PM 驗收時以原始碼更正票面。
