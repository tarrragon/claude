# TEST-GPD-005: 上限守衛測試只量產生器的單一組合，後續增加的變體越過上限仍維持綠燈

## 基本資訊

| 項目 | 內容 |
|------|------|
| 風險等級 | 中 |
| 分類 | test |
| 來源版本 | 0.5.0 |
| 來源事件 | 派發骨架行數守衛測試全綠，實際以 CLI 產生的骨架卻超過 prompt 長度上限、被 hook 硬擋 |
| 首次觀測 | 2026-10-20 |

## 症狀

一個產生器（派發骨架組裝函式）依多個開關組出輸出：是否觸及 hook、隔離模式、是否附測試入口、是否要求紅燈句。另有一個長度守衛（hook）規定輸出不得超過 30 行，並有一支測試把「骨架行數 ≤ 上限」綁在一起。

該測試只以一組參數呼叫產生器（觸及 hook、未隔離、無測試入口、無紅燈句），量得 30 行，剛好在上限上，全程綠燈。之後三張票各自替其他開關加句（隔離模式兩句、紅燈句一句、測試入口一行），實際派發用的組合長到 34 行，照骨架原樣派發必被擋，測試仍綠。

同一支測試的檔頭原本就記載過一次同族失效：骨架從 10-15 行長到 47-48 行，當時只驗關鍵字的測試全程綠燈。補上的行數測試修好了「量錯維度」，卻只量一個組合，等於把同一個盲區換到另一個軸上。

## 根因

1. **上限是對「所有可能輸出」的承諾，測試只抽查一點**。產生器的輸出空間是開關的笛卡兒積，最長的組合才是上限是否成立的判準；固定一組參數的測試量到的只是其中一格。
2. **增句的票不會回頭看守衛測試**。每張票只在自己的開關分支上加句，並以「未開啟該開關時輸出不變」作 E1 對照；守衛測試沒有開啟那個開關，因此對新增句子毫無感知。
3. **量到的那格恰好落在上限上**。剛好等於上限的綠燈不提供餘裕資訊，看起來與「還很寬鬆」同形；只要任一新變體多一行即越界，測試卻不會反映。

## 解決方案

1. 守衛測試參數化，涵蓋所有影響長度的開關組合，斷言取最長者。
2. 斷言值保留使用端需要的餘裕（例：產生器只是 prompt 的一部分，另需留給呼叫者填寫的行數），不以上限本身為斷言值。
3. 修正時以實跑紅燈證明：用修正前的產生器跑參數化測試，最長組合必須轉紅。

## 預防措施

| 層級 | 措施 |
|------|------|
| 撰寫測試 | 守衛類斷言（上限、配額、格式約束）的被測對象若是依開關組裝的輸出，測試以全部開關組合參數化；新增開關時同批把它加進參數表 |
| 實作新開關 | 替產生器新增開關或分支句時，搜尋綁定該產生器輸出的守衛測試，確認新開關在其參數範圍內 |
| 斷言值 | 斷言值寫成「上限減去使用端需要的餘裕」，並在測試註明餘裕的來源 |
| 與既有規則的關係 | 補充 `test-assertion-design-rules` 的 E2：E2 要求守衛測試含已知該紅的輸入；本模式要求守衛測試覆蓋被測輸出的整個組合空間，否則新出現的該紅輸入不在測試範圍內 |
