# TEST-GPD-1006: 補測既有分支時寫不出紅燈，改用對照測試；預期值抄自現行輸出而非規格，把程式缺陷釘成預期值

## 基本資訊

| 項目 | 值 |
|------|-----|
| 分類 | test |
| 來源版本 | 0.5.0 |
| 風險等級 | 中 |
| 首次觀察 | 2026-10-30 |

## 症狀

一張票只補測試：某個回退分支在真實資料下走得到，但沒有任何測試覆蓋。代理人發現現行程式已經會顯示該分支的文字，寫不出行為層紅燈，於是依測試鑑別力規則 E1 改用對照測試：同一批 fixture 下，條件成立時顯示一次、條件不成立時不顯示，兩者結果不同。

對照測試通過、合併、結案。下一張票才發現：規格要求這段文字附帶一個值（例如「本 UC 外（<domain>）」），程式卻一律傳空字串，畫面顯示空括號。剛合併的測試斷言的正是空括號，等於把缺陷寫成預期值。

## 根因

**寫不出紅燈被讀成「程式正確」**。紅燈的作用是證明測試能分辨對錯；補測既有分支時寫不出紅燈，只能說明程式有輸出，不能說明輸出符合規格。對照測試（E1）證明的是「條件會改變結果」，不證明「結果是對的」。

**預期值的來源是現行輸出**。代理人跑一次程式、看到輸出、把輸出抄進斷言。這種寫法的預期值與實作同源，實作有缺陷時，測試會一起帶著缺陷通過。規格才是預期值的權威來源，但流程中沒有一步要求回頭比對規格。

**與 IMP-GPD-020 同族**：兩者都是測試的預期值與實作共用同一個假設，所以測試沒有鑑別力；IMP-GPD-020 共用的是檔名慣例，本例共用的是現行輸出。

## 解決方案

- 補測既有分支時，斷言的預期值逐項對照規格條文寫出，並在測試或 Test Results 註明出處（規格編號與章節）。
- 寫不出行為層紅燈時，先問「現行輸出和規格逐字一致嗎？」。一致，才改用 E1 對照並照實記錄；不一致，就是找到缺陷，紅燈改以規格值寫出。
- 已合併的斷言若被證實釘住缺陷，修缺陷的票要一併改斷言，並在 Test Results 寫明改了哪些。

## 預防措施

- 派發補測票時，在驗收條件寫明「預期值取自規格 <編號> <章節>」，不寫「斷言現行行為」。
- 審查補測票時，對每個字面斷言問一句：「這個字串出自規格哪一條？」答不出來的，就是抄自現行輸出。
- 測試鑑別力規則可以補一句邊界：E1 對照證明條件會改變結果，不證明結果符合規格。
