# TEST-GPD-002：契約守衛斷言常數等於其值，而非驗證使用該常數的行為

## 基本資訊

| 項目 | 內容 |
|------|------|
| 風險等級 | 中 |
| 來源版本 | 0.4.0 |
| 發現時機 | 版本層級 Phase 4 並行評估，耦合視角回答防護類四問時 |
| 發現日期 | 2026-09-30 |

## 症狀

一支標為「守衛」的契約測試，要保證「程式把某類輸入當作 X 處理的集合，恰為 {A}」。測試的寫法是把程式內用來判定 X 的常數讀出來，斷言它等於 A：

- 測試全綠，正向對照也翻紅（正向對照改的是另一側的資料表，與常數無關）。
- 但判定 X 的實際程式碼即使改成不讀該常數、或另加一條不經常數的分支，這支守衛仍然全綠。

**本案具體樣態**：無向邊守衛以 `Set<String> _graphUndirectedNames() => {undirectedEdgeName};` 取得「Graph 認定為無向的邊型集合」，再斷言它等於 `{'association'}`。函式回傳的就是常數本身；建圖時真正決定哪些邊被當作無向的兩個判定點，沒有任何一處被這支測試觀測。

## 根因

**把「行為的輸入參數」誤當成「行為的輸出」來斷言**。常數是判定邏輯的一個輸入；契約要保證的是判定的結果。讀取常數並比對其值，等於在測「常數沒被改」，而不是「程式按契約運作」。

測試要讀到常數，往往需要先把私有常數改為公開，這個動作本身就是訊號：測試是透過實作細節取值，而不是透過行為的公開出口觀測結果。

**與 E2（守衛須含正向對照）的關係**：E2 只要求「已知應被攔下的輸入」確實被攔下。本案的正向對照改的是另一側的資料表，確實翻紅，所以 E2 通過；但被守的那一側（程式的判定行為）沒有任何輸入能讓它翻紅。E2 通過不代表兩側都有鑑別力。

## 解決方案

改為從行為的公開出口取值再斷言：以受測程式實際產出的結果（例如建圖後每條邊的無向旗標）計算「被當作 X 的集合」，斷言該集合等於契約值。

為判定行為另設一個正向對照：構造一個會被錯誤判定的輸入（例如讓判定邏輯多認一種），斷言守衛翻紅。

## 預防措施

- 撰寫契約守衛時自問：「如果判定邏輯不讀這個常數，本測試會紅嗎？」答否即為本模式。
- 為了讓測試讀取而把私有常數改為公開時，先確認是否有行為層的出口可以取代。
- 守衛有兩側（資料表一側、程式判定一側）時，每一側各需一個會翻紅的正向對照。
