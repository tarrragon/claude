# TEST-GPD-006: 相容性 fallback 只在舊版執行環境走到，閘門跑在新版時該分支從未被執行

## 基本資訊

| 項目 | 內容 |
|------|------|
| 風險等級 | 中 |
| 分類 | test |
| 來源版本 | 0.5.0 |
| 來源事件 | 為讓守衛測試相容宣告的最低 Python 版本，補上 `try: import tomllib / except ImportError` 的 fallback 解析；合併閘門的環境為較新版本，fallback 永遠走不到 |
| 首次觀測 | 2026-10-20 |

## 症狀

套件宣告支援的最低執行環境（例：`requires-python >=3.10`）低於實際開發與閘門使用的版本（例：3.12）。某段程式用了新版才有的標準庫，於是補一個相容性分支：

```python
try:
    import tomllib
except ImportError:
    tomllib = None   # 走自寫的最小解析
```

實作者以「指定最低版本實跑一次」驗證，結果為綠。之後閘門每次都在新版環境執行，`import tomllib` 成功，fallback 分支一次也不執行，全套件持續綠燈。審查以固定字串直接呼叫 fallback 解析函式，才發現它在另一個區段先出現同名欄位時，會回傳錯的值而且不報錯。

## 根因

1. **分支選擇由執行環境決定，不由測試輸入決定**。測試無法透過一般輸入走到 fallback，只能換執行環境或模擬匯入失敗；閘門只有一種環境，該分支就沒有覆蓋。
2. **一次性的最低版本實跑不構成持續驗證**。實作當下跑過 3.10 是綠的，但這只證明當下那次；之後 fallback 本身或它解析的設定檔有變動時，沒有任何持續執行的測試會察覺。
3. **fallback 通常是簡化實作**。為了不引入依賴而手寫的最小解析，本來就比正規實作窄（不分區段、只認單行），窄的地方正好落在沒有測試的分支裡。

## 解決方案

1. 把 fallback 邏輯抽成可直接呼叫的函式，以固定輸入測試，不依賴執行環境走到它：正常輸入、應拒絕的輸入（多行、格式不符），以及會讓簡化實作取錯值的輸入（同名欄位出現在其他區段）。
2. 若 fallback 必須經由匯入失敗觸發，以 monkeypatch 讓匯入失敗，在新版環境中走過整條路徑。
3. 評估是否改以提高最低版本宣告取代 fallback：只有一處依賴新版功能時，fallback 的維護成本可能低於提高宣告；依賴普遍時則提高宣告。

## 預防措施

| 層級 | 措施 |
|------|------|
| 撰寫相容分支 | 新增 `try/except ImportError` 或版本判斷分支時，同批補一個不依賴執行環境就能走到該分支的測試 |
| 驗收 | 驗收「最低版本可執行」時，除最低版本實跑外，確認該分支在閘門環境中也有測試覆蓋；只有一次性實跑者視為未持續驗證 |
| 與既有規則的關係 | 與 TEST-BAL-010（in-process import 遮蔽隔離環境的依賴缺失）同屬「測試環境與實際執行環境不同」的盲區，方向相反：該條是測試環境比實際寬鬆，本條是閘門環境比宣告的最低環境新 |
