# CQ-SCLK-001: 宣告的保證與實際行為脫節，且無測試訊號

## 症狀

註解、docstring 或防禦性程式碼宣稱了某個保證，實際行為並不提供它。測試全綠、靜態檢查全過、執行期無異常無日誌。落差只在下游某人依賴那個保證時才顯現，屆時症狀為「行為不符預期但找不到出錯的地方」。

## 三種常見形態

同一根源的三種樣貌，皆來自「寫下保證」與「實現保證」是兩個獨立動作，而只有後者會被測試檢查：

| 形態 | 具體樣貌 | 為何無訊號 |
|------|---------|-----------|
| 註解描述不存在的行為 | docstring 寫「重置時 X 與 Y 換為新值」，程式碼只換 Y，全檔從未讀取 X | 測試驗行為不驗註解。X 在當下沒有消費者，換不換都不影響任何斷言 |
| 註解描述不存在的對應關係 | 註解稱「此常數須與另一語言的某常數逐項一致」，該語言側根本沒有對應常數 | 一致性檢查若尚未建立（或正建立在這個前提上），無人會發現對應方不存在 |
| fallback 交出看似合法實則無效的物件 | `layer ?? CALayer()` 在失敗時回傳一個不在任何 hierarchy 中的孤兒物件 | 呼叫端對它操作全部成功回傳，只是沒有效果。無例外、無錯誤碼、無日誌 |

第三種最危險：前兩種至少在讀程式碼時可能被察覺，第三種連讀都讀不出來——`??` 看起來就是標準的防禦性寫法。

## 根因

**保證的宣告與保證的實現，由不同機制檢查，且前者根本沒有檢查機制。**

- 行為由測試檢查
- 型別由編譯器檢查
- 註解與 fallback 的語意由**無人**檢查

當三者一致時沒有問題。一旦某次修改只動了行為而沒動註解（或反之），落差就永久存在且無聲。時間拉長後，讀者對註解的信任會反過來成為傷害——註解說做了，所以沒人去查程式碼有沒有做。

## 為何比一般的過時註解嚴重

一般的過時註解（描述舊參數名、舊流程）讀者能從上下文察覺不對。本 pattern 的三種形態都描述**當下不存在的東西**：

- 「換為新值」——讀者無從得知那個值後來根本沒被讀取
- 「須逐項一致」——讀者不會去另一個語言的檔案確認對應方存在
- `?? CALayer()`——讀者看到的是一個合理的防禦性 fallback

三者都需要主動查證才能否證，而註解的作用正是讓人不必查證。

## 偵測

```bash
# 形態一：註解提到的欄位是否真的被讀取
# 先從 docstring 抽出宣稱會處理的欄位名，再確認該欄位除宣告外是否有讀取點
grep -n "<欄位名>" <檔案>
# 若命中只有「宣告」與「註解」兩類，無實際讀取 → 命中本 pattern

# 形態二：跨語言/跨模組對應關係是否雙向存在
# 註解稱與 X 一致時，實際到 X 確認
grep -rn "<常數名或錯誤碼>" <對應方目錄>
# 零命中 → 對應關係不存在

# 形態三：fallback 是否交出無效物件
grep -rnE '\?\?\s*[A-Z][A-Za-z]*\(\)' --include='*.swift' .
grep -rnE '\|\|\s*new [A-Z][A-Za-z]*\(\)' --include='*.ts' --include='*.js' .
# 逐一判斷：新建的空物件是否具備呼叫端期待的關聯（父容器、註冊、初始化狀態）
```

形態三的判準：**若 fallback 建立的物件缺少某個「只能由正常路徑建立」的關聯**（掛進 hierarchy、註冊到管理器、綁定到 context），它就是孤兒物件，應改為明確的錯誤路徑而非靜默降級。

## 修正

| 形態 | 修法 |
|------|------|
| 註解描述不存在的行為 | 二擇一：實作該行為，或把註解改為描述現況。若該欄位為未來預留，明說「為 X 預留，目前未使用」——預留與已實作是兩件事，讀者需要能區分 |
| 註解描述不存在的對應 | 改為前瞻語氣並標明依賴（「待 X 完成後建立」），不以現在式描述未來狀態 |
| fallback 交出無效物件 | 讓正常路徑保證物件必然存在（例如在 init 建立並以 non-optional 持有），或在失敗時拋出錯誤。不交出「能被操作但無效果」的替身 |

## 預防

| 措施 | 說明 |
|------|------|
| 註解提到欄位時，同時確認該欄位有讀取點 | 寫「重置時 X 換為新值」之前，先確認 X 真的會被誰讀 |
| 跨模組對應關係雙向查證後才寫進註解 | 「須與 X 一致」是可否證的斷言，寫之前到 X 確認它存在 |
| `??` 與 `||` 的右側必須是「等價可用」而非「型別相符」 | 型別檢查只保證能編譯，不保證那個物件對呼叫端有意義 |
| 預留欄位明確標註為預留 | 未使用的欄位若不標註，下一個人無從判斷是「還沒接」還是「忘了接」 |

## 適用範圍

任何語言。形態一與形態二與語言無關；形態三在有 null 合併運算子或可選型別的語言中特別容易出現（Swift 的 `??`、TypeScript 的 `??` 與 `||`、Kotlin 的 `?:`、C# 的 `??`）。

替換專案名稱與檔案路徑後仍成立。
