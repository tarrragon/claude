# 命名是分類的驗證程序

> **何時讀**：把一組觀察到的值整理成分類之前；或手上已有一份分類、要判斷它可不可信。
>
> **不適用**：分類是被設計出來而非從觀察值萃取的（新設計的 enum、event 型別），本文的第 1-2 步無對應物。判別見〈適用範圍〉。

## 材料出處

本文的推導材料來自一次 Flutter 桌面專案的 design token 萃取，以及同批的一則覆核紀錄。文中出現的三個角色：

| 角色 | 是誰 |
|------|------|
| 實作者 | 執行 token 萃取的代理人 |
| 覆核者 | 驗收該工作、並發現來源表缺陷的人 |
| 推導者 | 從上述材料推出本文的第三方，未讀原始檔 |

文中「那份規格」指該專案的 design token 規格；「這次」「同一批工作」皆指該次萃取。本文的**推導**由推導者負責，**數字與事實**經覆核者查證原始檔後確認。

## 核心主張

一份分類可不可信，取決於**它的錯誤有沒有經過一道會顯現出來的程序**。

分類寫在規格裡的時候，對的版本跟錯的版本外觀相同——都是一列標著角色的表格。沒有任何東西會因為它錯了而改變外觀，所以它不會被發現。逐一命名改變這件事：它把「這四個值屬於同一個序列」這種看不出對錯的宣稱，改寫成四個各自可被指認為錯的斷言。

**這條主張錯在哪裡才算錯**：若存在一種分類，其成員逐一具名、每個名字都能被成品否證（「成品」的定義見下節），而該分類仍系統性地為假，主張即不成立。

〈適用範圍〉列的三種失效條件**不是這種反例**——那三種情形下命名根本不產生驗證力（沒有成品可對照、成員太少無從分離、分類被外部凍結），所以主張的前件不成立，談不上反例。它們劃的是本方法的適用邊界。

## 命名能驗證分類的條件

三條缺一不可。

### 一、個別化：一個名字只蓋一個成員

「個別化」指把一個涵蓋 N 個成員的集合標籤，換成 N 個各自獨立的名字。

規格裡可以寫「表面層次」而不必知道它是什麼。給四個值各取一個名字則做不到——取名的人必須先查每個值實際承擔什麼角色。

集合標籤把 N 個宣稱壓成一個，而那一個宣稱的真值條件模糊到無法解決。個別化把它拆成 N 個各自要面對的問題。

### 二、語意內容：名字要能被成品否證

**「成品」指這批值實際被使用的地方**——不是規格，也不是這份分類本身。它隨領域而異：

| 分類對象 | 成品是 |
|---------|-------|
| design token | 畫面／artboard 上該值出現的位置 |
| DB 欄位群 | 該欄位實際存放的資料，以及讀寫它的程式 |
| 目錄結構 | 目前放在該目錄下的檔案 |
| 標籤體系 | 已被標上該標籤的項目 |

共同點是**它先於分類存在，且不因分類改變而改變**。分類是對它的描述，所以它能反過來判分類的對錯。

「能被否證」指存在一個成品上可指認的事實，該事實不成立則此名為錯。

`surfaceSegmentTrack` 斷言「這個色是分段控制元件的軌道底」，讀者拿著畫面就能判定它對不對。`surface4` 只斷言「它是清單裡第四個」，而這件事由列舉這個動作本身保證為真——它完成了個別化，卻沒有可被否證的內容，驗證力歸零。

判斷標準是一句話：**一個讀者只拿著這個名字跟成品，看不看得出它錯了。** 看不出來的話，命名這一步只是儀式。

**注意這條不等於「不准用序號」。** 序號式名字是這條不通過的一種形態，不是唯一形態——`surfaceLow` 不是序號，但若相鄰成員的用途重疊、或名字斷言與實際角色相反，同樣不通過。

### 三、對照來源：真值條件要能在規格之外解決

名字的對錯回設計檔判定，不回規格判定——規格是衍生物，也正是待驗的對象。

這一條解釋了為什麼命名比審查規格有效：審查規格的人手上只有規格，而規格的每一列都自洽。

## 帶順序詞的集合標籤會規定下一個成員怎麼命名

「表面層次」這個標籤裡的「層次」斷言了一個順序。四個值加一個順序詞等於一個隱含宣稱：它們構成一道明度階。

這個宣稱會外溢到三個地方——API 的形狀（`surface1` 到 `surface4`）、擴充規則（下一個淺灰綠色自動變成 `surface5`）、以及任何據此推理對比度的人。**假分類不只是錯的，它還規定了後續成員該怎麼被命名，於是每個新成員都繼承同一個錯誤。**

所以在命名這一步攔下它的收益高於表面看起來的樣子：攔下的是一列表格，避免的是一整條擴充路徑。

## 三層結構：每層記錄什麼，就是那層的判定依據

| 層 | 回答 | 可見性 | 記錄什麼 | 對錯回哪裡判定 |
|----|------|--------|---------|--------------|
| 原始值層 | 這個值是多少 | 私有 | 值 + 出現次數 | 來源檔（重新量測即可核對） |
| 語意層 | 這個值代表什麼 | 公開 | 語意名 → 原始值名 | 來源檔中該值的實際用途 |
| 元件層 | 這個元件用哪個 | 元件檔內 | 元件角色 → 語意名 | 該元件的渲染結果 |

「原始值層」指只記錄測到什麼、不作任何解釋的那一層；它私有，畫面不得直接引用。

語意層不記出現次數，因為次數不會讓一個定義為真。把次數帶進語意層等於把觀察混進定義——而「四個色出現次數相近、外觀也相近，所以是同一組」正是假分類的成因。

三條配套約束讓分層有效：畫面只引用語意層與元件層；原始值層是全專案唯一允許出現裸值的位置；每個語意名可回溯到原始值層的某個名字，映射逐條列在檔頭。

## 讓規則執行，而不是請求遵守

那份規格在同一張表裡寫了自我警告（角色欄是觀察不是定義、命名時須確認每個值實際承擔的語意），然後在那張表裡犯了它警告的錯。

### 執行者對照表

| 規則 | 載體 | 執行者 | 可否證 |
|------|------|--------|-------|
| 畫面不得引用原始值層 | 語言的私有修飾字 | 編譯器 | 是——違規編不過 |
| 裸值只准出現在原始值層 | 行內豁免標記 + 掃描器 | 工具 | 是——但覆蓋範圍須另查，見下 |
| 每個值要有自己的語意 | 逐一命名這個動作 | **無** | 否——查過與沒查過產物相同 |
| 角色欄要查證、不要推定 | 規格裡的一段話 | **無** | 否 |

第三列是本方法的核心機制，而**它原本沒有執行者**：把「逐一命名這個動作」寫成執行者，其真值由執行動作本身保證，結構與上文用來否定 `surface4` 的判詞完全相同。承認這一格為「無」，是本文對自己套用第二條件的結果。

**補上執行者的方式是產生痕跡**：操作程序的第 3 步要求每個名字旁記下來源座標，有座標可查即為已執行。執行者從「程序」變成「產物」，而產物可被否證。

行內豁免標記的做法是在唯一允許出現裸值的每一行標上一個固定字串，於是「其他位置出現裸值即違規」成為掃描器讀得懂的檢查。**例外能被機械辨識，禁令才有辦法自動執行**；例外只寫在文件裡的話，禁令也只能停在文件裡。

> **但「有掃描器」不等於「這條規則被保證了」。** 執行者掛在哪個事件上決定它覆蓋什麼——覆蓋寫入管道與覆蓋檔案是兩件事，而管道是開放集合。挑選執行點的完整判準見 `.claude/references/rule-enforcement-binding-points.md`。

## 邊界：可回溯不等於已驗證

三層結構提供一條從語意名回到原始值的路徑。**路徑存在不代表路徑的終點正確。**

同一批工作裡，字級檔的檔頭宣稱記錄了各階吸收哪些原始值。用容許小數的方式重新量測後發現：其中一個被記下的值**出現 0 次**（不存在，而規格與實作者都記了它），而出現次數最高的兩個值**兩邊都漏了**。根因是雙方都用只抓整數的字元類，小數被切成兩個整數，切出來的數字全部落在既有值域，所以輸出端毫無異狀。

階值本身沒錯，錯的是那張宣稱記錄來源的映射表。三個推論：

- **兩個獨立來源共享同一個抽取方法時，一致性不是證據。** 獨立性指方法的獨立，不指人的獨立。
- **儀器的錯誤若產出落在合法值域內的讀數，輸出端沒有訊號。** 這種錯誤靠換一把儀器重測才會現形，檢查輸出看不出來。
- **映射表本身是未經驗證的資料。** 它的外觀像稽核紀錄，於是沒有人稽核它。

核心主張在這裡也成立，而且是它自己失效的說明：那張來源表錯的時候跟對的時候外觀相同，所以沒有被檢查。命名把分類改寫成了錯會顯現的形式，卻沒有對來源表做同樣的事。

## 操作程序

每一步的執行者是**凍結這份分類的人**，第 4 步除外。每一步都要留下產物——沒有產物的步驟無法區分「跑過」與「跑順」。

1. **量測，並記下可重跑的指令原文與結果筆數**。方法名不是方法：「用 grep 掃過」不算，`grep -ohE '<pattern>' <files> | sort -n | uniq -c` 加上得到幾筆才算。下一步要挑戰它，指令沒留下就挑戰不了。

2. **換一把儀器重量一次**，並寫出兩者在哪一點不共用假設。「另一把儀器」的判斷標準是差集：列出第一種方法會漏掉或切開的形態、第二種方法會漏掉或切開的形態，**兩者的差集為空即不算另一把儀器**（同一個 regex 換寫法必然一致）。差集為空時要寫下「差集為空」而非跳過此步。兩次讀數不一致的位置就是要查的位置。

3. **把候選分類逐一展開成個別名字，每個名字旁記下來源座標**——那個值在來源裡的哪個位置承擔這個角色（檔名、元件名、畫面名、frame 名皆可）。**「查無」是合格的產物**，而且是第 5 步的輸入。沒有座標欄的名單視為此步未執行。

4. **由非命名者檢查每個名字能不能被成品否證**：為每個名字寫一句「若 X 不成立則此名為錯」，X 必須是成品上可指認的事實。**寫不出 X 即未通過。** 序號式名字必然寫不出 X，但寫得出 X 的名字也可能不通過——相鄰成員的 X 若互相涵蓋，或 X 與實際角色相反，同樣不通過。

5. **分不進任何序列的成員記為獨立角色**，並寫下它與最接近的序列成員在用途上差在哪。
   - **不可記為獨立的情形**：該成員與某序列成員的用途只差在程度（那是同一序列的另一階，不是獨立角色）
   - **獨立角色佔多數時回到第 3 步重切**——那表示原本的序列假設就不成立
   - **第三個出口**：一個名字同時承擔兩種用途時，拆成多個名字，而不是記為獨立

6. **把唯一允許的例外位置做成機器讀得到的標記，並記下執行者的註冊位置**（哪個 hook、哪個 CI 步驟、哪個 lint 規則）。**加標記而不接上執行者等於沒做。** 以一次故意違規實測確認它真的會擋。

7. **規格與來源不符時，先判斷哪一邊是約束方**：
   - 規格是**衍生物**（從設計檔、artboard、既有實作萃取而來）→ 以來源為準，回頭更新規格
   - 規格是**約束性契約**（DB schema、error code 契約、log level 契約、對外 API）→ **方向相反**，來源是它的產物，不符表示產物違約，改的是產物

   判別問一句：**這份規格是描述既有的東西，還是規定後來的東西？** 判錯的代價不對稱——把約束性契約當衍生物，會把既有的 bug 寫進規格合法化（實例：某欄位 99% 為 null 而據此把規格改成「多數為空」；某錯誤碼對到錯的 HTTP 狀態而據此把錯的對應寫進規格）。

   無論方向為何，**同時記錄不符的成因**。成因指向量測方法時回到第 2 步——那表示不符是量錯的，不是任一邊錯。

### 失敗態與終止條件

任一步無法產出該步的產物時**停止並記錄卡在哪一步**，不繼續往下走。這份分類此時的狀態是「未通過驗證」，不是「驗證中」。

全部走完且七項產物齊備時，這份分類的可信度是：**每個成員都有來源座標、都有一句可被成品否證的斷言、且兩次獨立量測一致**。這是它能提供的全部保證，不包含「分類切法最優」。

## 判讀徵兆

分類可能是假的，訊號有這幾種。**每條都附適用前提——前提不成立時判定「不適用」，而寫出前提為何不成立是必要的**，否則「不適用」與「查過沒命中」長得一模一樣。

| 徵兆 | 適用前提 |
|------|---------|
| 成員靠**值本身的相似**被歸在一起（顏色相近、數字接近、命名前綴相同），而不是靠用途 | 成員數 ≥ 3 |
| 集合標籤帶順序詞（層次、階、level、scale、tier），而相鄰兩階的差別代表什麼指不出來 | 該順序**不是功能性的**。若程式碼實際依賴該序數運作（如 log level 的 `>=` 過濾），順序詞為真，此徵兆不適用 |
| 規格裡有一欄放著角色或語意，而那一欄是看著值填的 | 存在這樣一份規格表 |
| 文件裡有一段話警告不要做某件事，而那件事沒有任何機制檢查 | 該文件有規範性段落 |
| 一份宣稱記錄來源的表，從來沒有被第二種方法重算過 | 存在來源映射表 |
| 一份宣稱有了第一個執行者之後，就沒有人再問還有沒有第二層 | 已查到至少一個執行者 |

## 懷疑之後做什麼：換一個查證管道

上一節給的是懷疑的時機，這一節給下一步。核心主張說「錯了要看得出來」，可執行的問題是：**要做什麼才看得出來。**

本文自身在成稿過程中被推翻多次，每一次都由一個具體動作觸發：

| 被推翻的宣稱 | 觸發它的動作 |
|------|------|
| 數字沿用敘述、未複驗 | 讀原始檔而非敘述 |
| 「這條規則已被機械保證」 | 查執行者的註冊設定 |
| 「經某條路徑寫入不觸發」 | 查有沒有第二層執行者 |
| 「落點是 commit 層」 | 實測多種路徑對各執行點的觸發 |
| 「非零離開碼會中止交易」 | 實測各狀態的離開碼是否被忽略 |

五者的共同點是**換一個查證管道去問同一件事**——讀另一份來源、查設定而非文件、實際執行而非推論。

**重讀不在這個集合裡**，因為重讀不會讓錯的地方長得不一樣。

### 一個不屬於上述集合的動作：讀到答案的下一句

本文另有一次修正來自純粹的往下讀：一段手冊寫了一句有歧義的話，緊接著就寫了消解歧義的方法。兩位撰寫者各自從前一句補出一個對稱，兩種讀法都太窄，而完整答案就在他們停手那個句號的後面。

**這個動作是重讀，不符合上一節集合的定義**，所以不編進去——依本文第 5 步，分不進序列的成員記為獨立角色。它與該集合成員的差別是：那五個是離開手上的文字去外部查證，這一個是不要提早離開文字。

兩者的共同上位是「不要在第一個看起來完整的答案處停手」，而那正是判讀徵兆最後一列的形態：句子提供了一個看似完備的答案，於是沒有人問它後面還有沒有。

## 適用範圍

**適用**：從既有 artifact 萃取分類——design token（來源是設計檔）、DB 欄位群（來源是既有資料與 schema）、目錄結構（來源是既有檔案分佈）、標籤體系（來源是既有標註）。共同點是**先有一批可重複量測的觀察值**，第 1-2 步才有對象。

**不適用**：分類是被設計出來的（新的 enum、新的 event 型別、新的 error code 集合）。這類工作沒有可量測的來源，第 1-2 步無對應物，且直接命中下方失效條件的第三項。本文的第 3-5 步仍可借用，但那時它是設計檢查而非驗證程序。

### 失效條件
