# 決策者快速參考清單（PM Checklist）

WRAP 決策框架的每階段自問清單。在決策時快速掃描使用。清單項目對齊 SKILL.md 各階段的「前置強制」與「必檢」，SKILL.md 改了階段內容時這一份要跟著改。

---

## 快速模式（5 分鐘）

適用：連續失敗、被困住、宣稱「做不到」

```text
[錨點] 誰是客戶？當前版本核心目標？
   → 這個問題影響核心目標嗎？否 → 建任務延後
   → 評的是單一實例還是跨集合的模式？模式 → 先量普及度再給嚴重性

[Step 0] 我手上的資訊夠做這個決策嗎？還是正在用假設替代資料？
   → 使用者說「我是 X」「推薦給我」「我該買哪個」→ 決策諮詢，必須基於當事人條件
   → 選項描述含「通常」「一般來說」→ 正在用平均值替代個人資料，先問 2-3 個關鍵變數

[W] 我有幾個選項？
   → 只有 1 個？→ 強制再找 2 個
   → 搜尋社群了嗎？→ 沒有 → 先搜尋再決定
   → 選項有實質差異嗎？→ 沒有 → 假選項，重新擴增
   → 全屬「新增工具」？→ 工具化偏誤，強制補「改造既有」與「零工具」

[R 核心] 這類問題的常見解法和成功率？（基本率 > 預測）
   → 問過去，不問未來
   → 搜尋的是問題本身的基本率，還是我預設解法的基本率？

[A 前置] 框架概括測試：能否用一句話概括所有方案？
   → 能 → 回 W 擴增多元選項
   → 否 → 進 A 核心

[A 核心] 投入這個問題的時間，會擠壓哪個更重要的目標？（機會成本）
   → 列出放棄什麼

[決定] 選項消失測試：以上選項全部被移除，還能怎麼做？
```

## 完整模式（15-30 分鐘）

適用：偏離核心、重大決策、個人化建議（Step 0 強制）

### 0. 錨點確認

- [ ] 誰是我們的客戶？
- [ ] 當前版本的核心目標是什麼？
- [ ] 這個問題影響核心客戶/核心目標嗎？
- [ ] 如果不影響：建提案/任務延後，回到核心任務
- [ ] 這次評估的對象是單一實例，還是跨集合的模式？模式 → 先量普及度（可 grep 的算命中數、不可的抽樣）再給嚴重性；兩個評估者分歧時先問評的是不是同一個對象

### Step 0. 資料充足度閘門

先分模式：問客觀知識（「X 和 Y 差別」）是資訊查詢，公開資料即可；問「我該怎麼選/做/買」是決策諮詢，**必須基於當事人條件**。決策諮詢跑六項：

- [ ] 我知道當事人是誰嗎？（年齡/身體/財務條件）
- [ ] 我知道當事人的目標嗎？
- [ ] 我知道當事人的限制嗎？（預算/時間/禁忌）
- [ ] 我知道當事人的環境嗎？（地區/可用資源）
- [ ] 我在用「平均值假設」替代「個人資料」嗎？
- [ ] 如果假設錯誤，後果會嚴重嗎？

判定：充足 → 進 W；不足 + 低風險 → 進 W 但標記假設；不足 + 中風險 → 暫停，漸進式問 2-3 個關鍵變數；不足 + 高風險 → 強制完整問卷 + 建議諮詢專業人士。跳過這一道的常見原因是反問打斷流暢度——流暢度與準確度的取捨交由當事人決定。

### W — 擴增選項

- [ ] 列方案前先寫下「我假設問題是 X 造成的」，再質疑 X 是不是真根因（假設層級多元，不只實作手段多元）
- [ ] 我有幾個選項？（至少 3 個有實質差異的）
- [ ] 當前專案有沒有類似解法？（grep / LSP）
- [ ] 社群有沒有人解決過？（GitHub Issues / 文件）
- [ ] 其他領域有沒有類比方案？（AI 知識 / 網路搜尋）
- [ ] 選項消失測試：以上選項全部被移除，還能怎麼做？
- [ ] 假選項偵測：選項之間是不同途徑，還是同一途徑的參數微調？
- [ ] 方案性質三類涵蓋：候選涵蓋「新增工具 / 改造既有 / 零工具或純文件」嗎？全屬新增工具 → 工具化偏誤，強制補另兩類
- [ ] 方案關聯性檢查：任兩方案可退化為同一方案或既有機制嗎？可退化 → 實質選項數重算
- [ ] 反向思考：若我相信的正好相反會怎樣？能提出有力相反論述 → 重新定義問題後從 W 重跑

### R — 現實檢驗

- [ ] 這類問題的常見解法有哪些？成功率？（基本率）
- [ ] 搜尋前問：我搜尋的是**問題本身**的基本率，還是**我預設解法**的基本率？（後者狹窄）
- [ ] 需要什麼事證才能證明這個方法可行？（事證問題）
- [ ] 有沒有辦法用最小成本驗證假設？5 分鐘內能得到答案嗎？（試水溫）
- [ ] 搜尋了具體案例嗎？讀了內文不只標題？（近距離檢視）
- [ ] 答案是清單類嗎？→ 逐項對 source 核對，找不到的標記候選幻覺，禁止整批信任
- [ ] 結論裡有「已強制 / 已實作 / 已涵蓋」這類事實宣稱嗎？→ 用 grep / ls / 讀程式碼驗過才當前提；動作不可逆或含 dissenting view 時必做
- [ ] 最強版本論證（Steelman）：能闡明被放棄選項的優點嗎？能列出選定方案的 3 個缺點嗎？
- [ ] 深度議題：對結論做了反向搜尋嗎？（學術批評 / 反方論點 / 失效情境 / 統計限制，至少 4 種方向）

### A — 拉開距離

**前置強制檢查**（任一觸發即回 W）：

- [ ] 框架概括測試：能否用一句話概括所有候選方案？「能」→ 選項多元性不足，回 W
- [ ] 反面框架識別：問題的反面框架是什麼？（未列出即強制停下列出）
- [ ] 相反論述檢視：若我相信的正好相反會怎樣？能提出有力相反論述 → 重新定義問題後從 W 重跑
- [ ] 工具選擇檢查（觸發：選工具前 + 預估步驟數 > 2 + 涉及 Write/Bash 組合）：
  - 物化：我是在解決「問題」（把文字寫進紀錄）還是物化成「工具」（用 Write 建檔）？
  - 步驟數：實際幾步？有沒有 1 步路徑被忽略？
  - 目的地：產出去 CLI 還是檔案系統？匹配需求嗎？
  - 白名單：偏好 heredoc Bash / Edit 直接編輯，次選 Write 類

**正式 A 階段**：

- [ ] 每個選項旁列出機會成本了嗎？（做法 / 機會成本 / 風險 / 不選其他的代價）
- [ ] 10/10/10：這個決定 10 分鐘後的感受？10 個月後對使用者/專案的影響？10 年後對生態/信任度的影響？
- [ ] 這個決策服務於哪個優先事項？優先事項衝突時哪個第一？
- [ ] 投入這個問題的時間，會擠壓哪個更重要的目標？
- [ ] 不值得投入的項目，是否已記錄到提案系統或任務延後？

**設計規則 / Skill / Hook 時另跑悖論識別**：

- [ ] 此規則是否本身違反它要保護的價值？
- [ ] 是否通過善意家長主義 4 條件？（實質傷害 / 介入有效 / 利益大於風險 / 最小限制）
- [ ] 「正確示範」是否本身違反它要禁止的模式？
- [ ] 設計者立場是否透明化？
- [ ] 是否預留「用戶可覆蓋」機制？

### P — 準備好犯錯

- [ ] 行前預想：假設 12 小時後失敗了，列出 3 個最可能原因（任一 > 50% → 重新評估）
- [ ] 每個原因配 1-2 個**可觀測的早期警訊**（「flaky 率 > 5%」，不是「感覺會出問題」）；跨 session 監測要包成監測 ticket 綁 trigger，不可無 trigger 延後
- [ ] 未來區間：最好結果？最壞結果？兩端都能接受？
- [ ] 安全係數：預估時間 x 1.3-1.5
- [ ] 回退計畫：失敗怎麼回退？回退成本是多少？回退成本 > 收益 → 重新評估
- [ ] 高成本決策（版本規劃 / 提案評估 / 發版前）→ 改用完整 premortem，原因不設上限、逐個深挖（見 `premortem-workflow.md`）

**提供建議時另跑自我暴露**：

- [ ] 暴露偏好：「我傾向 X，理由 Y」，不假裝中立提問
- [ ] 暴露推理鏈：列出步驟讓對方可追溯，不只給結論
- [ ] 暴露盲點：「我可能漏掉的角度有 Z」
- [ ] 不標「推薦（Recommended）」，改「我目前的猜測」或不標

### 5. 絆腳索設定

- [ ] 設定期限：非核心問題最多花多少分鐘？
- [ ] 設定失敗門檻：幾次失敗後切換方向？
- [ ] 設定偏離警報：什麼信號代表已偏離核心目標？

## 決策品質自測

完成 WRAP 後，用以下問題自測：

| 問題                                                   | 通過標準                  |
| ------------------------------------------------------ | ------------------------- |
| 決策諮詢時，當事人的條件確認過了嗎？                   | 是，或已標記假設          |
| 我考慮了幾個有實質差異的選項？                         | >= 3 個                   |
| 候選涵蓋新增工具 / 改造既有 / 零工具三類嗎？           | 是                        |
| 我搜尋了社群/文件嗎？                                  | 是                        |
| 我能闡明反對意見嗎？                                   | 是                        |
| 我列出了機會成本嗎？                                   | 是                        |
| 我做了行前預想嗎？                                     | 是                        |
| 每個預想的失敗原因有可觀測的警訊嗎？                   | 是                        |
| 我有回退計畫嗎？                                       | 是                        |
| 提供建議時，偏好、推理鏈、盲點都暴露了嗎？             | 是，或本次不是提供建議    |

7/10 以上通過 → 決策品質足夠。
6/10 以下 → 回到對應階段補充。
