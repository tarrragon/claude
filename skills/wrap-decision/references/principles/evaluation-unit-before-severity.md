# 嚴重性評估先固定評估單位，單一實例與跨集合的模式是兩個對象

一個發現被評成「輕微」還是「嚴重」，先取決於評的是什麼對象。同一句「遠端一個字都沒有執行」，當成一個句子評是一處校對問題，改一句就好；當成一種寫法評，全站 grep 出 33 篇，是規範問題。兩個評級都對，對的是不同的對象——而評估雙方沒有先說定對象是什麼，就會把對象的差異讀成判斷的差異。

## 為什麼審查流程看不見模式

逐篇審查的單位是一篇。每篇各自找到「一處、輕微」，回報各自結案，模式從來沒有被組裝起來——流程裡沒有那一步。看得到模式的人是讀過整個集合的人，而審查者每次只拿到一篇。所以模式層的嚴重性對逐篇審查是結構上不可見的，與審查者的能力無關。

嚴重性因此不能從單一實例直接給。實例層能給的是「這裡有一個候選」；嚴重性在兩件事之後才給：評估單位固定了（實例還是模式），而且普及度量過了——能 grep 的算命中數，不能 grep 的抽樣冷讀。沒有普及度數字之前，一個發現只能標「候選」。

## 反模式

- 從單一實例的修復成本推嚴重性：改一句話成本趨近零，所以「不嚴重」——量的是作者側，讀者側是每篇乘每處乘每個讀者
- 新發現直接歸進最接近的既有類別，嚴重性繼承那個類別：歸類的速度本身是訊號，量測需要時間、借用不需要
- 評估者用自己的閱讀自動補完，回報「讀得懂」：讀得懂與讀者要多做一步還原是兩件事，而審查者做的正是讀者做的事，盲區重合

## 修法

1. 給嚴重性之前寫下評估單位：這次評的是一個實例，還是一種形態
2. 形態層先量普及度再評級——可 grep 的跑全站計數，不可的抽三到五篇冷讀
3. 逐篇審查的產出對可能是模式的發現只標候選，嚴重性由另一個聚合步驟給；那一步在現有多輪審查流程裡要另外加，它不會從逐篇結案裡自己長出來
4. 兩個評估者分歧時，先問兩邊評的是不是同一個對象，再問誰對

## 跟其他抽象層原則的關係

[教學定位被讀成教室講課](teaching-is-not-lecturing.md)（#355）與[指令片段當主詞](command-fragment-as-subject-hides-the-actor.md)（#358）、[口語強調](spoken-emphasis-is-silent-in-text.md)（#357）是這張卡的 case 來源：三張都先被評成既有類別的輕微變體，拉出來量普及度之後各是二十到三十篇的模式。本卡管的是為什麼會低估——不是那三類寫法本身。

WRAP 決策框架的錨點確認原本問「誰是客戶、核心目標是什麼」，這張卡替它補第三個錨點：評估單位是什麼。那個問題在 Step 0 之前，因為選項的意義取決於對象是實例還是模式，對象沒定就擴增選項，擴的是錯的問題。

## 判讀徵兆

- 兩個人對同一個發現的嚴重性差一個量級以上
- 逐篇審查的 finding 清單裡同一種形態反覆以「一處」出現在不同篇
- 嚴重性判定的理由是修復成本（「改一句就好」）
- 新發現被歸進既有類別的速度快於量它普及度的速度
