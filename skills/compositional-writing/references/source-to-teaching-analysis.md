# Source to Teaching Analysis

本 reference 為「把外部分析文章或高密度研究材料，轉成教學型分析文章」情境。適用於分析師文章、投資人備忘錄、產業評論、研究摘要、AI 轉寫稿，也適用於從業者經驗談（訪談、社群貼文、口述整理）。目標是把 source 轉成讀者可重用的判讀框架，不是只做摘要、翻譯或語氣改寫。本檔另收一節任何體裁的文章都適用的〈引用評價時留意它評的時間點〉。

> **自包含聲明**：本文件不依賴其他 reference。讀完本文件即可獨立執行外部分析材料到教學文章的轉換。

---

## 何時參閱本文件

| 觸發情境                                            | 動作                                        |
| --------------------------------------------------- | ------------------------------------------- |
| 要把外部分析師文章改寫成自己的教學文章              | 跑完整 source-to-teaching pass              |
| 來源是從業者經驗談 / 訪談 / 口述整理 / 社群實戰貼文 | 先跑 source type gate、走機制重建 pass      |
| 改寫稿結論都在、但斷言靠口吻與權威支撐              | 跑機制重建 pass                             |
| 來源含從外部引用或轉述的說法（論壇說法、問答、AI 回答；範圍見 `keyword-bank.md`〈素材的說法當討論對象〉） | 走機制重建 pass，說法不當正文的討論對象（例外見同一條 bank 的合規清單） |
| AI 改寫稿讀起來流暢、但像原文摘要                   | 跑 deliverable pass                         |
| 文章術語密度像寫給同業、目標讀者跟不上              | 跑 reader-level pass                        |
| 來源文章的觀點與本文結論混在一起                    | 跑 source layering pass                     |
| 文章已套決策框架、但正文像分析過程記錄              | 跑 title promise 與 teaching narrative pass |
| 文章引用樂評、評測、使用心得、量測、考證或鑑定的結論、排名這類相對比較，或引用同時帶著評語的來源（不論引用的目的是佐證現況、佐證紀錄還是滿足收錄條件） | 讀〈引用評價時留意它評的時間點〉（任何體裁的文章都適用，不限外部分析改寫） |

不適用：純翻譯逐句校稿、學術論文正式摘要、內部 analyst-to-analyst 報告。這些產物可以保留原文的 reader contract 或 process metadata。

## 為什麼外部分析改寫需要獨立指引

外部分析文章同時帶有三種東西：事實材料、原作者 frame、原作者 reader contract。AI 或人類若只做風格轉換，會把三者一起搬進新文章。結果是文字符合目標風格，但結論仍沿用原作者視角，讀者仍需要原領域背景，文章也缺少可遷移的教學框架。

教學型分析文章要做的是「source transformation」：保留可驗證事實，辨識原作者判讀，重建適合目標讀者的推導，最後交付可重用的判斷問題與預警訊號。

---

## Source Type Gate：分析文還是經驗談

轉換流程的第一步是判別 source 自帶什麼。兩類 source 的轉換工作本質不同，混用流程會產出錯的知識類型。

| Source 類型                                  | 自帶的層                        | 轉換的核心工作                                     |
| -------------------------------------------- | ------------------------------- | -------------------------------------------------- |
| 分析文（分析師文章、備忘錄、產業評論）       | 事實 + 原作者判讀 + 分析層      | **拆層**：分開三層、防止原作者 frame 被當成事實    |
| 經驗談（訪談、社群貼文、口述整理、實戰分享，以及沒附可回溯資料的論壇說法、問答、AI 回答） | 事實 + 未附可驗證推導的判讀（從業者、論壇或 AI）、**無分析層** | **重建**：補建機制，把判讀從結論升級成可推導的判斷標準 |

判別訊號：source 的斷言靠什麼支撐。分析文的斷言後面有資料、機制、市場結構；經驗談的斷言後面是經驗本身（「做這行都知道」「資深的人都這樣做」）。經驗談的斷言是從業者走完推導後輸出的最後一步——推導路徑留在從業者腦中，素材裡只有結論。論壇說法與 AI 回答沒有附可回溯的資料或量測時也歸這一類，即使附了理由（「便宜唱臂撐不起好唱頭」本身就像一句機制）：那個理由判別時跟口吻同級，所以當成待重建的判讀；附了論文或量測的，仍歸經驗談，那份資料直接當推導前提引用，其餘照機制重建，不走分析文的 Pass 1（Pass 1 會把原作者判讀標明出處後留在文中，正好是〈重建之後說法放在哪裡〉要避開的形態）。

分析文走下方五個 Pass。經驗談先走機制重建 pass，再接 Pass 2（reader level）與 Pass 5（deliverable）。

---

## 經驗談 Source：機制重建 Pass

**經驗談轉教學的核心工作是重建分析層：作者對每個承擔判斷標準的斷言，都要能回答「為什麼成立、在什麼條件下不成立」。** 這兩個問句是作者拆素材時的工具，答案以機制與機制成立的條件寫進正文；斷言本身不進正文當被判決的對象（〈重建之後說法放在哪裡〉）。只做系統化整理——分主題、換書面語、加表格、補術語卡——會產出「披著教學結構的經驗談」：結構合規、結論都在、支撐全缺，讀者拿到的是要相信的規則，不是能自己推的判斷。

三層分工：

| source 內容層                          | 處理方式                                    |
| -------------------------------------- | ------------------------------------------- |
| 事實（規則條款、流程、事件）           | 保留，構成教材的 fact 層                    |
| 從業者判讀（閾值、口訣、「該這樣做」） | 當 hypothesis，重建支撐機制後才升為教材判斷標準 |
| 分析層（機制、量化、結構解釋）         | source 沒有自帶，由作者從領域通用知識補建   |

機制重建的操作，對每個承擔判斷標準的斷言問四個問題：

1. **這個斷言背後的成本結構是什麼？** 例：「絕不允許 X 發生」通常意味著 X 的代價跟預防成本嚴重不對稱——把兩側成本各自展開成可估算的組成，不對稱從口號變成估算框架。
2. **這個閾值是什麼的反推值？** 例：「不超過七成」「至少養兩家」這類 magic number 是某個約束條件的反推——找出約束（替補產能上限、驗證週期），數字降級為機制的例示，讀者換情境能重算。
3. **這個規則的設計者圖什麼？** 例：某個交易規則存在，是誰設的、保護誰的什麼利益——補上設計者的誘因分析，規則從「要背的條文」變成「可預測的行為」。
4. **這個操作對應什麼既有分析語言？** 例：「可無條件取消就先下單卡位」是免費選擇權、「規則不同下單膽量不同」是風險敞口管理——套上領域通用的分析語言後，多個操作能從同一機制推導出來。

重建的知識來源有兩條：領域通用理論（經濟學、賽局、選擇權思維、通路結構），或回頭追問原始從業者「為什麼是這個數」。素材與作者理論掌握度決定走哪條；兩條都走不通的斷言，標明「從業者經驗值、機制待補」，別偽裝成已推導；標明的方式是寫成知識狀態的陳述（「這一項目前只有經驗值，沒有找到量測或機制」），不引用原話再判決它（〈重建之後說法放在哪裡〉）。

**重建有停止線**：只有承擔判斷標準的斷言需要機制。氛圍性敘述刪除或降為 hook；心態與職場修為內容是合法的經驗分享，但知識類型是 career essay——分開成篇並標明定位，別混在分析教學裡稀釋兩邊。

反例（只換口吻）：

```markdown
量產初期放量時，不會讓單一家就超過七成，先分散再看各家表現逐步調整。
```

問題：七成是從業者的壓縮結論，教材原樣轉述，讀者換情境無法重算。

正例（重建機制）：

```markdown
量產初期的放量上限，由「單一家爬坡失敗時、其餘供應商短期能吸收的產能」反推。
替補家能在一個交期內補上三成，主力家的上限就是七成——比例跟著替補產能彈性變動，
替補弱就要壓低主力佔比、多養一家。
```

### 重建之後說法放在哪裡

素材裡的斷言（從業者的口訣、論壇的說法、問答或 AI 回答裡的結論）是拆出機制的材料。說法是主題還是素材、哪些文體與寫法不在此列，判斷問句與合規清單在 `keyword-bank.md`〈素材的說法當討論對象〉；這一節是說法判成素材之後的寫法。正文寫機制與機制成立的條件，不引用那句說法再判斷它在哪些條件下成立：「這句話在剛性與軸承上成立」要讀者同時拿著原說法、作者的判決與底下的機制三樣內容，讀者要的只有機制。作者的推論（沒有量過）是：機制寫完整時，讀者讀到那句說法，判斷得出它哪裡對、哪裡不對。寫法分四步：

1. **擬大綱時**，節依讀者讀完要做的決定與要理解的機制排列。素材裡的每一句說法只拿來檢查清單有沒有漏（它壓縮的機制要落在某一節），不當成一節的題目；素材有幾句說法就長出幾節，是大綱照素材排的訊號。
2. **初稿寫完與每次改寫一節之後**，跑 bank〈素材的說法當討論對象〉的 grep 找位置。命中處先回到大綱問兩件事：這一節為了讀者的哪個決定或哪個機制而存在；機制是否寫到讀者不靠那句說法也判斷得出自己的情形。這一節的題目來自那句說法時，重排大綱；機制不完整時，補機制。
3. **處理命中句本身**（大綱兩問都通過之後仍要做）：刪掉引用與判決；原說法說對的部分以機制的形式留下（「唱臂影響唱頭表現的地方有三項：……」）。
4. **說法錯得會讓讀者做錯事時**（照做會造成人身或設備的安全風險、會讓人買錯設備），在機制旁寫成機制之間的對照（「匹配用公式算；剛性與軸承取決於做工」）。同樣這幾種風險、而讀者會在賣場或論壇原句遇到那句說法時，機制寫完之後可以加一行「反例：」寫出原句與它對應的機制，不寫判決段（這一行列在 bank 的合規清單裡）。素材的斷言重建不出機制時，寫成知識狀態的陳述（「這一項目前只有經驗值，沒有找到量測或機制」），不引原話。

審查 finding 指出某段「轉述不忠實」「條件沒寫出」時，照 finding 補完轉述會把判決修得更完整，原說法、判決與機制一樣都沒少；先照 bank〈素材的說法當討論對象〉判（先查適用的文章，再用判斷問句判說法是主題還是素材）。推導、實例與這條規則的證據範圍（一個批次，沒有量過讀者的理解）見 [rewritten-claim-kept-as-the-subject](principles/rewritten-claim-kept-as-the-subject.md)。

## 五個 Pass

### Pass 1：Source Layering

Source layering 是把材料拆成事實、原作者判讀、本文推導。每句材料進正文前先問：

| 問題                                 | 層級       |
| ------------------------------------ | ---------- |
| 這件事有公開來源可驗證嗎？           | 事實       |
| 這是不是原作者或市場敘事的解釋？     | 原作者判讀 |
| 這是不是本文從多個材料合成出的框架？ | 本文推導   |

寫法規則：

- 事實放在背景或事件段。
- 原作者判讀只當 hypothesis prior，不直接當本文結論。
- 本文推導要明確標成本文整理出的框架或判斷問題。

反例：

```markdown
這代表基礎設施廠商正在垂直整合 data pipeline。
```

問題：若「垂直整合」是本文推導，這句把推導寫成事實。

正例：

```markdown
本文把這個收購視為「基礎設施廠商往 data pipeline 延伸」的訊號。這是本文判讀，不是事件本身。
```

本 Pass 的判斷標準卡：[external-analysis-source-layering](principles/external-analysis-source-layering.md)——那裡給「事實 / 原作者判讀 / 本文推導」三層的分層方式與混層的判讀徵兆。

### Pass 2：Reader Level

Reader-level pass 是把原文 reader contract 改成目標讀者 contract。先辨識原文寫給誰，再決定是否降一級。

| 原文類型     | 常見 reader contract   | 轉換策略                 |
| ------------ | ---------------------- | ------------------------ |
| 大眾新聞     | 只需要知道事件         | 補機制與可遷移框架       |
| 投資人備忘錄 | 預設懂市場 shorthand   | 降術語密度、補因果鏈     |
| 產業內部文   | 預設懂供應鏈與競爭格局 | 補背景角色與資料形狀     |
| 教材型文章   | 已經有教學推導         | 檢查是否符合本站段落責任 |

檢查法：

- 三句內連續三個以上跨領域術語，拆段或補卡。
- 一句話跨三個以上因果步，拆成多段。
- 讀者能背結論但說不出推導，補機制、公式、數字或例子。

本 Pass 的判斷標準卡：[cross-domain-reader-level-alignment](principles/cross-domain-reader-level-alignment.md)——那裡給讀者層級的定位順序，以及層級定了之後術語密度怎麼跟著決定。

### Pass 3：Internal Analysis

Internal analysis 是作者背後的 hypothesis 探索，不等於文章章節。可以用 WRAP 或其他決策框架做內部檢查：

- 要回答什麼問題？
- 手上 evidence 夠不夠？
- 有哪些本質不同的合理解釋？
- 每個解釋的 evidence weight 是什麼？
- 哪些觀察會推翻本文判讀？

這些問題要做完，但不直接當正文標題。正文標題描述讀者會學到什麼，不描述作者正在執行哪個分析步驟。

### Pass 4：Title Promise

Title promise 是標題對讀者做的合約。跑完內部分析後，列出文章每段是否服務標題承諾。

| 檢查項                                 | 行動                           |
| -------------------------------------- | ------------------------------ |
| 某段超過 20% 篇幅但不在標題承諾內      | 壓縮成背景句、移到別篇、或刪除 |
| 來源 prior 比正文機制更長              | 縮減 prior，讓主體回到本文承諾 |
| 標題承諾的是框架、正文卻在解釋作者動機 | 改寫主體或重命名標題           |

Title promise pass 保護讀者不被作者的分析過程帶離主題。

### Pass 5：Deliverable

Deliverable pass 確認文章交付的是可遷移框架，而不是原文摘要。結尾至少回答：

- 下次遇到同類事件要看哪些訊號？
- 哪些機制若成立，本文判讀才成立？
- 哪些觀察會削弱或推翻本文判讀？
- 讀者下一步該看哪個概念、卡片或案例？

常見責任順序：

```text
事件本身 → 結構性機制 → 長期影響 → 預警訊號 → 可遷移框架
```

這是一份責任清單，不是固定模板。不同文章可以調整順序，但不能缺少可遷移框架與失效條件。

## 引用評價時留意它評的時間點

**寫文章的人引用一份評價（樂評、產品評測、使用心得、效能量測、考證或鑑定的結論；逐字引用、轉述，或把評語寫成自己的敘述都算）時，留意這份評價評的時間點，以及評語依據的事物（被評的對象，比較的對象、範圍與標準，考證時拿得到的證據；定義見下文）從那時到讀者要判斷的時間點改變了多少。** 不論引用的目的是說明對象現在的樣子、佐證一項紀錄，還是滿足收錄條件，都從下面依序問的第 1 問開始；第 1 問的答案決定後面的問句要不要問。這一節是留意項，不是檢查條件。留意項的意思是：寫文章的人每一次引用評價都做這項判斷，而判斷的答案靠他對那個領域的了解，沒有年數門檻這類可以機械比對的條件。一份評價有效多久，隨對象與對象所處的階段而不同，沒有通用的年數；所以不訂「超過幾年就不用」的門檻，也不要求每一份舊評價都拿掉。判斷之後，寫文章的人把結果寫在引用的位置：照用的寫出評的時間點（論斷的對象是評價本身時連評價者一起寫），只取紀錄的寫明只取紀錄；整份來源都沒有引用時，不必交代：評語判成變化大而拿掉的這一種不要求留痕跡，因為被考慮過而沒有引用的來源數量多，逐份記錄的成本高於它防的錯。代價是一律拿掉從稿件看不出來，所以寫文章的人不因為嫌判斷麻煩就把舊來源整份丟掉。這一節適用於任何體裁的文章，不限外部分析改寫。沒有交稿紀錄的發布流程（直接發布、沒有提交訊息也沒有審查者）裡，下文規定寫進交稿紀錄的項目不寫：變化不大的依據改寫在引用的位置，論斷的位置與查證經過不寫，查證經過照樣不寫進正文。

舊評價失效，原因可能是被評的對象在這段時間裡變了，也可能是評語依據的其他事物變了，即使被評的那一個沒有變：評語是相對比較（「最快」、排名、「A 比 B 快」）時，比較的對象與標準變了，評語跟著失效；評語是依證據下的判斷（一句話出自誰、一件文物的年代、一份錄音的演奏者是誰這類考證與鑑定）時，之後出現的文獻、檢驗結果改變了證據，評語跟著失效。這兩種一樣照下面的問句與處置表判斷，判斷的對象照下一段「評語依據的事物」的定義擴大。另外，評價可以重做（量測可以重跑、找得到評的時間點較近的另一份評價）時，先重做或換成較近的那一份，做不到才照下面的問句判斷；重跑得到的是一份新的評價，評的時間點是重跑的日期與設定。

下文的「評價」指評價者針對對象在某一刻的表現所做的判斷或量到的結果；量測的數值是評價，量測用的設定是紀錄；依證據下的判斷（考證、鑑定的結論）也算評價。「評的時間點」指評價所評的那一刻：一場演出的日期、一個產品的版本、一次量測的日期與設定，評一張錄音時是那張錄音的版本（原始發行或某一次重製）。版本取到會影響評語談的那一項的粒度，韌體與小版本也算；來源沒有寫版本時，取評測或量測實際進行的日期，並寫出查不到版本；只查得到刊登日期時寫出刊登日期，並寫明它是刊登日期。評的是一段期間（年度回顧、用了三年的心得）時，取期間的終點並寫出期間。考證與鑑定取下判斷的日期（考證或鑑定完成的日期；只查得到發表日期時，照「只查得到刊登日期」的寫法標明），不取被考證的對象的日期，因為會改變的是之後才出現的證據。「評價所評的面向」指評語談的那一項屬性：評測談的還原速度、樂評談的音準；同一個對象在這一項上變化大，在另一項上可能沒有變。「評語依據的事物」指評語成立所依賴的事物：一律包括被評的對象；評語是相對比較時，另外包括比較的對象（被評的那一個以外、被拿來比的每一個）、比較的範圍（有哪些成員，以及範圍的界線，例如價位）與比較的標準；評語是依證據下的判斷時，另外包括下判斷時拿得到的證據。「論斷的對象」指引用的評價在稿件裡支撐的那一句論斷寫的是什麼，看讀者拿那一句做什麼來判，不看句子的主詞：讀者拿它了解評價本身的歷史（這位評價者當年的立場、一部作品當年被怎麼接受、一篇評論怎麼寫、那一次考證怎麼做）時，論斷的對象是評價本身；讀者拿它判斷被評的對象（選場次、選購、選型，或了解對象的演奏、功能、效能、一件事實現在成不成立）時，論斷的對象是被評的對象，即使句子的主詞是評價者或評論（一篇教讀者挑場次的文章逐場列出樂評寫了什麼；一篇選場次的文章寫「這一場有樂評」，讀者拿「有樂評」決定要不要去，也是這一種）。同一處引用讀者兩種用途都會拿時（交代當年的接受，又拿來推出對象現在如何），照被評的對象判。為了滿足收錄條件而找的評價一樣照讀者的用途判。「紀錄」指同一份來源裡不帶判斷的事實：那一場演了哪幾首、那一版有哪些功能、量測用的設定。

判斷時依序問：

1. **論斷的對象是評價本身，還是被評的對象。** 判法照上一段「論斷的對象」的定義。評價本身時，評價就是那一刻的事實：引用並寫出評價者與評的時間點（取法照第 2 問；論斷寫的是一部作品當年被怎麼接受時，另寫刊登日期），交稿時附的紀錄寫出那一句論斷的位置，不必問第 3、4 問。這一種跳過了變化的判斷，所以留下論斷的位置，讓審查者拿那一句核對讀者的用途。被評的對象時，接著問後面的問句。
2. **這份評價評的時間點是什麼。** 取評的時間點，不取刊登日期（一篇隔年才刊出的樂評，評的是前一年的演出）；考證與鑑定的取法見上面「評價」的定義。
3. **讀者拿這份評價要判斷的時間點是什麼。** 第 1 問判成被評的對象之後才問這一問。評語是依證據下的判斷時，讀者要判斷的是那件事實現在還成不成立，填現在，不論文章是不是回顧歷史。其餘的評價：教讀者做當下決定的文章（選購、選型、選場次），讀者要判斷的是現在；回顧歷史的文章，讀者要判斷的是當年，當年的評價正好是他要的（每一筆的「當年」是那一處所回顧的年份，例如那一款推出、那一場演出的年份，不是評價的年份；一份多年後才做的重評，評的時間點與當年不同）；其餘說明對象是什麼樣子的文章（概念說明、人物介紹），讀者要判斷的是現在。評的時間點與讀者要判斷的時間點相同時，不必問第 4 問，引用並寫出評的時間點。同一篇文章裡兩種引用都有時（選購指南裡有一段產品線的回顧），每一處引用各問一次。
4. **從評的時間點到讀者要判斷的時間點，評語依據的事物改變了多少。** 評的時間點晚於讀者要判斷的時間點時（多年後才做的重評），看的是同一段期間，只是方向相反：重評時的對象跟當年的對象差了多少；這時處置表的「現況」換成讀者要判斷的那一年，缺的資訊寫成要有那一年（或那一版）的評價才判斷得出。 被評的對象與每一個比較的對象看評價所評的面向，比較的範圍看有沒有加入新成員或改了界線，比較的標準看有沒有換，證據看之後有沒有新的文獻或檢驗結果。「沒有改變」要用正面的事實證明（之後的研究、目錄或版本仍然採用這個結論；範圍裡其他成員的評價查得到而沒有推翻結論）；查過而沒有找到新的文獻或評價，是查證的經過，照處置表歸判斷不出來。變化的速度看對象的種類與它所處的階段：一位演奏者早年成長的幅度大，幾年前的評價就可能不符合現況；生涯晚期變化的幅度與方向跟早年不同，成長放慢，技術這類面向也可能退步，所以看的是評語談的那一項。哪個年齡算早年、哪個算晚期，這一節不訂界線，由寫文章的人依那一位演奏者的情形判斷。產品換了主要版本、機器換了硬體之後，寫文章的人查評語談的那一項在新版本、新硬體上是否不同：換了版本不等於每一個面向都變了。已經發行的錄音、已經凍結的版本本身不再改變，只描述錄音或版本本身的評語（音色、功能）多年後仍然適用；凍結只說明被評的對象沒有變，評語依據的其他事物要另外判斷：拿它跟別的對象比較的評語（「同類裡最快」）要看比較的對象與標準，考證或鑑定這類依證據下的判斷（「這張錄音的演奏者是某某」）要看之後有沒有新的文獻或檢驗結果。同一個型號還在生產、韌體還在更新或零件會更換時，版本沒有固定，不算凍結；實體會老化的對象（耳機、喇叭、樂器）被評的那一件本身會變，停產也不算凍結。評價比較的是幾個對象時，每一個比較的對象各判斷一次；比較的範圍加入新成員、改了界線或標準換了（同類出了新的一代是範圍加入新成員，降價之後落進另一個價位帶是範圍的界線改了，評測改了量測的方法是標準換了）也算評語依據的事物變了。相對比較判的是比較的結論還成不成立：被評的對象、比較的對象、範圍與標準任何一項的變化推翻了結論（新機的對焦比原本「最快」的那一台快）時算變化大；這幾項都變了也沒有推翻結論時算變化不大；查不到新範圍裡被評的那一個以外的成員在那一項上的評價、判斷不出會不會推翻時，算判斷不出來。這段期間有寫文章的人已知或查得到的變動事件（改版、換硬體、換人、整修）時，先查那個事件有沒有動到評語談的那一項。這一問靠寫文章的人對那個領域的了解，沒有可以機械比對的答案；查過仍然答不出來時，照處置表的「判斷不出來」那一列。

判斷之後的處置：

| 判斷                               | 處置                                                                                                                                         |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| 評語依據的事物變化大 | 不把評語當成現況寫，拿掉評語；來源裡的紀錄需要時照樣引用，並寫明只取紀錄。同一篇另有一段交代對象過去的樣子、讀者在那一段不拿它判斷現在時，那一處照第 3 問另判（讀者要判斷的是當年），可以寫成「當年的評價是……」並寫出評的時間點；讀者在那一處了解的是當年的人怎麼評它時，照第 1 問的評價本身處理 |
| 評語依據的事物變化不大 | 評語可以當成現況引用，並寫出評的時間點（場次的年份、產品的版本、量測的日期與設定）。判成這一列時，寫文章的人把依據的事實（沒有改版、已經凍結、評語談的那一項在這段期間沒有變動的紀錄；相對比較另要比較的結論沒有被推翻的事實，例如範圍裡其他成員在評語談的那一項上的評價，依證據下的判斷另要證據沒有改變的事實，例如之後的研究仍採用這個結論）寫在引用的位置，或寫進交稿時附的紀錄（提交訊息、交給審查者的附註）；寫不出來的歸「判斷不出來」那一列。相對比較判成這一列時，引用的位置另寫出比較涵蓋到的時間點或範圍（「到 2023 年為止同價位的機種裡」）。只有「查過而沒有找到之後的評測或文獻」時，那是查證的經過，不是依據，歸「判斷不出來」 |
| 判斷不出來                         | 評語照樣引用，但句子寫成評的時間點當時的狀態，不寫成對現況的斷言；另外在引用的位置寫出缺的是哪一項資訊，寫成要有什麼才判斷得出來，並寫出評語談的那一項與從評的時間點起算的期間（用年份或版本寫）（評測寫 2021 年韌體 1.x 的對焦慢時：「要有 2021 年之後幾次韌體更新的對焦評測，才判斷得出現在的對焦是不是還那麼慢」）；原樣搬到別的個案也成立的句子（沒有寫出評語談的那一項，或沒有起算的年份或版本）不算，只寫「無法確認」也不算。讀者拿評的時間點與缺的那一項資訊跟對象現在的狀態比對。對象的事實可以寫在正文（版本、已知的變動事件；更新說明是紀錄，用來寫出變動事件）；這個對象在某個時間點之後有沒有評價，寫成要有什麼才判斷得出來，不寫成有或沒有。寫文章的人這一次查找的經過（查了哪些來源、哪些來源有沒有評價，例如「查了兩個評測網站」「近年沒有這台的評測」）寫進提交訊息或交給審查者的附註，不寫進正文，因為它不是這篇文章要交付的內容，讀者用不到。文章本身的主題就是一次考證或排查時（標題寫的是一句話的出處、一次故障的排查），查證經過是內容，照那一類文章的寫法寫進正文；引用別人的考證結論不屬於這一種。〈重建之後說法放在哪裡〉的「這一項目前只有經驗值，沒有找到量測或機制」陳述的是整個領域缺機制或量測，不是一個對象的評價有沒有出現，不在此列 |

論斷只寫出評價存在（選場次的文章寫「這一場有樂評」）時，那一句就是要處置的評語，評價所評的面向取那份評價談的面向（查不到那份評價談什麼時算判斷不出來）：變化大時拿掉那一句，或改寫成那一場的紀錄、不當成推薦的理由；變化不大時寫出評的時間點，依據照處置表寫在引用的位置或交稿紀錄；判斷不出來時寫出評的時間點與缺的那一項資訊（含那份評價談的面向）。

同一份來源常常同時帶著紀錄與評價。紀錄描述的是那一刻，當成那一刻的事實引用時不會過期（那一場演了哪幾首）；拿它說明對象現在的樣子時（把那一版的功能清單當成現在的功能），照第 4 問同樣判斷一次。需要的是紀錄時只引紀錄，不把評語一起帶進來；來源主要是一份評價、而評語判成不當現況用時，在引用紀錄的位置寫明只取紀錄。來源的評語沒有判成不能用、只是本篇用不到時，不必加這一句。

下列時機各照上面依序問的問句與處置表做一次：

- **為了滿足收錄條件（「只收有評測的」「要有樂評佐證」）去找證據，近期的評價找不到，把搜尋範圍擴大到更早的年份時**：找回來的每一份都從第 1 問判斷一次。收錄條件只確認評價存在，沒有確認它評的是什麼時候；教讀者做當下決定的文章裡，讀者拿「有評價」判斷對象，論斷的對象是被評的對象。
- **把不同年份的評價彙整成同一張表或同一份清單時**：同一欄裡的評價在版面上沒有新舊之分，讀者要自己從年份推出哪一筆不能當成現在的評價。逐筆判斷之後，列評語的那一欄只放下列幾種評價：第 1 問判成論斷的對象是評價本身的、評的時間點與讀者要判斷的時間點相同的（回顧那一段歷史的表）、判成變化不大的，以及判斷不出來的；每一筆寫出評的時間點，論斷的對象是評價本身的連評價者一起寫，判斷不出來的連缺的是哪一項資訊一起寫。判斷成變化大的那幾筆，評語不進這一欄；它們的紀錄（那一場的曲目、那一版的功能）需要時寫在正文或另一欄，並寫明只取紀錄。
- **評價出自知名的評價者或權威的媒體時**：照樣判斷一次。評價者的名聲不改變它評的是什麼時候的對象。

審查者查的是稿件有沒有留下這項判斷的痕跡，不查判斷的答案。審查者讀稿件、稿件給出的來源與交稿時附的紀錄，不另外搜尋對象的版本紀錄。審查時先判論斷的對象（下面「不開 finding」那一段），再用到兩個判別：

- **評語寫成當時的狀態，還是寫成對現況的描述**：兩件事都成立才算寫成當時的狀態。第一，句子有把評語限定在評的那一刻的詞（「當時」「那一場」「在 3.0 版上」「2021 年的測試裡」）。第二，稿件全文沒有任何一處拿這句評語推出對象現在如何的結論或推薦。缺任何一件，算寫成對現況的描述。審查者判不出是哪一種時，照實寫「判不出」，請寫文章的人確認，不自行歸類。
- **引用的是評語還是紀錄**：引用處只引了紀錄（那一場的曲目、那一版的功能清單、量測用的設定）、當成那一刻的事實寫時，不開 finding，不要求稿件寫出「只取紀錄」這幾個字。紀錄被拿來說明對象現在的樣子時，照評語處理；只寫出評價存在的句子（「這一場有樂評」）被拿來支撐推薦時算評語。稿件出自沒有交稿紀錄的發布流程時，下面「交稿紀錄缺……」那幾條不開，變化不大的依據改查引用的位置。

論斷的對象由審查者照定義自己判，不採寫文章的人的自述。判成評價本身時，引用的位置缺評價者、缺評的時間點、論斷寫的是作品當年的接受而缺刊登日期，或交稿紀錄缺那一句論斷的位置，各列一條可改；下面那幾條一律不開。判成被評的對象、而評的時間點與讀者要判斷的時間點相同時，不開 finding。兩個時間點不同時，或評的時間點在稿件與它給出的來源都查不到時（評語寫成寫文章的人自己的敘述、沒有出處，常常是這一種），下列情形各列一條可改，不列必修：

- 引用的位置沒有寫出評的時間點：審查者指出這兩個時間點；評的時間點查不到時寫「查不到」與查過的位置。
- 稿件自己寫出、或審查者讀稿件給出的來源時看到，被評的對象在這兩個時間點之間改版、換硬體、換人或整修，而評語寫成對現況的描述：審查者指出那個事件與看到它的位置，請寫文章的人重新判斷一次；那個事件有沒有動到評語談的那一項，由寫文章的人判斷，審查者不以它決定開不開這一條。
- 評語寫成對現況的描述，而引用的位置與交稿時附的紀錄都看不出寫文章的人依據哪一件事實判成變化不大：審查者請他寫出依據；寫不出時改歸「判斷不出來」那一列。評語是相對比較（「同類裡最快」）或依證據下的判斷時，對象本身已經凍結不算依據，要的是比較的結論沒有被推翻、或證據沒有改變的依據；交稿紀錄只寫查過而沒有找到之後的評測或文獻時，算看不出依據。
- 評語寫成評的時間點當時的狀態，而引用的位置沒有寫出缺的那一項資訊，或寫的句子原樣搬到別的個案也成立（沒有評語談的那一項、沒有起算的年份或版本）：審查者請寫文章的人照「判斷不出來」那一列補上。
- 評語寫成評的時間點當時的狀態，而審查者拿得到的交稿紀錄沒有寫出查了哪些來源：審查者請寫文章的人在交稿紀錄補上。
- 查證經過寫進了正文（文章本身的主題就是一次考證或排查時除外）：審查者請寫文章的人移到交稿紀錄。

評語依據的事物改變了多少、評語是否保留，由寫文章的人判斷；審查者指出的是時間點、事件與缺少的依據，不以相隔幾年判定引用合不合規，也不替他下結論。推導與個案見 [cited-evaluation-carries-the-date-it-judged](principles/cited-evaluation-carries-the-date-it-judged.md)。

## 自檢清單

- [ ] 已判別 source 類型（分析文走拆層、經驗談走機制重建）。
- [ ] 經驗談 source：承擔判斷標準的斷言都有機制支撐，訴諸權威（「資深的人都這樣」）沒有被沿用為教材論據。
- [ ] 經驗談 source：數字閾值都找到了反推邏輯、或標明「經驗值、機制待補」。
- [ ] 每個來源句子都能標成事實、原作者判讀、本文推導之一。
- [ ] 原作者 frame 沒有被寫成事件事實。
- [ ] 目標讀者不需要原文 reader contract 也能理解主體推導。
- [ ] 三句內沒有未解釋的連續跨領域術語。
- [ ] 內部分析框架沒有外露成正文標題。
- [ ] 正文段落都服務 title promise。
- [ ] 結尾提供可遷移框架、預警訊號與下一步路由。
- [ ] 引用了樂評、評測、使用心得、量測、考證或鑑定的結論、排名這類評價時，每一份都判斷過論斷的對象；論斷的對象是被評的對象時，判斷過評語依據的事物（被評的對象，相對比較另含比較的對象、範圍與標準，依證據下的判斷另含證據）改變了多少；引用的位置寫出了評的時間點（論斷寫的是評價本身時連評價者一起寫）或寫明只取紀錄（判斷沒有通用的年數；見〈引用評價時留意它評的時間點〉）。

## 反模式速查

| 反模式                           | 修法                                      |
| -------------------------------- | ----------------------------------------- |
| 只要求 AI「改成我們的風格」      | 改成「抽出可遷移判讀框架」                |
| 經驗談只做主題分類 + 書面化      | 跑機制重建 pass、把判讀升級成可推導的判斷標準 |
| 教材沿用「厲害的人都這樣」當論據 | 重建該斷言背後的機制、權威降為佐證        |
| 同一句 anecdote 攤進多篇         | 找出它支撐的機制、收斂到機制的歸屬篇章    |
| 把原作者分類直接當本文標題       | 標出這是原作者 frame 或本文 frame         |
| 引用機構名但沒有具體來源         | 刪具名 attribution 或重新查證             |
| 章節標題是分析 process           | 改成教學標題                              |
| 文章結尾只有事件結論             | 補下次遇到同類事件的判斷問題              |
| 讀者需要懂原領域 shorthand 才懂  | 降術語密度，補 bridge sentence            |
| 把多年前的評語當成被評對象現在的評價 | 判斷評語依據的事物改變了多少，處置見〈引用評價時留意它評的時間點〉 |
| 訂「超過 N 年的評價一律不用」    | 改成逐份判斷對象的變化，不用年數當門檻    |
| 被評的對象已經明顯改變，只在評語後面加上年份就照用 | 先判斷評語依據的事物改變了多少；變化大的照處置表拿掉評語，同一篇另有交代過去的段落時，那一處照第 3 問另判 |
| 因為舊評價不能用，把整份來源丟掉 | 拆開紀錄與評價，需要的紀錄照樣引用        |

**核心原則**：外部分析文章改寫的核心是 source transformation。保留事實、分離原作者判讀、重建目標讀者可理解的推導，最後交付可遷移框架。
