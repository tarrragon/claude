# 摘要另一份內容時寫出成員，計數只告訴讀者清單有多長

> **角色**：本卡是 `compositional-writing` 的支撐型原則（principle），被 SKILL.md 的〈索引建立〉原則與字句層 keyword bank 的「計數式摘要」類別引用。
>
> **何時讀**：在介紹另一份內容的位置寫句子時（文章結尾指向下一篇、`description`、目錄頁的交付欄、閱讀路線的說明欄），或審查時看到「四個追問、三種寫法、四類邊界」這類句子。

## 結論

摘要的職責是讓讀者不必打開原文，就知道原文交付什麼。「四個追問、三種寫法各自押的前提、四類邊界」做不到：讀者讀完知道有四個、三種、四類，不知道任何一個是什麼，還是要點進去。**計數交付的是清單的長度，摘要要交付的是清單的內容。**

這一類句子固定出現在介紹另一份讀者還沒讀的內容的位置。寫的人手上有那份內容，數字對他是完整的索引；讀的人手上沒有，數字對他只是一個長度。

## 為什麼既有的檢查放行

- **它在寫的人眼裡是精確的**：數字正確，而且比列出成員短，讀起來像合規的壓縮。壓縮的前提是讀者能從短形還原，計數在讀者手上沒有可還原的內容。
- **集合指涉規則碰不到它**：那條規則管回指已讀的集合（其他三篇、另外三本），句型是「其他＋數字」；計數式摘要預告一份未讀的內容，句型是「數字＋類別名」。
- **grep 分不出合規與違規**：「配對與成品兩個時刻」「exec 與 dev 兩種網址」同樣是數字加類別名，成員就寫在旁邊，是合規的。差別要讀句子才知道。

## 判讀

在介紹另一份內容的位置，逐一找出「數字＋類別名」的片語，問：**沒讀過那一篇的人，讀完這個片語知不知道成員是什麼。**

- 成員緊鄰數字寫出來了（「自連接、視窗函數與相關子查詢三種寫法」）：合規。
- 只有數字與類別名（「三種寫法」「四類邊界」）：違規。
- 量測事實（「差三個量級」「七十倍」）：合規，數字本身就是內容。

## 修法

- **把成員寫出來**，數字通常可以拿掉——成員列出來之後讀者自己數得出有幾個。
- **成員太多列不動時，寫它們共同的性質**（「需求沒說而資料會有的情形，例如重複、時區、補登」），不寫數量。連舉例都做不到，代表摘要的範圍太大，要切小。
- **寫完問一次：讀者讀完這句還需要點進去嗎。** 需要是正常的，但理由應該是想看推導與細節，不是想知道那幾項各叫什麼。

實例改寫：「拿一個真實需求做完這些決定：四個追問、三種寫法各自押的前提、四類邊界」→「拿『哪幾天氣溫比前一天高』這句需求做完這些決定：把『前一天』追問成日曆上的前一天還是資料上的前一筆；用自連接、視窗函數與相關子查詢各寫一次，找出三者共同押的前提（同一天只有一筆）；最後列出重複紀錄、時區、補登這幾種需求沒說的情形」。
