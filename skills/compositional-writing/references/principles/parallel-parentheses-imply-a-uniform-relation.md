# 一組並列的括號各裝不同東西時，讀者會先找一條統一規則

> **角色**：本卡是 `compositional-writing` 的支撐型原則（principle）、被字句層檢查與 reference 撰寫標準引用。
>
> **何時讀**：一列項目後面接著形式相同的括號時；以及審查一份條文型文件的可執行性時。

## 核心原則

括號是一個不宣告自己裝什麼的容器。單獨一個括號，讀者從上下文判得出它在做解釋、給例子、還是補定義。

**並列的一組括號會讓讀者假設它們做同一件事。** 版面上的同構本身是一個宣告，而讀者依那個宣告去解讀每一個括號；各裝不同東西的時候他找不到那條統一規則，於是逐個猜。

**每一個括號單獨看都通順，所以逐句自審過得去。** 要把整組並排才看得見它們不同構——而作者讀自己的括號時取回的是寫下它時的意圖，六個意圖各不相同這件事在他那一側從來不成立。

## 實例

一條規則列六個要記錄的項目，每項後面用括號說明這一項的紀錄要含什麼。作者的意圖統一：六個括號全部裝紀錄內容。

低階探針逐項判讀，回報六種不同的關係——解釋、定義、範例、驗證方法、紀錄內容、度量。

其中一處的誤讀有實際後果：「形態數（簽核人與日期）」被讀成「形態數就是指簽核人與日期」，也就是讀成定義。照這個讀法執行的人會去數簽核人，而規則要的是記下形態數並附上簽核人與日期。

## 修法

**換成表格的顯性對映。** 把那個關係寫進欄名，一次交代整組：

| 項目   | 紀錄要含     |
| ------ | ------------ |
| 形態數 | 簽核人與日期 |

表頭承擔了括號沒有承擔的責任——它說出這兩欄之間是什麼關係。

**或在括號裡加關係詞。** 「形態數（紀錄：簽核人與日期）」。這一個便宜，代價是每一個括號都要加，而加完之後版面通常已經在要求表格了。

**判定的動作是把整組括號抽出來並排，逐個寫下它與前面那個詞的關係。** 寫得出兩種以上就要改。

## 偵測

沒有關鍵詞可掃，形態可掃：連續三個以上以括號收尾的條列項。真正的判定要靠多份獨立逐項判讀——探針要被明令回報「這個括號跟前面那個詞是什麼關係」，問「這段清不清楚」問不出來，因為讀者會用意圖補完。

## 射程：條文層有效，對拆分點沒有預測力

一個看起來合理的外推是「關係不統一的括號標示著這一條混了兩件事，所以它可以當拆分點的預測器」。一次實測否證了它的一半：那次拆分的切點來自動作的時序，沒有一個由括號關係指出；而全檔並列括號最集中的一處（一張二十二項的檢查清單）關係反而統一（全部是路由），該節整節留在入口沒被拆。支持的那一半是同一次確實有一處關係不統一的括號暴露了混合——但暴露的是**同一條規則內部混了兩件事**，不是兩個該分家的章節。

所以本卡是條文層的檢查：它問這一條規則自己說清楚了沒有，不問這一份文件該切在哪裡。

## 判讀徵兆

- 三個以上連續的項目後面都有括號。
- 括號裡的內容形態不一（有的是名詞組、有的是完整句子、有的是指令）。
- 同一份文件的括號在不同段落做不同的事，而沒有任何標示。
- 這一組括號所在的條文被宣告為可執行的。
