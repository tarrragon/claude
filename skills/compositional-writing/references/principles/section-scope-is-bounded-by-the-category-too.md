# 段落的範圍由標題與所屬分類共同限定：標題沒寫出分類的條件時，題目範圍檢查放行的那一節

> **角色**：本卡是 `compositional-writing` 的支撐型原則（principle）、被 `structuring-with-solid.md` 的 S 單一責任與 `writing-documents.md` 的拆分判斷 引用。
>
> **何時讀**：一節內容落在標題的範圍內、各項檢查也都通過，而讀者指出它不屬於這個分類；或要判斷一節該留在原處還是移到另一個分類時。

## 核心原則

一篇文章的範圍是兩個限定的交集：標題寫出的對象，以及它所在分類已經限定的條件（哪一種語言、哪一個抽象層、哪一類對象）。作者在分類裡寫標題時，分類的條件對他是給定的，所以標題常常不寫它——放在某個程式語言的重構分類裡、講「依修改競爭判斷拆檔」的文章，標題不必寫出那個語言。標題因此比文章實際的範圍寬。**題目範圍檢查只拿段標去比標題時，一節講得比分類更泛的段落會落在標題的範圍內而通過。**

## 失效的形態

那篇拆檔教材的末尾有一節，把同一套方法套到規則文件、操作手冊與範本上。每一句都成立，也直接延伸前文的論點。拿段標對標題判定，它在範圍內：標題講拆檔，文字文件也是檔案。拿它對分類判定，它在範圍外：那個分類收的是某一種語言的程式碼，文字文件的拆分與語言無關。放在那裡的一節，修改理由是文件寫作的做法改了，與那個語言無關——正是那篇文章自己在教的單一職責。

另一種形態是整篇落在分類外：同一個分類裡一篇題為「非程式碼的重構」的文章，標題本身就寫出了它不在收程式碼的分類範圍內。

## 檢查

逐段標表在「在不在標題範圍內」之外另加一欄「在不在所屬分類的範圍內」，分開判定、分開記：

| 在標題範圍內       | 在分類範圍內 | 處置                                                 |
| ------------------ | ------------ | ---------------------------------------------------- |
| 是                 | 是           | 留在原處                                             |
| 是                 | 否           | 移到承接它的分類，原處留一句寫出目的地交付什麼的連結 |
| 否                 | 否           | 照題目範圍檢查的既有處置                             |
| 標題本身落在分類外 | —            | 整篇移到承接它的分類，舊網址保留重導向               |

分類的限定條件從分類的目錄頁（collection index）的描述與簡介讀；目錄頁沒有寫出時，以內容集合自己的分類規則為準。兩欄不合併：合併之後判定者只會比手上比較具體的那一個，通常是標題。移動的目的地要確實承接這個主題，形式是路由不是刪除。

寫作的當下可以先問一次：要加的這一節，換到同一個內容集合的另一個分類底下會不會更合適。

## 判定上的補充

- **換掉限定詞句子不用改，不等於落在分類外。** 同一篇裡分類內的實作節依賴這一節的論證時，這一節判在範圍內；把它搬走，留下的實作節就沒有論證。
- **目錄頁的描述可能混著出處條件**（「基於某段版本的經驗」）。判定只取主題條件，出處條件不限定內容範圍。
- 分類的限定條件很寬的集合（例如收各類方法論的分類），這一欄幾乎每次都判在範圍內，判別力來自標題那一欄。

## 為什麼審查抓不到它

寫標題的人手上有分類這個前提，審查者拿到的稿件路徑也帶著分類，兩者讀標題時都自動補上分類的條件——而規則照字面只比標題，比完它在範圍內。單一職責的變動理由測試原本也擋得住它，但那道測試以「文章越寫越長」為觸發條件，而那篇文章不長。

## 判讀徵兆

- 讀者說「這一節不屬於這裡」，而那一節在標題的範圍內。
- 一節內容換掉分類的限定詞（把語言名換成任何語言、把「程式碼」換成「文件」）句子都不用改。
- 標題沒有出現分類的限定詞，而分類的目錄頁寫了。

## 適用邊界

證據是一篇文章的一節、同一個分類裡的另一篇，以及一位讀者的指認。從目錄頁描述讀出限定條件的做法只在一個分類試過，那裡的描述剛好寫了限定詞；描述只寫主題的分類，判定落回集合的分類規則，那一步的一致性沒有量過。
