# 描述抽象概念要用貼合屬性的謂語

> **角色**：本卡是 `compositional-writing` 的支撐型原則（principle）、被字句層 keyword bank 與 multi-pass review 輪 8-9（keyword bank + reader simulation）引用。
>
> **何時讀**：寫技術 / 分析文章時、判斷描述抽象概念（分析角度、框架、判讀訊號）的動詞與形容詞是真的貼合概念屬性、還是只是順口但語義錯位——尤其在字句層 register 掃描與異源冷讀時。

---

## 論述基礎與限制

本卡基於一次多輪審查中、兩處中文搭配問題由人類冷讀 catch 的事故。一批文章跑完 register / cadence / 冷讀多輪 agent review 都沒抓到兩處「順口但語義錯位」的搭配——把一個分析角度擬人化成「說了一半、還有話沒說完」的說話者、用「直接」形容訊號的可辨識度。兩處都由作者以外的人類當場指出。限制：case 是中文寫作，但原則（描述抽象概念要選屬性相符的謂語）跨語言成立；且它是 register 類問題、agent 同源自審對它有結構盲區。

---

## 核心原則

**描述抽象概念時，選跟該概念真實屬性相符的動詞與形容詞，不套用習慣上順口、但語義錯位的搭配。** 抽象概念（分析角度、框架、訊號、指標）沒有人的行為屬性、也沒有具體物的物理屬性——給它配上不相符的謂語，句子讀起來順、但語義是錯的。判別方法只有一個問題：這個謂語真的描述了這個名詞的屬性嗎，還是只是順口。順口是語感慣性、不是語義正確。

四種常見錯配：

- **擬人化錯配**：把分析角度或框架當成會說話、有意圖的主體——「這個角度沒說完的話」「數字想告訴我們」「框架背後的潛台詞」。角度不會說話；它的屬性是涵蓋範圍，精確的說法是「這個角度沒有涵蓋 / 沒有提到的問題」。
- **形容詞錯配**：用習慣性但屬性不符的形容詞——「訊號很直接」。「直接」描述的是方式或態度（直接說、直接處理），不是訊號的可辨識度；訊號的可辨識度屬性用「清晰 / 明確 / 明顯」。
- **範疇錯配**：給概念配上另一個範疇的謂語或介詞框架——「前提在讀者這裡不存在」（命題沒有存在與否、只有適用與否）、「在讀者這裡」（人不是地點、進不了處所框架）。精確的說法是「不適用於讀者」「讀者具不具備」。
- **物理化錯配**：給抽象概念配上承重、支撐、懸掛類的動詞——「這個證據撐不撐得住」「論證掛在哪個前提上」「這套說法會垮」。證據跟結論之間沒有重量、沒有支點、沒有材料強度，那些動詞不帶進任何資訊，只是把讀者對物理世界的直覺借過來蓋住實際的關係。修法依句子在做什麼而分兩種：描述關係的換成關係動詞——論證**依賴**前提、資料**佐證**、責任由某人**負責**；足夠性斷言（宣稱某個對象足以或不足以滿足某個需求的句子）要寫出需求、判斷標準與機制，見〈足夠性斷言要寫出需求、判斷標準與機制〉。

物理化錯配有一個可以機械執行的偵測方法：**問這個動詞如果照字面成立，需要什麼物理條件**。它用來找出候選、不決定修法。需要重量、支點、材料強度、上下方位、身體部位的，就是借來的——抽象概念不具備那些屬性。「撐得住」需要承受力量的結構，「掛在」需要掛點，「咬得最深」需要牙齒。它也是四種裡唯一有一組高密度關鍵詞可掃的（撐 / 扛 / 掛 / 垮 / 頂 / 咬），另外兩種只能靠異源冷讀。但那組清單是抽樣、不是這一類的全部——違規義項只佔該詞用法少數的（「滑坡」的本義是山崩、「拿到的是理解」）漏在清單外，入選標準與兩個補位探針見 [keyword-list-needs-dominant-violating-sense](keyword-list-needs-dominant-violating-sense.md)。

這個判斷標準可以一般化到全部四種錯配：**問這個謂語（動詞、形容詞、介詞框架）照字面成立，需要主詞或賓語具備什麼屬性**——物理化要的是物理條件（重量、支點），擬人化要的是**主體條件**（一個自我、意圖、發話能力），範疇錯配要的是**範疇條件**（命題要有存在性才能「不存在」、人要是地點才進得了「在～這裡」），形容詞錯配問的是同一個問題的形容詞版。主體條件的判定沿轉喻鏈問：「作者自述」「該頁面自陳」合法——頁面是作者的發話面、主體在鏈上；「書自述」「角度沒說完的話」違規——鏈上沒有能發話的主體。「自 X」動詞另有一個極性軸：「自」承載第一方出處訊號，正面宣告時它做工（「該頁面上自陳為節選本」＝是它自己說的、不是第三方評的），否定句裡它不做工——「書裡沒有自述」要說的只是「沒有明說」，且「自述」的名詞義讓否定句多一層歧義。同一個詞正面合法、否定違規，命中是候選不是判決的又一個軸。

替換時還有一層：**原句描述的若是關係的程度（多深、多緊、多重），替換要用狀態詞而不是另一個動作動詞**。動作動詞會帶進一個施力的主體與一個承受的對象，而抽象關係之間沒有施力方向——「這本書跟協作形態咬得最深」換成「與協作形態耦合最緊」是對的，換成「咬合最深」只是換一個動作、缺陷原封不動。判斷方式是問這句在講什麼：講**關係本身**（證據與結論之間怎麼連上）用關係動詞（支持、依賴），講**關係的程度**（連得多緊）用狀態詞（耦合最緊、依賴程度最高）。

例外是**明示並就地展開的類比**：把物理意象在同一段裡逐項對應回真實機制（上限對應承重、超過會塌對應失效），那是刻意建立的模型而不是隨手借詞。判斷標準是那個意象有沒有被展開成可以逐項檢查的對應關係；沒展開的就是借詞。主詞本來就是實體或系統負載時不觸發。

## 反模式：順口的搭配蓋過語義的正確

**Instance 3（物理化）**：原句「取證據來源撐得住這個用途的那本」「這本書的結論能撐多重的決定」。結論沒有重量，這裡實際發生的關係是「這個結論可以支持多大範圍的主張」——換成「支持」之後，句子還多回答了一件原句迴避掉的事：支持什麼、支持到什麼範圍。**借來的物理動詞不只是不精確，它還讓作者不必回答那個問題**，因為「撐得住」聽起來已經像個答案。這是它跟前兩種的差別：擬人化與形容詞錯配是說錯了，物理化錯配是繞過了。

### 足夠性斷言要寫出需求、判斷標準與機制

換成「支持」之後，句子仍然可能沒有寫出支持什麼、到什麼程度：「足以支持」一樣沒說要支持哪個決定、到什麼程度算足夠。「撐」這一族在足夠性斷言裡，與「問題」這個詞是同一類（見 [「問題」與「回答」當框架詞](question-answer-frame-blurs-problem-issue-request.md)）：它佔著需求與判斷標準的位置，聽起來像答案，而內容沒有填進去。換成另一個動詞，只是把同一個空位換個詞佔著。

足夠性斷言改寫時寫出三件事：

- **需求**：要支持哪一個決定、承受什麼負載、維持多久。
- **判斷標準**：滿足到什麼程度算夠——門檻、範圍、條件。
- **機制**：靠什麼屬性滿足，或在哪一點不再滿足。

| 原句                         | 句子實際要交代的                       | 改寫要寫出的內容                                                                                     |
| ---------------------------- | -------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 這本書的結論撐得起實際決定嗎 | 結論能用在哪些決定上                   | 結論的資料來源與期間，足以判斷哪一類決定、不足以判斷哪一類，理由是資料涵蓋什麼                       |
| 這個證據撐不住               | 證據不足以支持某個主張                 | 主張是什麼、需要什麼樣的證據才成立、這個證據少了哪一項（樣本、對照、時間範圍）                       |
| 這套說法會垮                 | 論證在某個條件下不成立                 | 哪一個前提在什麼情形下不成立、不成立之後結論變成什麼                                                 |
| 方法撐不久                   | 方法無法持續執行                       | 持續執行需要什麼資源或條件、哪一項會先耗盡、大約在什麼規模或時間點                                   |
| 單台資料庫撐得住這個流量     | 單台資料庫在預估負載下能否符合服務目標 | 預估的負載（尖峰每秒寫入數）、判斷標準（例如 p99 延遲門檻）、瓶頸在哪一項資源，以及這些數字從哪裡量 |

描述關係、不是足夠性斷言的句子（論證掛在前提上、資料支撐結論、某人扛責任、跟某個條件咬得最深），換成關係動詞就完整：依賴、佐證、負責、耦合最緊。分界問一句：**這句話是否在宣稱某個對象足以或不足以滿足某個需求**。是，就寫出需求、判斷標準與機制；不是，換成關係動詞。

**系統負載不豁免。** 主詞是系統負載的句子（「撐住尖峰流量」「拖垮 OLTP」）有物理對應，而需求與判斷標準照樣被省略：「單台資料庫撐得住這個流量」沒說是在什麼延遲門檻、多少請求量之下，讀者拿它做容量決定時缺的正是那兩個數字。結構上的實際連接（「route table 掛在 subnet 上」）不是足夠性斷言，合規。

**Instance 1（擬人化）**：原句「這正是那個角度背後沒說完的話」。一個判讀角度被寫成「說了一半、還有話沒說完」的說話者。角度沒有「說」或「沒說完」這個行為屬性，它的屬性是「涵蓋了什麼、漏掉了什麼」。修正：「那個角度沒有提到的問題」。

**Instance 2（形容詞錯配）**：原句「判讀訊號很直接：……」。訊號的屬性是可辨識度（清不清楚、明不明顯），不是「直不直接」——「直接」形容的是行為的迂迴程度。修正：改用「訊號很明確」，或直接陳述訊號本身、拿掉這個評價性套語。

兩個 instance 的共同機制：作者走完思考、要下一個評價性的謂語時，抓了語感上最順的那個詞，而沒有回頭問它是否真的描述了主語的屬性。順口的搭配在同源自審裡讀起來完全自然——因為作者跟 agent reviewer 共享同一套語感慣性，這正是它需要異源冷讀的原因。

## 跟其他原則的關係

- [物理動詞佔住的內容](physical-verbs-stand-in-for-content.md)：下游，把「先判斷佔住哪一格」推到清單裡每一個動詞，補上失效結果、負擔、可信度各自要寫出的內容，以及負載情境的對照。
- [口語化修辭稀釋技術精度](colloquial-rhetoric-erodes-technical-precision.md)：同一取向、不同尺度——那條是整段語氣的口語化，本卡是單一詞對詞的搭配錯位；都是「順口壓過精確」，本卡更微觀。
- [避免濫用泛用詞](avoid-overused-generic-words.md)：都是用詞精確性、不同面向——那條是「一個泛用詞蓋多個不同情境」，本卡是「一個謂語配錯一個概念的屬性」。
- [入口由違規形態寫不寫得成 pattern 決定，佔比只決定能不能原樣進清單](keyword-list-needs-dominant-violating-sense.md)：下游、限定本卡的偵測層——判斷標準沒問題（「滑進去的失敗」「拿到的是理解」照本卡判斷標準都成立），漏抓是因為那兩個詞的違規義項只佔它們用法的少數，擴充清單解決不了。
- [結構譬喻頂替主詞與動詞](structural-metaphor-replaces-actor-and-verb.md)：同一類錯配在內容集合組織詞上的形態——「這本書承擔的角色是」是本卡的擬人化（書不具備承擔角色的主體條件），而「這條線」「各接一個面」「走 [某篇]」是組織者的結構地圖寫進了正文；那張卡給這組詞的 pattern 與合規邊界，主詞是物的「承擔」兩邊都適用。
- [教學散文的中性 register](teaching-prose-neutral-register.md)：本卡的搭配錯位無穩定關鍵詞、grep 抓不到、多輪同源 agent 自審全漏、靠人類異源冷讀 catch——跟中性 register 類違規同屬「同源盲區、真防線是文體異源視角」。

## 判讀徵兆

| 訊號                                                          | 該做的事                                                           |
| ------------------------------------------------------------- | ------------------------------------------------------------------ |
| 句子把一個角度／框架／數字寫成有意圖、會說話的主體            | 還原成該概念的屬性（涵蓋、遺漏、顯示），拿掉擬人化的動詞           |
| 用一個評價性形容詞形容抽象概念、讀起來順但停下來想不太對      | 問「這個詞真的描述了這個名詞的屬性嗎」，換成屬性相符的詞           |
| 抽象主詞或系統負載配上撐、扛、垮這類足夠性斷言                | 寫出需求、判斷標準與機制；換成「足以支持」「維持不久」不算修好     |
| 「自 X」動詞（自述／自陳／自稱）出現在否定句裡                | 「自」的第一方訊號在否定句不做工，多半要說的是「沒有明說」；正面宣告的第一方標記合法 |
| 「在＋人＋這裡／那裡」的處所框架                              | 人不是地點；讓人當主詞、換屬性相符的謂語（具備／執行得了／適用）   |
| 命題、前提、規則配上「存在／不存在」                          | 命題的屬性是適用範圍；換成「適用／不適用於」                       |
| agent reviewer 多輪回報 register 乾淨、但總覺得某句「怪怪的」 | 這類搭配錯位無關鍵詞可掃、同源自審有盲區，交作者以外的人類冷讀定奪 |
