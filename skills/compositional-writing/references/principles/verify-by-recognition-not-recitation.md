# 教學內容不預設考核情境，檢核動詞用識別與應用的動詞

> **角色**：本卡是 `compositional-writing` 的支撐型原則（principle）、被 SKILL.md 原則 3（意圖顯性與層級貼合）的讀者框架段引用。
>
> **何時讀**：教學文字用「說得出 / 答得出 / 講得出」檢核讀者或團隊的能力時；或審查時撞到判讀訊號、檢查問法、驗收段裡密集的對答句型時。

---

## 核心原則

**「說得出 / 答得出」當檢核動詞時，句子預設了一個考核情境：有一個問的人、答案要被說出來給人聽。** 教學內容的讀者不在那個情境裡——讀者為吸收知識而來，實際活動是自我評估理解與應用；文章的定位是建立識別能力與應用能力，檢核動詞就用那些能力自己的動詞。

判定問句逐句可執行：**這一句描述的情境裡，有沒有一個真實的問方與言說行為。** 有（會議上被追問、稽核要求列出、客服電話核身、向管理層爭取排程）——「說 / 答」描述實際發生的事，保留；沒有（讀者自己讀圖、工程師檢查自己的設計、團隊盤點自己的系統）——「說 / 答」是借來的考核框架，換成該能力的動詞。

替換不一律，按被檢核的能力選（一律替換會做出新模具，見 [cadence-homogenization](./cadence-homogenization.md)）：

| 被檢核的能力   | 動詞               | 例                                   |
| -------------- | ------------------ | ------------------------------------ |
| 讀圖、讀資料   | 識讀、辨別         | 能不能識讀兩種平均為什麼差這麼多     |
| 指出對象或理由 | 指得出、指認得出   | 指得出一個具體的隔離需求，才手動分割 |
| 列舉           | 列得出             | 列得出全部的回復路徑                 |
| 資料可查性     | 查得出             | 稽核日誌查得出誰在什麼時候取了哪一把 |
| 做決定         | 判斷得出、決定得了 | 下次遇到不同議題卻判斷不出來         |
| 對應、折算     | 對應得出、折算得回 | 每個權限對應得出它服務哪個動作       |
| 追蹤路徑       | 追得出             | 追不出這條路、入口接線就無人認領     |
| 工具計算       | 算得出             | 工具算不出這個 App 一共佔了多少      |
| 重建、驗證     | 重建得出、確認得了 | 靠這份清單重建不出來的段落回去補     |

## 檢核的出口：時機與路由，不是宣判

換對了動詞、檢核句還有第二層要對：**出口**。前置檢核的完整形態是三步——用需求句陳述前置（讀它會用到某組基本概念）、**主動提醒內容與回顧點**（直接列出會用到什麼、告訴讀者可以去哪裡回顧或補充——檢查的工作由文章做完、不派給讀者）、對還不熟的讀者給時機定性加路由（先從某個起點把概念建立起來、再回來讀；「還太早」是時機、不是能力宣判）。

同一句檢核的三版演進：「如果無法辨別，讀到的只是一疊數字」動詞對了、出口還是宣判（後果戲劇化、停在死路）；第二版邀請自我評估（「讀之前先想一下我是否具備 X」）——比宣判溫和、仍把檢查的工作派給讀者，而文章不可能要求讀者時時自我檢討；定稿是主動提醒：「讀它會用到⋯⋯。還不熟的話可以先從某個起點建立概念，再回來讀。」後果句可以存在（解釋前置為什麼是真的）但不能是段落最後一句、路由才是。自我評估的第一人稱問句仍可用在判準的執行步驟（操作型自問句），在前置提醒段它是可選變體、不是預設。

---

## 三類合法保留

判定看情境、不看詞面（命中是候選不是判決）：

1. **場景內真實對話。** 文中描述的情境本來就有問方與答方：客服來電者答核身問題、決策者追問成本去向、預算會議上說明時程、稽核要求列出存取清單、向監理機關通報。言說是場景的實際行為。
2. **協定與查詢語意。** DNS resolver 回答查詢、健康檢查端點回應探測——問答是這些系統的實際介面、甚至是協定詞彙。注意精度差：主詞是系統或清單時，「答不出」多半更精確寫成「查不出」——系統被查詢、不被質問。
3. **表達載體。** 測試名稱、註解、型別、錯誤訊息的本職是承載陳述——「名稱說不出這件事為什麼成立」合法，轉喻鏈上有作者、載體「說」是它的功能。

**自查問句另計。** 把判準寫成讀者可自答的問題（操作型自問句）本身合規；要看的是收尾——「答不出來就 X」的「答」多半可換成被檢核能力的動詞（「對應不出彙總問題就留在敘事段」比「答不出來就留在敘事段」精確）。

## 機制與家族

「說得出 X 才算懂」是教學者的職業慣性——教學現場以考核驗收學習，出題是驗收理解時最順手的框架；生成端（LLM）從教學語料繼承同一個慣性，檢核句密集的文體（判讀訊號、檢查問法、驗收段）命中最密。一次全站實測：196 處命中、修約 100 處、保留 53 處。

這是**借來的讀者框架**家族的第三個成員：演講姿態把讀者當聽眾（見 [write-for-readers-not-audiences](./write-for-readers-not-audiences.md)）、書評體壓縮把讀者當地圖共享者（見 [decodable-from-text-already-read](./decodable-from-text-already-read.md)）、考核框架把讀者當受試者——三卡的共同判定是先問讀者實際處在什麼情境。詞層的執行面掛在謂語判準上（見 [word-choice-fits-concept-attributes](./word-choice-fits-concept-attributes.md)）：「答得出」照字面成立需要一個對答的場。

## 判讀徵兆

| 訊號                                                 | 該做的事                                                           |
| ---------------------------------------------------- | ------------------------------------------------------------------ |
| 檢核句用「說得出 / 答得出 / 講得出」而情境裡沒有問方 | 換成被檢核能力的動詞：識讀、辨別、指認、列得出、查得出、判斷得出   |
| 主詞是系統、清單、資料而謂語是「答不出」             | 多半該寫「查不出」——系統被查詢、不被質問                           |
| 場景裡有真實的對話（稽核、客服、會議、追問、通報）   | 「說 / 答」描述實際行為、保留                                      |
| 主詞是名稱、註解、型別、錯誤訊息                     | 表達載體「說」是它的功能、保留                                     |
| 自查問句收尾寫「答不出來就 X」                       | 問句合規；「答」換成該能力的動詞（對應不出 / 確認不了 / 判斷不出） |
| 前置檢核句停在後果宣判                               | 定性改成時機（還太早）、段尾補路由（先讀什麼再回來）               |
| 批次替換時所有位置換成同一個動詞                     | 新模具警訊——按被檢核的能力逐處選詞                                 |
