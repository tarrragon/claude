# 把一段說法改寫成教學文章時，說法留在正文裡當討論對象：「引原話、判斷它在什麼條件下成立」是改寫留下的鷹架，斷言支撐審查的忠實度問句會把它修得更完整

> **角色**：本卡是 `compositional-writing` 的支撐型原則（principle），被 `source-to-teaching-analysis.md` 的機制重建 pass 與 `keyword-bank.md` 的〈素材的說法當討論對象〉引用。
>
> **何時讀**：教學文章的素材是使用者貼來的論壇說法、問答或 AI 回答，正文出現「常見的說法是……」「這句話在……上成立」「這個說法沒有涵蓋……」，或審查 finding 指出某段轉述不忠實、條件沒寫出時。

---

## 論述基礎與限制

這張卡來自一次寫作與多輪審查。使用者貼來兩段論壇說法（「插電的設備基本上不太需要管阻抗」「音響只剩喇叭與空間兩個問題，剩下的靠耳朵」「找一台 20 年以上的老擴大機加好的 DAC」）與一段 AI 生成的升級建議（含「便宜唱臂撐不起好唱頭」這個理由），要求寫成家用音響的教學文章。初稿把這幾句保留在正文裡，各自寫一段判斷它在什麼條件下成立。

第一輪審查的斷言支撐 reviewer 判定其中幾處「轉述不忠實」「條件沒寫出」，例如唱臂那一句只轉述了「能不能裝」，沒轉述「發揮不出表現」。這兩則 finding 的事實判斷是對的；照 finding 修完之後，唱臂那一段變成「這句常聽到的話由三件事組成……所以這句話在剛性與軸承這兩項上成立」，系統篇另有五處同一種寫法。同一輪的寫作規範 reviewer 對引號詞「地雷」給的修法是「改成『這個說法不成立的組合有下面幾種』」，同樣保留了判斷一個說法的框架。第二輪的冷讀 reviewer 把「這句常聽到的話」判成替讀者假設經歷，修法建議是改成「論壇與賣場常見的說法」；節奏同質化 reviewer 看到唱臂那一段在兩篇各拆解一次，修法建議是一篇只留結論。四個 frame 各自看到這幾段的一個毛病，給的修法都把那句說法留在正文裡。三份理解探針讀修正後的版本，都回報「論壇說法」這類回指要回頭找、唱臂那一段要拆開才看得懂。使用者讀到唱臂那一段時指出：不需要去釐清那句話，直接說明唱臂跟唱頭的關係；這種釐清是改寫原先問答留下的，多輪審查應該要察覺。

限制：這是一個批次（四篇、同一個 session）的觀察；改成正向陳述的效果由使用者的判斷與修正後的版本支撐，沒有拿兩個版本派探針比較讀者的理解。四個 frame 的修法都保留說法，是同一批稿件、同一個 session 派出的 reviewer 的結果，換一批稿件或另一個執行者派的 reviewer 是否一樣，沒有量過。

## 核心原則

**素材裡的說法是材料，教學文章的主題是說法底下的機制。** 論壇說法、問答與 AI 回答都是壓縮過的結論：「便宜唱臂撐不起好唱頭」壓縮的是唱臂的剛性與軸承精度、有效質量（effective mass）與唱頭順服度（compliance）的匹配、唱頭座（headshell）能否更換這三件事。改寫成教學文章時，這三件事才是讀者要帶走的內容；那句話本身只是作者拿到題目時的入口。

**把說法留在正文裡，段落的工作就從「說明機制」變成「判決說法」。** 一段「這句話在剛性與軸承這兩項上成立，匹配跟價格沒有直接關係」要讀者同時拿著三樣內容：原來那句話、作者對它的判決、判決底下的機制。讀者要的只有第三樣，前兩樣是作者改寫時的工作過程。正向陳述直接交付機制：「唱臂影響唱頭表現的地方有三項：有效質量與順服度的匹配決定共振頻率；剛性與軸承的精度決定唱臂本身是否跟著振動；唱頭座的設計決定能否換唱頭。」原說法說對的部分以機制的形式留在文章裡，說錯或說過頭的部分因為機制裡沒有它而不再出現，作者的判斷是不需要另外寫一句反駁（讀者是否因此判斷得出那句說法的對錯，沒有量過）。

**這一類的成因之一是素材的格式**（生成端自己的寫作習慣、把「寫成文章」讀成要回應那些說法，這兩個成因沒有排除）。 問答的格式是「有人提出一個說法、另一個人回應它」，改寫時最省力的做法是保留這個格式，把回應寫成文章。所以它集中出現在「把使用者貼來的對話或說法改寫成文章」這一步，而且每一個被貼來的說法都可能長出一段判決。跟 [fill-knowledge-gap-not-center-misconception](fill-knowledge-gap-not-center-misconception.md) 的差別在誤解從哪裡來：那張卡的「讀者會誤解」是作者想像出來的；這一類的說法實際存在，就寫在素材裡，所以作者覺得引用它是忠於來源，不覺得是在製造敘事中心。

**審查端會把它修得更完整。** 斷言支撐 frame 問斷言靠什麼成立，遇到引用的說法就追問「轉述是否忠實、成立的條件寫出了沒有」，這兩個問句預設那句說法應該留在文章裡。所以它對一段不完整的判決給出的 finding 是對的，而它建議的修法是把判決補完整：轉述得更忠實、條件寫得更全、反例列得更多。照著修的人修完之後，那一段更長、判決更細，讀者要拿著的三樣內容一樣也沒少。其他 frame 的修法也停在同一個框架裡：寫作規範 frame 把「地雷」換成「不成立的組合」，冷讀 frame 把「常聽到」換成「論壇常見」，節奏同質化 frame 把兩篇的重複拆解收成一篇。每一個 frame 問的問題（用詞、讀者處境、重複）都在說法已經在文章裡的前提下成立，沒有一個 frame 問「這句說法需不需要在文章裡」。缺陷在「說法被當成主題」這一層，finding 指向的是「判決不完整」這一層。

**說法不只佔住段落，也決定了大綱。** 素材裡每一句說法在初稿裡長成一節：「插電的設備不用管阻抗」長成〈阻抗與反電動勢〉，「只剩喇叭和空間」長成〈DAC 與擴大機的規格門檻〉，「老擴大機加 DAC」長成〈二手老擴大機〉，「剩下的靠耳朵」長成〈量測規格與聆聽偏好〉。把這幾節的判決句改寫成正向陳述之後，句子不再判決說法，各節的順序與範圍卻還是照說法排的：同一輪的題目範圍 reviewer 回報系統篇在標題之外多了五個獨立主題。所以段落層與文法層的改寫只換了寫法，缺陷在大綱這一層：文章的節由素材的說法決定，而不是由讀者要做的決定與要理解的機制決定。大綱照讀者的決定與機制組織、每一個機制寫完整之後，作者的判斷是讀者讀到那些說法時自己判斷得出哪裡對、哪裡不對，文章不需要替他強調（這一點沒有量過）。

## 反模式

- **引原話開段，再判斷它在什麼條件下成立**：「論壇上常見一種說法：……。這一節的比較是它成立的理由」「這句常聽到的話由三件事組成」。
- **用判決的詞組織段落**：「這句話在……上成立」「這個說法沒有涵蓋……」「這個說法裡的例外是……」「……不一定比較好」。
- **把素材裡的說法當段落的主詞**：段首寫「這個做法成立的理由有三項」，而「這個做法」指的是一句被引用的說法，而不是讀者會去做的那件事。
- **審查修法補完判決**：finding 說轉述不忠實時，修法是補上原說法漏掉的半句、再補一段成立條件。
- **只在段落層改寫**：判決句改成正向句，而節的順序與範圍仍然對應素材裡的一句句說法。

## 修法

修法落在大綱與內容的完整性，段落與文法的改寫在大綱定了之後才做。

1. **擬大綱時**，先寫出讀者讀完要做的決定與要理解的機制，節依這兩者排列。素材裡的說法拿來檢查清單有沒有漏：每一句說法壓縮的機制，都要落在某一節裡；說法本身不進正文，也不當成一節的題目。說法裡的條件（「現代固態擴大機」「一般的喇叭」）寫成機制成立的條件。
2. **寫每一節時**，把機制寫完整，到讀者拿自己的設備、自己的情形對得上的程度。說法說錯或說過頭的部分不引原話判決；錯得會讓讀者做錯事時的對照寫法（含讀者會原句遇到時的「反例：」一行）在 `source-to-teaching-analysis.md`〈重建之後說法放在哪裡〉。作者的推論是機制完整時，讀者讀到那句說法自己判斷得出哪裡對、哪裡不對，這一點沒有量過。
3. **偵測用 grep**：`keyword-bank.md` 字句層 bank〈素材的說法當討論對象〉的判決詞 grep 找出候選；pattern、何時跑與合規清單以那一條為準。命中之後回到大綱問兩件事：這一段所在的節，是為了讀者的哪一個決定或哪一個機制而存在；那個機制在文章裡是否寫完整，讀者是否不靠這一段也判斷得出。這一節的題目來自素材的說法時，重排大綱；機制不完整時，補機制。只把命中的句子改寫成正向句，是停在段落層。
4. **審查 finding 指向「轉述不忠實」「條件沒寫出」時**，先問這句說法需不需要在文章裡：說法本身就是文章的主題（例如一篇分析某個流行說法為什麼流行的文章）才留；說法只是素材時，照上面第 3 步回到大綱。

合規的形態與不適用的文體以同一條 bank 為準。例：引用有出處的研究結論當推導的前提（「依 Toole 在《Sound Reproduction》裡整理的量測，……」），那一句的主詞是研究發現，後面接的是機制。

## 判讀徵兆

| 徵兆                                                                 | 判讀                                                         |
| -------------------------------------------------------------------- | ------------------------------------------------------------ |
| 正文引用了素材裡的一句話，後面接「成立」「不成立」「條件是」         | 說法被留成討論對象，段落在判決它                             |
| 理解探針回報「論壇說法」「這句話」要回頭找，或某段要拆開才看得懂     | 讀者在處理說法與判決，機制被包在裡面                         |
| finding 指出轉述不忠實，修法建議是補上原說法漏掉的部分               | 修法停在判決不完整這一層，缺陷在說法被當成主題這一層         |
| 各節的題目與素材裡的說法一一對應，題目範圍審查回報標題之外有多個主題 | 大綱由素材的說法決定，改寫段落修不到                         |
| 素材是使用者貼來的對話、問答或 AI 回答                               | 生成端最容易保留「提出說法、回應說法」的格式，寫稿時先拆機制 |
| 引用的是有出處的研究發現，後面接的是機制                             | 合規，研究發現是推導的前提                                   |
