# 同一個對象在兩個集合各有一頁：從對象往外寫就會重疊，從各自集合讀者要做的判斷往回推才分得開

> **角色**：本卡是 `compositional-writing` 的支撐型原則（principle）、被 `managing-article-collections.md` 的「同一個對象在兩個集合各有一頁」段引用。
>
> **何時讀**：同一個工具、元件或概念在兩個模組或系列各有一頁、兩頁的段落大量重疊，正在考慮合併、指定唯一的家，或判斷兩頁各該寫什麼時。

## 核心原則

同一個對象在兩個集合各有一頁時，兩頁是否重疊，取決於頁面從哪一端寫起。從對象往外寫（它是什麼、怎麼裝、有哪些功能），兩頁拿到同一批材料，因為對象的事實不隨集合改變；從集合讀者要做的判斷往回推（這個對象在那個判斷裡負責哪一個環節），兩頁拿到不同的材料，因為兩個集合的讀者要判斷的事不同。以負載測試工具為例：可靠性集合的讀者在負載測試這一段要決定這一版的效能有沒有退化、能不能過 release gate；容量集合的讀者要決定目前的配置在延遲目標內處理得了多少請求、要加多少機器。同一個工具，在前一種判斷裡負責產生 regression 的證據，在後一種判斷裡負責找出受測服務的飽和點。

分段時依序問兩件事：

| 問句                                               | 答案                     | 這一段是什麼                                   | 處置                                             |
| -------------------------------------------------- | ------------------------ | ---------------------------------------------- | ------------------------------------------------ |
| 一、這一段是不是操作細節                           | 是                       | 操作細節（安裝、設定步驟、介面操作）           | 放實作文章或連到官方文件                         |
| 二、其餘的段落，原封不動放進另一頁還成立嗎         | 成立，而且是一個概念     | 對象所屬那一類做法的通用模型（open 與 closed model、施壓端飽和） | 抽成知識卡，兩頁都連卡，各自只寫它在本集合的作用 |
|                                                    | 成立，而且拆不成單一概念 | 對象層的深度內容（版本沿革、調校參數、商業版與開源版的差異） | 寫成其中一邊的深度文章（已經有深度文章的那一邊），另一頁連過去 |
|                                                    | 只在本集合成立           | 本集合的觀點                                   | 留在本頁，往下寫深                               |
|                                                    | 只在另一個集合成立       | 另一個集合的觀點（寫錯頁了）                   | 移到另一個集合的那一頁（已有同一個判斷就併進那一段） |

兩道問句分開問，因為操作細節放進另一頁也照樣成立，只問第二道的話它會被歸成知識卡。一段裡混了兩類以上（操作步驟與判斷、通用事實與它在某個集合的後果）時，先照類別拆成幾段再逐段問。抽成知識卡的段落，在兩頁都改成一句連到卡、寫出這個概念在本集合的判斷裡起什麼作用；觀點段落裡用到通用概念時，概念連到卡，順序與權重留在本頁。

第二道問句是假設性的，不論另一頁現在有沒有這一段；比對的是內容、順序與輕重，段標相同不算成立。集合規定每一頁都要寫的固定章節（取捨、排錯、定位）是兩頁差別最大的位置：照所屬集合工程師的視角寫，衡量哪些取捨、除錯時先查哪個症狀、照什麼順序查、每一項的權重都會不同。同樣看到延遲變高，可靠性的工程師先比對這一版跟基準的差距、找出退化的端點，決定擋不擋 release；容量的工程師先確認施壓端沒有先飽和，再看受測服務哪一項資源先到頂。這幾節是讀者最需要、也最沒辦法從官方文件拿到的內容，兩頁都寫，各自寫深；兩頁互相連結，連結文字寫出另一頁的觀點。

重疊被看成「兩邊在維護同一份東西」時，直覺的處置是合併或指定唯一的家。照兩頁從對象往外寫的現狀合併，合併後的那一頁仍然從對象往外寫，留下來的是通用材料，另一個集合的觀點段落在那一頁沒有位置（這一點是推論，個案裡沒有實際合併）。重疊的成因在頁面從對象往外寫，處置也落在寫法上。

## 個案

一個後端教材的可靠性模組與效能容量模組各有一組負載測試工具頁，同一個工具的兩頁標題一字不差。兩個獨立的分析者讀同一批頁面給出相反的判定（依兩個模組的規劃寫的「需與對方界定角度分工」判兩邊保留，依段落重疊判合併），接著的決策分析列出的選項全是合併與搬移。回頭逐段對照，重疊段落的主體是工具本身的事實，帶到模組觀點的只有連回本模組章節的一兩句；可靠性那一頁偏工具的使用手冊，容量那一頁偏工具的選型簡介，而可靠性關心的「接 CI 擋 release」在容量那一頁寫得比較完整。其中一個工具兩邊各有一篇深度文章，已經照觀點分開；其餘工具只有 overview。判斷標準只在這一組工具頁上用過，沒有在別的配對上量過。

## 反模式

- **把重疊當成住址問題**：問「這份內容該放哪一邊」，答案只能在兩頁之間選一頁或搬到第三處，問題本身已經假設兩頁該寫同一份內容。
- **規劃寫了「界定角度分工」而沒有判斷標準**：「角度」沒有落到任何一段可以檢查的位置，頁面照樣重疊。
- **依哪一頁比較完整決定誰留下**：完整度量的是通用材料寫得多不多，跟哪一頁的觀點比較有內容無關。
- **同名的標題**：讀者在搜尋結果與連結文字上只看得到標題與摘要，分不出兩頁，作者也少了一個逼自己說出觀點的位置。

## 修法

1. 兩頁並排，逐段依序問上面兩道問句，把每一段歸成操作細節、知識卡、本集合的觀點三類。
2. 歸成知識卡的段落，先查有沒有對應的卡，沒有就建卡，一段裡有幾個概念就拆成幾張，兩頁改成連卡。
3. 歸成本集合觀點的段落，從本集合讀者要做的判斷往下寫深。
4. 標題與摘要寫出這一頁的觀點。
5. 分類之後某一頁歸成本集合觀點的段落是 0 段時，那個集合的章節可以改成直接連卡；頁面的去留另外決定。

## 判讀徵兆

| 徵兆                                                         | 判讀                                                       |
| ------------------------------------------------------------ | ---------------------------------------------------------- |
| 兩個集合的同名頁面，段標大半相同或內容可以互換               | 兩頁都從對象往外寫，重疊的段落是知識卡或操作細節的候選     |
| 一個集合關心的判斷在另一個集合的頁面寫得比較完整             | 那一段沒有照觀點分配，搬回所屬的集合或抽成卡               |
| 分析時列出的選項全是合併、搬移、指定唯一的家                 | 選項建立在「兩頁該寫同一份內容」的前提上，先逐段分類再談搬 |
| 同一個對象的深度文章已經分得開，overview 卻重疊              | 重疊在 overview 的寫法，不在資料夾結構                     |
| 分類之後某一頁的觀點段落是 0 段                              | 那個集合的章節可以直接連卡；頁面的去留另外決定             |
