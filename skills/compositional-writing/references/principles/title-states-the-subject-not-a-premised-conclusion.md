# 教學文章的標題與段標寫主旨，結論留在正文裡推導走完的位置

> **角色**：本卡是 `compositional-writing` 的支撐型原則（principle）、被 SKILL.md 的敘事姿態段與字句層 keyword bank 引用。
>
> **何時讀**：替教學文章定標題或段標時；要拿另一篇的標題當連結文字時；審查時撞到「X 決定 Y」「X 不是 Y，是 Z」形式的標題或段標時。

## 規則

教學文章的標題是這一篇的主旨：講的對象是什麼、交付哪一種內容（一套機制的說明、幾種做法的取捨、一種判讀方法、一段流程）。段標是這一節的主旨。**標題與段標不寫成結論句**——「X 決定 Y」「X 不是 Y，是 Z」「X 才是 Y」這類斷言留在正文裡推導走完的位置。

## 為什麼結論句不進標題

讀者在乎一句結論的理由是由正文建立的，而標題是他還沒讀正文時看到的那一行。「快取標頭決定轉址收不收得回來」要成立，讀者得先知道快取會保存轉址回應、保存多久由標頭指定、保存期間用戶端不再詢問伺服器；知道這些之後「收不回來」才是一個問題。標題把答案寫出來，而問題要到正文中段才出現。

標題被別篇拿去當連結文字時，前提離得更遠：那一篇的讀者連本篇的主題都還不知道，他讀到的是一句關於陌生名詞的斷言。

**讀得懂的結論句也改寫成主旨**，理由有兩個。寫標題的人已經讀完全文，每一個前提都在他手上，他分不出哪些前提是讀者進來之前就有的；「標題裡有沒有謂語在下斷言」則是他看得出來的，所以規則定在看得出來的那條線上。其次，讀得懂的結論句沒有多交付主旨沒交付的東西——「ON 與 WHERE：連接條件與篩選條件各自的職責」與「ON 描述關係、WHERE 篩選結果」說出同樣的對象與內容種類，而結論在正文第一節就會出現。

## 寫法

1. **先寫主旨句**：這一篇講什麼對象的什麼。對象用領域裡通用的名字，內容種類寫出來（機制、選型、取捨、流程、判讀）。
2. **冒號之後寫這一篇涵蓋的成員**，用讀者認得的詞。成員寫得出來時不寫計數。
3. **想寫進標題的那句結論放回正文裡推導走完的位置**。確認正文那個位置真的有這一句；標題原本是它唯一的住址時，改標題等於刪掉結論。
4. **改完之後核對摘要欄位**（description 或同等的欄位）：標題改成主旨之後兩者可能重疊，遮住摘要只看標題猜得出全部內容時，重寫摘要去補標題說不完的範圍。
5. **改名之後核對引用點**：別處以完整標題當連結文字、以節名引用段標、或連到段標錨點的位置，要同一次改。

| 改前                                                             | 改後                                                   |
| ---------------------------------------------------------------- | ------------------------------------------------------ |
| 轉址回應的語意與撤回性：狀態碼管解讀，快取標頭管收不收得回來     | HTTP 轉址回應：狀態碼的語意與快取標頭指定的保存行為    |
| 某服務的實作：轉址路徑的可用性與可撤回性主導快取與點擊紀錄的取捨 | 某服務的實作：短碼生成、對照表儲存、轉址快取與點擊紀錄 |
| （段標）快取標頭決定瀏覽器還會不會回來，也就決定這一層的撤回延遲 | （段標）轉址回應的快取標頭與瀏覽器保存回應的時間       |

## 檢查方法：把標題當成別篇裡的一個連結文字讀一次

檢查的位置固定在讀者條件最差的那一個：他在另一篇文章裡讀到這個標題，沒讀過本篇。逐項問：

1. **謂語**：標題有沒有對某件事下斷言（決定、主導、取決於、不是、才是、等於、只是，或任何「主詞＋動詞＋受詞」的完整句）。有就改寫成主旨。
2. **名詞**：標題裡每一個名詞，這位讀者知不知道它指什麼。本篇正文才定義的詞換成他認得的詞。
3. **主旨**：只憑這一行，讀者說不說得出這一篇講的對象是什麼、讀完會得到哪一種內容。

段標用同一組問句，而讀者手上多了本篇前文：前文已經定義過的名詞可以用，謂語那一題不放寬。

「謂語」那一題寫的人自己判得出來。「名詞」與「主旨」兩題他判不準，因為他答的時候用的是讀完全文之後的知識；這兩題可靠的做法是把一批標題單獨交給沒讀過正文的讀者（低階模型的讀者探針合用），只給標題清單，問每一條：這一篇會講什麼、哪個詞不知道指什麼。

## 合規邊界

- **「對象＋動詞」而不下斷言的寫法是主旨**：「從入口程式看應用啟動流程」「用完整分析框架重新評估一個案例」描述的是這一篇做的事。
- **只有「主旨」那一題不通過的標題與段標同樣要改**：過短的標籤（「成本模型」「判讀方式」「往下讀」）與帶指示詞的名詞子句（「為什麼只收這幾本」「這個主題接到哪裡」）沒有下斷言，而不讀內文的人不知道判讀的是什麼、「這幾本」是哪幾本。處置是把指示詞與泛用標籤換成它指的東西，同一個標籤在多篇重複出現時每一篇各自寫出自己的對象；內容集合慣用的固定收尾段名（「下一步路由」「判讀訊號」「往下讀」）不是例外，寫成「內容種類：那一節實際連到或判讀的對象」。**寫不出有意義主旨的段標就移除**，那一節併進相鄰的節。標題為了寫出成員而變長可以接受。標籤被多處引用時的成本見 [compressed-label-cost-multiplies-with-citations](compressed-label-cost-multiplies-with-citations.md)。
- **適用範圍是教學文章**。歸納問題與解法的記錄（讀者帶著一個已經遇到的問題來）是否比照，本卡沒有材料判斷，由各內容集合自行裁定。
- **問句標題與懸念段標**由 [write-for-readers-not-audiences](write-for-readers-not-audiences.md) 處理；兩張卡合起來是：標題是直述句，而直述的內容是主旨。

## 成因與偵測

規範寫成「標題承載結論」時，生成端會取一篇文章裡最像結論的那一句，也就是推導最下游、前提最多的那一句。一次量測裡，那條規範生效之後建立的教學文章，標題命中謂語關鍵詞的比例是之前的將近五倍，含兩個子句以上的段標是之前的十幾倍。多輪審查對它不產生 finding：寫的人與審的人都讀過全文，結論句對他們是完整而準確的摘要，而規範這一側它是合規的。

關鍵詞只用來縮小要讀的範圍，「管理」「決策」這類名詞會混進來，命中後逐條判讀：

```bash
# 標題裡的謂語候選（摘要欄位的鍵名依專案調整）
rg -n '^title:.*(決定|主導|取決|不是|而是|才|就是|等於|只是|只有|由誰)' <內容根目錄>
# 兩個子句以上的段標
rg -n '^#{2,3} .*[，,]' <內容根目錄>
```
