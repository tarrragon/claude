# 名詞要求的「誰的、什麼的」也是槽位，論斷句與段標的省略藏在名詞裡

> **角色**：本卡是 `compositional-writing` 的支撐型原則（principle），被 SKILL.md〈每一句先填槽位再成句〉與字句層 keyword bank 的「名詞缺所屬」類別引用。
>
> **何時讀**：寫段標、段落首句與末句、總結段、過渡句時；或者審查時遇到主詞謂語都在、讀起來通順，而讀者說不出「什麼的」「誰的」的句子。

## 結論

「錯的來源不只一種，而輸出都不帶訊號」主詞與謂語都在，語法完整，照操作句的四個槽位（動作者、動詞、受詞、結果）查下來全部通過。它缺的成分在名詞裡：「來源」是什麼的來源、「輸出」是誰的輸出、「訊號」是什麼的訊號；「錯」是形容詞被當成名詞用，連什麼錯了都沒說。

**有一批名詞本身要求一個補足語**——來源、輸出、結果、原因、代價、差別、位置、範圍、邊界、訊號、層、線、情形。它們的所屬是句子的一格，跟受詞一樣要寫出來：寫在這一句，或寫在緊接的前一句。形容詞與動詞不直接當名詞用（「看不出錯」寫成「看不出答案錯了」）。

判斷問句：**這個名詞是誰的、什麼的，能不能從這一句或前一句逐字指出來。** 判定者不代填——從全文推得出來不算。

## 為什麼操作句的規格擋不住

槽位規格原先寫的範圍是「描述操作的句子」。論斷句、總結句、段標、過渡句沒有動作者，所以規則不觸發；就算觸發，主詞與謂語都在，四格全部通過。缺陷的定義是「讀者無法從這一句還原完整的命題」，而規則被寫成「操作句要填四格」——觸發條件比缺陷窄，於是規則在它自己沒寫到的句型上從不生效。

這一類集中在作者做抽象與收束的位置：段標、段落的第一句與最後一句、總結段、過渡句。作者寫到這些位置時手上有整篇的內容，「輸出」「那條線」對他都是完整的指涉。

同一個成因的另一個形態是**只寫在目錄頁、讀者看不到的框架詞**：「結果集由什麼決定，到這一篇有了完整的答案」裡的問題本身只存在於作者的編排底稿裡。這一半有字串可比對，腳本掃得到：取目錄頁的段標片語，找文章正文裡出現、而文章自己沒有定義的那些。

## 偵測：量過的三種做法

一組二十句的校準集（已知違規與已知合規各半，打亂、不標示），每種做法量一次：

- **關係名詞清單（字詞層）**：命中已知違規的一半、已知合規的七成。合規句的所屬常寫在前一句（「連接後的關係多了一列。原因是配對是逐列做的」），清單分不出來。**清單只能告訴判讀者該看哪裡。**
- **要低階模型把句子改寫完整、缺的成分標成【？】**：沒有鑑別力。違規句平均標出 2.5 個缺項、合規句 2.7 個，二十句沒有一句被任何一份判為無缺項——只給兩句話時，它把「共用資料的範圍」這類本來不必寫出來的成分也全標成缺項。
- **要低階模型從兩句裡逐字引出每個名詞的所屬、引不出就寫引不出**：三份裡至少兩份判「有引不出」的，名詞缺所屬這一類的違規抓到八之七，操作句那一類三之一，合規句被標出九之三（多是邊界情形）。它是三者裡唯一有鑑別力的，而它有效的理由是**任務從生成換成抽取**：列出缺什麼可以無限展開，指出一段逐字存在的文字要嘛做得到、要嘛做不到。

校準集裡還有一句標成合規的，是主 session 剛改寫的「回來的那批列本身也看不出錯」——探針判它引不出「錯」的所屬，判對了。改寫的人剛修完這一類，下一句就寫出同一類，這是生成端規格必須先於偵測的理由。

## 修法

- **寫的時候**：寫到段標、段落首末句、總結段、過渡句，逐句問判斷問句；把所屬寫進句子，或讓前一句先交代它。
- **審的時候**：對這些位置派逐字引出所屬的探針（每篇三份、指令逐字相同），至少兩份判「引不出」的列為候選，由主 session 逐條判讀。操作句那一類仍歸四槽位的冷讀與「這個動作是誰做的」探針欄。
- **目錄頁詞彙外漏**：用腳本比對目錄頁段標片語與文章正文。

## 譬喻被判定之後，先數它在集合裡出現幾次

被標出的譬喻常常是整個集合的用詞，不只出現在那一句：一次全分類掃描裡，「手上」指「這一步的中間結果」，出現三十多次，連段標與摘要都用它。只改被標出的那一句，同一個概念就有了兩個名字。判定一個譬喻要換之後，先在整個集合裡數它出現幾次、分出指同一個概念的那些，整批換成同一個領域用詞；指人的字面用法（「提問的人手上」）保留。

## 論述基礎與限制

校準集二十句，正例取自一篇教材改寫前的段標與收尾段、以及另一篇文章裡已判定的操作句；每種探針各三份。樣本小，量到的是這幾種做法在這批句子上的相對鑑別力，不是漏報率；正例與反例的標籤由主 session 判定，至少錯了一句（「回來的那批列本身也看不出錯」那一句）。

## 每一句先填槽位再成句（生成端規格）全文（自 SKILL.md 移入）

> SKILL.md 1.49.0 的〈每一句先填槽位再成句（生成端規格）〉原文，逐字保留，1.50.0 因入口檔 token 預算外移；SKILL.md 只留四個槽位、兩格補充與路由。

上一節定的是整份稿件的定位；這一節定的是每一句的規格，寫的當下就用，不等審查。

描述一個操作的句子由四個槽位組成——**動作者**（人、腳本、工具、系統元件）、**動詞**（這個領域裡的操作：執行、轉換、比對、寫入）、**受詞**（動詞在這個領域裡能作用的對象）、**結果**（輸出或狀態變成什麼）。每個槽位填的都是這個領域裡實際存在的東西；量詞計數的是領域裡的單位。

寫操作句的順序是先列槽位再成句：

| 槽位       | 遠端沒有執行任何指令 | 遠端一個字都沒有執行 |
| ---------- | -------------------- | -------------------- |
| 動作者     | 遠端                 | 遠端                 |
| 動詞       | 執行                 | 執行                 |
| 受詞       | 指令                 | 字                   |
| 量詞的單位 | 指令（零個）         | 字（零個）           |

右邊那一句在中文語法上完整、讀起來通順，而「執行」在這個領域裡作用的對象是指令、程式、命令——**沒有任何系統逐字執行東西**。「一個 X 都沒有 Y」在口語裡成立的前提是 X 是 Y 的計數單位（「一個字都沒說」成立，字是說話的單位），搬到「執行」上前提不成立，句子照樣通順，因為中文語法不檢查受詞跟動詞在領域裡合不合。讀者要做四步還原（認出慣用語 → 把字對回指令 → 把一個都沒有對回零個 → 重組），而左邊那一句直接就是終點。

判斷標準是**受詞是不是動詞在這個領域裡能作用的對象**：寫的當下逐句可判、不需要上下文。量詞槽位另有一條：**範圍在句內具名**——「任何指令」具名、單位在領域內，過；「一個字」具名、單位在領域外，不過；「徵兆完全一樣」範圍沒具名，不過，而且那篇文章的下一節給了分辨方法，「完全」跟內容矛盾。範圍寫在同一句或緊接的前一子句都算具名。**判定者不代填槽位**：單位要寫在句子裡，判定者從上下文推得出來不算——一次實測判定者替「完全一樣」補了「逐項相同的徵兆」這個單位然後放行，那正是規格要擋讀者做的動作換成審查者在做。判斷標準是是非題「單位有沒有寫在句子裡」，寫成「推不推得出單位」它永遠通過。先前的「拿掉強調事實變不變」要有人先拿掉才知道，是後驗的，本節的判斷標準取代它。同一個標準管三種變體：受詞填了領域外的名詞（「一個字都沒有執行」）、動作者填了指令片段（「`tr -d '\r'` 處理的是行尾」——被處理的是輸出裡的位元組，行尾轉換是處理的結果，「行尾」填在受詞槽位是錯的）、位置槽位填了指示詞（「字串比對在這裡會失敗」——「這裡」不是領域裡的位置）。

這一節放在生成入口、與字句層 bank 分開，理由是 bank 是反模式清單、給審查者掃已寫好的稿，而寫的人跟審的人是同一個模型時，審查端對這一類的偵測率是零——同一個模型覺得自然的句子，它寫出來、它審過去。生成器需要的是正向規格：寫每一句操作描述之前先填四個槽位，槽位填不出領域內的名詞就不成句。慣用語進不來，因為慣用語的受詞幾乎都在領域外。

**論斷句、總結句、段標與過渡句同樣要填槽位，而它們的缺口多半在名詞裡。** 這一節原先只寫操作句，而同一種省略在不描述操作的句子裡更常見，也更難看出來：「錯的來源不只一種，而輸出都不帶訊號」主詞與謂語都在、語法完整，四個槽位查下來全部通過，缺的是名詞自己要求的補足語——來源是什麼的來源、輸出是誰的輸出、訊號是什麼的訊號；「錯」是形容詞被當成名詞用，連什麼錯了都沒說。所以槽位多一格：**本身要求「誰的、什麼的、哪兩者之間的」的名詞**（來源、輸出、結果、原因、代價、差別、位置、範圍、邊界、訊號、層、線、情形）要把它的所屬寫在這一句或緊接的前一句裡；形容詞與動詞不直接當名詞用（「看不出錯」寫成「看不出答案錯了」）。判斷問句是**這個名詞是誰的、什麼的，能不能從這一句或前一句逐字指出來**，判定者同樣不代填。改寫：「錯的來源不只一種，而輸出都不帶訊號」→「答案錯掉的成因不只一種，而引擎一種都不會報錯」。

這一類集中在作者做抽象與收束的位置——段標、段落的第一句與最後一句、總結段、過渡句——寫到這些位置時逐句問一次。**只寫在目錄頁、讀者看不到的框架詞也是同一個成因**：「結果集由什麼決定，到這一篇有了完整的答案」的問題本身只存在於作者的編排底稿裡。審查端的偵測與它的量測在 [noun-without-its-owner-passes-the-slot-check](noun-without-its-owner-passes-the-slot-check.md)。

**動作者那一格要問主詞能不能做這個動作，槽位另加時機與觸發原因。** 「一個檔案被幾個不同的需求修改過，可以從版本歷史數出來，這個數字決定哪些檔案值得回頭讀」逐格查下來每一格都填了名詞，而讀者說不出數的人是誰、他在工作流程的哪一步去數、為什麼需要這個數字。三種形態讓動作者缺席而格子看起來是滿的：**條件句寫對象的狀態、後面接沒有主詞的祈使**（「一個檔案同時對上兩列時，依……來分」——誰分？）、**被動句或「由……」只交代次要動作的動作者**（「由工具改寫……處置是從統計排除」——誰排除？）、**指標當主詞**（「這個數字決定」「commit 數會把……」——數字不做決定，讀排行的人才做）。寫描述做法的句子、條件句與段落首句時，順序是**誰 → 在什麼時機（讀者工作流程裡的一步，不是對象的狀態）→ 做了什麼 → 為什麼會觸發**：「工程師做 code review、查看檔案的修改紀錄時，從版本歷史發現它被幾個不同的需求修改過」。判斷問句是**這一句描述的事，誰做、在工作流程的哪一步做、為什麼會發生，能不能從這一句、前一句或所在段落的第一句逐字指出來**（同段的祈使句沿用段落第一句寫出的動作者）；動作者用文章已有的角色（讀排行的人、歸類的人、解衝突的人），指標與清單只當受詞或依據。**審查修正是這一類最常見的產地**：修正的人讀過審查意見，那條意見交代的情形他已經知道，於是只寫答案、把問題的主語放在句首——把審查意見改進稿件時，先把它交代的情形寫進句子再寫處置。詳見 [topic-first-sentence-drops-actor-and-timing](topic-first-sentence-drops-actor-and-timing.md)。

**組織全篇的框架詞也要過槽位。** 「X 回答的問題是：……」「這一層問的是……」把系統元件寫成應答的一方：健康檢查在領域裡做的是定期執行一條指令、依結果標記狀態，沒有回答任何提問，動詞與受詞兩格填的都是譬喻。寫的當下把「回答」換成元件實際做的動作（執行、量測、比對、送出、標記），把「問題」換成它實際指的那一種——問句、故障、要處理的事項、主題或需求，判斷問句是「這個『問題』翻成英文要從 question、problem、issue、topic、requirement 裡選哪一個」。框架詞還會往下游造句型：內容被當成問句引出來，就寫成正反問句；總覽句沿用「由 Z 接手」的骨架而手上還沒有具名的 Z，就寫成同義反覆的排比。三者各自的判讀在 [question-answer-frame-blurs-problem-issue-request](question-answer-frame-blurs-problem-issue-request.md)、[a-not-a-question-as-noun-clause](a-not-a-question-as-noun-clause.md) 與 [parallel-clause-filled-with-the-topics-definition](parallel-clause-filled-with-the-topics-definition.md)。

描述一個工具或指令要寫成好幾段時，段與段之間的順序跟著槽位走：讀者會看到什麼 → 這個工具做什麼 → 為什麼需要它（機制，系統元件指名）→ 不做的具體後果 → 副作用；這是段與段之間的順序，每一段的第一句仍是那一段的主題句。動作者槽位填對之後段落順序通常自動修正——操作者視角的順序就是讀者的問題序。詳見 [command-fragment-as-subject-hides-the-actor](command-fragment-as-subject-hides-the-actor.md) 與 [spoken-emphasis-is-silent-in-text](spoken-emphasis-is-silent-in-text.md)。
