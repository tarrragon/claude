# 壓縮標籤省下的字數是一次，展開成本乘以引用點數

> **角色**：本卡是 `compositional-writing` 的支撐型原則（principle）、被 SKILL.md 的「索引建立」段引用。
>
> **何時讀**：替表格列名、欄位標籤、章節標題或任何會被別處逐字引用的名字取短名時。

## 核心原則

替一個概念取短名時，省下的字數付一次，還原限定語的成本乘以讀者數與引用點數。兩側的量級不對稱，所以標籤越像術語、被引用得越廣，短名的收益越小而代價越大。

[語句的自足義務由消費單位決定](sentence-self-sufficiency-by-consumption-unit.md) 把檢索鍵位（title、description、表格鍵欄、卡名、錨點）的義務定為識別充足——讀者能指認它索引的是哪個命題——並記下跟精簡規範衝突時精簡優先。本卡限定那條優先序：**精簡優先的前提是這個鍵只有一個消費點**。鍵一旦被別處逐字引用，它同時是錨點，而錨點有兩個性質讓天平倒過來：

- **引用點只交付那個字串。** 引用的形式是逐字比對，加字即斷開比對；每一個引用點因此只給得出短名本身，補完的責任全部落回讀者。
- **修復成本同樣乘以引用點數。** 既有標籤要改時，它與全部引用點必須同一次改，否則錨點斷開；而那個乘數只會隨時間變大。

## 判準

識別充足的可執行判準是兩個問句：

1. 這個標籤裡的每個名詞，讀者知道是哪一個嗎。
2. 每個動詞，讀者知道主詞是誰嗎。

兩題都答得出來才算識別充足。

**例外兩種**：表頭語境下已經自足的通用欄位標籤（「觸發」「反應」在該表結構下無歧義），以及領域內有正式定義而讀者一跳查得到的術語。

## 為什麼既有的檢查走不到它

壓縮標籤讀起來是完整的詞，於是每一條以「殘片」為入口的檢查都放行。

[中文壓縮術語要保留完整名詞頭](compressed-chinese-terms-need-head-noun.md) 查的是名詞頭被砍到只剩形容詞或單字，那種形態自己就現形。本卡的形態名詞頭健在、語法完整、放進表格第一欄成立、拿去 grep 也命中，那張卡的四道檢查全數通過；被砍掉的是限定語，而限定語的缺席在語法上沒有痕跡。

一致性掃描同樣無效，理由更基本：**周圍都是對的**。壓縮是零星發生的，同一份文件的其他位置多半寫了完整形，所以掃描找不到可比對的異常，逐句自審讀起來也通順。

根因在時序。壓縮發生在作者剛把一件事想清楚的當下，限定語在腦中太顯然、寫出來像廢話——而像廢話正是讀者需要的形態，他沒有經歷那次想清楚的過程。審查抓不到的原因相同：熟悉該文件的審查者持有同一份脈絡。已知的兩個實例都由讀者問「這個標籤是什麼意思」暴露，而回答那個問題所花的查詢步數本身就是量測值。

## 偵測與修法

偵測的入口是引用點數，而引用點數可以直接算：

```bash
rg -F -l -- "<標籤字串>" <內容根目錄>
```

命中兩個檔以上的標籤就是錨點，錨點逐個跑那兩個判準問句。掃描的對象是定義處的標籤清單，**不是全文的段標**——用段標當代理會量到模板重複而不是引用（一次實測：段標出現次數的前幾名全部是 `YAML`、`Problem` 這類模板欄位）。

修法分兩種情形：

- **標籤還沒有被引用**：直接把限定語補回標籤，成本是一次。
- **標籤已經是錨點**：改動與全部引用點同一次進行，改完回頭跑一次同一條掃描確認沒有殘留舊字串。

兩種情形共用一條：限定語補回標籤本身，不補在鄰欄——讀者先讀標籤才決定要不要讀那一列，補在鄰欄的限定語落在他已經跳過的位置。

## 跟其他原則的關係

- [引用錨點用語意標題、不用位置編號](reference-by-semantic-title-not-number.md)：錨點寫法家族的第一員。那裡的錨點是結構排列的 derivation，本卡的錨點是完整概念的壓縮；共同的失效是字面完好而語意 silent 指錯。
- [集合命名用角色、不內嵌數量](name-collections-by-role-not-count.md)：家族的第二員，名字裡內嵌成員數。三員的共同結構是把只在作者側成立的前提寫進了會被複製的標識符。
- [軸名取了次好的代理變數](axis-named-by-proxy-not-mechanism.md)：相鄰而不同。那裡的名字選了較弱的代理、機制寫在括號裡；本卡的名字選對了機制，砍掉的是限定語。兩者共用同一個對讀者的傷害——讀者只拿得到名字，作者讀名字時腦中補的是完整版。
- [語句的自足義務由消費單位決定](sentence-self-sufficiency-by-consumption-unit.md)：母卡。它給義務的名字（識別充足），本卡給那個義務可執行的判準，並限定它的精簡優先序。

## 判讀徵兆

| 訊號                             | 該做的事                                                             |
| -------------------------------- | -------------------------------------------------------------------- |
| 有人問「這個標籤是什麼意思」     | 回答所花的查詢步數就是量測值；把限定語補進標籤，讓下一個讀者直接讀得懂 |
| 某個標籤在兩個以上的檔案裡逐字出現 | 它是錨點，跑兩個判準問句                                             |
| 標籤的限定語寫在鄰欄或括號裡     | 讀者先讀標籤才決定要不要讀鄰欄，把限定語搬進標籤本身                 |
| 同一組名字有長短兩版             | 短版住在哪個消費位；住在檢查清單或路由表要優先修                     |
| 剛把一件事想清楚，正在替它取名   | 限定語此刻讀起來像廢話，這是壓縮的觸發時點；判準問句在這裡跑最便宜   |

**核心**：短名的收益結算一次，展開的代價由每一個讀者、每一個引用點各付一遍。
