# 教學與檢討內容寫給帶問題來的讀者、不是要被吸引的聽眾

> **角色**：本卡是 `compositional-writing` 的支撐型原則（principle）、被 SKILL.md 原則三（意圖顯性與層級貼合）+ 字句層 keyword bank（敘事姿態 grep）引用。
>
> **何時讀**：為教學文章、檢討報告、原則卡決定標題形式與敘事視角時；或審查時撞到問句標題、懸念段標、第一人稱事件敘事、要判斷該不該改時。

---

## 論述基礎與限制

本卡從一篇檢討文章的事故抽出：標題是問句、段標帶懸念、全文以第一人稱事件時間線組織（第一版被退、第二版還是被退、追問之後才想清楚）、核心判斷標準壓在全文後半。該篇與同批內容經過多輪 reviewer audit、敘事姿態問題零 finding、由文體異源的讀者指出。

限制兩項：**單一案例**（一篇文章、一種文體背景——LLM 生成的教學敘事）；**受眾狀態的斷言沒有量測**（「讀者自帶問題來」從內容的抵達路徑推導、沒有讀者行為資料佐證）。

---

## 核心原則

**演講與教學文章面對的受眾狀態不同、姿態因此不同。** 演講面對注意力隨時會流失的聽眾、hook / 懸念 / 個人故事是維持注意力的合法工具。教學與檢討內容的讀者由搜尋或路由帶來、自帶問題與動機、他要的是判斷標準與脈絡——被扣住的答案對他是額外成本。把演講技巧搬進教學內容、代價全部落在資訊結構上。

### 形態一：懸念型修辭

問句標題、懸念段標、三幕劇遞進（第一次失敗 → 第二次失敗 → 轉折 → 頓悟）。共同點是**把結論扣住、逼讀者陪跑完整個過程**：

- 標題是檢索錨、錨要承載結論。問句標題把一篇文章唯一保證被讀到的 surface 用來提問。
- 懸念弧把核心判斷標準壓到文末、違反「核心原則先行」——跳讀的讀者先撞到案例、最後才拿到定義。

判別線是**位置**：操作型自問句（判斷標準的執行步驟、如「把型別名稱唸出來、還剩什麼資訊」）合規、它是讀者要執行的動作；出現在標題 / 段標 / 結論位、答案被扣在後文的問句是懸念型、改直述。

**修懸念的方向是壓平敘事、不是搬運結論。** 把判斷標準抽成開頭一段直接給、推導擺後面，讀者拿到的是一段沒有支撐的話、只能硬記——概念要由讀者沿著推導自己長出來、不是被交付。灌輸與懸念是同一個缺陷的兩個方向：都讓結論與推導脫節。分工是標題承載結論（檢索錨）、開頭承載情境定位（讓讀者判斷自己在不在射程內）、判斷標準在推導走完的位置浮現。文首的「觸發場景 / 整理目的 / 本文邊界」欄位組同理——它把各段結論先摘出來放在推導之前、是灌輸的欄位化形態；需要交代事件來源時一句話就夠。

### 形態二：第一人稱事件敘事

檢討內容以「我做了、我被退、我才想清楚」的個人時間線組織。兩層問題：可重用的判斷被包在一次性的個人經歷裡、讀者要自己做一次抽象才能套用；「某人說了什麼、我當下怎麼想」把判斷的成立條件藏進對話重現、條件本身沒有被陳述。

修法是**把事件單位換成條件單位**：「reviewer 問了 X」改成「若對這個做法問 X 而答不出來、就該重新檢討」。脈絡照樣保留（做錯了什麼、為什麼錯、為什麼糾正）、載體從個人時間線換成客觀條件、人物以角色出現、順序以推導組織。內容來自實際事件這件事、開頭一句話交代就夠。

## 為什麼多輪審查抓不到

三層、由深到淺：

1. **規範缺位**：「檢討用客觀視角」「標題是直述句」不存在於任何規範時、compliance reviewer 產生不了 finding——零 finding 與「沒有問題」是同一個訊號、審查報告不會標示自己沒看什麼。
2. **frame 射程**：字句層 keyword bank 是現象枚舉、問句標題 / 懸念弧 / 第一人稱不在枚舉內；persona register 檢查掛在批次審查的讀者旅程 frame 下、單篇檢討通常不進那條流程。
3. **同源文風預設**：問句標題勾興趣、三幕劇遞進是生成端高頻預設文風、同源 reviewer 共享「故事帶入是好教學」的直覺。這層與 register 同源盲區同構、異源冷讀是殘餘的防線。

---

## 修法：防線主力在生產側

敘事姿態是寫的當下決定的文風預設、靠審查撈是逆風。把規則寫進生產側規範與模板、生成時就不產生；審查側的 grep 是補位：

```bash
rg "^title:.*[？?]"                        # 問句標題（frontmatter）
rg "^#{2,} .*[？?]"                        # 問句段標
rg "才想清楚|還是被退|我到底|我於是"       # 敘事轉折詞
```

命中是候選不是判決：操作型自問句、「」內引用、以敘事為目標的內容合規。第一人稱密度是輔助訊號——檢討類文章的「我」密度顯著高於同類其他篇時逐處判定。

內容模板若寫成「問題情境 → 範例 → 解法」、「問題情境」會被最省力地填成個人事件劇；模板要明定情境的單位是條件（什麼樣的程式、什麼操作會遇到）、「這來自實際事件」的宣告開頭一句話帶過——展開成「觸發場景 / 整理目的 / 本文邊界」欄位組是灌輸的欄位化形態。

## 判讀徵兆

| 徵兆                                          | 該做的行動                                        |
| --------------------------------------------- | ------------------------------------------------- |
| 標題或段標以問號結尾                          | 把答案寫進標題、問句降到正文當操作步驟            |
| 核心判斷標準出現在全文後半、前半是遞進的失敗敘事  | 敘事壓平成條件推導、判斷標準在推導走完的位置浮現      |
| 開頭有一段未經推導的結論摘要或結論欄位組      | 抽掉、開頭改承載情境定位、結論交給標題與推導      |
| 檢討文章的「我」密度顯著高於同類其他篇        | 逐處判定：事件來源開頭一句話帶過、正文改條件視角  |
| 正文重現「某人說了什麼、我當下怎麼想」的場景  | 抽出那句話背後的條件、改寫成「若 X 則該重新檢討」 |
| 審查多輪零 finding 但異源讀者一眼指出語氣問題 | 先查該維度在不在規範與 frame 射程內、缺位先立規範 |

## 邊界

- **以敘事為目標的文體**：演講稿、簡報、隨筆、故事性寫作——懸念與第一人稱在那裡是設計、本卡不適用。
- **一句話的事件來源交代**：「這來自一次實際的兩輪退件」這類開頭一句話合規、它宣告內容來源、正文才是判斷標準的載體；展開成多欄位的結論摘要組就越界了。
- **操作型自問句**：判斷標準的執行步驟寫成問句合規、答案由讀者自己的材料產生、沒有被扣住的結論。

對應的 blog report 卡 slug 是 `write-for-readers-not-audiences`。
