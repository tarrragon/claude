# Content Pressure Resolves By Expansion Not Compression

> **角色**：本卡是 `compositional-writing` 的支撐型原則（principle）、被 [SKILL.md 原則一（Atomization）](../../SKILL.md)的內容壓力段與 [writing-articles](../writing-articles.md) 的自檢清單引用。
>
> **何時讀**：寫作時判斷標準裝不進表格格、概念裝不進標題、範例讓段落過長、想裁內容遷就容器時；或審查時撞到「像簡報的文章」時。

## 核心命題

教學文章的內容超出容器的自然大小時、合法的出口都在結構層、壓縮內容遷就容器在這些出口之外：

| 出口         | 做法                                                                   | 適用條件                                                                                                                                                                                       |
| ------------ | ---------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 就地展開     | 表格下方加延伸段、判斷標準在正文攤開；標題只承載結論、推導由正文交付       | 內容是本篇專屬、其他文章用不到                                                                                                                                                                 |
| 外部化成卡片 | 概念拆成知識卡、範例寫進卡片、文章引用卡片承接論證                     | 概念會被多篇引用、或概念值得擁有獨立的討論空間；前提是內容集合已有可被引用的卡片層                                                                                                             |
| 換成連結     | 刪掉格內的壓縮重述、格子改放指向既有落點的連結、正文只留本篇專屬的判讀 | 概念已經有卡或有專章承載、而格內那句是它的 gloss——外部化的既完成版本。**限 gloss**：本篇的程序要逐項消耗的列舉（要填的欄位、要對照的類別、要驗的項目）不適用，那份列舉留在本篇、只有定義留在卡 |

壓縮內容遷就容器不在出口之列：判斷標準裁成殘語、範例被砍、推導縮成口訣、都是把裁決權交給容器——內容量不因容器形狀而可裁。內容自身冗餘、誤置或過時時、刪除是合法處置——但觸發源是內容的性質、跟容器形狀無關。第三個出口（換成連結）與它不同源：那裡刪的是自身冗餘的內容、這裡刪的是**容器誘發**的冗餘——表格三欄的形狀讓作者填一句自撰的 gloss 而不是放一條連結、即使那個概念在同一個內容集合裡已經有完整落點。一次對兩章教學內容的逐列判定裡、這一類的列數多於前兩個出口相加；另一章卡層零覆蓋的判定裡它一列都沒有（該篇的主處置全落在先收斂載體與補句內成分）——**分布隨內容集合的卡層覆蓋與跨章關係變動、不可推廣**、每次改寫重跑分診。

選出口有一個前置檢查：**確認這個概念在內容集合裡只有一個版本**。同一個概念在兩篇以上有互不相容的定義時、三個出口都會把矛盾保留下來——展開會寫出兩套更詳細的版本、連結會把讀者送到一個用不同語彙描述同一件事的地方、外部化成卡則會把其中一套固化成被多篇引用的權威而另一套繼續存在。

兩個判斷標準把這個檢查變成可執行的動作。**雙向對映測試**：把兩篇的成員（階段名、欄位、責任項）並排，逐項問能不能互相對映完整；只存在於一側的成員就是不相容的證據，而它通常是損失最大的一項（讀另一篇的人拿不到它）。**動作測試**：問讀者會不會為這件事做同一個動作兩次——一篇的產出是另一篇的輸入時是互補、兩篇是同一個動作的兩份指示時是衝突。互相連結、語彙不同、各自宣稱處理另一半都不是分工的證據。

處置順序是先指定單一權威載體、其餘各篇沿用它的語彙並重新界定自己承擔哪一段（保留獨立的那一面、剩下不足以成篇才併篇）、載體補反向指標、再對剩下的內容選容器出口。出口之間的排序規則：**論證承重壓過跨篇重用**（既承重又跨篇的概念，判斷標準留在本篇展開、定義連出去，不整段搬走），而兩者都後於前置檢查——載體未定之前做容器決策，是在對一個還會被改寫的對象選容器。載體選的是內容而住址是另一個問題：**判斷標準完整度決定哪一套內容留下**（殘缺的那套當載體會把殘缺擴散到每一處引用）、**引用數只決定住址搬不搬**（它承擔遷移成本、不是品質——引用多而內容殘缺時保留住址、把完整那套搬進去）。**兩套各有對方缺的成員時，載體要先補齊才有資格當載體**——收斂不是挑一套刪掉另一套，跳過補齊這一步會讓收斂本身丟掉內容（實例：兩套交接欄位，一套缺主責角色、另一套缺三項 payload）。同一對象已有一張卡時，卡通常是住址（入連數最高、本來就是可被多篇引用的獨立短頁）。「把兩套同步成一份」是另一個機制（有共同起源的副本漂移）的修法、對平行發明會產出兩邊都不像的第三套；「兩套並陳讓讀者對照」把選擇丟給最沒有材料選的人。這種矛盾在單篇視角下不落空——每一篇單獨讀都自洽——所以它要在改寫前的分診階段查、不能等審查逐篇讀。

出口選擇的判斷標準是**概念角色**：主線概念（本篇論證繞著它轉）必須就地展開——外部化會讓讀者跳出去讀卡、論證線斷裂；支撐與背景概念可以拆卡——知識卡是承載單一術語或概念、可被多篇引用的獨立短頁——卡片自帶範例、文章保留「什麼情境用哪張卡」的判讀敘事。

**擴充的對象是結構、每句的字數另有裁決者**：卡片盒筆記法的擴充彈性指的是卡片數、範例數、討論空間可以長——句子的長短由消費單位分配管（見 [sentence-self-sufficiency-by-consumption-unit](sentence-self-sufficiency-by-consumption-unit.md)）、metadata 由精簡規範管。把本卡讀成「全域加長」跟把容器壓力讀成「該壓縮」是同一類錯：都把裁決權交給了錯的層。

## 為什麼內容會被裁去遷就容器

生成端的**容器形狀先驗**：生成文字時、標題傾向固定的長度帶、表格格傾向短語、段落傾向固定節奏——這個規律在輸出端可直接觀察。形狀先驗讓因果方向反轉：本該由內容決定容器、實際上內容被裁切去符合容器的預期形狀——一個需要三句話的判斷標準放進表格格時被裁成殘語、或者作者根本沒展開、因為容器的形狀暗示「這裡只該放這麼多」。人工寫作有同構推力：「讓文章乾淨」是正當追求、用壓縮實現它就走錯了出口——文章變短的合法方式是外部化（細節住進卡片、每篇自然短）、把每句削薄是錯的實現。

## 反模式：簡報式文章

壓縮遷就容器的終點形態：標題句化、表格當主體、格內塞判斷標準殘語、段落退化成條列的連綴——讀者拿到談話要點（talking points）、缺推導與範例。簡報這個文體的正當性主要來自**有講者在場補完**、文章沒有講者、把文章寫成簡報等於把補完責任丟給不存在的人。

| 形態                                     | 違反什麼                                                                                                                          |
| ---------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| 表格是段落的主體、正文只有表格前後各一句 | 「表格不是終點」的寫作規範——每格需要延伸段或拆卡                                                                                  |
| 表格格裡是判斷標準殘語（無主詞、指涉懸空）   | 同時命中單句消費位（[sentence-self-sufficiency-by-consumption-unit](sentence-self-sufficiency-by-consumption-unit.md)）的自足要求 |
| 段落由條列連綴、沒有推導句銜接           | 條列之間的推導被壓掉、讀者拿到結論拿不到理由                                                                                      |

邊界：**簡報式的判定看消費單位、不看表格密度**。checklist、audit 清單、規格表、以及教學內容裡的查表型段落（判讀徵兆表、對照表）表格形態都合法——消費單位是逐項執行或逐列查詢、每列的自足義務由句自足規則承接。違規的精確形態是承載推導的內容被塞進表格、推導句從正文消失——判定問「推導存在的段落、它的推導還在不在正文」；純參考內容（環境變數表、API 對照）不觸發。

## 自查清單

- [ ] 每個表格格裝得下完整判斷標準；裝不下時選了出口（延伸段、拆卡、或換成連結）、沒有裁內容
- [ ] 想外部化的概念是支撐或背景角色；主線概念留在正文行內展開
- [ ] 格內的每句自撰解釋都確認過內容集合裡沒有既有落點；有落點的改放連結、不寫 gloss
- [ ] 刪成純連結之前分清重述與列舉：讀者的下一個動作是「逐項填它」或「逐項對照它」時，那份列舉留在本篇
- [ ] 刪成純連結之前打開目的地、把成員並排：換成連結與先收斂載體在外觀上無法分辨（兩者都是「別處已經有了」），差別在目的地那一套與本篇是不是同一個切法；少了這一步，誤判方向永遠偏向連結
- [ ] 被連到的目的地與本篇語域一致（讀者被帶到一個看起來不是給他讀的頁面之後，後面的連結他不會再點）
- [ ] 選出口之前跑過前置檢查：這個概念在別篇有沒有不相容的版本（雙向對映 + 動作測試）；有的話先收斂載體再選容器
- [ ] review 時反向掃一次：哪一段的推導只存在於表格裡、正文沒有承接
- [ ] 文章讀起來有推導句銜接、條列與表格是輔助不是主體
- [ ] 查表型與 checklist 型段落沒有被誤判成簡報式（那類段落的表格形態合法、判定看消費單位）

## 跟鄰近原則的分工

- **句自足**（[sentence-self-sufficiency-by-consumption-unit](sentence-self-sufficiency-by-consumption-unit.md)）：那卡管句子的成分完整度、本卡管內容的量對容器的關係；表格格是交會點——格內殘語同時違反兩卡。
- **原子化**（SKILL.md 原則一）：拆卡的單卡 scope 仍由原子化判斷標準管（認知負擔、focus 完整度）；本卡管「何時該拆」、原子化管「拆出來的卡合不合格」。
- **判定分工**（[multi-pass-review-frame-granularity](multi-pass-review-frame-granularity.md) 的判定層段）：「表格當主體」是候選不是判決——判定看文體與消費單位、checklist 型內容合法。

**核心**：容器該服務內容——內容裝不下時、換出口（延伸段）或換容器（卡片）、內容量不因容器形狀而可裁。
