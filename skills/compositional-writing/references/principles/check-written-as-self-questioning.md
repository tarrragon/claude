# 規則與教材把檢查寫成執行者自問自答的口語：「每一處都問：……嗎」「這一問沒有固定的答案」「照著問就判得出」，工程文件寫成檢查項、判定依據與判定條件的屬性

> **角色**：本卡是 `compositional-writing` 的支撐型原則（principle），被字句層 keyword bank 的〈教室形式〉形態六引用。
>
> **何時讀**：寫規則、skill 或教材裡要執行者做一項檢查的句子，寫出「問一次」「判斷問句」「這一問沒有固定的答案」「照著問就判得出」這類句型時；或讀到兩個字面很像的說法，分不出一個要靠領域知識、一個不必時。

## 論述基礎與限制

本卡從一次概念命名的檢討抽出。那一批替一個分流用的概念取名為「只憑問句與輸入就判得出的答案」，收尾時列出兩組批外的字串，問要不要統一成這個名字：留意項的強度句「這一問沒有固定的答案」6 處，以及「照著問就判得出」11 處。讀原文時發現後一組講的是另一件事：「物理化錯配有一個照著問就判得出的偵測方法：問這個動詞如果照字面成立，需要什麼物理條件」，這項檢查要靠讀者對語言與物理的了解，照那一批的定義正好不屬於「只憑問句與輸入就判得出」。兩個說法的字面只差幾個字，意思相反。

使用者指出三件事：「沒有固定的條件」才是對的語法，「這一問沒有固定的答案」太口語化，不適合工程或教學文件；「照著問就判得出」是同一個問題，工程文件會寫成依照特定規格檢查就能確認；名字裡也不應該出現「問句」這個名詞，前後文寫的是要執行者先問問看自己，而工程文件寫的是先檢查、先確認。那個名字之後改成「固定的判定條件」，跟強度句「這項判斷沒有固定的條件」是同一個概念的兩面。改寫時使用者另外指出槽位規則的「主詞做不做得了這個動作」也是同一類：工程文件不說「做不做得了」，說「能不能」加動詞，寫成「主詞能不能執行這個動作」。

已有一張原則卡收過同一個裝置在教材裡的形態：[teaching-is-not-lecturing](teaching-is-not-lecturing.md) 的形態四「判定標準包裝成自問自答」（「問自己一個問題：回退時間是分鐘級、小時級、還是不可回退？」）與形態五「問得出／問不出替代指標名稱與通過標準」，本 skill 的字句層 bank 有對應的 grep（`問自己|問一個問題|然後問`、`問得出|問不出來|問不出`）。本卡補三個那張卡沒有涵蓋的面向：同一個裝置出現在規則檔與 skill 本身，也就是負責擋這個裝置的那些條文裡；規則檔的寫法（「每一處都問：」「問一次：」「判斷問句」「這一問」）不在 bank 的那兩條 pattern 裡；可能補語「判得出」把判定的性質藏起來，讓兩個意思相反的說法長得一樣。

一個 repo 的規則檔與 skill 裡，這組句型的字串計數：「判斷問句」53 處、「問一次」74 處、「這一問」52 處、「照著問就判得出」11 處。字串計數混了合規的用法（例如討論語法上的「正反問句」），違規的處數沒有逐處判過。讀者因為這組句型而做錯檢查的頻率也沒有量過；本卡的證據是一組字面相近、意思相反的說法，以及使用者對語域的判斷。

## 核心原則

**這組句型寫的是執行者照做時的心裡動作，不是檢查本身。** 「每一處都問：讀者讀得懂這一段的論證嗎」交代了執行者要在心裡問一句話；「這一問沒有固定的答案」交代了那句話難答；「照著問就判得出」交代了照那句話問下去會有結果。三句都沒有寫出檢查的四個部分：檢查的對象、檢查依據的規格或事實、什麼結果算通過，以及這項判定有沒有固定的條件。工程文件與教材寫的是後面這四項：「每一處檢查不認識這個專案的讀者能不能讀懂這一段的論證；這項判斷沒有固定的條件」。

**口語版本裡看不到判定的性質，所以兩個意思相反的說法長得一樣。** 「照著問就判得出」與「只憑問句與輸入就判得出」都在說「判得出」，一個指要靠了解才判得出，一個指不靠了解就判得出。判定的性質（有沒有固定的條件、要不要領域知識）在這兩句裡都只能從「判得出」這個可能補語推，而可能補語描述的是執行者能不能做到，不是判定本身的屬性。寫成屬性之後兩者分得開：一個是「判斷標準是一項明確的檢查，判定要靠對語言的了解」，另一個是「這項判斷有固定的判定條件」。

**「問句」把檢查的格式當成檢查的名字。** 規則寫「判斷問句是……」時，這個名字指的是檢查的格式（用一句問句表達），不是它檢查什麼；讀的人照字面去問自己，回答完就算做過了，而寫規則的人沒有要求寫出回答的依據。工程文件用檢查項、判定標準這類名詞指檢查的內容，用「確認」「依……檢查」這類動詞寫出依據。

**可能補語描述讀者的能力時合規。** 「讀者答得出這一節在講什麼」「審查者從紀錄看得出他省了哪一步」寫的是被量測的對象：讀者或審查者的能力，這正是要寫的內容。違規的是可能補語頂替判定標準的屬性，或頂替檢查依據的位置。

## 反模式

- **規則對執行者下「問一次：X 嗎」**：句子交代了心裡的動作，沒交代檢查的對象與依據；執行者問過、答過，紀錄裡沒有任何可查的東西。
- **強度句寫「這一問沒有固定的答案」**：「答案」與「這一問」都是對話的說法；讀的人可能讀成「沒有標準答案，所以怎麼答都可以」。強度句寫判定的屬性：「這項判斷沒有固定的條件」。
- **用「照著問就判得出」「照規則就判得出」描述一項檢查**：讀者分不出這項檢查要不要領域知識，也看不出依據寫在哪裡。
- **替一個判定的性質取名時，名字裡放「問句」或可能補語**：名字描述的是執行者的動作與能力，判定本身的性質要從字面推。
- **改寫時只把「問」換成「檢查」**：「每一處都檢查：讀者讀得懂嗎」仍然是一句問句；檢查的對象、依據與通過條件要寫成陳述。

## 修法

1. **找出要執行者做一項檢查的句子**，候選字串是「問一次」「都問」「逐處問」「逐句問」「判斷問句」「這一問」「那一問」「照著問」「判得出」「答得出」「做不做得了」「做得了」「做不了」。字串是候選，每一處判它寫的是檢查本身，還是讀者或審查者的能力；後者合規。
2. **把檢查寫成陳述**：檢查的對象（每一處寫到內部專案的段落）、依據（論證用到的事實在不在本篇裡）、通過的結果（事實都在文章裡）。原句的問句內容可以留在冒號後面當檢查項的內容，但動詞換成「檢查」「確認」，並寫出依據。
3. **強度句寫判定的屬性**：「這項判斷沒有固定的條件」，不寫「這一問沒有固定的答案」。
4. **檢查的對象是一個動作時，寫「能不能」加動詞**：「主詞做不做得了這個動作」寫成「主詞能不能執行這個動作」，「做得了」「做不了」寫成「能執行」「不能執行」（「那個人做得了演奏」寫成「那個人能演奏」）。
5. **判定的性質寫成屬性，不用可能補語**：有固定的條件、要靠哪一種了解（語言、領域、情境）、依據哪一份規格。原句是「照著問就判得出的偵測方法」時，寫成「偵測方法是一項明確的檢查：這個動詞照字面成立需要什麼物理條件；判定要靠對語言與物理的了解」。「明確的檢查」只表示檢查項寫得出來，判定有沒有固定的條件要另外寫在同一句，不寫的話讀者會把「明確」讀成「固定的判定條件」。
6. **替判定的性質取名時**，名字寫出判定依據什麼、有沒有固定的條件，不放「問句」與可能補語；名字定下之後照 [unnamed-halves-are-unextracted-variables](unnamed-halves-are-unextracted-variables.md) 的做法只寫在一處。

## 判讀徵兆

| 徵兆                                                     | 判讀                                                 |
| -------------------------------------------------------- | ---------------------------------------------------- |
| 規則寫「每一處都問：……嗎」，紀錄要求只寫「判過了」       | 檢查寫成了心裡的動作，依據與通過條件沒有寫出來       |
| 兩個說法都寫「判得出」，一個要靠領域知識、一個不必       | 判定的性質藏在可能補語裡，字面分不開                 |
| 強度句寫「沒有固定的答案」，讀者回報「那就怎麼判都可以」 | 「答案」把判定寫成對話，讀者讀不到「沒有固定的條件」 |
| 一個概念的名字裡有「問句」                               | 名字指的是檢查的格式，不是檢查的內容                 |
| 「讀者答得出這一節的主題」這種句子被當成違規             | 誤判：可能補語在描述被量測的能力，合規               |
