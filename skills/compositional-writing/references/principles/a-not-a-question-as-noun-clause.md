# 正反問句嵌進句子當名詞：位置判讀、與高頻句型的撞形，以及謂語要寫出的判斷標準

> **角色**：本卡是 `compositional-writing` 的支撐型原則（principle），被字句層 keyword bank 的「正反問句當名詞」類別引用。
>
> **何時讀**：句子裡出現「連不連得到」「對不對」「讀不讀得到」這類正反問句，讀者覺得拗口卻說不出哪裡不對時；或者翻成英文才發現原文沒說清楚判斷標準時。

正反問句（「能不能」「連不連得到」「對不對」「有沒有」這類 A 不 A 形式）在中文裡是問句。它被寫進一個句子裡，當主語、受詞或介系詞的受詞時，承擔的是英文 whether 子句的角色：一整段「某件事成不成立」被當成一個名詞來談。英文的 whether 放在子句最前面，讀者一開始就知道後面整段是一個名詞；中文的正反問句沒有開頭標記，問句的形式出現在子句中間的動詞位置，讀者讀到那裡才知道前面那段是一個問句，再回頭把它重新歸類。

判讀分兩件事，彼此獨立：**正反問句在句子裡的位置**，以及**它的謂語是否寫出判斷標準**。

## 失效的形態

一篇服務端監控的教材描述容器健康檢查的盲區：

> 自檢的問題盲區是程序以外的路徑：它在程序所在的容器裡測，別的容器連不連得到它、入口的路由對不對都不在它的問題裡，由服務網路內的探測接手。

讀者要做四件事才還原得出命題：

- **兩段正反問句並列在主語位置**，讀者讀到「都不在」才知道前面兩段是主語。
- **「連」先被讀成「連……都」**：句子前段有「連」、後段有「都」，讀者先套進這個高頻句型，套不進去才退回來。
- **「對不對」先被讀成附加問句**（right?）：「入口的路由對不對」第一眼像「入口的路由，對吧」。
- **一句三個「它」指兩個對象**：自檢、被監控的程序、又回到自檢。

正反問句坐在介系詞後面時另有一種撞形：「再對讀不讀得到它寫一條規則」的「對」是介系詞，而「對」本身又有「正確」的意思。

改寫的方向是直述，或用「是否」「能否」——它們放在所標記的內容前面，作用接近 whether：

> 自檢只確認程序在自己的容器裡能回應；請求能否從別的容器到達程序、入口 Nginx 是否把請求轉到正確的服務，自檢都不檢查，由服務網路內的探測接手。

## 位置判讀

同一篇十五處正反問句按位置分成四組：

- **接在「問」「檢查」「確認」「判斷」這類動詞後面當受詞**（「讀取缺口問的是有沒有人知道」）：中文語法給這類動詞留了接問句的位置，讀起來自然。五處。
- **用「」標成引語**（健康檢查回答「這個程序自己的端點回不回應」）：引號告訴讀者這是被引出來的直接問句。三處。
- **放在「X 回答的問題是：」後面、沒有引號也沒有問號**：讀者先當直述句讀，讀到正反問的動詞再改。三處，修法是加引號與問號，或改用「是否」。
- **當主語、接在介系詞後面，或多段並列**：沒有任何前導詞預告問句，介系詞「對」與並列的「都」又各自撞上高頻句型。四處，負擔最重。

位置判讀的問句是：**「讀者讀到這段正反問句之前，有沒有一個詞（『問』『檢查』、引號、問號、『是否』）告訴他接下來是一個問句？」** 有，就留；沒有，就改成直述或「是否」。

## 謂語要寫出判斷標準

正反問句還讓作者不必寫出判斷標準，這一點與位置無關。「入口的路由對不對」的「對」是照什麼算對，「打不打得通」的「通」是請求、封包還是連線到達了哪裡，句子都沒寫；中文接受「對不對」作為一個完整的問句，所以寫的當下不覺得少了什麼。翻成英文時這一格被強制填上：whether the ingress routes requests to the right service 與 whether the ingress route configuration is valid 檢查的對象不同，前者要發請求看它落在哪個服務，後者讀設定檔就能判斷。這是 [翻譯探針](translation-forces-disambiguation.md) 量得到的那一層。

判斷問句：**「把正反問句的謂語（對、通、到、行）單獨拿出來，讀者說不說得出它是照什麼標準判斷的？」** 說不出來，改寫時把標準寫進去。這一條在每個位置都適用，包括讀起來自然的「檢查」受詞位置：「門檻還對不對得上基線」寫出了標準，「拿到的回應對不對」沒有。

## 成因與偵測

那篇文章的組織框架是「每一層監控回答一個問題」，框架把觀察者擬人化成應答的一方，作者每次描述一個觀察者檢查什麼就引一句問句，正反問句的密度跟著框架走。這個框架本身另有一個缺陷，見 [「問題」與「回答」當框架詞](question-answer-frame-blurs-problem-issue-request.md)。

正反問句有固定詞形：

```bash
# 需要 PCRE2：(\p{Han})不\1 抓 A 不 A，有沒有另外列
rg --pcre2 -n '(\p{Han})不\1|有沒有' <檔案>
```

命中是候選，判定走位置與判斷標準兩個問句。這條 pattern 抓不到夾在句中的「X 嗎」。

寫的人知道每個「它」指誰、「對」照什麼標準，讀起來是通順的，同源的審查者也一樣，所以這一類要靠掃描。寫這張卡的初稿時，用這條 pattern 掃自己，找到七處正反問句坐在沒有前導標記的位置，都寫在分析這個形態的段落裡。

## 論述基礎與限制

證據是一篇文章、一位讀者的指認，以及同篇十五處的位置分類。依位置分組的負擔排序是從語法機制推出來的，還沒有用理解探針或翻譯探針量過。
