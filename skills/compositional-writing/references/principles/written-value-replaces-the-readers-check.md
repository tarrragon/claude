# 寫出特定實例的值，就取代了讀者本來要做的查證

> **角色**：本卡是 `compositional-writing` 的支撐型原則（principle）、被 SKILL.md 的「意圖顯性與層級貼合」段引用。
>
> **何時讀**：要寫某個機型、環境或安裝的具體值與處理方式，而讀者本來應該在自己的系統上查它時。

## 核心原則

一段文字寫出特定實例的值之後，它就佔據了讀者原本要自己查的那個位置。讀者要的是「我這一台是什麼」，而文章給了「有一台是什麼」——兩者在版面上長得一樣，而**特定實例的值正好是他那一台會不一樣的那些**；在每一個實例上都相同的那幾類（規範定義、公開介面的行為、機制）本來就不必他查。

推論是**危害與正確性無關**。文中的值可以完全正確、來源可以完全可靠，而讀者把它用到自己的系統上仍然是錯的，因為它從來就不是關於他的系統的。

**判別問句：讀者拿這一句去用，他是去查自己的系統，還是直接照抄。**

## 為什麼「標註未驗證」不夠

分層標註（驗過 / 標註未驗證 / 移除）對大多數未驗證內容是合理的處置，而它對這一類失效，差別在**誰承擔預設**。

標註假設讀者會讀到那個標記、並且因此改去查自己的系統。不寫假設他不會。前一個假設要讀者的自律才成立，後一個由文字的結構保證——**沒有可抄的東西時，不需要任何人記得規則。**

還有一層讓標註更弱：標註是給讀完那一段的人看的，而照抄的人多半是搜尋直接落在那一行、複製、離開。他經過的路徑上沒有那個標記。

## 與「不預設讀者熟悉特定專案」的失效方向相反

|            | 專案綁定敘事               | 本卡                           |
| ---------- | -------------------------- | ------------------------------ |
| 讀者的狀態 | 讀不懂——缺少那個專案的脈絡 | 讀懂了，而且相信了             |
| 失效的訊號 | 當場就有：他卡住了         | 沒有：文字讀起來完全正常       |
| 浮現的時點 | 閱讀當下                   | 他把那個值用到自己的系統上之後 |

第二欄的失效不可能由讀者回報——他不會知道問題出在這份文字。這使它只能在寫作端擋，而擋的方式是不留可抄的東西。

## 「需要實機才寫得了」多半是誤判

把**有了會更好**講成**需要**是這一類的常見伴生判斷。一個主題通常拆得成兩半：**問題的形狀與該去哪裡查**（在哪一層、用什麼機制、退到哪裡），以及**某個實例上的具體答案**。前一半不需要那台機器，後一半依本卡不該寫——所以「等機器」這個判斷同時擋掉了該寫的那一半、又保留了不該寫的那一半。

把「需要實機」寫進待辦另有下游代價：往後每個看到它的人會跳過那一項去等硬體，而它現在就寫得了。

## 修法

**把描述換成該去哪裡查。** 不寫「這個欄位在那一台上是什麼」，寫「這個欄位要在自己的機器上用什麼指令看」——寫成查法對每個讀者都成立，而且它交付的是能力不是答案。

**機制需要具體例子才講得清時，用明顯的佔位值並寫明它是佔位的。** 跨層的表示法差異、欄位的形狀這一類，抽掉數值就看不懂；保留一個一眼看得出是編出來的值，機制保住而照抄的誘因消失。

**不受這一條約束的三類**：機制、規範定義、公開介面的行為。它們在每一個實例上相同，讀者查證與照抄得到同一個答案，所以寫出來沒有取代任何東西。

## 跟其他原則的關係

- [讀者定位是能力宣稱、不是知識宣稱](audience-is-professional-not-layperson.md)：反向的一對。那一條管**該寫而沒寫**（省略在產物上沒有痕跡），本卡管**不該寫而寫了**（寫出來在產物上完全正常）。共同點是兩種缺陷都在稿件上看不出來，所以偵測都得靠稿件以外的東西。
- [錨點標籤的自足義務隨引用點數上升](compressed-label-cost-multiplies-with-citations.md)：同屬「寫下來的東西會被複製」這個family，而複製的後果不同——那裡是短名被複製而讀者解不開，這裡是值被複製而讀者不該用。

## 判讀徵兆

| 訊號                                   | 該做的事                                                   |
| -------------------------------------- | ---------------------------------------------------------- |
| 想在句子後面補一句「未經驗證」         | 先問這一句拿掉之後論證還在不在，在就拿掉，不用標註         |
| 待辦寫著「需先實機確認」               | 拆成形狀與具體答案兩半，前一半現在就寫、後一半不寫         |
| 文中出現一個真實裝置或環境的識別值     | 問它服務的是機制的說明還是查詢的結果，說明用的換佔位值、查詢結果刪 |
| 一段話回答的是「有一台是什麼」         | 讀者要的是「我這一台是什麼」，改寫成他自己查得到的形式     |
| 來源可靠、值也正確，仍覺得哪裡不對     | 危害與正確性無關——問這個值是不是關於讀者的系統             |

**核心**：每個實例上都相同的那些讀者不必查，而他必須查的正好是這份文字不該替他回答的。
