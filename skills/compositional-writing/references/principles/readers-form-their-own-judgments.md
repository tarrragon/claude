# 評價由讀者自己形成：寫作交付材料，不交付速成印象

> **角色**：本卡是 `compositional-writing` 的支撐型原則（principle）、被 SKILL.md 原則 3（意圖顯性與層級貼合）的評價交付段引用。
>
> **何時讀**：文章、文件或註解裡出現「優雅 / 出色 / 經典 / 值得 / 紮實 / 必讀」這類評價語時；或寫作時發現自己在對某個對象下判斷、而不是在給讀者判斷的材料時。

---

## 核心原則

**傳達觀點的寫作交付材料——事實、屬性、行為、取捨、後果、推導——評價由讀者用材料自己形成。** 主觀評價語是預先消化過的結論：讀者拿到的是印象、不是理解。印象建立得很快，而它取代的正是讀者形成自己想法的過程——被評價餵大的讀者記得「這個很經典」，拿不出「它處理了什麼、代價是什麼」。

判定不看評價準不準：**準確而溫和的評價同樣是速成印象**。問題在交付形態（結論對材料）、不在強度——強度失實（誇飾）是另一軸，一句不誇張的「這本書很紮實」照樣違規，因為讀者無從檢驗、只能收下印象。

分界的操作測試：**讀者能不能用文中已給的材料檢驗這句話。**「這個做法在寫入密集的場景成本高」可檢驗——場景與成本都是材料；「這個做法很優雅」不可檢驗——優雅住在作者的審美裡。

**明確的立場**：讀者端確實存在速成期待（想直接拿「哪個好」「值不值得」），而傳達觀點的寫作不以滿足它為目標——迎合速成期待生產的是印象的搬運，交付材料生產的是理解的建立，讀者帶走自己能重算的判斷。

---

## 邊界

- **評鑑文體例外**：評測文、比較文的本職就是給評價——但評價要附材料與判斷標準（測了什麼、在什麼條件下、輸在哪一項），讓讀者可以不同意。
- **推導收尾的結論合法**：判斷標準在推導走完的位置浮現——那是讀者跟著材料自己走到的，不是被餵的印象；摘要位置回收前文推導過的結論同理。
- **判斷句不是評價語**：界線用操作測試畫、不用詞面畫。
- **註解同理**：程式碼註解寫商業邏輯與約束，不寫「這段很乾淨 / 很 hacky」的鑑賞——鑑賞不改變讀程式的人的任何行動。
- **凍結外部名照抄**：書名、版本名、獎項名裡的評價詞是命名事實。
- **機制描述不觸發**：「失效時指標會漂亮」的評價詞描述現象外觀、不是推薦。

---

## 修法

1. **評價換材料**：想寫評價時問「我看到什麼，讓我這樣覺得？」把看到的那個東西寫出來（處理了什麼問題、用什麼代價、在哪裡失效），評價刪掉。讀者讀完材料，自己會得出那個評價。
2. **角色標籤用功能、不用地位**：排序或分類時的標籤寫它做什麼（設計語彙、調度模型、問題的來歷），不寫它的地位（奠基經典、必讀名著）。
3. **強度另行處理**：掃到評價語同時檢查誇飾軸；本卡的修法對強度正常的評價同樣適用。

## 判讀徵兆

| 訊號                                                    | 該做的事                                                       |
| ------------------------------------------------------- | -------------------------------------------------------------- |
| 句子用「優雅 / 出色 / 經典 / 值得 / 紮實」下判斷        | 操作測試：讀者用文中材料檢驗得了嗎；不行就寫材料、刪評價       |
| 排序或分類的角色標籤寫地位而非功能                      | 換成功能標籤：它做什麼、回答哪個問題                           |
| 評價詞在書名 / 版本名 / 獎項名裡、或描述失效現象的外觀  | 凍結外部名與機制描述、不觸發                                   |
| 註解在鑑賞程式碼（乾淨 / hacky）                        | 換成商業邏輯與約束                                             |
| 用「讀者就是想要結論」當評價先行的理由                  | 不以滿足速成期待為目標——交付材料、結論由推導交付               |
