# 以對象起手的句子：缺少的動作者、時機與觸發原因，審查修正寫出這類句子的成因與偵測方式

> **角色**：本卡是 `compositional-writing` 的支撐型原則（principle），被 SKILL.md〈每一句先填槽位再成句〉與字句層 keyword bank 的「對象起手句」類別引用。
>
> **何時讀**：寫描述做法的句子、條件句（「X 時，……」）、段落首句，或把一條審查意見改進稿件時；或者審查時遇到主詞謂語都在、讀起來通順，而讀者說不出是誰在做、在工作流程的哪一步碰到、為什麼會發生的句子。

## 結論

「一個檔案被幾個不同的需求修改過，可以從版本歷史數出來，這個數字決定哪些檔案值得回頭讀修改紀錄」主詞、謂語、受詞都在，讀起來通順，而讀者讀完說不出三件事：數的人是誰、他在工作流程的哪一步會去數、為什麼他需要這個數字。句子以被討論的對象（一個檔案）起手，用被動句把動作者藏起來，再讓指標（這個數字）當「決定」的主詞，做決定的人從句子裡消失了。

讀者讀一句描述做法的句子時，要拿到的是 5W1H 裡的**誰**（動作者）、**什麼時機**（工作流程裡碰到這件事的那一刻）、**做什麼**、**為什麼會觸發**。正常的順序是先寫誰在什麼時機做了什麼，再寫他看到什麼、為什麼要這樣做：「工程師做 code review、查看一個檔案的修改紀錄時，從版本歷史發現它被幾個不同的需求修改過」。判斷問句是：**這一句描述的事，誰做、在工作流程的哪一步做、為什麼會發生，能不能從這一句、前一句或所在段落的第一句逐字指出來。**

## 三種形態

- **條件句起手、後面接沒有主詞的祈使**：「一個檔案同時對上兩列時，依每次修改的寫入者是人還是工具來分」。「時」看起來交代了時機，而它寫的是對象的狀態，不是讀者工作流程裡的一步；「分」是誰分，句子沒寫。改寫：「讀排行的人對照這張表時，有些檔案同時符合兩種類型……兩種類型的處置不同，所以他依每次修改的寫入者是人還是工具，把這個檔案的修改分到兩種類型」。
- **被動句或「由……」只交代次要動作的動作者**：「工具產生的檔案由工具改寫，沒有人帶著意圖編輯……處置是從統計排除、衝突靠重新產生」。改寫有動作者（工具），而句子要交代的是處置——誰從統計排除它、兩個分支衝突時誰重新產生它——那兩個動作沒有主詞。
- **指標當主詞**：「這個數字決定哪些檔案值得回頭讀」「commit 數會把同一個需求的多次 commit 各算一次……所以這份清單只用來挑……」。數字與清單不做決定，做決定的是讀排行的人；指標寫成主詞，讀者分不清這一句是在描述工具的行為，還是在告訴他該怎麼用工具的輸出。改寫：「這條指令數的是每個檔案被幾個 commit 改過……讀排行的人只拿這份清單挑出要讀修改紀錄的檔案」。

改寫用的動作者多半是文章本來就有的角色（讀排行的人、歸類的人、解衝突的人、開發者），不必另外造。

## 為什麼四槽位檢查放行

四槽位規格（動作者、動詞、受詞、結果，見 [command-fragment-as-subject-hides-the-actor](command-fragment-as-subject-hides-the-actor.md)）裡有動作者一格，而這三種形態逐格查下來每一格都填了名詞：

- 被動句與「由……」句有動作者的位置，填的是次要動作的動作者，主要動作的動作者槽位不在句子裡，檢查者找不到一個空著的格。
- 指標當主詞時，動作者那一格填了名詞，格子不是空的；四槽位檢查受詞是否在領域裡，沒有檢查主詞能否做這個動作。
- **時機與觸發原因不是四槽位的成員**。條件句的「X 時」看起來填了時機，而它寫的是對象的狀態。

所以要加兩件事：動作者那一格問**主詞能不能做這個動作**（數字不能決定、清單不能挑選），以及多兩格——時機（工作流程裡的哪一步）與觸發原因（為什麼會發生）。

## 審查修正是這類句子最常見的產地

一篇教材裡被讀者指出的四句，用 `git log -S` 查，全部由多輪審查的修正 commit 加入；同篇另一句同形態的句子來自初稿。審查意見本身帶著脈絡：steelman 那一輪問「一個檔案同時符合兩種類型時怎麼辦」「commit 完全不帶需求編號時怎麼辦」，修正的人讀過那條意見，誰在什麼時機會碰到這個情形對他是已知的，所以他只寫答案，把問題的主語放在句首接著寫處置。讀者沒讀過那條意見，拿到的是一句沒有問題的答案。

同一個現象也發生在剛學到這條規則的人身上：收到上面那次指認之後，第一版改寫的範圍交代寫成「範圍從以版本歷史數出每個檔案被幾個不同的需求修改開始」，同樣沒寫是誰在數，第二次才補上「用腳本讀 git 歷史」。

## 偵測

**逐字引出動作者、時機與原因的探針**（做法與 [noun-without-its-owner-passes-the-slot-check](noun-without-its-owner-passes-the-slot-check.md) 相同、改問不同的格）。十七句校準集：改寫前七句、改寫後七句、原本合規三句，打亂、每句單獨給、沒有上下文；三份低階模型指令逐字相同，要它逐字引出「誰」「時機」「原因」，引不出就寫引不出。判定規則：「誰」引不出，或引出的是指標、清單這類不能做動作的名詞，三份裡至少兩份如此就標記。

- 改寫前七句標記五句；其餘十句標記一句，是範圍交代句（探針把「本篇的範圍」當成主詞），範圍交代句沒有在描述動作，判為誤報。
- 漏掉的兩句缺口都在句子後半：前半有正當的動作者（「由工具改寫」「腳本數的是不同的需求」），缺動作者的是後半的「排除」「決定」。探針被要求只回答主要動作，挑了有主詞的那一個。**派這個探針時要求逐個動詞引出動作者**，而那個版本的雜訊很高，見本節最後。
- 「時機」欄有鑑別力（改寫前有兩句三份全數引不出時機，改寫後沒有）；「原因」欄沒有（探針把任何一個子句當原因填進去）。

**關鍵詞找候選**（改寫前整篇一百六十句實測）：

- 指標接「決定」：`(這個數字|需求數|commit 數|它)[^。，]{0,4}決定`，排除前面是「用」「拿」「依」的——命中兩句，兩句違規。
- 句首名詞接被動：`被|由` 接「修改、改寫、寫入、產生、編輯」——命中五句，多數是候選而非違規。
- 條件句接沒有主詞的祈使：`X 時，依|照|先|把`——命中三句，一句誤命中。

三條 pattern 只縮小要讀的範圍；「常見的拆檔門檻是行數」這種沒有被動也沒有條件句的形態，三條都抓不到。

**逐個動詞引出的版本在整篇文章上跑過一次。** 改完被讀者指出的句子之後，同一篇教材的全文 214 句散文分成三批，每批派三份低階模型，指令改成列出每一個描述動作的動詞、逐字引出它的動作者與時機。結果的雜訊很高：探針把「是」「屬於」「等價」這類描述狀態的動詞也列進去，沒寫主詞的祈使句一律回報引不出，幾乎每一句都有至少一個動詞被標記。這個版本只產出候選，判讀時再套兩條條件才收斂：

- **只看描述某人在工作流程裡做的動作**（歸類、排除、加進、重跑、比較、判讀、列出、移到、檢查）。描述工具或機制自身行為的句子（git 的改名偵測決定衝突的形態、`--first-parent` 只走主線）、狀態動詞、定義句與解法陳述（「根本的解法是……」）不算。
- **這一句與所在段落的第一句都沒有寫出動作者才算**。段落第一句已經寫出動作者時，同段後面的祈使句沿用它；要求每一句或每兩句重寫一次動作者，步驟說明會變得冗長，而讀者讀一段程序時手上有那一段開頭交代的角色。

至少兩份引不出、又通過兩條條件的共 37 句，全數補上動作者（讀排行的人、執行腳本的人、歸類的人、解衝突的人、開發者、團隊）後提交。三條關鍵詞 pattern 在同一篇扣掉重疊只命中 8 句，其餘候選來自探針。

## 修法

- **生成端**：寫描述做法的句子、條件句與段落首句時，先填動作者、時機、做什麼、為什麼四格再成句。動作者是能做這個動作的人、角色、工具或程式；指標與清單只當受詞或依據（「讀排行的人用需求數決定」）。時機寫讀者工作流程裡的一步（「對照這張表時」「rebase 到拆分之後的版本時」），不寫對象的狀態。
- **審查修正**：把一條審查意見改進稿件時，先把那條意見帶給作者的脈絡（誰在什麼時機會碰到這個情形）寫進句子，再寫處置。
- **審查端**：派逐字引出動作者與時機的探針、逐個動詞回答，至少兩份引不出動作者或引出指標的列為候選，再過兩條條件（只看工作流程裡的動作；這一句與所在段落的第一句都沒有動作者），通過的由主 session 逐條判讀改寫。

## 論述基礎與限制

校準集十七句、三份探針，來自同一篇文章；標籤由改寫的人判定，標籤與改寫出自同一個判斷，可能同向偏誤。「指出的四句都來自審查修正」來自一篇文章的版本歷史，其他文章的比例沒有量過。逐個動詞的版本只在一篇文章（214 句）上跑過，兩條篩選條件是那一次訂的，沒有在另一篇文章上驗證；補上動作者的 37 句也沒有再派探針確認改寫後引得出。

## 判讀徵兆

- 句子以被討論的對象起手（「一個檔案」「工具產生的檔案」「commit 數」），讀者讀完問得出「誰做的」「什麼時候」。
- 「X 時，依……」「X 時，把……」的 X 是對象的狀態，後面的動詞沒有主詞。
- 數字、指標、清單、排行當「決定」「挑」「判斷」的主詞。
- 審查修正加進來的句子讀起來像一條條文，前後沒有交代它回應的是什麼情形。
