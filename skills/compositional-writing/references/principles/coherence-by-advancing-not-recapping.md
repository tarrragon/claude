# 連貫靠句句推進：讀者付出的每一次閱讀成本都要換到內容

> **角色**：本卡是 `compositional-writing` 的支撐型原則（principle）、被 SKILL.md 原則 3（意圖顯性與層級貼合）的推進句段引用，與 `coherence-by-shape-not-reader-memory` 合成形狀層／句層的配套。
>
> **何時讀**：段落讀起來不連貫時；發現自己在寫過場句把前文摘一次再出發時；或要判斷一個譬喻該不該留（先問這個概念有沒有現成術語）、說明順序該由什麼驅動時。

---

## 核心原則

連貫的載體是**推進句**：前句的成果是後句的條件，句句朝同一個方向，沒有任何一句要求讀者回頭。回收語——把剛讀完的內容摘一次再出發——不製造連貫，只暴露斷點：**需要一句回收才接得下去的位置，就是上一句沒接好的位置**。修法是把承接改寫成推進（「釐清 X 之後，實務上還需要 Y」——X 是前文剛交付的成果、直接當後句的條件），把回收句寫得更漂亮修不到根。

逐句可執行的判準有兩問，第一問不過就往下問第二問：

1. **這一句要求讀者往前走，還是回頭？**回收式過場與迂迴指代都是回頭——要讀者重新取用剛讀過的內容。
2. **讀者付出的這一次閱讀成本，換到了內容嗎？**懸念否定要讀者記住一個還沒填的缺口、文章自指把讀者從主題拉到版面、姿態描述交付的是關係的元資料、頂替術語的譬喻要讀者多建一筆對映——四者都不是回頭，但讀者付出了而沒換到東西。

五類共用的機制是第二問（付出換不到內容），第一問只覆蓋其中兩類——**掃描時兩問都要跑**，只跑第一問會漏掉五類中的三類。

## 五類要刪的字

| 類型       | 實例                             | 為什麼是廢字                                                                                       |
| ---------- | -------------------------------- | -------------------------------------------------------------------------------------------------- |
| 回收式過場 | 「立場站定、量尺在手」           | 把前兩件事各摘四個字再講一次，讀者剛讀完、增量是零；四字對仗的節奏感讓它讀起來像在做事             |
| 懸念否定   | 「仍然沒有答案——」               | 先宣告缺口再揭曉誰補的微型懸念弧；直接說還有什麼要討論、哪裡處理                                   |
| 文章自指   | 「承接的就是這一段」             | 「這一段」指文章的版面結構；讀者在讀主題內容，不在讀這篇文章怎麼編排自己                           |
| 迂迴指代   | 「就是做這件事的量尺」           | 為了鉤回上一句多轉一手；「就是提供這個評估的標準」直接                                             |
| 姿態描述   | 「質疑的是那三本共同的問題本身」 | 描述論戰的形狀（誰不同意什麼的什麼），不交付問題的內容；把問題寫出來之後，升層關係讀者自己看得出來 |

姿態描述這一類要單獨展開，因為五類裡只有它 grep 抓不到：「A 質疑 B 的問題本身」「C 不同意的是前提」讀起來有論證密度，實際交付的是關係的元資料——問題是什麼、前提是什麼，一個字都沒說。修法是把被指涉的內容直接寫出來，對立姿態的詞（質疑、挑戰、反對）通常整個省下。

## 譬喻先問有沒有現成術語

技術寫作的概念多數已經有名字——標準、判準、準則、門檻、成本、邊界。這些詞在領域內所指穩定，讀者一看就對得上，而且中英文技術文件用的是同一組詞（標準 / criteria / standard，而不是 the yardstick）——這一句以台灣技術語境與英文技術文件的常見用詞為據，沒有做語料量測。**概念有現成術語時，術語優先，譬喻不進場**：譬喻要讀者建立一筆對映（量尺＝判準集），術語不用——那筆對映的成本是憑空多出來的，換到的只有畫面感。

譬喻的位置在**這個概念在讀者的語言裡還沒有名字**的地方：新機制、跨領域借來的結構、還沒有人命名的現象。那裡沒有術語可用，譬喻是唯一的載體，此時才問第二個問題——服役長度。

判定順序，第一層答完通常就結束：

| 層 | 問題                         | 答案與處置                                       |
| -- | ---------------------------- | ------------------------------------------------ |
| 一 | 這個概念在領域裡有現成術語嗎 | 有 → 用術語，譬喻不進場，第二層不必問            |
| 二 | 沒有術語時，這個譬喻服役多久 | 貫穿全篇 → 留；兩三句就拆場 → 純成本，換字面說法 |

成因是語域混入：譬喻有畫面、有文采，那是散文的審美；技術文件的語域要的是所指穩定。同一個作者會在同一篇裡兩邊都寫，因為「量尺」讀起來比「標準」**更好**——而那個更好是散文的判準。與 [word-choice-fits-concept-attributes](word-choice-fits-concept-attributes.md) 正交：「量尺」沒有錯配，它只是佔了一個已經有名字的位置。

實測形態：同一個「標準」的概念，總覽段用術語、專節用「量尺」譬喻，同一篇裡分裂成兩個名字而三輪審查都沒攔到——**掃描要跨全篇對同一個所指，不是逐段看**。本卡初版把判準寫成單層的服役長度，那是在沒有先問「有沒有現成術語」的前提下給的；服役長度因此降為第二層。

相鄰的另一類是**層級錯位**：總覽段每一環只背「關係＋名字」，判準的內部構造（「四支柱」是什麼）屬於下方專節；總覽背了專節的細節，讀者就得在總覽層 hold 一個當下用不到的名詞。

## 連結掛在句中已有的名字上

為了掛連結而另造括號標籤——「（評分的判準）」——是為連結服務的字：句子裡已經有書名或節名時，連結直接掛在那個名字上，括號標籤整個消失。判別方式：把連結語法拿掉之後，括號裡的字對讀者還有沒有資訊——沒有就是標籤、不是內容。

## 順序由讀者的問題序驅動

素材的來源鏈（一本書接一本書、一個來源接一個來源）服務作者的整理過程；讀者的問題序（怎麼做 → 怎麼評 → 還剩什麼）服務讀者的推導過程。兩者不一致時以問題序為準；被推遲的項目集中在句尾一次交代，不在論證中途插入推遲宣告（「X 是之後的事」）——中途的推遲會逼出另起一段、再逼出回收過場。

## 對照範例

原稿（兩段、一次懸念、一次回收）：

> 無論站哪一邊，實作一段時間之後都要回答同一個問題：自己寫出來的這套測試好不好。Khorikov 的《Unit Testing Principles, Practices, and Patterns》給的四支柱判準就是做這件事的量尺，對兩派都適用——它對倫敦學派的系統性批評也建立在這把量尺上（評分的判準）。而判準寫下來、交給機器或 agent 執行的時候，Bach 與 Bolton 的《Taking Testing Seriously》質疑的是爭單元邊界的那三本共同的問題本身：要先分開的是「執行事先寫好的判準」與「設計判準、發現沒人想到要問的問題」這兩種活動，單元的大小是之後的事（機器接手判準之後人還做什麼）。
>
> 立場站定、量尺在手，「這些測試案例是怎麼推出來的」仍然沒有答案——四本立場書都沒給這個程序，Aniche 的《Effective Software Testing》承接的就是這一段：從規格推導案例的步驟（推出測試案例的程序）。

改寫版（一段、單向推進）：

> 無論選擇哪一種做法，測試寫完之後都要評估同一個問題，這套測試到底有沒有問題？Khorikov 的《Unit Testing Principles, Practices, and Patterns》就是提供這個評估的標準，這個標準無論對哪一派都適用。這本書中對於倫敦學派的批判也是基於這個系統。而判準寫下來、交給機器或 agent 執行的時候，Bach 與 Bolton 的《Taking Testing Seriously》提出了一個討論，怎麼評估「執行事先寫好的判準」與「設計判準、發現沒人想到要問的問題」這兩種活動？這其實是三本理論書都在討論的共同問題。釐清測試的方向之後，實務上還會需要討論單元的大小——三本理論書在這一題沒有取得共識，《Taking Testing Seriously》給出解法——以及怎麼從規格推導到測試案例（Aniche 的《Effective Software Testing》）。

逐項對應：「站哪一邊／立場站定」→「選擇哪一種做法」（拆選邊譬喻）；「量尺」三現→「標準／系統」（頂替術語的譬喻拆場）；「四支柱」刪（層級錯位、細節下放專節）；「質疑的是…問題本身」→ 把問題寫出來（姿態描述換內容陳述）；「立場站定、量尺在手」刪、換「釐清測試的方向之後」（回收過場換推進承接）；「仍然沒有答案——」刪（懸念否定）；「承接的就是這一段」刪（文章自指）；「單元的大小是之後的事」從中途移到句尾與案例推導並列（推遲項集中交代）。範例聚焦在刪字、拆譬喻與排序三個維度；改寫版的其餘用字取捨不作為本卡的規範內容。

## 什麼時候不成立

- **節首的定位重述**：空降讀者需要「這一節在整篇的什麼位置」，節首一句重述定義或關係是 [coherence-by-shape-not-reader-memory](coherence-by-shape-not-reader-memory.md) 的形狀鞏固。分界在服務對象與位置：節首定位句服務從任意節點進入的讀者、合法；段間回收句服務同一個線性讀者、把他剛讀完的再摘一次、刪。
- **沒有現成術語的長程譬喻**：概念在領域裡還沒有名字、而譬喻貫穿全篇每節回扣時，它是導航地標，保留。有術語可用時這一條不適用——長不長程都該換成術語。**本站目前沒有存活的實例**（原本用來例示的兩處譬喻在第一層判準下都被換成術語了），這一層由機制推導、尚未被案例驗證。
- **摘要位置的回收**：目錄、description、推導收尾的總結句，消費單位即壓縮形態，不適用逐句推進判準。
