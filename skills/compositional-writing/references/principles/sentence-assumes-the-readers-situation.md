# 替讀者假設他可能沒經歷過的情境或頻率：「這個位置每週都會遇到的那場對話」把一個條件寫成讀者的日常，改寫成職責或條件並寫出發生的前提

> **角色**：本卡是 `compositional-writing` 的支撐型原則（principle），被字句層 keyword bank 的「替讀者假設情境與頻率」類別引用。
>
> **何時讀**：稿件寫出「每週都會遇到」「躲不掉的」「天天開會」「你一定遇過」這類替讀者決定他經歷過什麼、多常發生的句子，或用一個情境帶出一本書、一個做法的用途時。

## 論述基礎與限制

一份書單在文法重寫之後，審稿的人讀到一句：「Difficult Conversations 處理的是這個位置每週都會遇到的那場對話：某個人交出來的成果不夠好，而這件事得由這個位置去講。」審稿的人指出這一句不應該假設每週都會有那場對話，要用確實的方式說明，而不是假裝讀者有這個情境——讀者可能從來沒經歷過。

依這個判斷用關鍵詞掃整個書單集合（`每週都|每天都|每次都會|天天|經常要|常常要|一定遇過|都遇過|都經歷過|躲不掉的|免不了|總會遇到|遲早會`），除了被指出的那一句，另外找到四處同一類：同一篇的「這裡的人經常要向上回報進度」、「哪兩個團隊要天天開會」兩處、「這個位置躲不掉的承諾問題」；一處判成合規（段首寫明「這個代價的形狀具體是這樣」的假設例子）。這組關鍵詞裡，在那個集合實際命中過的是「經常要」「天天」「躲不掉的」，其餘是補進來防同類變形的成員。

同一組關鍵詞在同一個網站的其他集合命中 43 行、40 個檔，等距抽 11 處，只有 2 到 3 處是替讀者假設情境（「你天天用的 CLI」「它遲早會撞到失敗」，後一句的「它」是讀者自己寫的程式，頻率加在讀者身上；「生產 App 天天在正確處理」的主詞同樣是物，而頻率描述的是那個系統自己的運作）；其餘的頻率描述的是系統或機制自己的運作（「生產 App 天天在正確處理」），或寫在條件、程序階段與判讀訊號之下（「導入期間管理員仍要天天登入主機」「規則清單每週都在加新案例」）。另一次在兩個資料夾實跑，11 行只有 1 處是這一類（「真正天天影響你的是其中幾條」），而它的文法主詞是物、頻率卻加在讀者身上——只看文法主詞判，這一句會被放行，所以判讀問句改成問這個頻率描述的是誰的經歷。關鍵詞只抓得到帶固定頻率詞的形態；用描述假設情境、不帶頻率詞的句子沒有量過。

## 核心原則

**一句話替讀者決定了他經歷過什麼、多常發生時，它把一個條件寫成了讀者的日常。** 「這個位置每週都會遇到的那場對話」裡，「每週」是作者沒有資料的頻率，「那場」預設讀者認得那場對話。對經歷過的讀者，這一句讀起來像共鳴；對沒經歷過的讀者——剛進這個位置的人、在這個位置但團隊沒有這類情形的人——這一句說的是一件不是他的事。這類讀者可能推論「我是不是哪裡做錯了，所以沒遇過」，或推論這份內容不是寫給他的（這兩種推論是推導，沒有量過）；兩種推論都不是這一句要交付的。

**這類句子要交付的是一個條件。** 「這個位置要去指出某人交出來的成果不夠好」是這個位置的職責，它沒有固定的頻率：成員交出來的成果不夠好時，由對別人的產出負責的人指出這件事。寫成職責或條件時，經歷過的讀者認得出那個情境，沒經歷過的讀者也知道這件事在什麼條件下會發生、發生時這本書有什麼用。

**它可能跟虛構經驗出自同一個生成機制，只是方向相反。** 作者虛構自己的經驗（「我們團隊曾經」）是把一段不存在的實踐當成論證的權威來源；替讀者假設經驗是把一個未必存在的處境當成讀者已經擁有的前提。生成端學到的「有說服力的文章」形態是讓讀者覺得「這說的就是我」，替讀者造出一個他會點頭的情境正好符合那個形態（這是推論，這次沒有量測支撐）。頻率詞（每週、天天、躲不掉）是這個情境最容易被看到的痕跡。

**誇大的頻率也是同一類。** 「介面畫在哪裡，決定了哪兩個團隊要天天開會」要說的是一個機制（介面的位置決定哪兩個團隊之間要協調），「天天」把機制換成了一個沒有根據的頻率，讀者拿自己的團隊去對，對不上時會懷疑機制本身。

## 反模式

- **用頻率詞替讀者決定日常**：「每週都會遇到」「經常要」「躲不掉的」「你一定遇過」。
- **用指示詞預設讀者認得一個情境**：「那場對話」「那種會議」，前文沒有描述過時，讀者不知道指的是哪一場。
- **用誇大的頻率代替機制**：「天天開會」「永遠在救火」，要說的是哪兩件事之間有依賴。
- **把書的用途綁在讀者必須先有的處境上，而那個處境沒有寫成條件**：讀者無從判斷自己落不落在那個處境裡。

## 修法

1. **寫成職責或條件**：「這個位置每週都會遇到的那場對話」→「這個位置的職責包含的一種對話：團隊成員交出來的成果不夠好時，由對別人的產出負責的人指出這件事」。
2. **寫出發生的前提**，讓讀者能判斷自己落不落在裡面：「有三個以上的團隊、交接面開始需要設計時」，而不是「團隊大了以後一定會遇到」。
3. **誇大的頻率換回機制**：「天天開會」→「之間要持續協調」，並寫出協調的原因（介面畫在哪裡）。
4. **來源的判斷與撰稿者的判斷分開寫**：「多數這類對話難開口，是因為……」若是來源（書、文件）中的分析，寫出來源的名字（「依《書名》的分析……」）；是撰稿者自己的判斷時，寫出依據或刪掉「多數」（這一項這次只觀察到一處）。
5. **標明了的假設例子保留**：段首寫明「這個代價的形狀具體是這樣」、接著用一個假設的處境示範機制，讀者知道那是示範，不是在說他的經歷。

判讀問句是這個頻率描述的是誰的經歷、有沒有寫在一個條件或程序階段之下。條件寫在同一句、或同一段裡這一句之前都算；條件要是讀者拿得來對照自己處境的事實，「在某些團隊裡」「團隊大了以後」寫在條件的位置，讀者仍然對照不了。合規的形態與指示詞那一型的候選 pattern，以本 skill bank〈替讀者假設情境與頻率〉那一條為準。

## 判讀徵兆

| 徵兆                                               | 判讀                                           |
| -------------------------------------------------- | ---------------------------------------------- |
| 頻率描述讀者的經歷，而且沒有寫在條件或程序階段之下 | 一個條件被寫成讀者的日常，沒經歷過的讀者對不上 |
| 「那場」「那種」指向一個前文沒有描述過的情境       | 指示詞預設讀者認得這個情境                     |
| 把一本書的用途寫成「你一定遇過的那個時刻」         | 書的用途綁在一個沒寫成條件的處境上             |
| 「多數」「通常」沒有來源，接在書的介紹後面         | 撰稿者的判斷與來源的判斷混在一起，要分開寫     |
| 頻率描述系統或機制的運作，或寫在條件、程序階段之下 | 合規                                           |

## 跟其他原則的關係

- [AI 生成的內容不虛構經驗與出處](no-fabricated-experience-or-attribution.md)：最接近的一張。那張卡處理作者虛構自己的經驗與出處，經驗是證據宣稱；本卡處理可能出自同一個生成機制、朝讀者那一方的形態：替讀者假設他的經驗與頻率，把一個條件當成讀者已有的前提。那張卡的判定先問事件存不存在，本卡的判定問這個處境是不是每一位讀者都有，不是的話寫成條件。
- [教學內容不預設考核情境](verify-by-recognition-not-recitation.md)：那張卡處理句子預設一個讀者沒有的考核情境（有人在問、答案要說出來）；本卡處理的是預設讀者有一個工作情境，兩者都是替讀者造出一個他不在其中的場景。
- [教學與檢討內容寫給帶問題來的讀者](write-for-readers-not-audiences.md)：「這說的就是我」是經營聽眾注意力的手法；讀者由搜尋帶來、自帶要查的事，他需要的是判斷自己落不落在那個條件裡，而不是被一個情境拉進來。
