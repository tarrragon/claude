# AI 生成的內容不虛構經驗與出處

> **角色**：本卡是 `compositional-writing` 的支撐型原則（principle）、被 SKILL.md 原則 3（意圖顯性與層級貼合）的敘事姿態段引用，也是字句層 keyword bank 虛構經驗軸的判讀依據。
>
> **何時讀**：處理 AI 生成或 AI 協作產出的內容時；文章出現第一人稱團隊經驗（「我們團隊曾經」）、第三人稱角色（PM、reviewer、同事、新人）或精確出處宣稱（「某書第 N 頁寫道」加引號引文）時；以及發現一篇虛構之後、要決定盤點範圍時。

---

## 核心原則

**經驗宣稱是證據宣稱，出處宣稱是可回溯性宣稱——兩者都是論證的承重件，虛構它們是造假，不是修辭選擇。**「我們團隊曾經踩過」把一段不存在的實踐當成論點的權威來源；「某書第 N 頁寫道」把一個走樣的轉述包裝成可翻頁核對的逐字引文。讀者對這兩種句式的信任比對一般論述高，虛構恰好挑中了信任最高的位置。

機制在生成端：模型把「有說服力的文章形態」當模板填充——好文章開頭有親歷故事、論點旁有名人書頁引文，於是經驗與出處被**形態需求**生成出來，而不是從事實取回。這解釋了兩種形態為什麼同時出現在同一篇、也解釋了引文為什麼「接近真的」——它是從真實來源的記憶壓縮再重建的，出處與字面在重建中走樣。

跟敘事姿態原則（寫給帶問題來的讀者、不用演講姿態）的分工：那一張管**真實事件**的敘事姿態，把第一人稱時間線改寫成條件視角；本卡管**事件本身不存在**。姿態改對了、虛構仍是虛構，而且條件視角的改寫會把虛構藏得更深——「若團隊對某個做法又愛又恨」讀起來像從真實事件抽象來的。改寫虛構經驗之前要先判定它是不是虛構。

---

## 三個掃描面

**第一人稱經驗宣稱**有穩定關鍵詞，掃得到：我們團隊、我們的團隊、我們公司、我們曾、我當時。這是作者把自己寫進場景的那一種。

**第三人稱角色**沒有穩定關鍵詞，靠逐篇讀開場：PM、reviewer、同事、新人、負責人，以及「團隊士氣」「大家都說」這類需要有一群人才成立的名詞。單人加 AI 的專案裡這些角色是形態需求的產物，而他們身上掛著的往往正是文章的動機句（「PM 無法判斷這張單能不能關掉」）——動機句由虛構角色承擔時，整篇的問題設定跟著失去來源。

**精確出處宣稱**同樣預設待驗：第 N 頁寫道、原文第 N 章說、開場白就寫著。精確度本身是訊號——越精確的位置宣稱越需要有人真的翻過。

---

## 修法

1. **經驗宣稱要有可指認的來源。** 寫的當下問：這段經驗發生在哪、有什麼可指認的紀錄。有真實事件——依敘事姿態原則改條件視角、來源一句話交代；沒有——整段拿掉，論證改掛在可查證的來源或條件推導上。條件視角不需要虛構主體也成立：「重構的 diff 裡測試改動量跟生產程式碼相當、而這次改動沒有改變任何外部行為時」承擔了原本由虛構故事承擔的開場功能。
2. **引文逐字核對、出處寫到可回溯層級。** 帶引號的引文要對原文逐字核對；核不到原文就改成轉述、拿掉引號；出處精確度只寫到驗證過的層級（驗過網頁就寫網頁、沒翻過書就不寫「第一頁」）。
3. **角色存在性逐篇問。** 文中的每個角色在事件當時存不存在。不存在的角色連同他承擔的情節一起拿掉，該情節說明的問題改由條件語言承載。
4. **判定單位是生成批次，不是關鍵字命中。** 一篇被判定虛構之後，先用版本歷史查它跟誰同批生成（同一個 commit、同一個日期、同一組結構模板），把整批列入待驗逐篇處理。關鍵字只曝光批次裡形態最明顯的少數幾篇——**清單清空不等於批次清空**。
5. **具名錨點與情節分開驗。** 具名的檔名、行數、日誌規模可能是真的，而它前後的情節是補完的。錨點對回專案紀錄，對不上的數字跟情節一起拿掉；對得上的保留錨點、情節仍要問有沒有人在場。

## 判讀徵兆

| 訊號                                                    | 該做的事                                                                   |
| ------------------------------------------------------- | -------------------------------------------------------------------------- |
| AI 生成的內容出現「我們團隊 / 我們曾 / 我當時」的經驗宣稱 | 問這段經驗發生在哪、有什麼可指認的紀錄；沒有就整段拿掉、論證改掛可查證來源 |
| 文中有 PM / reviewer / 同事 / 新人 / 團隊士氣這類角色    | 問他們在事件當時存不存在；第三人稱角色不進第一人稱 grep、靠逐篇讀開場      |
| 「某書第 N 頁寫道」加引號引文                            | 逐字對原文；核不到就轉述去引號、出處只寫到驗證過的層級                     |
| 引文讀起來對、但查到的原文措辭或出處不同                 | 記憶重建的走樣——以查到的為準，不要保留「比較順」的版本                     |
| 修虛構經驗時直接套條件視角改寫                           | 順序錯了——先判定事件存不存在，虛構的要拿掉而不是改寫                       |
| 一篇被判定虛構、而它有同批生成的兄弟篇                   | 用版本歷史把整批拉出來逐篇驗——關鍵字清單清空不等於批次清空                 |
| 具名的專案錨點配著一段情節                               | 錨點對回專案紀錄，對不上的數字與情節一起拿掉                               |
| 真實事件的工作紀錄、「」內他人自述                       | 候選不是判決——這兩類合規                                                   |
