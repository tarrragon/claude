# 字句層 keyword bank（完整清單）

> **何時讀**：做字句層審查、跑多輪審查的 Round 1-A、batch review、寫作 audit 時；逐類跑這份清單，不憑記憶重編 pattern。
>
> **同目錄**：各類別的判讀與修法在 `principles/` 對應的原則卡與 `writing-articles.md` 等 reference；入口與路由在 SKILL.md〈When to Consult This Skill〉。
>
> **溯源**：本檔原為 SKILL.md 1.49.0 的同名節，1.50.0 因入口檔 token 預算外移，內容逐字保留（連結改為相對本檔；下文「本 skill」指整個 compositional-writing skill）。

**這一節是本站字句層檢查的唯一權威清單。** 其他地方（SKILL.md 的 frontmatter description、multi-round-review 的 Round 1-A、專案規範）出現的枚舉都是摘要，數量與成員以這一節為準。做字句層審查時打開這一節逐類跑，不要憑記憶重編 pattern——重編版通常把不同類別的詞混進同一條 regex，命中之後無法判定是哪一類違規。

寫多篇章節 / report 卡 / knowledge card 後做**多輪 agent reviewer audit** 時、本 skill 應該跟 multi-round-review skill 同時啟動。觸發詞「多輪審查 / Round 1/2/3 / batch review / 寫作 audit」會同時啟動兩個 skill：

- **multi-round-review** 規劃 frame 切換結構（Round 1 compliance / Round 2 cadence / Round 3 self-application）跟跨輪 finding 整合工作流
- **本 skill（compositional-writing）** 提供每輪 frame 的字句層 keyword bank — Round 1-A 寫作規範 reviewer 必須跑：
  - **正向陳述優先 grep**：`rg "不[行可是要能該支對符夠必]|無法|沒[做有]|而非|而不是"`、加上**否定起手定義句**（原 pattern 漏「而是」、抓不到「不是 X、而是 Y」的後半）：`rg "不是[^。「」]{0,30}而是|不是[^。「」—–]{0,25}[—–]\s*是|不是[^。「」，、]{1,25}[，、]\s*是|不在[^。「」]{0,30}而在|與其[^。「」]{0,25}不如|不只.{0,15}更"` — **連接詞家族不只「不是…而是」**：`不在…而在`、破折號形式 `不是 X — 是 Y`、以及裸逗號形式 `不是 X，是 Y` 各自漏過一次才被補上，所以手寫這條 pattern 時會系統性地只想到最典型的那一個。字元類的 `[^。「」]` 護欄不可省——少了它會跨句配對並命中引號內的引用，產生假陽性。**這一類若已由某個 lint 工具強制執行，工具那一份 regex 是權威**，手動掃描要取它的涵蓋範圍而不是自己重編；兩份並存時會各自腐爛，而腐爛的方向固定是手寫那一份較窄 — 主要敘述要正向、反例對照的少量負向可保留；判別在「核心概念第一次正面出現在句首、還是被擠到『而是』之後」。**合規邊界**：糾正已文件化誤讀的「不是 A、而是 B」仍列可改——修法保留糾正語意（例如改寫成「條件是 B；A 不是判斷條件」），概念前置不因糾正目的豁免
  - **口語修辭 grep**：`rg "其實|實務上|真的|碰巧|立刻撞牆|沒事"`
  - **地區用語 grep**：單詞層 `rg "集群|默認|質量|視頻|函數|文件夾|接口"`（封閉集合、掃得到）；慣用語層 `rg "拍腦袋|拍板|靠譜|給力|接地氣|一波|死磕|躺平|內卷"`（已知個案、**非窮舉**——慣用語是開放集合、grep 追不完、新個案要靠目標地區讀者冷讀，同源 reviewer 回報「地區用語 clean」對慣用語層不可當真，見 [`regional-idioms-evade-keyword-bank`](principles/regional-idioms-evade-keyword-bank.md)）
  - **廢話前綴 grep**：`rg "值得注意的是|需要說明的是|實際上|基本上|事實上"`
  - **裝飾符號 grep**：`rg "✅|❌|⚠️|🚨|🟡|🟢|⭐|📌|✓|✗"`
  - **對讀者喊話 grep**：`rg "很多人|大家|不少人|你的|你在|你把|你正在|你補|你天天|你會|你可能|先讀懂|先釐清|別搞混|別被"`（**裸「你」非窮舉**：實測過 `你正在`、`你補完` 這類「你 + 一般動詞」逃過原 pattern，回報 clean 前另跑一次裸 `rg "你"` 逐處判定） — 教材中性陳述、不安撫情緒 / 不第二人稱代入 / 不祈使控制閱讀（hook / narrative 段落輕度第二人稱可留）。**裸所有格 / 主詞（你的 X / 你在 X）也算、不限「你 + 動詞」的祈使 / 預測句型**；grep 對裸『你』非窮舉、真防線是 reader-simulation 冷讀（同源 grep 抓不到 register、見 [multi-pass-review-frame-granularity](principles/multi-pass-review-frame-granularity.md)）
  - **自評誇飾 grep**：`rg "教科書級|堪稱|可謂|完美|經典|範本級|大師級|漂亮地|優雅地|最佳實踐|best practice"` — 品質 verdict 頂替技術理由、換成機制 / 條件；命中後的合法性判定用位置功能兩軸（文體契約 × 行動耦合）——hook 段的強度合法、判斷標準段零容忍、判定前先定位、見 [hyperbole-legitimacy-by-position-function](principles/hyperbole-legitimacy-by-position-function.md)
  - **必然性框架 grep**：`rg "天生|與生俱來|本質就是|本來就是|必然|唯一|註定|理所當然"` — 把設計選擇講成自然法則、還原成條件性（物理 / 法律 / 數學事實除外）。**合規邊界**：SSOT／權威住址／裁決陳述中的「唯一」（如「唯一權威定義」「唯一標準指令」）與由機制定義直接蘊涵的「必然」（如「A 與 B 必然分屬兩個 commit」）合規；違規限把可變的設計選擇講成自然法則，改寫成條件句反而會失去 SSOT 語意
  - **澄清式框架 grep**：`rg "最容易誤|容易誤判|常見的?誤判|要點破|直覺會?帶偏|抵抗.*的直覺|你以為|會困惑|值得記"` — 把「讀者會誤解」當敘事中心是知識缺口訊號、不是澄清時機；補正向模型與機制讓誤解無從發生、不提醒讀者一個他本不需要有的困惑。界線是具體第一人稱實測敘事跟真實診斷區分（逾時 vs 被拒、症狀層 vs 根因層）保留、只有把假想誤會當主題句起手的才改；同義變體多、grep 抓不全、靠 reader-simulation 語意判定（「這段在補正向知識、還是在提醒讀者會犯錯？」）。見 [fill-knowledge-gap-not-center-misconception](principles/fill-knowledge-gap-not-center-misconception.md)
  - **歸因語氣 grep**：`rg "承認|暴露了|證明了失敗|被迫"` — 描述系統行為用「信號」「反映」「顯示」等中性觀測詞、避免「承認」「暴露」等責任歸因詞；「被迫」在描述外部強制約束時可保留。**合規邊界**：「承認」的主詞是規範／文件對實作的認可（非人對過失的認錯）時合規
  - **宣導語氣 grep**：`rg "你可能沒注意|你可能不知道|想像一下|把.{1,5}想成|跑得好好的|聽起來很|其實很簡單|說穿了就是|等於拆未爆彈|乾瞪眼|延遲引爆"` — 預設讀者無知或用情緒管理取代事實陳述；讀者是專業人士、直接描述情境與後果
  - **泛用詞濫用 grep**：`rg "坑|東西|搞|弄|處理一下|情況"` — 同一個泛用詞蓋過不同具體情境時、依情境換精確詞（意外 / 陷阱 / 出問題 / 發生狀況）；命中密集且各指不同事才算違規、真泛指 / 引號引用 / 輕度 hook 合規；「坑」另有地區偏移面（某些地區高頻、某些少用）。**合規邊界**：「視情況」「預設情況下」為固定搭配，不計入「情況」命中。見 [avoid-overused-generic-words](principles/avoid-overused-generic-words.md)
  - **位置與集合指涉 grep**：`rg "前者|後者|前兩[本篇章個]|另外[一二三四五兩][本篇個章條張]|其他[一二三四五兩][本篇個章條張]|其餘[一二三四五兩][本篇個章條張]|下一[本篇章節]|上一[本篇章節]|這一側|那一側"` — 解碼材料要在讀者已讀的文本裡：位置與數量是作者腦中地圖的 derivation、連作者自己都常數錯（實測同一篇三次計數三次全錯）；**集合指涉即使計數正確也要給成員或方向**——數字只證明數過、不承載意義，成員各自的方向才是讀者要用的資訊。命中是候選——緊鄰具名清單的行內計數、全稱比較（宣稱對全體成立、方向不參與意義）、已具名集合的向後回指、時間距離的遠指（「那個年代」）都合規；判定看綁定在不在已讀文本、命中時順手驗計數。集合成員多到列不動是分類規劃要拆的訊號、不是省略的授權。見 [decodable-from-text-already-read](principles/decodable-from-text-already-read.md)。**這條 pattern 的成員是從論述型內容歸納的，換體裁要重做形態盤點**——清單型內容（書單、工具比較、選型表）的結構單位是「一篇裡的一組並列成員」，指涉因此走序數，主流形態是 `前一本|下一本|上一本|本篇第[一二三四五六]本|上述[兩三四]本|前面幾本|第[一二三四五六]本`，跟論述文的「前者 / 後者」沒有交集。一次實測：論述文那組 pattern 在一批書單上回傳 86 個命中而逐處判定全部合規，該體裁的三十處違規一個都不在裡面，修完之後命中數只動一。判斷標準見 [keyword-pattern-does-not-transfer-across-genres](principles/keyword-pattern-does-not-transfer-across-genres.md)
  - **計數式摘要（無穩定 pattern，按位置逐句讀）**：在介紹另一份內容的位置——文章結尾指向下一篇的句子、`description`、目錄頁的交付欄、閱讀路線的說明欄——逐一找「數字＋類別名」的片語（「四個追問」「三種寫法」「四類邊界」「上線前的三件事」），問沒讀過那一篇的人知不知道成員是什麼。成員緊鄰數字寫出來的合規（「自連接、視窗函數與相關子查詢三種寫法」），量測事實合規（「差三個量級」），只有數字加類別名的違規。**grep 分不出兩者**，`rg "^description:.*[一二三四五六七八九十兩]+ ?(個|種|類|項|條)"` 只用來縮小要讀的範圍。「位置與集合指涉」那條管回指已讀的集合（其他三篇），碰不到這一類。見 [counted-summary-delivers-only-the-length](principles/counted-summary-delivers-only-the-length.md)
  - **名詞缺所屬（無穩定 pattern，按位置逐句讀）**：在段標、段落的第一句與最後一句、總結段、過渡句，逐一找本身要求「誰的、什麼的、哪兩者之間的」的名詞（來源、輸出、結果、原因、代價、差別、位置、範圍、邊界、訊號、層、線、情形）與被當成名詞用的形容詞或動詞（「看不出錯」的「錯」），問它的所屬能不能從這一句或前一句**逐字指出來**；指不出來就違規（「錯的來源不只一種，而輸出都不帶訊號」）。**名詞清單只能用來知道該看哪裡，不能當判決**：一次二十句的校準裡，清單命中已知違規的一半、也命中已知合規的七成，因為合規句的所屬寫在前一句（「原因是配對是逐列做的」）。判定某個譬喻要換之後，先數它在整個集合裡出現幾次，整批換成同一個領域用詞——只改被標出的那一句，同一個概念就有了兩個名字。只寫在目錄頁而讀者看不到的框架詞是同一個成因，那一半可以用腳本掃。見 [noun-without-its-owner-passes-the-slot-check](principles/noun-without-its-owner-passes-the-slot-check.md)
  - **對象起手句（缺動作者、時機與觸發原因；pattern 只找候選）**：在描述做法的句子、條件句、段落首句與審查修正加進來的句子，逐句問誰做、在讀者工作流程的哪一步做、為什麼會發生，能不能從這一句、前一句或所在段落的第一句逐字指出來。候選 pattern 三條——指標當主詞 `rg "(這個數字|需求數|commit 數|行數|分數|它)[^。，]{0,4}決定"`（前面是「用」「拿」「依」的合規）、句首名詞接被動 `rg "(^|[。；])\s*[^，。；：]{2,20}(被|由)[^，。；]{1,16}(修改|改寫|寫入|產生|編輯)"`、條件句接沒有主詞的祈使 `rg "(^|[。])\s*[^，。；：「」]{2,22}時，(依|照|先|把|改|用|回到)"`；一篇一百六十句的實測裡三條去重後命中九句、明確違規四句，「常見的拆檔門檻是行數」這種沒有被動也沒有條件句的形態三條都抓不到。審查端派逐字引出「誰／時機／原因」的探針，**逐個動詞回答**（只問主要動作時，前半有動作者、後半缺的句子會漏掉），至少兩份引不出動作者或引出指標、清單的列為候選；「原因」欄沒有鑑別力。**逐個動詞的版本雜訊很高**——一篇 214 句的實跑裡，狀態動詞與沒寫主詞的祈使句讓幾乎每一句都被標記——候選要再過兩條條件才收斂：只看描述某人在工作流程裡做的動作（工具與機制自身的行為、狀態動詞、定義句、解法陳述不算），以及這一句與所在段落的第一句都沒有寫出動作者（段落第一句寫出的動作者由同段的祈使句沿用）；那一次通過兩條條件的有 37 句。**合規邊界**：範圍交代句、定義句、描述機制本身行為的句子（「git 的改名偵測決定衝突的形態」，主詞是能做這個動作的元件）。見 [topic-first-sentence-drops-actor-and-timing](principles/topic-first-sentence-drops-actor-and-timing.md)
  - **讀者會先想到別的東西的譯名（嚴重；無穩定 pattern，逐個譯名問）**：先列出稿件裡所有由外文概念翻來的中文詞——`rg -o "[一-龥]{2,}（[A-Za-z][^）]*）" <files>` 抓得到附了原文的那些（輸出會連前面的中文子句一起抓進來，要手動截出括號前的譯名），沒附原文的要另外讀（漏附原文本身也違反原文錨點規則）——逐個問「除了要譯的這個概念，軟體或介面裡還有沒有另一個讀者常碰到的東西也叫這個名字」，有就是必修（游標、把手、書籤、捷徑）；軟體以外的日常意思不算（旗標、交易、鉤子合規）；日常功能相似不能當合規理由。已知個案：`rg "游標" <files>` 指的不是畫面上的游標時（分頁或逐批讀取的 cursor 寫「接續標記（cursor）」、資料庫的寫「查詢結果的讀取物件（cursor）」）。**已知個案非窮舉**，這類譯名是開放集合；同源審查者知道那個詞在稿件裡指什麼，所以回報「譯名 clean」不可當真，拿不準的候選交給術語探針，問法加一欄「在技術文件裡讀到這個詞，第一個想到什麼」。另查反方向的錯誤：英文術語第一次出現的位置沒有任何中文說明，同樣違規（量過仍無可靠中譯、第一次出現附了一句中文描述的英文詞合規）。只寫英文這個方向沒有可用的 pattern——實測 `rg "[一-龥] ?[A-Za-z]{4,} ?[一-龥]"` 在一篇分頁文章命中三十處，多半是第一次出現已附中文之後的合規裸用——所以逐個英文術語找它的第一次出現讀。見 [borrowed-everyday-word-as-translated-term](principles/borrowed-everyday-word-as-translated-term.md)
  - **縮寫術語 grep**：`rg "判準"` — 「判準」是「判斷標準」的縮寫，詞面只在科學哲學與教育評量有穩定所指，工程讀者讀不出來；一律寫「判斷標準」，狀態義寫「X 條件」（停止條件、完成條件）。全站替換過兩次仍回流，所以 `content/` 由 lint 規則 `TERM-abbreviation` 以 error 擋下；**skill 目錄不跑 lint，這一類要手動掃**。討論這個詞本身時加「」或行內程式碼。見 [term-probe-measures-register-not-invention](principles/term-probe-measures-register-not-invention.md)
  - **序數、計數與字母代號當名字 grep**：`rg "[一二三四五六七八九十兩]支|[一二三四五六七八九十]步|第[一二三四五六七八九十][步支節級層章階種類條項]|前提[一二三四五]|兩個軸|另一個軸|這個軸"` 與 `rg "\b[A-E][0-9]?\b 那|\b[A-E][0-9]? 與 [A-E][0-9]?\b"` — 正文裡的實體用作者的索引當名字（「第一支的篇落在七步的第三步」「D 與 E 在這裡」），讀者要回頭翻才知道指什麼；判讀用變數名稱測試（當成程式變數名稱過不過得了審查）與落點測試（從中段落進來知不知道它指什麼），修法是用問題／動作／判斷標準／描述命名、段標拿掉序號。**詞綴隨內容變、這條 pattern 非窮舉**：換一個分類先盤點那裡用的是支、步、級、節、層、階段還是別的。命中是候選——緊鄰清單且隨即逐一具名展開的計數、量測事實的數字、外部凍結編號、確實在描述位置而前一句剛列完成員的序數都合規；**「集合不會再變」不構成放行理由**。命中密集的段落順手問它是不是在寫作者的編排思路（各篇怎麼分組、兩篇怎麼分工、改哪一篇），那一類整段移出正文。見 [ordinal-labels-are-the-authors-index](principles/ordinal-labels-are-the-authors-index.md)
  - **部分與一側當名字 grep**：`rg "一部分|另一半|這一半|那一半|這部分|那部分|另一部分|那一側|這一側|另一側|另一邊"` — 被切開的集合沒有名字、切分依據沒寫出來（「有一部分判斷標準交得出去」「交不出去的那一半」），或「一側」當成「就……而言」的譬喻（「在條件這一側還有路」）；命中後問讀者只讀這一句說不說得出每一塊是什麼、以及被切開的整體是什麼（「同一條線的另一半」每一塊有名字而整體沒有，違規）；裸「這部分」回指而前面沒有切分的，按指涉問題改成那一塊的名字。**豁免**：組成句「X 是 Y 的一部分」（部分與整體都在句內）、所屬寫在同一句的「子表這一側……父表那一側」、字面比例。全站實跑 618 處候選、116 處要改，其中兩處的模糊切分底下是寫反的論斷——命名時才發現對不上；替換文字裡新出現的關係（並列、包含、因果）要回原文核對。修法是先寫依據、再用業界術語／案例名／描述短語命名，見 [unnamed-halves-are-unextracted-variables](principles/unnamed-halves-are-unextracted-variables.md)
  - **命名的旁白 grep**：`rg "取一個名字|各取|下文都用|以下逐一說明|以下分別說明"` — 命名的句子另外宣告取名或約定下文用法（「盲區有兩種，各取一個名字，下文都用這兩個名字」）。判讀用刪除測試：刪掉這個子句，讀者少了什麼；什麼都沒少就刪，改成「分成 A 與 B」再逐一定義，成員多時用清單列名字、下一段起逐一解釋。**合規邊界**：「下文把 X 稱為 **Y**」這類子句本身帶著所指與名字，刪掉會失去名字，保留。見 [unnamed-halves-are-unextracted-variables](principles/unnamed-halves-are-unextracted-variables.md)
  - **正反問句當名詞 grep**：`rg --pcre2 "(\p{Han})不\1|有沒有"`（需要 PCRE2） — 「連不連得到」「對不對」「讀不讀得到」這類 A 不 A 問句被當成主語、受詞或介系詞的受詞用，承擔英文 whether 子句的角色而沒有開頭標記，讀者讀到動詞才知道前面那段是問句。命中後問兩件獨立的事：**位置**——讀者讀到它之前，有沒有一個詞（「問」「檢查」「確認」、引號、問號、「是否」）告訴他接下來是問句；沒有就改成直述或「是否」「能否」；主語位置、介系詞「對」後面與多段並列加「都」最重（撞上「連……都」與附加問句「對不對」兩個高頻句型）。**判斷標準**——把謂語（對、通、到、行）單獨拿出來，讀者說不說得出照什麼標準判斷；說不出就寫進去（「是否把請求轉到正確的服務」），這一條在「檢查」後面的受詞位置同樣適用。**合規邊界**：接在「問」「檢查」後面且謂語有標準的、「」內的引語、程式碼。pattern 抓不到夾在句中的「X 嗎」。寫的人知道「對」照什麼標準，所以分析這個形態的段落本身也會寫出它（一次實測七處），要靠掃描。見 [a-not-a-question-as-noun-clause](principles/a-not-a-question-as-noun-clause.md)
  - **「問題」與「回答」當框架詞 grep**：`rg "回答的問題|回答的是|問的是|問題是："` — 系統元件被寫成回答問題的一方，「問題」一個詞同時指檢查的內容、故障、歸屬的範圍與需求。命中後逐處問：這個「問題」翻成英文要從 question、problem、issue、topic、requirement 裡選哪一個；選得出就用那個意思的中文詞重寫並寫出內容（哪裡壞了、處理什麼、屬於哪個範圍、誰需要什麼），同一篇每處選的不同代表一個詞承擔了多個所指；「回答」換成元件實際做的動作（執行、量測、比對、送出、標記）。單獨的「問題」詞頻太高不直接掃，從框架詞找到集中的文章再逐處翻譯；建在這個框架上的自創術語（「問題盲區」）會同時帶著問句與故障兩種讀法。**合規邊界**：場景裡有人實際提問、業界固定術語（「N+1 問題」）、動詞片語「出問題」（密集重複時才換）。見 [question-answer-frame-blurs-problem-issue-request](principles/question-answer-frame-blurs-problem-issue-request.md)
  - **排比的同義反覆（無穩定 pattern，按位置逐句讀）**：讀總覽句、段落首句，以及三個子句以上的排比（「X 的 Y，由 Z 接手；X 的 Y′，由 Z′ 接手……」），逐個子句做**定義代換**——變動格（Z）是否只從話題（Y）的定義就推得出來、不需要本篇的任何其他資訊（「問題盲區由問另一個問題的層接手」）；是的話資訊量是零。輔助檢查是**語序翻轉**：改成動作者在前（「問另一個問題的層接手問題盲區」），變得明顯空洞的子句就是被話題在前的語序遮住的那一個。排比裡有子句打破骨架、或總覽句寫在它所總覽的對象被介紹之前，都是候選訊號。修法：填實際的配對（具名的元件、人或步驟），或寫出這組分類帶來、讀者從定義推不出的判斷；填不出名字的子句不進排比。「每個半句能獨立判真」對它放行（同義反覆必然為真），四槽位也常放行（角色描述有名詞頭，看起來像已填的槽位）。見 [parallel-clause-filled-with-the-topics-definition](principles/parallel-clause-filled-with-the-topics-definition.md)
  - **脈絡懸置 grep**：`rg "等下再|稍後再|之後會(講|談|提到)|後面會(提到|講|說明)|下面會(提到|講)|如前所述|前面(提過|說過|講過|幾個小節|兩個小節)|上[一面](提到|說過)|用一句話(總結|概括)|一言以蔽之"` — 把脈絡寄存在讀者工作記憶裡的三種句式：前向懸置（「等下再討論」是沒有內容的欠條、到期時讀者已不記得）、位置回指（「前面兩個小節」要讀者持有位置地圖、中斷後的讀者不持有）、壓縮總結（「用一句話總結」把形狀推遲到文末補交）。判定看指涉攜帶什麼——只有位置或時間違規、攜帶內容名（最好再帶連結）是合法路由（「那正是 C 那本要處理的問題」）；緊鄰的近距指涉（「見下表」而表在下一行）、「」內引用、已具名對象的向後回指合規。同類的結構層形態**列舉鳥瞰**（「分成兩組、第一組四本講……」）grep 候選 `rg "分成[兩三四五]組|第[一二三四]組"`、要讀者 hold 整張清單才能繼續讀，修法是關係鏈——成員逐個以它與前一個成員的內容關係進場；緊鄰表格或清單且各成員隨即具名展開的合規。見 [coherence-by-shape-not-reader-memory](principles/coherence-by-shape-not-reader-memory.md)
  - **教室形式三形態**（教學定位被讀成教室講課時的殘留，三個形態各有檢查方式）：
    - **形態一：情境故事開場**——判別是刪掉開場第一段之後，不熟這個主題的讀者還能不能判斷這篇跟他要找的東西有沒有關係。開場的職責是寫出這篇討論哪些東西：逐一列出各段落的主題，寫到讀者能逐項對照自己需要的程度；適用的版本、環境與另有專篇的面向接在內容之後。只交代範圍（「範圍從 A 開始，到 B 為止」）也不夠，讀者要先知道整個主題由哪些部分組成，才看得懂 A 與 B 之間有什麼。改前：「本篇的情境來自一次實際排查⋯⋯」；改後：「這篇整理電腦經由 Wi-Fi 用 adb 連線到 Android 手機之後，遠端排查用到的指令：在多台裝置中指定要操作的那一台、擷取螢幕畫面與錄影並確認傳回的檔案完整、查出畫面最上層是哪個 App 的哪個 Activity、用 logcat 篩出某個元件啟動前後的紀錄、查詢 App 權限與使用者限制這類狀態，以及放寬安裝管控的修改型指令。」
    - **形態二：省略主詞受詞**——grep 抓不到（缺的字沒有關鍵詞），靠冷讀（2-B′）或理解探針。判別是每一句的操作主體讀者在只看這一段的情況下能不能還原。改前：「回答的卻是沒問的那個問題」；改後：「把 `dumpsys user` 的輸出交給 `grep -i restriction` 過濾時，比對到的行包括 `Guest restrictions` 區塊裡的 `no_install_unknown_sources`；這個區塊列的是 guest 使用者型別的預設限制。」結果寫成可以觀察到的狀態（安裝、執行、成功、失敗、沒有回應、回傳哪個錯誤碼）；「裝得起來」「被擋住」「撈到」只說了結果的方向或用了口語動詞，沒有說出結果是什麼
    - **形態三：教室互動語句 grep**：`rg "該問誰|要問誰|容易搞錯|容易讀反|容易認錯|前面提到的|前面說的|先確認.*再|先讀懂.*再|注意這裡"`。修法是把互動句改成直述——「這裡容易讀反」改成引導看對的欄位並給出正確的讀法；「不能預設第一行就是有焦點的那一組」改成「`dumpsys window` 替每個顯示器各印一組 `mCurrentFocus` 與 `mFocusedApp`，讀輸出的人跳過兩個欄位的值都是 `null` 的那幾組，值不是 `null` 的那一組屬於有焦點的顯示器」。command 中性陳述語句合規
    - **形態四：判定標準包裝成自問自答 grep**：`rg "問自己|問一個問題|然後問"`。改法是拆成條件與通過標準
    - **形態五：「問得出/問不出」替代指標 grep**：`rg "問得出|問不出來|問不出"`。改法是寫出指標名稱與通過標準
    - 根因與判讀徵兆見 [teaching-is-not-lecturing](principles/teaching-is-not-lecturing.md)
  - **補充資訊歸位**（先備知識與環境陷阱有沒有跟在所屬的指令旁邊）——grep 抓不到，判別問句是「讀者在讀到哪個位置時會需要這段資訊」。遊離的形態：參數的理由獨立成段而讀者掃表格時跳過它、環境陷阱跟在無關的段落後面。修法是搬到所屬的指令或概念旁邊——表格欄位裡、或緊跟指令的說明段。改前：`-G 16M` 的放大理由寫在表格下方一段散文裡；改後：搬進表格的用途欄。見 [supplementary-knowledge-follows-its-parent-concept](principles/supplementary-knowledge-follows-its-parent-concept.md)
  - **敘事姿態 grep**：問句標題 `rg "^title:.*[？?]"`、問句段標 `rg "^#{2,} .*[？?]"`、敘事轉折詞 `rg "才想清楚|還是被退|我到底|我於是"`、輔助訊號是檢討類文章的「我」密度顯著高於同類其他篇 — 教學與檢討內容寫給帶問題來的讀者、標題寫主旨、結論與判斷標準由推導交付（不設懸念、也不把結論抽到開頭灌輸）、檢討用客觀條件視角；操作型自問句（判斷標準的執行步驟）與「」內引用合規、標題 / 段標 / 結論位扣住答案的問句違規、未經推導的開頭結論摘要與欄位組同屬違規；這類是生成端高頻預設、審查是補位、防線主力在生產側規範與模板。**虛構經驗軸（AI 生成內容）**：第一人稱複數經驗宣稱 `rg "我們團隊|我們的團隊|我們公司|我們曾|我當時"` 與精確出處宣稱（「第 N 頁寫道」+ 引號引文）預設待驗——經驗宣稱是證據宣稱、虛構是造假不是修辭；先判定事件存不存在、再改姿態（順序反了會把虛構藏進條件視角）；引文逐字核對、出處只寫到驗證過的層級；真實事件的工作紀錄與「」內他人自述合規。**grep 只覆蓋三個掃描面裡的一面**：虛構的人更常以第三人稱出現（PM / reviewer / 同事 / 新人 / 團隊士氣），沒有穩定關鍵詞、靠逐篇讀開場，而動機句常掛在這些角色身上；**判定單位是生成批次不是關鍵字命中**——一篇被判定虛構之後用版本歷史查同批（同 commit / 同日期 / 同模板）整批逐篇驗，清單清空不等於批次清空（一次實測：關鍵字命中 6 篇、實際同批 31 篇）。見 [no-fabricated-experience-or-attribution](principles/no-fabricated-experience-or-attribution.md) 與 [write-for-readers-not-audiences](principles/write-for-readers-not-audiences.md)
  - **結論句標題與段標 grep**：標題 `rg -n '^title:.*(決定|主導|取決|不是|而是|才|就是|等於|只是|只有|由誰)'`、兩個子句以上的段標 `rg -n '^#{2,3} .*[，,]'` — 教學文章的標題與段標寫主旨（對象與交付的內容種類）、不寫成結論句；命中後問這一行有沒有謂語在下斷言，有就改寫成主旨、把那句結論放回正文裡推導走完的位置（先確認正文那個位置真的有這一句）。**合規邊界**：「管理」「決策」這類名詞的命中、描述這一篇做什麼事的「對象＋動詞」（「從入口程式看應用啟動流程」）、並列成員的逗號合規；歸納問題與解法的記錄是否比照由各內容集合裁定。「名詞讀者認不認得」那一半沒有關鍵詞可掃，寫的人自己判不準（他讀過全文），靠只給標題清單的讀者探針。改名之後同一次核對連結文字、節名引用與錨點。見 [title-states-the-subject-not-a-premised-conclusion](principles/title-states-the-subject-not-a-premised-conclusion.md)
  - **用詞搭配錯位 grep**：`rg "說完的話|背後.{0,8}的話|想告訴|潛台詞|訊號很直接|訊號.{0,4}很直接"` — 把抽象概念（角度 / 框架 / 訊號 / 數字）配上不貼合屬性的謂語：擬人化錯配（角度不會「說」、數字不會「想告訴」）與形容詞錯配（訊號的可辨識度是「清晰 / 明確」不是「直接」）。無穩定關鍵詞、grep 只抓已知形態、真防線是異源冷讀（跟 register 類同屬同源盲區）。見 [word-choice-fits-concept-attributes](principles/word-choice-fits-concept-attributes.md)
  - **物理化錯配 grep（同一張卡四種錯配裡唯一有一組高密度關鍵詞可掃的）**：`rg "撐得住|撐不住|撐得起|撐不起|能撐|撐住|撐起|撐不久|站得住|站不住|站得起|站不起|掛在|扛|垮|頂得住|咬得|咬合|啃"` — 抽象概念（證據、論證、結論、判斷標準、方法、責任）配上承重、支撐、懸掛類的動詞。證據跟結論之間沒有重量、沒有支點、沒有材料強度，那些動詞不帶進資訊，只是把讀者對物理世界的直覺借過來蓋住實際的關係。**偵測可機械執行**：問這個動詞照字面成立需要什麼物理條件——需要重量、支點、材料強度、上下方位的就是借來的；這一步找出候選、不決定修法。**修法看句子在做什麼**：描述關係的（論證掛在前提上、責任由誰扛）換成關係動詞——論證**依賴**前提、資料**佐證**、責任由某人**負責**；足夠性斷言（宣稱某個對象足以或不足以滿足某個需求的句子：證據撐不撐得住、方法撐不久、這套說法會垮、資料庫撐得住這個流量）佔著需求與判斷標準的位置，與「問題」這個詞同一類，改寫要寫出**需求**（支持哪個決定、承受什麼負載、維持多久）、**判斷標準**（滿足到什麼程度算夠）與**機制**（靠什麼屬性滿足、在哪一點不再滿足）——換成「足以支持」「維持不久」仍然沒寫，不算修好。分界問一句：這句話是否在宣稱某個對象足以或不足以滿足某個需求。**清單裡的其他動詞同樣先判斷佔住哪一格**：拖垮、壓垮、扛不住佔住失效的形態與傳遞路徑（寫出哪個元件失效成什麼樣子——變慢、無回應、崩潰、資料錯誤——經由哪一項共用資源傳過去），硬扛、啃佔住負擔（誰承擔哪些工作、代價是什麼），掛在、咬合佔住關係（依賴、隸屬、耦合程度），站得住佔住可信度（多半整句不寫）；負載情境再分容量、過載、故障擴散、突發緩衝與耗盡時間，「負載」本身要寫出單位，容量數字只留在範例情境並標明來源，見 [physical-verbs-stand-in-for-content](principles/physical-verbs-stand-in-for-content.md)。**例外**：明示並就地展開成可逐項對應的類比（物理意象在同一段被對回真實機制）合規；沒展開的就是借詞。**系統負載不豁免**：「撐住尖峰流量」「拖垮 OLTP」有物理對應，而需求與判斷標準照樣被省略，要寫出負載量、判斷標準（例如延遲門檻）與瓶頸在哪一項資源；結構上的實際連接（「route table 掛在 subnet 上」）不是足夠性斷言，合規。先前的全站實測（716 個命中行判 68 個違規）是在系統負載豁免下量的，取消豁免後違規數會上升。**這串清單是抽樣、不是這一類的全部**——能進清單的只有違規義項佔該詞用法多數的詞，而本義合法的直譯（「滑坡」的本義是山崩，違規的只有 slippery slope 借來的義項；「下滑 / 滑落 / 滑向某個狀態」合規）與詞頻過高的泛用動詞（「拿到的是理解」——讀書得到的是理解、該說學到 / 讀出來 / 得到的教訓；而「拿到的需求 / 拿去用」合規）都漏在清單外，加進去只會用噪音蓋掉訊號。兩者改用探針：**補語型態探針**（「⋯⋯的是」後面接的是完整斷言而非名詞組時，前面那個動詞多半選錯——精準的認知動詞容得下子句、物理取得動詞只容得下名詞組）與**本義探針**（那個詞在本語言的本義是什麼詞性、什麼類別，跟句子把它當成什麼在用合不合）。換詞時同義詞要按語境分散，一律替換會用新模具換舊模具。判斷標準與清單的分工見 [keyword-list-needs-dominant-violating-sense](principles/keyword-list-needs-dominant-violating-sense.md)。見同一張 principle 卡
  - **結構譬喻頂替主詞與動詞 grep**：`rg "條線|書線|各接|承接|接得住|接不住|一個面($|[^向])|那一面|這一面|走《|，走 \[|住在|決定落在|決定的對象|承擔的角色|從印象變成"` — 內容集合的組織者替自己的結構取了空間與搬運的名字（分類是幾條「線」、每一篇「承接」一個「面」、讀者「走」到下一篇、判定「住在」某一篇），寫進正文之後佔住了主詞與動詞。三種形態各藏一個槽位：譬喻當單位名藏主詞（換成集合裡實際的單位名：書單、主題篇、面向；「一側」照〈部分與一側當名字〉判）、搬運與居住動詞藏動作（換成實際的動作與動作者：討論、涵蓋、讀、收在、寫在、在這一篇的用途是）、轉化句藏動作者（「把 X 從印象變成數字」→「用哪幾項數字取代對 X 的印象」；「X 的決定落在 Y」→「X 討論的主題放在 Y 上」）。分工句寫成「這三本各自討論不同的面向：《A》討論…，《B》分析…」，句子本身就是分工；寫成「一個面向」時，同一句或下一句寫出是哪個面向。**判讀分兩種問法**：線、面、接、承接、走、住在、落在這組空間與搬運譬喻，先問這個詞描述的是不是內容集合的結構（分類、篇章、目錄頁、讀者的閱讀路徑、判定寫在哪裡），描述系統、市場或領域對象的多半合規，仍逐處問主詞做不做得了這個動作；轉化句與「承擔的角色」不是空間譬喻，不套這一問，改問〈每一句先填槽位再成句〉的「這一句描述的事誰做、主詞做不做得了這個動作」。集合的目錄頁（索引頁）也是集合的結構，照這一條判。**換詞**：替換詞照同一條再掃一次、判讀照樣問；依語境寫出實際的動作，不全篇換成同一個詞（「承接」一律換「涵蓋」是新的模具），換成「銜接、串起、扮演…角色、負責承載」只是換一個譬喻。**pattern 非窮舉**（詞取自一個書單集合與它的新稿）：掃一個集合時，讀它的目錄頁、範本的段標與分工句，找出當「處理／討論／收」主詞的組織名詞與連結前面的動詞；補進的詞先抽樣，違規義項佔多數才加（判斷標準見 [keyword-list-needs-dominant-violating-sense](principles/keyword-list-needs-dominant-violating-sense.md)），命中多半是「第二層」這類序數分層的，歸〈序數與代號命名〉；逐類表這一列寫出補進的詞與讀了哪幾份檔案，沒補到詞時寫讀了哪幾份。以舊文章為範本寫新稿時什麼時候掃，見〈批量 sibling 寫作的生成端輪替〉。誤報依集合差很多：基礎設施類的「承接」多半是系統元件承接流量，財務類多半是「承接量」。**轉向其他條目的情形**：「承接」的主詞是正在讀的這一篇或這一個模組、描述它自己怎麼編排（「承接的就是這一段」「本模組承接另一模組的概念判讀」），歸 Core Principles 第 3 節〈連貫靠句句推進〉的文章自指；描述另一篇、另一個模組涵蓋或沒涵蓋某個主題（「模組七沒有一篇承接這個主題」）照本條判；「接得住／接不住」宣稱足不足夠時，照〈物理化錯配〉的足夠性斷言寫出需求、判斷標準與機制；主詞是物的「承擔」同時是〈用詞搭配錯位〉的擬人化；「這條線」指分界或判斷標準時，換成現成術語（判斷標準、門檻、邊界）。**合規邊界**：系統元件承接流量、連線或請求（「由 Cloud NAT 承接出站連線」）、市場交易的承接（承接量、承接買盤）、當譯名用的「承接（assume）」、人接手一件事（「這個決策由誰承接」）；領域裡本來就叫「線」的名詞（產品線、資產線、時間線、邊界線、圖表的曲線、職涯的技術路線）；字面的線性排列，限定排列的是實體或版面（「不排成一條線」；「把地基串成一條線」是組織譬喻，不在此列）；「線索」；「住在」的主詞是檔案、目錄、資源，或系統裡的規則、資料與元件（「collation 住在欄位上」「最佳化器住在引擎裡」），描述內容集合時主詞是內容、判定、解釋的改「寫在」；主詞是人的「承擔的角色」；「決定落在哪一格」這類讀者在選項之間的選擇，以及讀者、改動、書、篇或判定「落在」某個條件、選項或分類（意思是屬於）；引號內示範對話裡的用法。規則類文件（規則檔與 skill，包括本 skill）用承接、住在、落在描述路由目的地、資料夾，或內容寫在哪一個檔、哪一段、哪一處（「承接這個主題的資料夾」「推導住在 report 卡」「多份落在同一處」）的用法還沒有判定：審查時不列 finding，逐類表寫「未判定」，改寫到這些行時保留原詞；規則類文件裡其餘的結構譬喻（「這條線」「各接一個面」）照本條判。改寫時補出的主詞或對象，回到被介紹的對象（書、文件）與稿件前文核對。見   - **替讀者假設情境與頻率 grep**：`rg "每週都|每天都|每次都會|天天|經常要|常常要|常常會|總是要|永遠在|一定遇過|都遇過|都經歷過|躲不掉的|免不了|總會遇到|遲早會"` — 一句話替讀者決定他經歷過什麼、多常發生（「這個位置每週都會遇到的那場對話」），把一個條件寫成讀者的日常；沒經歷過的讀者對不上，可能推論自己做錯了什麼、或這份內容不是寫給他的。修法是寫成職責或條件並寫出發生的前提（「這個位置的職責包含的一種對話：團隊成員交出來的成果不夠好時，由對別人的產出負責的人指出這件事」）；誇大的頻率（「天天開會」「永遠在救火」）換回它要說的機制（「之間要持續協調」）；「多數這類對話難開口」若是引用的分析，寫出來源的名字（「依《書名》的分析」），是撰稿者自己的判斷時寫出依據或刪掉「多數」（這一形態沒有 pattern，逐處讀介紹來源的句子）。**判讀問句是這個頻率描述的是誰的經歷、有沒有寫在一個條件或程序階段之下**：描述讀者的經歷而沒有條件的是這一類（「真正天天影響你的是其中幾條」的文法主詞是物，頻率仍然加在讀者身上），只看文法主詞兩個方向都會判錯。條件寫在同一句、或同一段裡這一句之前都算；條件要是讀者拿得來對照自己處境的事實（「有三個以上的團隊、交接面開始需要設計時」），「在某些團隊裡」「團隊大了以後」不算條件。第二人稱的形態（「你天天用的」「你一定遇過」）同時落在〈對讀者喊話〉，用詞照那一條改。**這一類的主要防線是異源冷讀，pattern 是輔助**：它只抓帶頻率詞的形態，命中多半是系統或機制自己的運作；用指示詞預設讀者認得一個情境的形態沒有固定關鍵詞，候選用 `rg "那場|那種|那一刻|那個時刻"` 掃這次的掃描檔案集，命中後問前文有沒有描述過那個情境、這個處境是不是每一位讀者都有。**合規邊界**：頻率描述的是系統、程序或機制自己的運作（「排程每天執行一次」「債齡每天都在增加」），或讀者以外的第三方與外部事件（「客訴每天都在發生」「每天都有上百個搶購活動」）；頻率寫在條件或程序階段之下（「主機經常重建的環境裡」「導入期間管理員仍要天天登入主機」）；頻率寫在判讀訊號裡（「規則清單每週都在加新案例時，代表……」）；有資料來源的頻率；段首寫明「具體是這樣」「舉一個例子」的假設示範；沒有主詞的類比句（「裝修完之後每天都在受益」）不屬這一類，照〈用詞搭配錯位〉判。見 [sentence-assumes-the-readers-situation](principles/sentence-assumes-the-readers-situation.md)
  - **散文夾程式（計數找候選）**：去掉程式碼區塊後，一個散文段落裡行內程式碼達十處以上的列為候選——`python3 -c 'import re,sys;[print(f,n) for f in sys.argv[1:] for n in [max([len(re.findall(r"`[^`\n]+`",p)) for p in re.sub(r"```.*?```","",open(f).read(),flags=re.S).split("\n\n") if not p.lstrip().startswith(("|","-","#",">"))]+[0])] if n>=10]' <檔案…>`。命中後問這些行內程式碼拼起來是不是一段讀者該整塊看的程式（一個查詢、一條指令、一段輸出）；是的話程式與逐行解釋移進區塊寫成註解、推導留散文。各自是獨立名字的（欄位名、路徑、設定鍵）不必移，一串工具名是清單問題。十處是縮小候選的門檻、不是判定條件。**計數掃不到的形態是散文描述一段頁面上沒出現的程式**（「多一則三星之後回 101」「換成 `NOT EXISTS` 回 102」「展開之後是……」），行內程式碼只有兩三處，改用句型找候選：`rg '(多|加|再加|刪掉?|改成)[一兩]?[則列筆張個][^。]{0,20}之後|換成[^。]{1,20}回|展開(之後|成)|也修不掉'`；能跑的就把程式與資料寫出來實跑、結果寫成註解，跑不了才照「不補」處理。見 [code-fragments-in-prose-make-readers-reassemble](principles/code-fragments-in-prose-make-readers-reassemble.md)
  - **指令引數未說明的檢查**：有詞形可掃的三類——`rg -n '^\s*[a-z].* /[a-z][a-zA-Z0-9_./-]*'`（指令裡的絕對路徑）、`rg -n '^\s*[a-z].* [A-Z][A-Z_]{3,}'`（全大寫的常數引數）、`rg -n '<[a-z_]+>'`（佔位符，用來對照哪些位置已經被解釋過）。**命中是候選、而更重要的是漏網的那些**：小寫識別碼形式的引數（`secure`、`windows`、`allow`）沒有穩定詞形，grep 抓不到，要逐條指令過判斷標準問句。判定看那個位置的說明在不在全文裡，不看指令本身寫得清不清楚——**區塊裡的字面值讀起來永遠是完整的**，所以逐句自審與同源冷讀對這一類一律回報通過。見 [literal-operand-hides-the-change-point](principles/literal-operand-hides-the-change-point.md)
  - **並列括號的關係檢查**：沒有關鍵詞可掃、形態可掃——`rg -n "^\s*[-*0-9].*（.+）\s*$"` 找出以括號收尾的條列項，連續三個以上就把整組抽出來並排，逐個寫下它與前面那個詞的關係（解釋 / 定義 / 範例 / 驗證方法 / 紀錄內容 / 度量）。**版面上的同構本身是一個宣告**，讀者依它去解讀每一個括號，各裝不同東西時他找不到那條統一規則就逐個猜——一次實測六個括號被探針判讀出六種關係，其中「形態數（簽核人與日期）」被讀成定義而照此執行的人會去數簽核人。每一個括號單獨看都通順，所以逐句自審過得去、要整組並排才看得見。修法是換成表格的顯性對映（讓表頭說出那個關係），或在括號裡加關係詞。條文被宣告為可執行時零容忍。**合規邊界**：嚴重度依條文可執行性分級——可執行條文零容忍列可改；目錄型列表與純說明性條列降為 Info；AUQ label／description 等規格字面的括號（內容為欄位規格非解釋）不計。見 [parallel-parentheses-imply-a-uniform-relation](principles/parallel-parentheses-imply-a-uniform-relation.md)
  - **懷疑某個詞本身不通用時有第二個探針：術語探針**。對象從一段文字縮成一個詞，問多份低階模型這個詞在該領域指什麼——作者對自己寫過幾百次的詞已經沒有陌生感，這一項自審測不出來。設計上多一個條件：**同批混入至少兩個已知通用的術語且不標示哪個是控制**，控制詞收斂才代表分歧可歸因到詞本身。回答分四類讀而收斂度只分得出前三類（收斂＝通用、各給不同定義而都有把握＝一名多義、全部沒見過＝非通用）；第四類是少數份有把握而它們一致指向另一個所指——這個詞在同一個領域已經有主人，處置只能換掉且要換成描述，所以 prompt 要多一句「有把握的那些，寫出它指的東西」。而**非通用不等於自創**——真實存在於別的領域的詞在這裡讀不出來是語域錯配，處置相同而檢討的歸因不同。這一項也用來判口語譬喻算不算正式書面語，替換要先列詞形分佈再按義項走，見 [term-probe-measures-register-not-invention](principles/term-probe-measures-register-not-invention.md)。
  - **grep 抓不到的那幾類有一個補位偵測：翻譯探針**。把同一段中文派給多份低階模型翻成英文，判斷標準是份與份之間的分歧——**中文允許不決定的語法項，英文強制決定**（主詞、單複數、所有格的方向、並列的轄域、字面義還是譬喻義），譯者無法把原文的模糊態原樣搬過去。它對本節底下這幾類特別有效：頂替術語的譬喻（有現成術語的概念多份會收斂到那個術語、用譬喻的會分歧成多個英文詞——這是譬喻判斷標準的量測方式）、回收式過場那類零資訊句（中文的四字節奏讓空話讀起來像在做事、英文沒有那個節奏支撐）、位置與集合指涉裡的跨頁綁定（原語言讀者掃過去不停、翻譯者必須決定意思）、以及所有格方向與並列轄域這類 bank 沒有涵蓋的語法項。指令的產出是「翻譯時我必須自己決定、而原文沒有明確給出的東西」那一欄、譯文是副產品。**收斂也要驗一步**：三份收斂到同一個讀法通常是好消息，而收斂到同一個**錯誤**的讀法指的是原文替譯者做了決定、只是做錯了（一次實測：三份把「那一篇的三本」全部譯成 three statements，成因是指涉在同一句裡換了對象而句尾的鄰近詞把讀法拉過去）——回原文查一次那個讀法對不對，這一步的成本是一條 grep。**自稱可機械執行的條文有兩個語法項要先關掉**：基數（「對應到一個容器元件」不決定至少一個還是恰好一個，而一個關係對到兩個元件時兩者判定相反）與否定的轄域（「不」加單音節動詞可以是不執行這個動作、也可以是不施加這個要求，在規則文裡分別代表保留它與可以不填）。這一類的**分歧不會進探針自己的決策清單**——譯者當下沒有意識到自己在決定，所以要把譯文並排逐句對照，「決策清單很短」不代表原文乾淨。稿件要先通過理解探針才跑這個——命題層還沒收斂就跑會被大量低層 finding 淹沒。詳見 [translation-forces-disambiguation](principles/translation-forces-disambiguation.md)
  - **翻譯探針的獨立性不可讓渡：不要在寫作當下自己產出譯文當校對。** 訊號來自份與份之間的分歧，而分歧要能歸因到原文，前提是譯者無法用意圖補完——寫這段的實例自己翻是最極端的形態，餵整篇脈絡給它是同一件事的弱化版。一次十份對照（指令逐字相同、只差讀到的範圍）結果完全分離：有脈絡的 5/5 譯成作者意圖的讀法且零人標記不確定，無脈絡的 5/5 譯成另一個讀法。**會傷到讀者的歧義，正好是作者毫無困難就能解決的那一種**，所以自譯對它全盲、產出的譯文是一張錯誤的合格證明。寫作端要留下的是一個問句，不是譯文——**沒讀過前文的人拿這一句，能不能定位到唯一的對象**；答不出來就當場具名。見 [probe-independence-is-not-transferable](principles/probe-independence-is-not-transferable.md)。
  - **命中數不是涵蓋率**：一條回傳大量命中的 pattern 讀起來像「這一類有在管」，於是「這個體裁的這一類還有沒有別的形態」不會被問——零命中至少還會讓人懷疑 pattern 寫錯了。跑完一批修正之後回頭比對命中數：修了幾十處而數字幾乎沒動時，修的東西與量的東西不是同一批。這個對照免費（改動前後各跑一次），而它是涵蓋缺口最早的訊號。**掃描指令本身也要驗**——同一個 session 內三次因為指令而非內容漏報：zsh 的字串沒斷行、`uniq -c` 的輸出被誤讀、以及要求前後脈絡的 regex 略過了靠近行首行尾的命中。回報 clean 之前，先拿一個已知會命中的字串餵給同一條指令。 **這三種裡最後一種有個可執行的修法，而它背後是一組相反的失效方向**：換行與儲存格分隔符要**替換成單一空白**，不要刪除、也不要拿它們當切段的邊界——拿來切段會讓跨行或跨格的命中漏報，直接刪除會把相鄰的字接成原文沒有的字串而生出假命中，兩者都不報錯。取前後脈絡的掃描因此寫成不限長度的形式（`.{0,20}` 而不是 `.{20}`），並在回報零行時先看計數是不是也為零——**計數非零而脈絡零行，零的是切段不是內容**。
  - **這些 grep 曝光候選、不做自動判定**：命中後要不要算違規有品味核心；且 LLM reviewer 跟作者共享文體、同源自審對 register 類（否定起手 / 喊話 / 誇飾 / 概念前置）有結構上限 ——「不是 X、而是 Y」這種 LLM 高頻自產句型最容易全員放水。grep + 同源判定只負責曝光候選、register 層的真防線是文體異源視角（human cold-read 或 prompt 採「挑剔否定起手 / 概念後置」對抗姿態的 reviewer）、同源回報的「clean」不可當真
  - **判斷標準外交接**：驚嘆號等標點強度重複、逐字重複兩處歸「同一件事兩形」（結構層一致性判斷標準，非本清單類別）；skill / reference 檔頭缺三段式（何時讀／同目錄／溯源）歸結構約設定判斷標準（self-application sweep 的 self-grep 對象）。兩者字面上像字句層問題、但本清單無對應類別，不列為本清單 finding
  - **1-A 掃描的另兩份判斷標準（非本清單成員）**：跑 1-A 全批掃描時，「隱含詞」歸文件撰寫明示性判斷標準，合規邊界已載於該專案的文件撰寫明示性規則（其撰寫前檢查清單一節）；「優化」等禁用詞豁免範圍與 zhtw cross_strait／confusable 命中判專案 canonical 歸語言約束判斷標準，合規邊界已載於該專案的語言約束規則（禁用詞那一條）。本清單不重複載述條文內容，語意與命中規則以各自正本為準

**逐類表留在版本控制看得到的位置**：照本節跑完一批稿件的產出是一張逐類表——掃了哪幾類、各命中幾處、每處的語意判定，零命中的類別也列。這張表（連同探針回報的歸因，如果跑了探針）寫進 commit message 或專案的工作紀錄；只寫在對話回覆裡不算留下紀錄，因為對話結束之後沒有人讀得到它，而「完全沒跑」與「跑了零命中」在產物上看起來一樣。

詳細各維度的判讀規則跟修法、見對應 reference（writing-articles / writing-documents 等）跟 principles 目錄內的 cadence-homogenization / colloquial-rhetoric / regional-terminology / decorative-symbols / multi-pass-review-frame-granularity 等原則卡。

協同要點：

- 單獨用 multi-round-review、容易漏字句層 — reviewer prompt 列「規範遵循」但漏 grep 具體 pattern
- 單獨用本 skill、容易漏跨輪 frame 規劃 — 知道要檢查字句層、但缺「Round N+1 用什麼新 frame」結構
- 兩個 skill 一起啟動 — multi-round-review 給結構、本 skill 給每輪的 grep checklist

寫作對象是「單篇 + 完稿前自己 review」時、用本 skill 第 6 原則（多輪 Re-read Pass）的 5 輪 frame 即可；寫作對象是「跨多篇 + agent reviewer 平行 audit」時、multi-round-review 接手結構規劃、本 skill 在 reviewer prompt 內被引用作為檢查清單。
