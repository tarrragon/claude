# Reference Authoring Standards

本文件為 compositional-writing Skill 的 reference 撰寫品質規範。適用對象：新增或修改本 Skill 任何 reference 的作者（人類或代理人）。

> **自包含聲明**：閱讀本文件不需要先讀其他 reference。品質驗收 metric（M1-M2）見 `meta-metrics.md`；本文件聚焦「如何寫出符合品質的 reference」。

## 支撐本檔的原則卡

- [parallel-parentheses-imply-a-uniform-relation](principles/parallel-parentheses-imply-a-uniform-relation.md)：一組並列的括號各裝不同東西時，讀者會先找一條統一規則——給可掃描的形態（連續三個以上以括號收尾的條列項）與嚴重度依條文可執行性分級。
- [judgment-rule-fixes-the-trigger-and-trace-not-the-answer](principles/judgment-rule-fixes-the-trigger-and-trace-not-the-answer.md)：要靠判斷的條文分成什麼時候判斷、判斷留下什麼、判斷的答案三個部分，前兩個寫成查得到的事實，第三個不寫成條件；支撐〈要靠判斷的條文寫成留意項〉。

## 何時參閱本文件

| 觸發情境                    | 動作                           |
| --------------------------- | ------------------------------ |
| 新增一份 reference          | 遵循本文件的結構模板和品質標準 |
| 修改現有 reference          | 確認改後仍符合五項必要要素     |
| 審查 Skill PR/Ticket        | 逐項對照本文件的「驗收清單」   |
| 懷疑某 reference 違反原子化 | 執行「職責單一性測試」         |

## 一份合格 Reference 的五項必要要素

### 要素 1：情境聲明（何時讀這份文件）

每份 reference 的開頭必須有明確的「情境說明」段落，讓讀者在 30 秒內判斷適用性。

**必須回答的問題**：

- 這份 reference 服務哪種寫作情境？
- 讀者帶著什麼問題進來？
- 不適用的情境是什麼？

**範本**：

```markdown
本 reference 為「撰寫 prompt / instruction / Agent 派發」情境。

適用：給 AI 模型的指令；Ticket Context Bundle；結構化派發 prompt。
不適用：文件（見 writing-documents.md）；程式碼註解（見 writing-code-comments.md）。
```

**反例**（情境不明確）：

```markdown
本文件說明寫作原則的應用。
```

---

### 要素 2：職責單一性（原子化測試）

每份 reference 只服務一個讀者群體、回答一類問題。

**判斷方法（原子化測試）**：

| 問題                     | 若需要「和」連接兩個答案 | 行動     |
| ------------------------ | ------------------------ | -------- |
| 「這份文件的讀者是誰？」 | 兩個不同讀者群體         | 必須拆分 |
| 「讀者帶著什麼問題來？」 | 兩類不相關問題           | 必須拆分 |
| 「讀完後讀者能做什麼？」 | 兩件不相關的事           | 必須拆分 |

**反例**（雙重職責）：

一份 reference 同時說明「如何撰寫 prompt」AND「如何撰寫其他 reference」——兩個讀者群體、兩種產出，必須拆分。

---

### 要素 3：自包含性（M2 通過）

讀者**不看 SKILL.md 和其他 reference** 的情況下，能獨立理解並套用。

**自包含清單**：

- [ ] 開頭有情境說明（不依賴 SKILL.md 判斷適用性）
- [ ] 文件內所有原則在本文件內展開（不引用其他 reference）
- [ ] 專有名詞在首次出現時給出就地定義
- [ ] 無「見 writing-xxx.md」的交叉引用（禁止鏈式）

**可接受的外部引用**：

- 引用外部公認資源（Anthropic 官方文件、業界標準）
- 引用 SKILL.md 觸發路由（只在「閱讀決策」表格中）
- 引用 meta-metrics.md 的量測方式（品質驗收場景）

---

### 要素 4：結構一致性

本 Skill 的所有 reference 遵循相同的段落骨架，便於讀者跨文件快速定位。

**標準骨架**：

```markdown
# [Reference 名稱]

[1-3 行情境說明，含適用/不適用聲明]

> **自包含聲明**：[說明閱讀本文件是否需要其他前置文件]

---

## 何時參閱本文件（或：情境定位）
[觸發情境表格]

## 為什麼 [情境] 需要獨立指引
[說明此情境的特殊性，與一般文件的差異]

## [核心原則 × 情境] 的應用
（依情境選擇相關原則展開，每個原則含判斷標準 + 反例 + 正確做法）

## [情境特有章節]
（例如：Token 節省策略、結構化範例、自檢清單、反模式速查）

## 延伸閱讀（可選）
```

**允許調整**：

- 章節名稱可隨情境調整（「Token 節省策略」僅適用 prompt；「Log 結構化格式」僅適用 logs）
- 字數無硬性上限，但每個章節應只承載一個概念（M4 候選閾值 ≤ 3000 tokens）

---

### 要素 5：范例的具體性

範例必須足夠具體，讀者能「複製後略作修改直接套用」。

**範例品質標準**：

| 標準                 | 說明                                                    |
| -------------------- | ------------------------------------------------------- |
| 有反例對照           | 每個原則至少一組「錯 vs 對」範例                        |
| 反例真實             | 反例應來自真實常見錯誤，不是刻意構造的極端案例          |
| 正例可直接套用       | 正例使用佔位符 `{ticket_id}` 等，讀者換掉佔位符即可使用 |
| 說明節省量（如適用） | Token 節省策略應標注估計節省比例                        |

## 新增 Reference 的決策流程

在建立新 reference 前，先回答以下問題：

```text
1. 此情境是否已有 reference 覆蓋？
   是 → 擴充現有 reference（不新增）
   否 → 繼續

2. 此情境的讀者群體是否唯一（原子化測試）？
   否 → 拆分或重新定義情境邊界
   是 → 繼續

3. 此情境是否需要對核心原則的「情境翻譯」？
   否 → 考慮是否應放入 SKILL.md 核心原則速查表（不需要獨立 reference）
   是 → 建立新 reference

4. 新 reference 加入後，SKILL.md 路由表的每個情境是否仍然唯一對應？
   否 → 情境切分重疊，重新設計邊界
   是 → 確認可新增
```

## 單句消費位的資訊自足

Reference 的讀者是 runtime 的 LLM 與跳讀的維護者、句子經常被抽離消費：checklist 逐項執行、表格格被單獨引用、判斷標準句被 grep 命中、規則句被複製進 prompt。這些**單句消費位**的句子必須在句內資訊自足；段落敘事位的句子可以依賴鄰句、壓縮合法。

資訊自足是正向規格、四個條件——命題完整、指涉閉合、實詞可反推、一句一命題——驗收用**抽離重讀**：句子單獨交給沒讀過上下文的讀者、命題能不能無歧義復原。四條件的完整定義與機制見 [sentence-self-sufficiency-by-consumption-unit](principles/sentence-self-sufficiency-by-consumption-unit.md)。

錯 vs 對（checklist 項、實際案例）：

| 版本 | 句子                                                                                         | 抽離後                           |
| ---- | -------------------------------------------------------------------------------------------- | -------------------------------- |
| 錯   | 反比結構無法用文體先驗的無意滑動解釋、所以警惕等級最高                                       | 「反比結構」「無意滑動」指涉懸空 |
| 對   | 「話最滿的段落恰好最難查證」這種全篇分布比單點升格更難歸因於無意的文風滑動、所以警惕等級最高 | 每個指涉句內閉合、命題可獨立判真 |

## 要靠判斷的條文寫成留意項

寫條文的人寫一條規則、一張原則卡或 reference 的一節，而它要執行者做的判斷沒有可以機械比對的答案（答案依對象、對象所處的階段或領域而不同）時，把這一條寫成**留意項**。留意項指：執行者每一次遇到觸發的情形都做這項判斷，做完留下痕跡，判斷的答案由執行者決定。痕跡指執行者寫下的判斷結果與依據。這一節適用於本 skill 的 reference，也適用於任何給執行者照做的規則文件。這一節的「審查者」指事後讀產物或紀錄的人，包括之後接手的人與事後檢討的人。

一條留意項分三個部分，各自的寫法不同。下表的例子取自本 skill 一條現成的留意項（引用評價時，留意它評的是對象在什麼時候的狀態）：

| 部分         | 寫法                                                                 | 例                                                                         |
| ------------ | -------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| 什麼時候判斷 | 寫成查得到的事實                                                     | 文章引用了樂評、評測、使用心得或量測                                       |
| 判斷留下什麼 | 寫成查得到的事實                                                     | 引用的位置寫出評的時間點；判成對象變化不大的，寫出依據的事實               |
| 判斷的答案   | 留給執行者，並明講它沒有機械的條件；不替它訂年數、次數這類門檻       | 被評的對象在這段時間改變了多少                                             |

「什麼時候判斷」與「判斷留下什麼」讓讀條文的人查得到這一條有沒有被執行；「判斷的答案」保留判斷。寫條文的人把判斷的答案也寫成條件（「兩個時間點不同就拿掉評語」「超過十年的評價不用」）時，照做的人達成了條件，而仍然適用的舊評價被刪掉、不適用的新評價被留下。只寫「要留意」而沒有觸發與痕跡時，執行過與沒執行過的產物相同。

**跟〈條文的可觸發性與效力方向〉那一組驗收項的分工**：觸發、痕跡與審查者的判別，照那一組寫成查得到的條件。判斷的答案，以及一個個案歸到哪一種判斷結果，不受那一組的兩項約束（「沒有要件寫成讀者的主觀狀態」與「每一個可能的結論各有自己的正面觸發條件」）：留意項的答案本來就靠執行者對那個領域的了解，約束它的是每一種結果都要留下痕跡。「依據寫不出來的歸判斷不出來」這種排除式的入口，在留意項的處置表裡可以用。

寫的時候照下面的順序：

1. **寫出判斷的問句，確認它是留意項。** 分三種情形：
   - 問句答得出機械的條件（標題的字元數、檔案的位元組數）：直接寫成條件，不套這一節。
   - 條文打算用一個看得到的量（年數、次數、行數）或一個看得到的事件（「不同」「換過版本」）直接指定處置：先判這個量是判斷的直接證據，還是在頂替一個看不到的判斷。判別的做法是找反例：舉得出「達到門檻而規則的理由沒有成立」或「沒達到門檻而理由已經成立」的個案，它就是在頂替。頂替的那一種，被頂替的判斷寫得成查得到的條件時（「這個函式在版本歷史裡被幾個不同的需求修改過」）改用那個條件；寫不成時才寫成留意項。
   - 門檻是刻意的護欄：量確實在頂替判斷，而寫條文的人刻意不讓執行者當場判斷。下列任一種成立時，門檻留著，不改成留意項，並在條文寫出是哪一種：判錯的後果不可逆（刪除、對外發送）；執行者在那一刻的省力選項正好是「不做」（審查至少幾輪）；幾個人要對同一個結果有一致的預期（發版的條件、告警的升級門檻）。護欄可以跟留意項並用：達到門檻一律做，沒達到門檻時照留意項判斷。

   判成不套這一節時，在交付時附的紀錄寫一句依據（是機械條件、是直接證據，或是哪一種護欄）。
2. **觸發寫成執行者做了的動作**（「文章引用了評價」），不寫成他自述的目的（「文章要用評價說明現況」）。觸發寫成目的時，執行者可以說自己的目的不是那一個，而讀條文的人查不到他的目的，這一條就等於沒有觸發。看得到的量可以當觸發（「函式超過 50 行時，判斷要不要拆」），不能當答案；拿量當觸發的代價是門檻以下的個案不會被判斷，所以觸發的門檻訂得低一些，讓更多個案進到判斷。
3. **問句旁邊，判斷的每一個方向各給一個例子**（上表那一條的方向是對象「變了」與「沒變」），每個例子寫出它依的是哪一項屬性。只給一個方向時，讀的人把那個方向當成預設的答案。
4. **每一種判斷結果各寫出處置與痕跡。**
   - 「判斷不出來」也是一種結果，痕跡是產物裡寫出缺的是哪一項資訊，查了什麼寫在交付時附的紀錄（查找的經過不是產物要交付的內容時，產物的讀者用不到它；產物本身就是考證或排查的紀錄時另論）；它的處置可以跟另一種結果相同（通常選可逆的那一種）。這條規則不會有判斷不出來的情形時，寫出理由。
   - 有一種結果不必留下任何依據時，它的成本最低，執行者會一律選它。所以每一種結果的依據都寫在審查者讀得到的位置（產物裡，或交付時附的紀錄，例如提交訊息）；條文只要求執行者「說得出」依據時，做過判斷的產物與沒做的產物在審查者眼前相同。某一種結果的依據寫不出來時，條文規定它改歸哪一種結果。
   - 痕跡要帶這一個個案專有、別人回頭查得到的事實。原樣搬到另一個個案上仍然成立的句子（「已評估，無需調整」「經判斷變化不大」）不算痕跡。
   - 處置是把觸發的內容從產物拿掉時，產物裡沒有位置留痕跡，連觸發過這件事也看不出來。寫條文的人決定這一種留不留痕跡，並把決定寫進條文：要留的，規定寫在交付時附的紀錄（拿掉了什麼、依的是哪一項事實）；不留的，寫出理由，並把「一律拿掉」列為這一條的反模式，因為它是一條看不出來的省力路徑。
   - 同一次工作裡多處觸發時，痕跡可以收成一張表，每一處一列。
5. **在這一條的開頭寫出它的強度**：這項判斷每一次都做；沒有機械條件的是它的答案；寫出不訂的門檻是哪一種（例如年數）；不要求執行者一律採取同一種處置。只寫「這是留意項，不是檢查條件」時，讀的人分不出是每次都要做，還是可以不做。
6. **寫出審查者查什麼。** 審查者查觸發的事實與痕跡，指出查得到的事實，請執行者重新判斷或寫出依據；審查者不查答案，不拿年數這類量決定通過與否。嚴重度分兩種寫：觸發了而完全沒有痕跡，或痕跡是可以原樣搬到別的個案的套話，是查得到的未執行，嚴重度由這份規則自己訂；審查者對答案有疑慮時只指出事實，不列這份規則最高的那一級。審查者決定要不要指出某一處觸發的情形時用到的判別，同樣寫成查得到的事實；這些判別只寫在一個位置，別處連過去。審查者一處觸發的情形都沒找到時，報告也留一列，寫出找過哪幾種形態。這條規則沒有任何人事後讀時，寫明這一步不適用與理由。
7. **把一條既有的條件改成留意項之後，掃舊條件留下的句子。** 用舊條件的關鍵詞（例如「對不上」「拿掉」「不並列」）掃這份文件，以及抄了這一條的其他文件（摘要、清單、複製到別處的副本），逐處判這一句是在要求判斷，還是在替判斷給答案。步驟、對照表與別處抄的句子，不會跟著條文開頭宣告留意項的那一句一起改。
8. **拿個案照條文走一遍。** 個案的選法：每一種處置至少有一個個案落到它，另加一個落在兩種處置邊界上的個案，以及一個想省事的執行者會怎麼選的個案。每個個案寫出經過哪幾句、落到哪一種處置，寫進交付時附的紀錄；做得到時，請沒寫這一條的人也走一次。個案全部落到同一種處置時，問句沒有鑑別力，或有一種處置的成本最低。兩個人走同一個個案而落到不同處置時，找出他們分開的那一句，把那一句的判別寫成查得到的事實。同一份文件裡另有條文由同一個動作觸發時，挑一個個案讓兩條都走一遍；兩條的處置相反時，寫出先照哪一條。

推導與實測見 [judgment-rule-fixes-the-trigger-and-trace-not-the-answer](principles/judgment-rule-fixes-the-trigger-and-trace-not-the-answer.md)。

## 驗收清單

新增或修改 reference 後，逐項確認：

### 職責單一性

- [ ] 原子化測試通過（一個讀者群體、一類問題）
- [ ] 無在標題或聲明中宣稱承擔多重職責

### 從原則卡壓出來的條目：壓縮後三問

把一張原則卡壓成本檔的條目時，壓出來的那一份要自己過這三問，三問都在該條目的範圍內回答、不准往卡裡找答案。

- [ ] 這一句有幾層帶極性的詞（`禁止`、`沒有`、`不`、`免除`）——**兩層以上就拆成兩句**。實測一條疊了三層的條目被三份獨立讀者全數讀成相反的意思，而同一份清單裡只疊一層的條目三份全對，所以失效的是層數而不是否定句本身
- [ ] 這一句用到的承重術語，在同一節之內有定義嗎——**判不出通過條件的條目等於不存在**（實測有讀者明確回報「無法確定判斷通過或不通過的標準，因為定義沒寫」，另有讀者把沒定義的術語擴張到不該命中的詞上）
- [ ] 這一句的每個指涉詞（「那個數字」「它」「那三項」），先行詞在同一節之內出現過嗎——壓縮最常刪掉的就是指涉的來源，而本體那一句通常是完整的

**連結不算定義。** 節末指回原則卡是對的，而清單的消費單位是逐項勾選，所以每一項要自足到判得出通過。驗收問一句：照這一項工作的人，在不打開那個連結的前提下說得出通過條件嗎。

**為什麼這三問要獨立跑**：壓縮的人剛寫完那張卡，審查的人也讀過它，兩者讀條目時都會自動把卡上的內容補回去——**本體正確正是衍生形不被檢查的原因**，而補完發生在讀者這一側且無聲。機械掃描也放過它：疊加的極性沒有固定字串，掉落的定義是一段不存在的文字。判讀見 [derived-operational-form-needs-its-own-check](principles/derived-operational-form-needs-its-own-check.md)。

### 條文的可觸發性與效力方向

- [ ] 沒有要件寫成讀者的主觀狀態（「無法判定時」「有疑義時」「不確定時」）——換成去查文件就有答案的條件，並加一句把讀者的自我評估排除在外（例如「判定者自認顯然成立，仍須依前句的客觀條件判定」），否則他會用「我覺得這裡很明顯」把外部條件繞回主觀狀態
- [ ] 沒有極性詞當判定點的名字——**極性詞指把判定結果本身當成名字的那些**（「成立／不成立」「通過／不通過」「有效／無效」），描述條件的動詞不算（「滿足」「違反」不是極性詞）；讀者會替直述句自行加回極性，所以要廢除並禁用。同一次把雙重否定清完（**雙重否定指一句裡有兩層否定疊在同一個命題上**，「不使第一點不成立」是典型；單處還解得開，三處並存時讀者會在其中一處取到相反的極性並帶去別的款次）
- [ ] 條文沒有宣告某組結論的個數、互斥性或窮盡性（那三項是排除法的全部輸入，寫出來等於交給讀者一張走捷徑的地圖；想擋排除法的那句禁止語若附帶它們，擋的與給的在同一句，實測零效力）
- [ ] 每一個可能的結論各有自己的正面觸發條件——**正面觸發條件指「當 X 成立時落入這一個」這種形式**，「不屬於前面那些就落入這一個」不算；上一項拿掉了讀者原本用來做排除法的結構說明，所以每一個結論要有自己的入口，讓逐個查跟排除法一樣便宜（便宜指讀者要讀幾處才決定得了）
- [ ] 零引用的條款逐款寫下「它被引用會發生什麼」——**零引用的作用域是這一批讀者的產出**（沒有任何一份的依據句引用過它），不是指文件內部沒有互相引用；**更差指的是判定結果**（某一支會把原本判對的讀者推向判錯）。答案是「會讓結果更差」的那一類，處置是刪除而不是搬位置；答案是「有幫助」才進位置判斷，「沒作用」的直接刪

判讀見 [subjective-precondition-never-fires-for-the-misreader](principles/subjective-precondition-never-fires-for-the-misreader.md) 與 [rule-text-can-have-negative-effect](principles/rule-text-can-have-negative-effect.md)。

### 要靠判斷的條文（留意項）

條文要執行者做的判斷沒有可以機械比對的答案時，逐項確認；條文裡沒有這種判斷時，這一組不適用。

這一組裡的「痕跡」指執行者寫下的判斷結果與依據；「審查者」指事後讀產物或紀錄的人。條文是留意項時，〈條文的可觸發性與效力方向〉那一組的「主觀狀態」與「正面觸發條件」兩項只管觸發、痕跡與審查者的判別，不管判斷的答案，也不管一個個案歸到哪一種判斷結果。

- [ ] 觸發這項判斷的條件是查得到的事實，而且寫成執行者做了的動作（「文章引用了評價」），不是他自述的目的（「文章要用評價說明現況」）
- [ ] 條文裡直接指定處置的量（年數、次數、行數）或事件（「不同」「換過版本」），都舉不出「達到門檻而規則的理由沒有成立」的個案；舉得出的那些已經改成查得到的條件或留意項，或在條文寫明它是護欄與保留的理由
- [ ] 問句旁邊，判斷的每一個方向各有一個例子，每個例子寫出它依的是哪一項屬性
- [ ] 每一種判斷結果各有處置；「判斷不出來」這一種寫了處置，或寫了這條規則不會有這一種的理由
- [ ] 每一種判斷結果要留下的痕跡，寫明了位置（產物裡，或交付時附的紀錄）；處置是把內容拿掉的那一種，寫明了留在交付時附的紀錄，或寫明不留的理由
- [ ] 條文要求痕跡帶這一個個案專有的事實，並寫明原樣搬到另一個個案仍然成立的句子不算痕跡
- [ ] 這一條的開頭寫出了：這項判斷每一次都做；沒有機械條件的是它的答案；不訂的門檻是哪一種；不要求執行者一律採取同一種處置
- [ ] 條文寫出了審查者查觸發的事實與痕跡、不查答案，也寫出了完全沒有痕跡時的嚴重度；這條規則沒有人事後讀時，寫了這一項不適用的理由
- [ ] 這一條是從既有的條件改成留意項時，舊條件的關鍵詞在這份文件與抄了這一條的其他文件裡都掃過，每一處命中都判過是在要求判斷還是在替判斷給答案；新寫的條文寫明這一項不適用
- [ ] 交付時附的紀錄裡有走過的個案：每一種處置至少有一個個案落到它，另有一個落在兩種處置邊界上的個案；每個個案寫出落到哪一種處置

判讀見 [judgment-rule-fixes-the-trigger-and-trace-not-the-answer](principles/judgment-rule-fixes-the-trigger-and-trace-not-the-answer.md)。
