# 分工邊界

> 何時讀：不確定某件事該由本 skill 還是相鄰資產處理時；判斷某個失效該寫成契約欄位還是審查項時；或執行中要查與相鄰資產的交界事實時（模式 C 沿用 `foundation-design` 的接手順序、原生佈局掃描與執法工具的分工、地基波第四塊的 checkpoint、範本的產物形狀與本 skill 的填寫程序如何分工）。
>
> 同目錄：三種模式在 `modes-a-b.md` 與 `mode-c.md`，填寫問句與多形態在 `field-questions.md`，寫票句型在 `dispatch-language.md`，症狀處置在 `examples-troubleshooting.md`；〈契約齊全的定義〉留在 `SKILL.md`，**〈外部資產與跨檔用詞的地址〉在 `addresses.md`**——本檔出現的方法論、範本、執法工具、判別問句、狀態矩陣、特徵測試，地址一律查該表。
>
> 溯源：自 SKILL.md 的〈分工邊界〉一節搬移（v1.4.0）。外移釋出 730 字元，但同次修法另新增內容，SKILL.md 淨值仍升——外移的效果是騰出空間，不是使檔案變小。

## 分工邊界

| 相鄰資產 | 它管什麼 | 本 skill 管什麼 |
|---------|---------|---------------|
| 元件庫雙向約束方法論 | 判準：誰能用什麼、每個元件必須定義什麼、容器亦為元件、派發語言；加上粗粒度的執行步驟 1-7 | 其執行步驟 4-5 的展開：從三種起點走到判準被滿足的程序 |
| `foundation-design` skill | 地基入口與路由：token 萃取、接手模式的盤點→命名→固化順序、特徵測試閘門、測試基座 | 消費 token 名；模式 C 沿用其接手順序 |
| `ux-design-evaluation` skill | 畫面級：狀態矩陣、gate、輸入、錯誤恢復、導航、回饋；其互動回饋檢查清單含溢出 affordance 與版面保障（審查項） | 元件級契約；狀態集欄的填法引用它；把同一類失效寫成契約欄位（內容政策、空間不足策略）而非審查項 |
| `doc` skill 的元件庫規格範本 | 產物形狀 | 填寫程序與問句 |
| `dart-style-guardian` skill 與同類執法工具 | 抓裸值與寫死文字；原生元件直用的偵測依方法論「禁自製元件」委派給執法工具 | 不以執法工具取代容器契約；頁面層原生佈局掃描仍可入執法工具，容器缺件靠本 skill 的判別問句 |
| `version-bootstrap` skill 地基波 | 編排 i18n → design-system → UX 審查 → 元件庫四塊的順序 | 第三塊之後、第四塊「元件庫實作」之前的契約產出；第四塊的前置 checkpoint 是〈契約齊全的定義〉 |
