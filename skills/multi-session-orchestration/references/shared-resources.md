# 共用資源協調

多條線共用三種資源：合併閘門（`worktree merge` 預設的合併前全套件）、全機重度測試名額（`run-with-timeout` 取得的 heavy slot）、主 checkout 的本地 main。本檔記錄協調這三種資源的做法、每條暫行規則的撤除條件，以及兩種環境異常的處置。

---

## 1. 合併閘門與 main 的變動速度

**原則**：閘門驗證需要時間（排隊加上跑套件），main 在這段時間內被他線推進，合併 commit 就會過期而寫不進去。

| 狀況 | 判別 | 處置 |
|------|------|------|
| 合併在 CAS 時反覆失敗，期間 main 有非豁免改動 | 閘門 log 結束行的結果為「拒絕」，或出現 CAS 失敗訊息 | 閘門尚未做到「先取得名額、持有到寫入完成」時（包含閘門本身正在上線的自舉情境），通知各線暫停推送非票面檔，完成後解除；已做到者，驗證期間他線無法寫入 main，不需人工暫停 |
| 閘門紅燈 | 閘門 log 結束行的結果為「紅燈」 | 先用 main 跑同一個失敗測試。main 也紅 → 屬 main 既有回歸，開票交給造成回歸的那條線（查 `git log` 最後改到該函式或測試的 commit）；main 綠 → 本分支造成 |
| 想略過閘門（skip-gate） | — | 必須由用戶裁定，PM 不得自行授權他線略過；理由寫入 merge commit 與票面 |

**暫停推送的寫法**：「只改票面的 commit 可以推送（閘門視為豁免），其他檔案先不推 main；worktree 內工作與本地 commit 照常。」解除時同樣逐線通知。

**例外放行**：暫停期間，若某筆修正正是為了讓被等待的合併能過閘門（例如修掉 main 上的紅燈），可例外放行合併。

## 2. 名額佇列

| 規則 | 目的 | 撤除條件 |
|------|------|---------|
| 每線同時排隊上限 N 筆（N 由 PM 依名額數與佇列長度設定） | 等待上限會讓排在後面的人逾時被拒時，限制同時送出的筆數 | 閘門不再因預估等待過長而拒絕排隊之後，只剩公平分配的作用；其他線暫停時可例外 |
| 收到 125（等待名額失敗） | 讀 125 前一行的閘門訊息判別語意：寫著「預估等待超過上限」→ 照訊息的預估秒數等待後重送；寫著持有者疑似卡住 → 記錄持有者資訊回報 PM，不重送 | 閘門行為改版、125 的語意改變時，PM 重新告知各線 |
| 已在佇列中的舊版閘門程序 | 閘門程序在啟動當下就從主 checkout 載入程式，新版上線不影響已在排隊的程序 | 不重送（重送會排到尾端）；等待超過預估的 2 倍才處理（預設值，預估本身偏差大時 PM 可調整；倍數太小會把正常的慢排隊當成異常而重送）。更新 worktree 基準對已排隊的程序**無效** |

**佇列飽和時**：名額只有一個，每小時能處理的筆數固定（每筆耗時以閘門 log 的套件耗時為準）。放寬上限不會變快，只有減少閘門次數才會縮短總時間。

## 3. 批次合併

**條件（全部成立才能合成一批）**：

| 條件 | 理由 |
|------|------|
| 各票改動的檔案互不重疊 | 不重疊就不會衝突，紅燈時也容易歸因 |
| 每張自帶測試 | 紅燈時能分開判斷 |
| 每張已審查通過 | 批次只省閘門次數，不省審查 |
| 每批最多 5 張 | 閘門可能間歇紅燈，限制一次紅燈要排查的張數 |

**做法**：從最新 main 開整合 worktree → 依序 merge 各分支（有衝突就在整合分支上解並重審衝突處）→ `worktree merge --branch <整合分支> --message "<列出全部票號>"` → 寫入後各票 Solution 註明批次 merge commit，實地觸發逐張做。

**紅燈歸因**：

| 失敗型態 | 歸因方式 |
|---------|---------|
| 固定失敗、本機可重現 | 本機分別在 main 與各分支跑失敗測試，只有某支紅就歸給它 |
| 間歇失敗，或只在合併後出現 | 逐一單獨送閘門 |

修正一律放回原票的分支再併入整合分支，**不在整合分支上直接修**，否則修正無法追溯到票。

**送出前**：先把最新 main 併進整合分支，確認和已在佇列中的他筆合併不改同一檔，避免拿到名額後才撞衝突。

## 4. 主 checkout 的本地 main

- 各線共用同一個本地 main，任何一線 `git push` 都會帶出所有本地 commit。
- 後果：在主 checkout 提交的非票面變更，會被他線的推送一併帶上 main，等於略過閘門，而提交者自己並沒有推送。
- 因此非票面修改一律在 worktree 做、經閘門合併；暫停推送期間尤其不在主 checkout 提交 `.claude/` 變更。
- 推送前以 `git diff --name-only origin/main main | grep -v '^docs/work-logs/'` 確認範圍。

## 5. 環境異常

| 異常 | 判別 | 處置 |
|------|------|------|
| 推送失敗：SSL self signed certificate | `openssl s_client -connect github.com:443` 看 issuer；若是網路過濾設備（例如 DNS 過濾的封鎖頁憑證）→ 網路攔截 | 交用戶處理網路；**禁止** `http.sslVerify=false`：驗證失敗正是在告知「對方不是 GitHub」，關閉驗證等於信任攔截設備，推送內容可被讀取或竄改。期間本地閘門合併照常，推送暫停；worktree 派發守衛若要求票已在 origin，新票派不出去 |
| load 高、swap 接近用盡 | `uptime`、`sysctl vm.swapusage`、依 CPU 與 RSS 排序的 `ps` | 名額機制只限制重度任務數量，不限制記憶體；向用戶回報並提供減壓選項（關掉已停止的 session 等），不自行終止他線程序 |
