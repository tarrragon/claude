# neurodivergent-output 版本紀錄

新到舊。版號規則與兩個住址（本檔與 `SKILL.md` frontmatter 的 `metadata.version`）見專案的 skill 同步規範。

**Version**: 1.10.0 — 取回 1.9.0 的散文改寫，疊在 1.8.1 的版本紀錄外移結構上。本檔的版本紀錄從 1.8.0 起，中間缺 1.9.0 一節，因為 1.9.0 只存在於框架庫而未進本檔。

事件經過：框架庫 v2.37.0 帶入 1.9.0，內容為六處散文改寫（開場句從「不只是清楚或簡短」改為「清楚與簡短是地板，之上由格式承載狀態、優先序與下一步」；衝突章從「只有一對真正衝突」改為明說該對如何裁決並給未列出的配對一個回退順序；範圍規則改以受眾為主詞；三處規則內文收緊）與 `metadata.portable: true` 宣告。v2.45.0 那次同步以 1.8.0 為基礎做版本紀錄外移、標為 1.8.1 推回，繞過了 1.9.0——1.8.1 相對 1.8.0 只差七行（版號、portable、檔尾三處），而 1.9.0 相對 1.8.0 差二十九行，後者的改寫因此整份消失。1.8.1 的紀錄自述「skill 的指令內容一個字都沒改」，該敘述對 1.8.0 成立，對它實際取代掉的 1.9.0 不成立。

本次由一個 2026-08-26 從框架 v2.40.2 導入、此後未再改動該檔的 consumer 保存下 1.9.0 原件（與框架庫 `cb5ff92` 的該檔位元相同），取其內容、保留 1.8.1 的結構，版號順延為 1.10.0 而不重用 1.9.0，使框架庫歷史上的那個號與本次的合併結果可以分辨。

**Version**: 1.8.1 — 版本紀錄搬到同目錄的 `CHANGELOG.md`。skill 是 runtime 整份載入的檔案，而沒有任何規則要求任何人讀版本紀錄，留在 SKILL.md 等於每次叫用都付一次無效讀取。SKILL.md 末尾留一行指過去，版號的兩個住址改成「CHANGELOG.md 最上面那一條 + frontmatter 的 metadata.version」。skill 的指令內容一個字都沒改。

**Version**: 1.8.0 — 補記版本紀錄段。此前版本號只存在於 frontmatter 的 `metadata.version`，文末沒有紀錄段，所以 1.8.0 之前的變更內容查不到。
