# 子行程執行脈絡（cwd／環境變數）與 runtime 探針

hook、CLI、子行程常以 cwd、git 狀態或專案根環境變數解析根目錄與寫入位置。runtime 探針本身也是一次執行，它的 cwd 與 env 決定被測程式走哪條解析分支。

## SUB-1 探針判定符合預期，被讀成真實執行的行為已驗證

| 欄位 | 內容 |
|------|------|
| 症狀 | 以腳本實跑 hook／CLI 的新舊對照判定全部符合預期，事後在真實執行中觀察到的寫入位置與探針報告不同 |
| 常見誤判 | 探針跑的是真實程式，所以判定與落點代表真實執行 |
| 實際機制 | 被測程式依 cwd 與 env 解析根目錄；探針的 cwd 或 env 與實際呼叫不同時走另一條分支，判定可能剛好一致而落點不同；細節見來源 pattern |
| 檢查方法 | (1) 列出被測程式讀的執行脈絡：`grep -nE "getcwd\|os\.environ\|environ\.get\|rev-parse\|Path\.cwd" <被測檔>`；(2) 以唯一識別值、照實際呼叫的 cwd 與 env 執行：`(cd <實際 cwd> && <ENV=值 ...> <執行命令> <含識別值 probe-id 的輸入>)`；(3) 列出寫入落點：`find <所有候選根> -name "*<probe-id>*"` |
| 正向對照 | 刻意以不同 cwd 或少帶一個 env 跑同一情境，`find` 列出的落點必須改變；落點不變，代表該輸入不影響解析，或識別值沒有進到寫入檔名 |
| 判讀標準 | 每個情境的報告有 cwd、env、程式碼版本、落點四項，落點與預期一致，且舊碼在同一形狀下結果不同 → 驗證有效；只記判定、缺落點或缺舊碼對照 → 未完成 runtime 驗證。探針產物若會被受驗的偵測器命中，驗證後刪除並確認 `find` 計數為 0 |
