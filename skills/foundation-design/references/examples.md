## 查重粒度不足導致的兩次反向錯誤

本 skill 的前身宣稱「UI 的 token 與元件庫沒有承接者」而重新設計了一套，實際上該對象已有 `SKILL.md`〈維度與產物〉表的四層鏈路。實測其原文：`i18n` 0 次、`UX 審查` 0 次，四塊中只涵蓋兩塊。改為路由層後方向反轉：UI 列指了方法論卻漏掉 `ux-design-evaluation`，資料庫列宣稱 seed 由 `state-storage.md` 承接，實測該檔 `seed` 出現 0 次。前者讀章節標題就下結論，後者讀檔名就下結論。**錯誤的缺口宣告誘發重複建置，錯誤的承接宣告誘發漏做，後者更難發現。**

## 萃取揭露規格漂移

規格散文記「圓角 10/12、字級 12–22」，量測設計畫布實得圓角 5/7/8、字級 10–19，兩邊各寫各的、無機制發現。處置：以畫布實測值建 token、規格改為指向 token 不再複述數值。

## 萃取不等於照抄

同一份畫布的間距實測出七種值，那是產生器輸出而非設計過的尺度。token 化時歸納為離散具名階並記錄映射；照抄會把雜訊固化成規格。

## 權威形態不符時的正確取用

一個單機 collector 的資料庫維度，權威是 SaaS 訪談框架。其中 migration 版本化紀律與 Embedded SQLite 段落適用，多租戶隔離不適用（該 repo `tenant` 0 命中）。產物欄填「改寫產物：migration baseline，不含租戶隔離」，對得上真缺口（現況為 `CREATE TABLE IF NOT EXISTS` 常數、無 `schema_version`）。

## 產物有而判準無

一個 PHP 服務有完整的 seeder 與 factory，且有整合測試覆蓋。產物層填「已存在於 `database/seeders/`」；判準層仍標「無判準」並建框架缺口票，因為框架無從判斷其量級與冪等策略是否合格。兩層分開填，否則會對一個已完成的東西標「待定：缺口」。
