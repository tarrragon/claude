# 選取類前置呈現：獨立成列與判定條件

本 reference 為「判斷『使用者尚未從一組候選中做出選擇』這個前置狀態是否須在畫面狀態矩陣獨立成一行」情境。原屬 `screen-state-matrix.md`，因補齊範例後超出體量門檻獨立為本檔（同組兩檔，逐檔互指）：

| 檔案 | 內容 |
| --- | --- |
| `screen-state-matrix.md`（入口） | 核心概念／四欄定義／填寫範例／填寫步驟／BDD 展開／UC 步驟對應檢查／路由可達性檢查／無 UI 入口路由表／initializing／反模式：happy path／退出路徑的例外邊界／檢查清單 |
| `screen-state-matrix-selection-prestate.md`（本檔） | 選取類前置呈現：獨立成列與判定條件 |

適用：畫面在使用者操作前需要先「從一組候選中做出選擇」（選一個項目、選一個節點、選一種模式）；判斷「未選定」是否該有自己的一行、而非「已選定」狀態某欄位留白；多個畫面依賴同一個選取值時，判定各畫面是否都需要「未選定」狀態、以及該值的設定入口與清除時機。
不適用：等待外部事件（網路回應、系統初始化）造成的過渡態，屬 `screen-state-matrix.md`〈容易漏列的狀態：initializing〉；四欄本身的定義與填寫方法，屬 `screen-state-matrix.md`〈四欄定義〉〈填寫步驟〉。

> **自包含聲明**：本檔判定「選取類前置呈現」是否須獨立成列，需要先讀 `screen-state-matrix.md`〈四欄定義〉理解「顯示 / 可用操作 / 進入條件 / 退出路徑」四欄的意義；本檔在使用「四欄」一詞時不重述定義。

---

使用者操作前需要先「從一組候選中做出選擇」時（選一個項目、選一個節點、選一種模式），選擇動作完成之前的畫面呈現是一個真實狀態——不是「已選定」狀態的某個欄位留白，而是操作邏輯不同的另一個狀態：選定前使用者能做的只有「選」，選定後才能做選定之後才存在的操作。這類前置呈現同樣需要在矩陣裡有自己的一行；把它當成「還沒填值的已選定狀態」而不獨立成列，會漏掉它自己的可用操作欄和退出路徑欄，兩者往往和「已選定」狀態不同。

**判定條件**（三項皆成立即屬「選取類前置呈現」，須獨立成列）：

| 條件 | 說明 |
|------|------|
| 1. 未決定因非等待外部事件 | 停留在此狀態的原因是「使用者尚未做出選擇」，不是等待網路回應、系統初始化等外部條件（外部等待屬 initializing，見 `screen-state-matrix.md`〈容易漏列的狀態：initializing〉） |
| 2. 選擇動作由使用者觸發 | 選定的動作是使用者可操作的一項（點選、勾選），不是系統自動代為選定 |
| 3. 選定前後的呈現或操作有實質差異 | 選定後，「可用操作」欄或「顯示」欄會出現選定前不存在的內容，不只是把選取值填入既有欄位 |

三項皆成立時，「未選定」是一個獨立狀態，須符合兩項要求：

1. 四欄需完整填寫。
2. 退出路徑至少要有「返回」或「離開此畫面」一項——不可因為使用者最終應該會做出選擇，就預設不需要退出路徑。

未選定狀態同樣可能是使用者想放棄這次操作的時刻，適用 `screen-state-matrix.md`〈反模式：假設使用者只走 happy path〉的判斷。

**跨畫面共用的選取值**：多個畫面依賴同一個選取值時（例如兩個畫面都要顯示「目前選定的項目」），每個依賴此值的畫面都各自需要「未選定」這一行——不能因為另一個畫面已經處理過「未選定」，就假設這個畫面不會遇到同樣的狀態。除了在各畫面各自列出「未選定」狀態，還須明確記錄兩件事，缺一即為設計缺口：

| 要求 | 內容 |
|------|------|
| 設定入口 | 這個選取值在哪個畫面、透過使用者的哪個操作被設定（寫入） |
| 清除時機 | 這個選取值在什麼條件下被清除（回到未選定）：使用者主動取消、切換到其他候選對象、離開整個功能範圍等 |

沒有清除時機的選取值，會在使用者切換情境後殘留舊值，導致畫面顯示與使用者當下操作對象不一致——例如使用者已經切換到另一個項目，某個畫面卻仍顯示舊選取值遺留的內容。

## 三段鏈式範例

情境：一個清單頁與一個詳細頁，兩者都依賴「目前選定的項目」這個共用選取值；使用者需先在清單頁選定一個項目，才能在詳細頁看到內容。以下示範如何判定「未選定」是否須獨立成列，驗證段的判定屬「設計產出物」（判定規則：產出物能在執行期被啟動、看得到它運作的屬執行期行為，驗證段寫 Given/When/Then；契約表、判定結果這類靜態文件屬設計產出物，驗證段寫檢驗問句加預期答案）。

【輸入】

```
SPEC 片段（UC 主要成功場景，去識別化）：
  步驟 1：使用者從清單中選定一個項目
  步驟 2：系統顯示該項目的詳細資訊
  清單頁與詳細頁都需要顯示「目前選定的項目」
```

【產出】

```
形態：決策表 + 契約表

判定選取類前置呈現：

  條件                                     | 判定
  ---------------------------------------- | ----------------------------------
  停留原因是使用者未選定（非等待外部事件） | 是
  選擇動作由使用者觸發                     | 是（點選清單項目）
  選定前後顯示/操作有實質差異               | 是（選定後詳細頁才顯示內容，清單頁高亮選定項）
  結論                                     | 屬選取類前置呈現，兩畫面皆須獨立成列

畫面狀態矩陣（節錄，僅列與本判定相關的狀態）：

  畫面   | 狀態   | 顯示                 | 可用操作               | 進入條件                     | 退出路徑
  ------ | ------ | -------------------- | ---------------------- | ---------------------------- | ------------------
  清單頁 | 未選定 | 清單，無高亮項       | 選取項目                | 進入畫面                     | 返回上一頁
  清單頁 | 已選定 | 清單，選定項高亮     | 選取其他項目、取消選定 | 選取項目觸發                 | 取消選定 → 未選定
  詳細頁 | 未選定 | 「尚未選定項目」提示 | 無                      | 清單頁未選定時進入（若允許） | 返回清單頁
  詳細頁 | 已選定 | 選定項目的詳細資訊   | 返回、取消選定          | 清單頁選定觸發               | 返回 → 清單頁

共用選取值的設定入口與清除時機：

  項目     | 內容
  -------- | --------------------------------------------------
  設定入口 | 清單頁「選取項目」操作
  清除時機 | 使用者於清單頁執行「取消選定」，或離開清單頁與詳細頁所屬的功能範圍
```

【驗證】

```
檢驗問句
Q 兩個畫面的「未選定」狀態是否都補齊了四欄，尤其退出路徑？
  預期：是——清單頁與詳細頁的「未選定」列皆有退出路徑（返回上一頁／返回清單頁），
  沒有因為「使用者本來就該選一個」而省略

Q 選取值的設定入口與清除時機是否都有明確記錄？
  預期：是——設定入口指向具體操作（清單頁選取項目），清除時機列出至少一個
  使用者可觸發的清除路徑（取消選定），不是只寫「使用者選了別的就會變」這種
  沒有具體觸發點的敘述

Q「未選定」狀態是否只是「已選定」狀態某欄位留白，而非獨立狀態？
  預期：否——依判定條件第 3 項，選定前後顯示與可用操作皆有實質差異
  （詳細頁未選定時無內容、已選定才顯示資訊），確認為獨立狀態而非欄位留白
```
