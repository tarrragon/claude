## 核心原則

**狀態清單之外，標籤、圖示、選中態與版面各自承載語意。** 按鈕的六種時間軸狀態（見 `interaction-feedback.md`〈按鈕級回饋〉）處理的是操作時序，本檔八項判斷標準處理的是同一元件在靜態呈現時容易被誤讀的語意落差。

### 1. 切換元件的標籤要能區分「現態」與「動作」

名詞標籤（「管理模式」）容易被讀成當前狀態指示；消歧做法是狀態顯示與動作按鈕分離（非互動現態文字 +「切換」動作鈕）、改用自帶 on/off 語意的控件（switch / segmented control）、或最低成本把標籤改成動詞句（「切換到 X」— 不動結構、現態仍不可見）。三種做法的選擇順序固定：先看值數，二值狀態（開／關）一律改用 switch 或等義控件（即使切換會連動畫面其他區域增減元素，如「管理模式」開啟後每列多出刪除按鈕，仍先判二值再套用）；三值以上且切換會連動畫面其他區域增減元素時，拆成狀態顯示＋動作鈕；三值以上但沒有連動增減元素時，先看全部選項能否在一列內完整並排顯示而不截斷：能 → 改用 segmented control（選中的分段即為現態）；不能，或前述做法暫時受版面限制無法採用時，才用動詞句做最低成本過渡，且動詞句不解決現態不可見的問題，屬權宜而非首選。不幫助消歧的圖示是雜訊、移除。

2. 非互動的狀態指示不與可點元素同形混排（子項見 2.1～2.10）

### 2.1 前提

- (1) 本項的「指示」指畫面上不可點的狀態指示，也就是按下去沒有任何反應的元素。
- (2) 指示符合下列任一形態即合格，(a)(b) 各自獨立判定、可同時成立：
  - (a) 明顯非可點元素形態，依 2.2～2.7 判定；
  - (b) 移出動作列，依 2.8 判定。
- (3) (a) 的判定與指示是否和可點元素排在同一列無關：同列的指示只要屬 (a) 即合格；指示屬 (b) 也不影響 (a) 是否成立，(a) 仍依 2.2～2.7 判定。
- (4) 畫面上沒有可點元素時，本項不適用。「不適用」只用於整項。2.3 每一軸的結果只有「不同」與「相同」兩種。

### 2.2 比較對象

- (1) 可點元素指同一畫面上所有按下去會有反應的元素，含按鈕、可點 chip、文字連結，非窮舉。比較範圍是整個畫面，不限指示所在的列；此全畫面比較範圍只屬於 (a)，(b) 的比較範圍見 2.8(1)。整列可點時，該列本身不進入本款的比較集合，依 2.8(1) 判定為動作列，列上元素依 2.5 處理。
- (2) 執行順序：① 先列出畫面上所有可點元素；② 逐一對每一個可點元素填 2.3 的兩軸，並在同一列記下這個可點元素給的結論——兩軸皆「相同」記「否決 (a)」，至少一軸「不同」記「不否決」；③ 讀 ② 的表：只要有任何一列記「否決 (a)」，指示就不屬 (a)，其他列記什麼都不改變這個結果；全部列都記「不否決」，指示才屬 (a)。填表途中出現「否決 (a)」時可以停止，結論已定。

### 2.3 兩軸

- (1) 構成要素軸。構成要素有兩項：文字或圖示（文字與圖示算同一項；純幾何形狀不算圖示，界線見 (3)）、區塊（底色或外框圍住文字或圖示的範圍）。有區塊必定有文字或圖示，所以一方不會同時缺少又多出。判定方式：先分別列出雙方（指示、對方）具備的項目再比對，再依下表判定：

  | 比對結果 | 判定 |
  | --- | --- |
  | 指示缺少對方具備的一項 | 不同 |
  | 指示多出對方沒有的一項 | 依 2.4 |
  | 兩者具備的項目相同 | 相同 |
- (2) 區塊高度軸。指示與對方都有區塊時才比較，達到 2.6 的門檻記為不同；以下情況記為相同：任一方沒有區塊（不比較）、專案沒有尺寸 token（不成立）、未達 2.6 的門檻。這裡的「相同」表示此軸不提供差異，判定只剩構成要素軸。
- (3) 圖示與純幾何形狀的界線：純幾何形狀只有以下幾類：點、直線或直條、圓環、內部不含文字或圖示的純色圓形或方形。其他圖形一律算圖示，含勾號、箭頭、三角形。

### 2.4 多出規則

- (1) 指示多出對方沒有的一項時，須同時滿足以下兩點，這一項才算不同；不滿足時，構成要素軸記為相同：畫面上另有一個可點元素具備該項；指示與那個可點元素至少在一軸上不同。
- (2) (1) 的第二點依 2.3 判定，可以是任一軸。2.2(2) 本來就要求指示與每一個可點元素比較，讀者須把那一次比較的結果取回這裡用——那次比較兩軸皆為「相同」時，第二點即不成立，不是系統自動處理，須讀者自行取回核對。

### 2.5 徽章

附在可點元素熱區內、按下去觸發該可點元素本身的徽章，不是本項的指示，不做比較。整列可點時，列上沒有自身動作的元素（按到它與按該列其他位置結果相同）比照本條，不是本項的指示，不做比較。

### 2.6 門檻與量測

- (1) 區塊高度軸記為不同的門檻：在專案尺寸 token 階梯上，指示的區塊高度比對方至少低一階。
- (2) 專案沒有尺寸 token 時，區塊高度軸不成立，記為相同，只看構成要素軸。
- (3) 比較須在專案支援的所有字級、斷點、密度下都達到門檻；任一條件下未達門檻，此軸記為相同。
- (4) 指示或可點元素的高度不在專案尺寸 token 階梯上時，視同專案沒有尺寸 token，此軸不成立，記為相同。

### 2.7 不可靠訊號

描邊或實心、圓角或直角、底色深淺，都不是可靠的可點性訊號，不作為比較依據。比較依據只有構成要素與區塊高度兩軸。

### 2.8 (b) 移出動作列

- (1) 執行順序：① 確認指示所在的列上有沒有任何可點元素（來源 (i)）；② 確認這一列本身是不是整列可點——按下列上空白處會不會觸發動作（來源 (ii)）；①② 須各自獨立確認，確認來源 (ii) 不成立不代表來源 (i) 也不成立，列上是否另排有可點元素須獨立確認。③ 讀 ①② 的結果：只要有任何一個來源成立，這一列是動作列，指示不屬 (b)；兩個來源都不成立，這一列不是動作列，指示屬 (b)。
- (2) (b) 只看指示所在的列，不與畫面其他位置的可點元素比較。

### 2.9 例示

同一種指示形態，換了畫面上的可點元素，結果可能相反。以下例示須連同比較對象一起讀，不可單獨當成合格形態：

- (1) 不加底色與外框的純文字：畫面上的可點元素全都帶區塊時，指示對每一個可點元素都缺少區塊，屬 (a)。畫面上只要有一個不帶區塊的可點元素，指示對它構成要素相同，區塊高度軸不比較、記為相同，不屬 (a)。
- (2) 圓點：畫面上有一排可點的純色圓形色票（例如顏色選擇器）時，圓點與色票都沒有文字、圖示與區塊，構成要素相同；區塊高度軸不比較、記為相同，不屬 (a)。

### 2.10 理由

本條只適用於 (a)(b) 都沒有達成的指示：同列有可點元素時，使用者預設整列可點，按到指示時「沒反應」會被讀成壞掉。

### 3. 選中態是（底色, 文字色）的成對設計

單獨覆寫選中底色會脫離主題的成對機制、元件庫不會為自訂底色反推文字色，淺底疊淺字就是「選中後看不到字」；對比方向成對反轉（底淺配深字），逐狀態驗 WCAG AA（一般字級 4.5:1、大字 3:1）。

### 4. 水平清單溢出要有捲動 affordance（邊緣漸層、下一項半顆露出、箭頭、捲軸指示）

截斷的預設讀法是「壞了 / 被旁邊的元件遮住」、不是「可以捲」；選項少時優先消除溢出（wrap / 選單），截斷邊緣避免緊貼固定按鈕（視覺歸因會錯）。

### 5. 關鍵回饋文字要有版面保障

flex 寬度競爭會把「已選擇: 3/45」壓成「...」（state 正確、使用者零資訊）；ellipsis 對短關鍵資訊是錯誤的降級策略，改縮格式或最小寬度。兩者順序固定：先縮短格式（去除不影響理解的前綴或單位），仍不足才設定最小寬度並由鄰近元件讓步；讓步規則（誰讓步、怎麼降級）路由至 `component-contract-design` skill 的〈空間不足策略〉欄，本項只決定先後。回饋鏈要驗到像素層、並在窄幕驗收。

### 6. 版面擠壓先分「換算錯 vs 分配錯」再動手

等比縮放（換算類）sizing 套件不驗證空間分配：換算工具工作在常數層（設計稿座標 → 裝置座標、發生在 layout 之前）、空間分配發生在 layout 協商層（有限寬度分給動態內容：計數、i18n 字串、使用者資料），兩層獨立、比例正確不等於空間夠用（隱含假設「實際內容 = 設計稿內容」被動態內容打破）。換算錯查套件用法；分配錯補三層（設計層空間競爭規格：誰讓步怎麼降級；實作層把 flex 組合當顯式優先權決策；驗證層窄幕驗收 / layout test）。設計層的空間競爭規格本 skill 不另立格式與欄位 — 一律路由至 `component-contract-design` skill 的〈空間不足策略〉欄，本 skill 只負責標出「這裡需要一份空間競爭規格」，內容與填寫規則交由該欄位的定義處理，避免兩份 skill 各自定義同一件事。其他響應式方案（constraint-based layout、breakpoint）保證層各異；引入「解決某維度」的套件時，記錄它不保證的層、缺口層掛對應驗證。

7. 同一圖形只承載一個語意（子項見 7.1～7.4）

### 7.1 前提

- (1) 本項的「圖形」範圍同 2.3(3) 所指的圖示與純幾何形狀（2.3(3)：「其他圖形一律算圖示」）：涵蓋 2.3(3) 的兩類——圖示與純幾何形狀，二者皆在本項射程內。
- (2) 本項不受 2.1(4) 限制：畫面上沒有可點元素時，本項仍適用。

### 7.2 判定

- (1) 同一圖形在全畫面只承載一個語意。
- (2) 比較對象是畫面上所有圖形，不限指示與可點元素之間；兩個可點元素用同一圖形表達不同語意，也違反 (1)。
- (3) 「語意」指圖形代表的事物或動作，不含可點與否：同一圖形只差可點與否、代表的事物相同時，不違反 (1)。語意不同指的是所指的事物或動作本身不同（例如「篩選」與「匯出檔案」）。
- (3-2) (1) 與 (2) 所稱的「同一圖形」與「兩個圖形」，一律依本款判定，不得以其他方式認定：判 (1) 時，先依本款判畫面上的圖形兩兩是不是同一個，判為同一個的才依 (5) 往下判語意。兩個圖形是不是同一個，依下列兩步判，不得跳步：
  - ① 兩端各自寫出它畫的是什麼，且兩端用同一種寫法。可用的寫法只有下列甲、乙兩種。**只寫畫的是什麼，不得寫它代表的意思**——寫成「篩選圖示」不算完成本步，須寫「漏斗」；依畫面上看到的線條寫，不得由它旁邊的文字或它代表的語意反推。顏色、大小、粗細、比例、朝向、填滿與否、描邊或實心都不是「畫的是什麼」，不寫進這兩句；寫進去了也不列入 ② 的比對。**兩句寫完之後、進 ② 之前，先逐項檢查下列 (a)(b)(c)，並把檢查結果逐項寫出來**：命中任一項，兩端一律改用乙重寫，改寫完成才進 ②；三項皆未命中，才可以用甲。**未逐項檢查就進 ② 者，本步未完成**，不得在未寫出檢查結果的情況下逕行宣告兩端是不是同一個圖形。不得拿寫法不同或用詞不同的兩句去比對：(a) 受評的畫面或材料本身沒有指出它畫的是什麼，讀者是為了比對才自行替它歸類出一個名稱（例如把一條封閉曲線叫「橢圓」）；(b) 一端寫出的是指稱整體的名詞，另一端寫出的是線、弧、角、筆畫這類輪廓的組成部分；(c) 兩端寫出的名詞不同，而指不出這兩個名詞在輪廓上的具體差別。
    - 甲、整體名稱：用一個名詞指稱整個圖形——圖示寫它畫的是什麼（例如「漏斗」「音符」），純幾何形狀寫 2.3(3) 的類名。
    - 乙、輪廓走法：不指稱整體，改逐項寫出輪廓本身——由哪幾條線構成（幾條、直的還是彎的、往輪廓的內側還是外側彎）、這些線在哪裡相接、相接處是不是角、有幾個角、閉不閉合、輪廓之內還有沒有別的線。**本目所列的每一項都要寫，兩端都要寫**；材料看不出某一項時，該項寫「看不出」，不得略過。漏寫任一項者本步未完成，不得進 ②。
  - ② 用甲寫時，兩端寫出的不同，即是兩個圖形，到此為止；相同，即是同一圖形。**用乙寫時不適用前句**：一律先逐項比對乙所列的各項，再依比對結果合成本款結論。同一項的內容相同而只是用字不同（例如「三條直線」與「三段直線」），不算不同；內容本身不同，即是不同。同一項的內容以數量、比例、倍數或分數表述時，**先把兩端換算成同一種表述再比**：換算後數值相同者，內容相同，不得因表述形式不同就記為內容不同。**逐項比對只在該項兩端都寫出內容時進行。兩端都寫「看不出」的項，略去不比，其餘各項照常比，本款結論不因該項受影響。該項只有一端寫出內容、另一端寫「看不出」的，該項無從比對；不得以此作為該項內容不同的理由。整項未寫的項，不屬無從比對，也不屬略去不比：任一項有一端或兩端整項未寫的，即是 ① 乙目所稱的漏寫，本款不比對該項、不合成結論，回 ① 乙目補寫後重跑本款；不得以該項無從比對為由，逕依下列合成的第三種情形宣告本款不輸出結論。比對結果依下列合成：有任一項比出不同，即是兩個圖形；乙所列各項除略去不比者外全部比出相同，即是同一圖形；有項無從比對而無項比出不同的，本款不輸出兩者是不是同一個圖形的結論。** 乙所列之外的敘述，即使寫了也不列入比對。① 兩句以外的任何差別，皆不使兩者成為兩個圖形，顏色不同、粗細與大小不同都在此列。例如：描邊與實心變體算同一圖形。
- (4) 本項與第 2 項各自判定，第 2 項的結論不改變本項的結論。
- (4-2) 本項與第 8 項各自判定，第 8 項的結論不改變本項的結論。第 8 項判不違反——包含依 8.2(4) 的文字豁免判不違反——不使本項也不違反；兩端旁邊各有文字標明語意，不是本項的豁免事由，本項沒有文字豁免。反向亦然：本項的結論不改變第 8 項的結論。兩項都命中時怎麼記缺口、怎麼處置，依 8.3(2)。
- (4-3) 判本項 (1) 與 (2) 所稱的「同一圖形」，一律依 (3-2)。第 8 項的判定步驟不得用以回答這個問題：8.2(2) 的換色比對、8.2(3) 的清單與其各目界定句，都不是圖形同一性的判定法，不得援引來說兩個圖形是同一個或不是同一個（見 8.3(5)）。
- (5) 兩個圖形的語意是否同一，依下列三步判，不得跳步：
  - ① 把兩端各自寫成一句。代表動作的寫成「對 X 做 Y」，X 是被作用的對象、Y 是動作；代表事物或狀態的寫成「X 的 Y」，X 是所指的對象、Y 是它的狀態、屬性或類別。兩句寫不出來就不算完成本步。
  - ② 依 ① 的兩句形態選分支，只能選一條：
    - 一句是「對 X 做 Y」、另一句是「X 的 Y」：走 (6)。
    - 兩句都是「X 的 Y」：X 與 Y 都相同才語意同一；只要有一格不同，就是兩個語意。
    - 兩句都是「對 X 做 Y」：先比 Y。Y 不同即是兩個語意，到此為止，不再比 X；Y 相同而只有 X 不同時，動作本身相同，屬語意同一。
  - ③ ① 的兩句之外的任何相似都不構成語意同一，下列三者皆不得作為判語意同一的理由：共用同一個名詞（該名詞須在兩句落在同一格才算數）、同屬一個主題或功能領域、兩端各自與同一個第三方圖形語意同一。
- (6) 一端是狀態指示、另一端是造成、設定或解除該狀態的動作時，代表的事物相同（例如「已套用篩選」的指示與「開啟篩選面板」的按鈕）。本款只在 (5)② 的第一條分支下可用；兩端都是動作時一律回 (5)② 的第三條分支，不因兩端各自與同一個狀態指示語意同一而彼此語意同一——造成某個狀態的動作與解除該狀態的動作，動作本身不同，是兩個語意。本款所稱造成、設定或解除該狀態的動作，須是該狀態成立與否會隨這個動作改變者；動作改變的只是該狀態的參數——程度、數量、設定值等該狀態成立之後才有的屬性——而該狀態成立與否不隨它改變時，不屬本款所稱的動作，本款不成立。

### 7.3 處置

違反 (1) 時，處置是更換其中一方的圖形；不是改指示形態或移出動作列（那是第 2 項的處置）。

### 7.4 例示

- (1) 違反：畫面上兩顆可點按鈕都使用旗子圖示，一顆用於切換語言至英文版、另一顆用於檢舉此則留言；兩者代表的語意不同（語言選擇 vs 檢舉），違反 (1)，此結果與畫面上有沒有指示無關。
- (2) 不違反：畫面上兩顆可點按鈕都使用分享圖示，一顆用於分享文章、另一顆用於分享相簿；兩者都是「對 X 做 Y」形態，Y 相同（分享）而只有 X 不同，依 7.2(5)② 動作本身相同、語意同一，不違反 (1)。

8. 顏色不作為唯一區分依據（子項見 8.1～8.5）

### 8.1 前提

- (1) 本項的「區分」指使用者要分辨兩個以上不同語意時所依據的視覺差異。「語意」指該元素代表的事物、狀態或類別。
- (2) 畫面上不存在兩個以上靠視覺差異分辨的語意時，本項不適用。「不適用」只用於整項。
- (3) 本項不限載體：圖示、純幾何形狀、文字顏色、底色、邊框色、線條顏色皆在射程內。

### 8.2 判定

- (1) 兩個以上語意之間，使用者可依據的視覺差異只有顏色時，違反本項。
- (2) 判本項依下列三步，依序執行，不得跳步。任一步得出「不違反」即結束判定，不進下一步。本款不用「成立／不成立」描述各步的結果，各步的結果一律照該步寫出的判定語直接寫：
  - **第一步（前置關）**：先依 8.2(4) 判本畫面是否符合該款——該款要求哪些條件、哪些文字不算，全依該款判，本款不另行規定。
    - (甲) 符合 8.2(4)：前置關擋下，判不違反，到此為止；此時判不違反的依據是 8.2(4)，不是以下兩點。
    - (乙) 前置關擋下時，**不比對 8.2(3) 清單內的任何差異**。第一點與第二點皆不予判定；作答不得寫出兩點的判定結果，不得以清單內的任一項差異作為判定的並列理由、補充理由或供參考的附帶論述——寫出來即為未套用本目。
    - (丙) 不符合 8.2(4)：前置關未擋下，往下走第二步。
  - **第二步（第一點）**：把這些元素承載語意的顏色全換成同一個顏色，看還剩下哪些差異，再逐項對照 (3) 的清單。
    - (甲) 換色這個操作的兩側都是封閉的：**顏色那一側全部歸一**——色相、明度、彩度、深淺、對比換完後一律相同，不存在「換色後仍有明度差／深淺差／對比差」這種狀態，出現這種敘述表示換色沒有執行完，不得作為本步的判定理由；**顏色以外那一側一動不動**——換色前是什麼，換色後還是什麼。
    - (乙) 換色後仍在的每一項差異，**先逐項問它是不是使用者用來分辨這些語意所依據的差異**——這些元素各自代表什麼語意、這項差異跟著哪一個語意走，兩者說得出對應才算數。說不出對應的，本步不算它，即使它的項名寫在 (3) 的清單上。本目不得省略，也不得以「項名寫在清單上」代替。
    - (丙) 經 (乙) 篩掉之後還剩下的差異裡，**有** (3) 清單內的任一項：判不違反，到此為止，不進第二點。**一項都沒有**：往下走第三步。
  - **第三步（第二點）**：這些元素各自旁邊有沒有文字標明它代表什麼。**有**：判不違反。**都沒有**：使用者可依據的差異只有顏色，判違反本項。
- (3) 本清單各項依 8.1(1)，須是使用者用來分辨這些語意所依據的差異；與語意無對應關係者不算。本清單逐項封閉：只有清單列出的項目算數，且各項仍須通過本款引言的對應關係要求。換色後仍在但不在清單內的差異，不算第一點所問的那種項目，不使判定停在第一點——第一點問的是有沒有剩下清單內的項目，不是有沒有剩下任何差異。可區分的差異有：形狀、大小、位置、圖示、存在與否、填滿與否、線條樣式、文字內容。**明度、深淺、對比強弱、彩度、色相都不在本清單內——它們是顏色的維度，換色後一律相同，不會成為「換色後仍剩下的差異」。**清單各項的內涵，依本款之內的界定句判，不得只憑該項名稱自行認定；這些界定句只界定本清單各項的內涵，不改變第 7 項對「同一圖形」的判定。
  - ① 形狀：指這個元素是哪一個圖形，由輪廓本身決定，與這個圖形怎麼擺無關。同一個圖形旋轉、鏡射、翻面之後仍是同一個形狀；兩個元素之間只差朝向、擺放方位、哪一條邊或哪一個角朝上時，不算形狀差異，不得據以說第一點還剩下清單內的項目。判別法：把其中一個轉一轉、翻一翻能與另一個重合，兩者就是同一個形狀。**判別時不得先替兩端各自取一個整體名稱再比名稱**：受評的畫面或材料本身沒有指出它畫的是什麼，而判定者為了比對自行替它歸類出一個名稱時，兩端取到的名稱幾乎必然不同，而名稱不同不是形狀差異，不得據以說有形狀差異。一律以能不能重合判；重不重合看不出來時，本項不算有差異。
  - ② 位置：指承載語意的那個元素，靜止時落在版面上的哪一點。元素隨時間移動、晃動、搖擺、來回位移是動態行為，不是位置差異；元素本身的靜止落點相同時，不算位置差異。
  - ③ 文字內容：指文字寫出來的是哪些字。字形、字重、字距、字級與大小寫寫法都是同一串字的呈現方式，不算文字內容差異。
  - ④ 靜態總則：本清單各項限元素靜止時的視覺屬性。元素隨時間變化的行為——移動、閃爍、變形、播放動畫——不是本清單中的任何一項；要用這種行為區分語意，須另指出一項落在本清單內的靜止差異。
  - ⑤ 預設值：主張某項差異落在本清單某一項的人，須指出是哪一項，並指出條文哪一語句寫出了這項差異就是那一項——清單句裡該項的項名本身即指這項差異，或本款之內、本目之前的界定句已把這項差異歸入那一項；該項名列在清單上這件事本身，只支持那一項在清單內，不足以充當這一句。**本目所稱的界定句，限於 8.2(3) 引言與本目之前的 ①②③④ 四目**；8.2(3) 以外的任何語句——含第 2 項、第 7 項與 2.3 各款的界定句——都不是本目所稱的界定句，不得引來支持歸屬，引了也不算數。該歸屬要成立，得先補一個條文沒有給的定義（判定者自己對該項名稱的理解、題材常識、元素的其他屬性），就視為不在清單內，不算第一點所問的那種項目。判定者自認該歸屬顯然成立，不改變本款結果：本款問的是條文有沒有給出這個歸屬，不是判定者有多確信。
- (4) 各自旁邊有文字標明語意者不違反 (1)，即使換色後沒有剩下 8.2(3) 清單內的任何差異。該文字須與所標語意同時可見；須先觸發才出現者（tooltip、長按提示、說明彈窗）不算。本款所稱「旁邊」，指**該文字是與這個元素並列的另一則文字，不是這個元素本身的一部分**：元素自己寫出來的字，凡位於該元素邊界之內者，都不是本款所稱的標明文字，該元素在本款視同旁邊沒有文字。元素本身寫出的字仍是一項可看見的差異，依 8.2(3) 的「文字內容」項判，不在本款。本款要求畫面上承載語意的每一個元素旁邊都有這樣的文字；只有一部分元素有的，本款不符合，前置關不擋下。
- (5) 顏色搭配其他差異時不違反 (1)：顏色可以承載語意，本項要求的是它不獨自承載。

### 8.3 射程與交界

- (1) 比較對象是畫面上承載語意的所有元素，不限元件邊界。同一個元件的兩個實例分別用兩種顏色代表兩個語意，也在射程內。
- (2) 本項與第 7 項各自判定。第 7 項治同一圖形承載兩個語意，本項治兩個語意只靠顏色區分。
  - ① **本款只管「同一組元素兩項都命中之後，缺口怎麼記、怎麼處置」，不是缺口的成立要件。** 某一項有沒有命中，依該項自己的款次判；只有一項命中時，那一項照記一個缺口，不因為另一項沒命中而不記。讀成「缺口只在兩項都命中時才記」是誤讀。
  - ② 同一組元素兩項都命中時，記一項缺口，以本項為準。
  - ③ 記一項缺口不等於處置只需滿足一項。8.4 給的兩條處置之中，只有「補一項 8.2(3) 所列的差異」且補的那一項是形狀時，才一併把第 7 項的違反處置掉；選「補一則符合 8.2(4) 的文字」結案、或補的差異不是形狀時，第 7 項的違反仍在，**須另依 7.3 更換其中一方的圖形，該缺口才算關閉**。「本項的處置涵蓋第 7 項的處置」只在補形狀那一條處置下成立，反之在任何情形下都不成立。
- (3) 底色與文字色的成對設計與 WCAG AA 比值屬第 3 項，不在本項。第 3 項問顏色看不看得見，本項問顏色以外還有沒有訊號，兩項對同一組顏色可以一過一不過。
- (4) 可點性的判定屬第 2 項。2.7 已規定底色深淺不作為可點性的比較依據，本項不改變該條。
- (5) 同一個外觀屬性在兩項可以有相反的判定結果，這不是矛盾，各依自己的款次判：填滿與否在 8.2(3) 是使用者可依據的差異，描邊與實心在 7.2(3-2)② 不使兩者成為兩個圖形。本款不使「這兩者是不是同一個圖形」有兩個答案——這個問題只由 7.2(3-2) 回答，本項不判它。兩套判定互不援引——第 7 項判出的「同一圖形」或「兩個圖形」，不作為 8.2(2) 第一點判定結果的理由；8.2(2) 第一點的換色比對與 8.2(3) 的清單，也不作為兩個圖形是不是同一個的理由（第 7 項那一側的同款條文為 7.2(4-3)）。要判 8.2(2) 的第一點，依 8.2(2) 與 8.2(3)；要判兩個圖形是不是同一個，依 7.2(3-2)。

### 8.4 處置

違反 8.2(1) 時，為每個語意補一項 8.2(3) 所列的差異，或補一則符合 8.2(4) 的文字。**改變顏色本身不構成處置**——換成對比更強的色相、拉開明度差、改用色盲友善色票，都仍是「只有顏色」。

### 8.5 例示

- (1) 表單畫面：必填欄位的標籤以橘色顯示、選填欄位的標籤以一般文字色顯示，兩者旁邊都沒有星號或「必填」字樣。違反 8.2(1)：第一步的前置關未擋下（旁邊沒有標明文字，不符合 8.2(4)）；第一點把兩種標籤的文字色全換成同一個顏色後，剩下的差異裡一項清單內的都沒有（標籤各自寫的字雖然不同，但那些字跟「必填」「選填」這兩個語意沒有對應，依 8.2(2) 第二步 (乙) 不算數），往下判第二點；第二點兩類標籤旁邊都沒有文字標明，判違反。處置是為必填欄位補星號或「必填」字樣。
- (2) 同一份表單改為必填欄位標籤後加一個橘色星號、選填欄位無星號。不違反：使用者區分兩類欄位所依據的差異是星號的存在與否，屬 8.2(3) 的「存在與否」，換色後仍剩下「存在與否」這項差異。**星號本身是橘色不構成違反**——8.2(1) 問的是使用者可依據的差異是不是只有顏色，此處的差異不是顏色。

### 三段鏈式範例：第 2 項——非互動指示與可點元素形態的判斷

情境：一個狀態指示與一個可點元素同列，判斷該狀態指示目前的視覺樣式是否會被誤認為可點。驗證段的判定屬「設計產出物」。

【輸入】

```
SPEC 片段：一個清單項目同一列同時有一個「已同步」狀態指示與一個「刪除」按鈕；
「刪除」按鈕為填色圓角矩形（有文字＋底色區塊），高度 40；狀態指示目前的視覺
樣式是無邊框文字包在一個有圓角的淺色底色區塊裡（有文字＋底色區塊），高度 28，
比「刪除」按鈕低一個專案尺寸 token 階
```

【產出】

```
形態：決策表
判斷依據                                     | 結果
畫面上的可點元素                             | 「刪除」按鈕（填色圓角矩形，有文字＋
                                                底色區塊，高度 40）
狀態指示的構成要素                           | 文字＋底色區塊
與「刪除」按鈕比較構成要素軸（2.3(1)）        | 相同（兩者皆有文字與區塊，指示未缺少
                                                也未多出任何一項）
與「刪除」按鈕比較區塊高度軸（2.3(2)、2.6(1)）| 不同（指示 28 低於按鈕 40，達專案尺寸
                                                token 階梯的至少一階）
逐一比較結果（2.2(2)）                        | 對唯一的可點元素「刪除」按鈕已在區塊
                                                高度軸不同，滿足「對每一個可點元素
                                                都至少一軸不同」
結論                                         | 屬 (a) 明顯非可點元素形態，合格，不需
                                                改為其他形態；「無邊框」與圓角深淺
                                                不是判斷依據（2.7），判斷依據只有
                                                構成要素與區塊高度（2.3）
```

【驗證】

```
檢驗問句
Q 「無邊框文字包在圓角淺色底色區塊」是否因為外觀像 chip 而自動合格？
  預期：否——條文不再以外觀類名作為判斷依據，需逐一與畫面上的可點元素比較
  構成要素與區塊高度兩軸（2.3）；本情境合格的依據是指示的區塊高度低於
  「刪除」按鈕，達尺寸 token 階梯的至少一階（2.6(1)）

Q 若把狀態指示的高度改成與「刪除」按鈕相同（40），是否仍合格？
  預期：否——構成要素軸相同（皆為文字＋區塊，2.3(1)），區塊高度軸也相同
  （未低於按鈕，2.3(2)），兩軸皆同即不屬 (a)（2.2(2)③），須移出動作列（2.8）
  或改為其他形態；同色同高只差圓角或描邊不足以構成合格（2.7）
```

### 三段鏈式範例：第 5 項——窄幕下關鍵回饋文字的處理順序

情境：一個計數文字在窄螢幕下與旁邊的操作按鈕共用同一列空間，判斷該不該被壓成省略號。驗證段的判定屬「設計產出物」。

【輸入】

```
SPEC 片段：一個顯示「已選擇: 3/45」的計數文字，元件所在容器在窄螢幕下寬度不足，
與旁邊的操作按鈕共用同一列空間
```

【產出】

```
形態：決策表
判斷依據                               | 結果
「已選擇: 3/45」是否為關鍵回饋文字      | 是（讓使用者知道目前選取進度，缺這則資訊
                                          使用者無法判斷操作是否符合預期）
空間不足時是否應該讓此文字被壓成省略號 | 否（省略號會讓使用者拿到零資訊）
應該怎麼處理                           | 優先縮短格式（如「3/45」不含「已選擇: 」前綴）；
                                          仍不足則設定最小寬度，改由旁邊的操作按鈕
                                          讓步（縮小或換行）
```

【驗證】

```
檢驗問句
Q 窄幕下空間不足時，是否應該讓「已選擇: 3/45」被壓縮成「...」？
  預期：否——關鍵回饋文字要有版面保障，ellipsis 對短關鍵資訊是錯誤的降級策略

Q 「縮格式」與「設最小寬度改由旁邊元件讓步」兩個做法的優先順序為何？
  預期：先嘗試縮格式（去掉非必要前綴），仍不足才設最小寬度並要求旁邊元件讓步——
  縮格式的代價較低（不影響其他元件版面），應優先嘗試
```
