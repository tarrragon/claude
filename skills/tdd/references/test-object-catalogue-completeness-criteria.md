# 四、齊全判準

> **何時讀**：已填完測試對象目錄（或正在填寫途中檢查缺口），需要驗收目錄本身是否齊全、機械可判時；或需要判定「同一行為同時載於多個來源類別」時該保留哪一條、其餘如何附註不違反來源唯一時。
>
> **同目錄**：入口檔 `test-object-catalogue.md`（單位判定、來源類別、契約欄位表、派發語言句型在此）；姊妹檔 `test-object-catalogue-starting-points.md`（三種起點的推導程序，起點 A 步驟 A8 執行本檔機械檢查）。
>
> **溯源**：原為 `test-object-catalogue.md` 的〈四、齊全判準〉節，補齊範例後全檔超出單檔 token 門檻；依讀者任務三問判定本節是驗收時刻的獨立讀者任務（填寫與驗收分屬不同時刻），外移為獨立檔（搬移程序見 skill-design-guide `references/splitting-an-existing-skill.md`）。

一份測試對象目錄可被視為齊全，須同時滿足以下判準：

| 判準 | 機械檢查方式 |
|------|------------|
| C1：覆蓋性 | 各規格與使用案例的每個可驗證條目在目錄有對應行（扣除合法跳過） |
| C2：欄位完整 | 目錄每行的每個契約欄位非空（跳過條件可為空，代表必測） |
| C3：規格條目不被兩行引用 | 每行的「來源規格條目」不重複（同一條規格條目不被兩行引用） |
| C4：跳過合法 | 每個「跳過條件與理由」非空的行，其理由引用分層測試策略跳過條件表或元件庫規格豁免清單的具體條款 |

> **C3 比對的單位是規格宣告，不是欄位字串**：一條規格條目（如一條 FR）內含多個規格宣告（各自有不同的觸發條件或輸入分支、宣告不同的結果）時，各宣告是不同的來源規格條目，以 `{SPEC-ID} FR-{N}／{分支描述}` 分行登錄，不違反 C3。同一個規格宣告的不同驗收面向（如終端回饋訊息的是否出現、內容、可讀性）不是不同宣告，不得以附註分行；附註文字只是面向名稱時，C3 判為重複。機械比對時，先去除〈多來源取最具體〉的「（亦見 …）」附註，保留分支描述後比對。

**多來源取最具體（C3 的判斷依據）**：同一行為同時載於多個來源類別時，取其中最具體的條目作為「來源規格條目」欄位值——具體性順序為畫面狀態矩陣列優先於使用案例步驟、使用案例步驟優先於規格功能需求（FR）；其餘同義來源不另立行，以括號附註於該欄位值之後（例：`{SPEC-ID} §4.2 載入中→正常（亦見 {UC-ID} 步驟 3）`），避免同一行為出現兩行而違反 C3。

## 與既有覆蓋率判準的關係

| 既有判準 | 測的東西 | 與本目錄的關係 |
|---------|---------|--------------|
| 行為場景覆蓋率 | 所有業務場景都有測試（量） | 補充——本判準回答「質」：每個測試的規格來源、斷言來源、形態是否填寫完整 |
| 分支覆蓋率 | 每個分支代表一個業務決策（程式碼層級指標） | 測不同的東西——本判準是規格層級的 spec-to-test 追溯指標 |
| 整體新增程式碼覆蓋率基線 | 扣除跳過層後的合理基線 | 不衝突——程式碼覆蓋率仍然適用，本判準在其之上增加規格追溯維度 |

本齊全判準**補充**既有覆蓋率判準，不取代。既有判準回答「測了多少」，本判準回答「每個測試是否對應到規格、對應是否完整」。
