# 規模買不到異源視角

> **角色**：本卡是 `multi-round-review` 的支撐型原則（principle）、被「規模與來源是兩件事」那條基本原則引用。
>
> **何時讀**：跑完多輪審查、字句層掃描回報乾淨，而外部一眼就看到違規時；或準備用「加一輪」「多派幾個 reviewer」來補 register 類的漏抓時。

一個 session 派出的所有 reviewer 與探針構成單一來源。它們讀的是同一份稿、拿的是同一個人寫的 prompt、繼承同一個 context 建立起來的框架。增加數量提高的是**覆蓋的面**，不是**視角的來源數**。

而 register 與用詞搭配這一類違規的偵測依賴的正是來源。「讀起來自然」由文體先驗決定，同一個先驗底下讀幾次都自然；派十個 reviewer 去讀，得到的是同一個先驗的十次執行。

## 同一個判斷標準，套在自己的文字上通過、套在別人的文字上不通過

這一類違規有時有可機械執行的判斷標準。物理化錯配就有一條：問這個動詞照字面成立需要什麼物理條件，需要重量或支點的就是借來的。

一次併行寫作的實測：兩個執行者同時處理同一批內容，各自跑完四輪審查（一邊三十餘個 agent 涵蓋十五個 frame，另一邊十六個 reviewer 加十三份探針），各自的字句層掃描都回報乾淨。交換檢視時，各自一眼看到對方一處違規，兩處都在對方跑過多輪掃描之後仍然存在。

其中一處落在小節標題上，而且判斷標準就是上面那條。寫的人在那一輪用同一條標準逐句掃過自己的文字（包括那個標題）並判定通過；另一邊拿到同一份稿、套用同一條標準，當場判定不通過。

差別不在標準，也不在誰比較仔細。**寫的人讀到自己下的標題時取回的是意圖，讀者取回的是字面。**

同一輪裡有一個對照組能說明關鍵詞清單不是主因：同一個執行者的探針抓出了另一處清單外的同類違規。所以它對這一類是有偵測力的，它只是對自己下的標題沒有。

## 為什麼派 reviewer 補不了

派出去的 reviewer 拿到的 prompt 由作者撰寫。prompt 裡的用語、舉的例子、劃定的注意範圍，全部來自同一個文體先驗——一個把某個搭配讀成自然的人，寫出來的審查指令也不會把它列為要注意的形態。

作者濃縮過的位置風險最高：標題、小節標題、摘要欄位、表格的鍵欄。正文的句子還有機會被當成陌生文字重讀，標題不會，它是作者剛剛決定的那個意思的代號。

## 修法

**把併行的另一個執行者當成異源視角，而不只是衝突來源。** 兩邊同時動到同一批檔案時，第一反應通常是協調提交邊界；邊界要協調，而那個場合同時提供了平常拿不到的東西——一個讀同一份稿、卻不繼承你的 context 的讀者。

**交換的單位是掃描而不是評價。** 請對方「掃我的、我掃你的，用同一份規範」會得到可判定的結果；請對方「看看我寫得好不好」會得到同源的評價，因為對方會用你的框架回答你的問題。

**不要用加輪次或加 agent 數來補這一類。** 那買到的是更多同源的執行。沒有併行執行者時退回既有的異源手段（外部冷讀、低階模型探針），並且記得自己派的探針仍在同一棵派發樹上——它們的價值在於不會自動補完殘缺的句子，不在於來源不同。

**優先掃自己濃縮過的位置。**

## 判讀徵兆

自己的掃描回報乾淨，而外部一次就指出違規。出現時要問「我的掃描為什麼漏了」，不是「這次比較不小心」。

「這一句我讀過很多遍」是訊號而不是保證——重讀次數多代表同一個先驗被執行了很多次。

違規集中在標題與摘要欄位，而正文相對乾淨。

跑完多輪之後回頭問「這幾輪裡有哪一輪的執行者不是我派的」。答案是零時，register 這一層的結論要標「未經異源抽查」。

## 邊界

本卡談的是判定要讀懂「讀起來對不對」、無法完全 regex 化的違規。形式違規（裝飾符號、失效連結、編號錯位）不適用，那一類加工具就解決。

實測樣本只有兩處，而且兩個執行者不是隨機取樣的獨立觀察者——它們是同一套規範下的兩個執行者。機制論述不依賴樣本量，「外部一次就抓到」這個效果量不該從兩個實例外推。
