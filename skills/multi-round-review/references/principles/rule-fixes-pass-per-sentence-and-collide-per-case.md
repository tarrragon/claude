# 規則的修法逐句驗證會通過、套到案例上才互撞：改完才查得到的事實管不了動手之前的步驟，修完要拿任務重走

> **角色**：本卡是 `multi-round-review` 的支撐型原則（principle）、被「整合 finding 跟 fix 工作流」的〈修完拿任務重走一次，再派下一輪〉引用。
>
> **何時讀**：照 finding 修規則類文件（規範、agent 指令、skill）之後、派下一輪之前；以及要定義一個給好幾條規則共用的概念、或要替一條規則補例外的時候。

## 核心原則

照 finding 修規則時，每一條修法都在它被問的那個位置、以句子為單位寫成，也以句子為單位驗收；而讀者照規則做事時，是拿一件任務從頭走到尾，一個任務同時經過好幾條規則。兩者的單位不同，所以修法在句子層通過，在任務層互相衝突。

一次實測：一組規則檔做完結構調整之後，同題的入口理解探針歧義從 25 處降到 11 處，下一輪修完又升到 14 處。把後一輪的 7 個位置追到引進那句話的修改：4 個的句子是前一輪修正新寫的，2 個是新句子跟更早的規則套在同一個案例上衝突，1 個是舊句子。

## 四種機制

**改完才查得到的事實，被拿來決定動手之前的步驟**。一個「改動的級別」由工具比對 diff 判定，改完才查得到；叫用寫作 skill、讀規則分冊卻要在動手之前做。用級別決定這兩步要不要做，規則裡就一定有一個「先改、再判、判完補做」的時點，讀者分不清看事前還是事後。探針連續兩輪三份全數指出，措辭換過兩次，時間順序的矛盾都還在。這一種換措辭消不掉。

**在被問的位置補答案，不查同一個對象上的其他規則**。探針問「補 frontmatter 欄位算哪一級」，修法在級別的定義裡補一句；另一節早就要求修改既有檔案時順手補缺的欄位，兩條同時套到「改一個錯字」上就衝突。探針問「提交工具回錯誤怎麼辦」，修法寫「照錯誤訊息修正」；另一條規則說錯誤落在別人的檔案時不修。每一句單獨讀都對，以句子為單位的檢查（段名引用、關鍵詞掃描）看不到。

**集中成唯一住址時，原位置留下摘要**。新的一節收齊了某一類情形，原本那一節留了一句處置不同的短句，兩句是同一次修改寫的。

**定義裡的例子被讀成判定標準**。被定義的詞本身沒有定義，定義後面接一個例子，讀者只能拿例子推邊界。

## 修法

- **定義共用概念時寫出它的時點**：這個值在工作流程的哪一步之後才查得到。用到它的規則，動作排在那一步之後；動作必須更早做時，那條規則不看這個概念，改成無條件做，或改看一個事前就查得到的事實。
- **修完拿任務重走一次，再派下一輪**：把探針用的任務與這一輪 finding 的案例逐一走過修改後的規則，每一步寫出經過哪幾條規則、各自給什麼處置。同一步出現兩種處置、或某一步沒有任何規則管，就是下一輪會被指出的位置。那一次走九個案例，在派探針之前找出三處。
- **修一則 finding 之前，列出同一個對象上的其他規則**：被修的那一句作用在什麼對象上（一種檔案、一個 exit code、一個動作），全組檔案裡還有哪些規則作用在同一個對象上，逐條對過再寫。
- **集中成唯一住址時，原位置只留連結**，不留帶著處置的摘要。
- **定義先於例子**：被定義的詞在同一處寫出定義；例子緊接在定義之後，寫出它示範的是定義的哪一部分。
- **修法預算**：一則修法新增的限定子句，不多於它刪掉的；刪掉一條例外時不寫替代句。
- **能不讓執行者判語意的分界就不判**：改成保守的預設，整條分界連同它的定義一起刪掉。
- **修完的驗收交給異源的讀者，並留下可以重跑的案例**：作者自己重走會帶著作者的 context；封閉案例題加預期答案見 [要理解探針列出「有兩種讀法的位置」是審查題](listing-ambiguities-is-a-review-task-not-a-probe.md)。

## 判讀徵兆

| 徵兆 | 判讀 |
| --- | --- |
| 同一處歧義換過兩次措辭仍然被指出 | 矛盾在時間順序或結構，不在措辭；先查觸發條件在什麼時點查得到 |
| 新的歧義落在這一輪剛寫的句子上 | 修法只在句子層驗收，沒有拿任務重走 |
| 探針的「兩種讀法」是兩條規則各給一種處置 | 修法沒查同一個對象上的其他規則 |
| 探針問「X 算不算」，而文字裡只有一個例子 | 被定義的詞沒有定義，例子被當成判定標準 |
