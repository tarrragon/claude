# 「我以為觀測到的」躲在「引用的」那一欄裡，因為它看起來有來源

> **角色**：本卡是 `multi-round-review` 的支撐型原則（principle）、被「整合 finding 跟 fix 工作流」的質疑步驟引用。
>
> **何時讀**：一個 finding 的依據是某份工具輸出或清單顯示，而要決定採不採信時；以及設計 fact-check 的責任分派時。

## 核心原則

**查核責任的分類法只有「引用的」與「推導的」兩欄時，虛構的觀測會被歸進「引用的」，因為它看起來有來源。** 那正是它躲過查核的方式：查核者看到來源就轉去查來源，而那個來源並不存在。

四欄才窮盡：

| 欄               | 定義                                         | 查核動作           |
| ---------------- | -------------------------------------------- | ------------------ |
| 引用的           | 有外部來源可查                               | 回原始來源比對     |
| 我量測的         | 工具輸出在**我自己的**對話紀錄裡，可原地重跑 | 重跑那條指令       |
| 我推導的         | 沒有來源，引用前要重算（再分已複核／未複核） | 重算               |
| 我以為觀測到的   | 那次呼叫從未發生                             | 撤回               |
| 別人量的，我引用 | 來源真實，而在**別人的**對話紀錄裡           | 自己跑一次，或標明 |

**第二欄的定義就是分界線，而它有兩層**：在不在對話紀錄裡可以驗（「我記得看過」不能），以及**在誰的**對話紀錄裡。 兩者在報告的文字上完全同形——「清單顯示」「輸出顯示」「我量到」讀起來沒有差別。

## 兩個子形態：來源不存在，與來源說的是別的事

| 比較項       | 第一個實例       | 第二個實例                     |
| ------------ | ---------------- | ------------------------------ |
| 來源         | 不存在           | 存在，而它說的是別的事         |
| 為什麼躲得過 | 沒有東西可以查   | 查了會查到東西，而查到就是放行 |

第二個實例的形狀：一份報告舉某兩個項目當某類設定的實例，而被引用的來源是一份清單裡的兩行文字。實查之後那兩個項目屬於另一種檔案類型，那個設定欄位對它們並不適用——**來源真實存在，只是它說的不是這件事**。

一句話說完這個缺口：**「有來源可查」這一欄查的是有沒有來源，不查來源說的是不是這件事。** 第二個子形態因此更難防，因為查證的動作會成功，而成功本身就是放行訊號。

## 分類欄位本身就是偵測程序

第二個實例是**被這張分類表自己抓出來的**：回報者在填四欄時逐項問「這一項的來源在不在對話紀錄裡」，走到那一項就發現自己引的是清單裡的兩行文字而不是實際的設定。它的自述是「兩欄分類法下我會把它放進『引用的』，因為清單裡確實有那兩行」。

所以這張表的用途有兩層，而第二層原本沒被看出來：**它讓下游知道哪些數字該重跑，也讓填表的人在填的當下發現自己引錯了。** 後者不需要任何人起疑——填欄位這個動作本身就是逐項的追問。

這與[分類是被問句逼出來的](disclosure-yields-one-bucket-classification-yields-layers.md)是同一個機制往前推一步：那裡是問句讓報告者分出原本沒有的類，這裡是欄位讓他在分類的過程中撞見一個錯誤的歸類。

## 為什麼這個變體比標準形態難察覺

虛構結果的標準形態發生在工具呼叫發出之後、真實結果返回之前。這一次填的是**一份從未被呼叫的工具的結果**，所以沒有「呼叫與結果之間」那個可疑的時間窗。

兩個反向的信用來源讓它更穩固：**三次一致**（同一組數據在三則獨立訊息裡一致出現，而一致讀起來像穩定）、**真數據替假數據背書**（同一份報告裡的字元數、行數、佔比全部經查為真，於是那一項顯示觀測不會被單獨挑出來懷疑）。

## 第五類的失效模式與第四類相反

| 比較項     | 我以為觀測到的       | 別人量的，我引用                       |
| ---------- | -------------------- | -------------------------------------- |
| 來源       | 不存在               | 真實存在，而且通常是對的               |
| 被查出的機率 | 一問就穿             | 查了也對，所以沒有人會再查             |
| 危害       | 數據是假的           | 數據是真的，而**責任鏈斷了**           |

第五類的問題落在查核次數上：**它把「別人驗過」記成「我驗過」，於是那個數字在下游被當成過了兩道查核，實際只過了一道。** 數字本身可以完全正確——一次自陳的實例裡四項數據事後補跑全部相符，而相符是運氣，不是查核。

**產生它的機制是語氣一鍋端。** 同一份回報裡有些數字經過獨立重跑、有些沒有，而兩者在對外的文字上語氣完全相同。這與[要求揭露只擋得住省略](disclosure-yields-one-bucket-classification-yields-layers.md)是同一個機制在另一個受詞上——那裡是零命中的來源被壓成一句，這裡是「驗過」與「讀到」被壓成同一種語氣。

**放大器：來源方越可靠，第五類越不會被發現。** 上游的數字幾乎都對時，下游轉述後的「相符」是常態，而常態不產生訊號；上游偶爾出錯，第五類反而會早早被抓到。所以這個缺陷的隱蔽程度與上游的品質**同向**——協作對象越可信，責任鏈斷得越徹底，而「我們的 reviewer 很可靠」正好是最不該用來放行的理由。

**推論：外部查核偵測不到第五類。** 查核者去驗那個數字，數字是對的，於是它通過——而通過本身沒有回答「這是誰驗的」。所以這一類只有兩個入口：**回報者自己標記**，或**流程強制要求附上自己那一次跑的輸出**。前者依賴自律，後者是可執行的，所以契約要把它寫成欄位而不是提醒。

判準因此落在一個問句上：**這個數字我親手跑過嗎**。它取代的是「來源在哪」——來源可以在，而不在我這裡。

## 偵測：問一個必須回到原始輸出才答得出來的後續問題

有效的動作是問一個**只有握著原始輸出才答得出來的後續問題**（那一次問的是「這兩個機制你分不分得開」）。直接質疑走不到那裡——「你確定嗎」得到的是同一個斷言再說一次，而斷言的第二次與第一次在文字上無法區分。回報者為了回答就得回去看原始輸出，而一回去看就發現它不存在。附帶性質是**對方不知道自己正在被驗**，所以它不會產生防衛式的補強。

**這個問法對第五類無效**：回報者回去看，看到的是別人訊息裡那個真實的數字，於是它再確認一次。第五類要靠分類欄位，不靠追問。

## 限制

單一個案。四欄那一部分的論證不依賴頻率——兩欄會把第四類歸進第一類，這是分類法的性質而不是統計；偵測方法只跑過一次。

## 判讀徵兆

- 報告裡的觀測用「清單顯示」「輸出顯示」這類動詞，而那份輸出沒有出現在對話紀錄裡。
- 同一組數據在多則訊息裡一致出現，而它只有一個來源。
- 同一份報告裡其他數字經查為真，於是整份報告獲得了信用。
- 追問用的是「你確定嗎」。

## 跟相鄰原則的關係

- [要交出物件，不要交出關於物件的判斷](ask-for-the-object-not-the-verdict.md)：同源而施力點不同。那張卡直接要求交出物件；本卡問一個只有握著物件才答得出來的後續問題，於是回頭取物件的動作由回報者自己發起。時機也不同——那張用在已經起疑時，本卡用在還沒起疑、只是想把一件事問清楚時，而虛構的觀測通常不觸發起疑。
- [要求揭露只擋得住省略，要分層得改成要求分類](disclosure-yields-one-bucket-classification-yields-layers.md)：分類法的性質相同。那張卡的「沒查」那一格與本卡的第四欄是同一個設計——類別要窮盡，少一格時落在那一格的東西會被歸進最接近的一格，而最接近的通常是「已經驗過」的那一格。
- [finding 清單列的是抽樣位置](fix-the-class-not-the-cited-instances.md)：那張卡的修法要求掃描指令先拿一個已知會命中的字串驗過管道，本卡是同一個設計在觀測端的形態——要求那次呼叫真的發生並且留下痕跡。
