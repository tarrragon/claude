# 常識是相對於讀者背景的

> **角色**：本卡是 `multi-round-review` 的支撐型原則、被 Round 2-B 的術語知識卡覆蓋維度引用。
>
> **何時讀**：判定某個術語需不需要解釋或建卡時、或審查判定「術語都很常見」時。

## 結論

術語要不要解釋的判準是「目標讀者群裡最不熟悉的那個人能不能理解」，不是「作者覺得這個術語夠不夠常見」。

常識相對於背景而存在。同一個術語在一個生態圈裡人人皆知，在鄰近生態圈裡完全陌生：

| 術語類型         | 覺得是常識的背景   | 需要解釋的背景             |
| ---------------- | ------------------ | -------------------------- |
| 某語言生態的工具 | 該語言的日常使用者 | 其他語言背景的工程師       |
| 網路層參數       | 後端與維運         | 前端與行動端               |
| 作業系統機制     | 該系統的長期使用者 | 其他系統背景、純託管環境者 |
| 雲端網路概念     | 基礎設施工程師     | 只用過平台即服務的開發者   |
| 效能調校選項     | 該領域的調校經驗者 | 該生態外的所有人           |

## 為什麼審查抓不到

作者寫某個領域的教材時已經熟悉該領域的術語，把自己的熟悉度投射成「讀者也知道」。審查者若與作者背景相似，會有完全相同的盲點——雙方都把這些術語當成「做過這行就知道的東西」，於是整批術語在多輪審查中被靜默放行。

這個盲區無法靠增加輪次跨越，因為每一輪的審查者共享同一組背景假設。要跨越它必須換視角：假裝自己是讀者群裡最不熟悉的那一端，逐一掃描文中術語，任何需要另外查詢的都是缺口。

## 理想做法

指定一個具體的「最遠讀者」——不是抽象的「初學者」，而是「來自鄰近生態、有經驗但不熟這一套工具的工程師」。以他的視角逐段讀，標出每個他要停下來查的詞。

標出之後分三種處置：主線術語行內展開、支撐術語連到卡片（卡片不存在就是建卡訊號）、背景術語首次出現時連結、後續裸用。

## 判讀徵兆

- 審查報告出現「術語都是該領域常見詞彙」這類判定，而沒有列出實際掃描過的術語清單。
- 文章的讀者定位橫跨多個技術生態，但術語解釋的密度只對應其中一個。
- 作者與審查者的背景高度重疊。
