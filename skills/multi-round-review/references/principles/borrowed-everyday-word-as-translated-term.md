# 借用中文日常詞當術語譯名的誤讀：譯名的選法與量測

> **角色**：本卡是 `multi-round-review` 的支撐型原則（principle）、被 1-A 寫作規範 audit 的譯名檢查、2-B⁶ 術語探針與嚴重度量尺引用。寫作端的同一張卡在 `compositional-writing`。
>
> **何時讀**：要替一個外來的技術術語寫中文譯名、沿用一個查得到的既有譯名、或審查時看到一個譯名讀起來像日常用語時；也用在考慮「乾脆只寫英文」的時候。

## 核心原則

**一個外來術語的中文譯名，借用了中文裡已經有日常意思的詞時，讀者讀到的是日常意思。** 這是嚴重的寫作錯誤，嚴重在讀者會照字面學錯：他不會停下來問，因為那個詞他認得。

實例是 cursor。英文的 cursor 至少指三樣東西：畫面上的滑鼠或文字游標、資料庫逐筆讀取查詢結果的物件、分頁回應裡記錄下一頁從哪裡接續的字串。三者的共通點是「標記目前位置」，所以英文讀者用同一個字不覺得有問題。中文的「游標」在日常與軟體介面裡已經固定指畫面上的游標，把它拿來譯資料庫的讀取物件或分頁的接續字串，詞面帶來的是畫面上那個箭頭——讀者讀到「伺服器回傳一個游標」，第一個問題是這跟滑鼠有什麼關係。在軟體這個領域，「游標」這個詞已經有主人。

**只寫英文是把翻譯工作交給讀者。** 它避開了錯的譯名，代價落在讀者身上：每次讀到都要自己把英文對回一個中文概念，而不熟這個英文詞的讀者連對回的起點都沒有。第一次出現寫「中文（original term）」，中文負責讓讀者讀懂，英文負責讓讀者查得到、對得上程式碼裡的名稱（`next_cursor`），兩者各有工作，不能只留一個。

**譯名要讓詞面直接說出這個東西做什麼。** 找不到既有譯名時，自己組一個描述功能的短語，甚至寫成一句話；判斷標準是讀者第一次讀到就知道它是什麼。分頁的 cursor 譯成「接續標記（cursor）」：伺服器給的一個標記，記錄下一頁從哪裡接續。資料庫的 cursor 譯成「查詢結果的讀取物件（cursor）」。畫面上的那一個仍然是游標。

## 寫的當下：每個譯名問一次

寫下一個由外文概念翻來的中文詞時，問：**除了要譯的這個概念，軟體或介面裡還有沒有另一個讀者常碰到的東西也叫這個名字？** 有的話，就不用它：讀者在技術文件裡讀到它會先想到那一個——「游標」是畫面上的游標，「把手」是介面上的拖曳把手，「書籤」是瀏覽器書籤，「捷徑」是桌面捷徑。軟體以外的日常意思本身不構成違規：「旗標」的日常意思是旗子、「交易」是買賣，而軟體與介面裡沒有另一個東西叫這兩個名字，合規；「鉤子」「管線」「記憶體」「執行個體」同理。比對的是中文名稱：看台灣的軟體介面上那個東西實際顯示的中文字，英文同名不算——例如英文 header 另指文書軟體的頁首，但那個東西在台灣介面上顯示的是「頁首」，不能拿來判定「標頭」違規；兩份探針曾這樣從英文反推。日常功能相似不能拿來當合規的理由：「游標」也是「標記目前位置」，讀者照樣先想到畫面上的游標。

這個問句改寫過三次，每一次都由三份探針的實測逼出來。第一版問「這個詞在軟體領域裡是不是已經是另一個東西的名字」，兩份把「鉤子」判成違規——它們把要譯的概念本身也算成「另一個東西」，所以現在的問句明寫「除了要譯的這個概念」。第二版改問「讀者在技術文件裡第一個想到的是不是要譯的這個概念」，判斷者（探針）就把軟體以外的日常意思算進來：兩批實測裡，有一份因為書籤的日常功能相似而判成合規，另有兩份把「旗標」、一份把「執行個體」判成違規，理由是讀者會想到旗子、會讀成「執行出來的個體」。問句因此落回第一版的方向，但把比較範圍限定在軟體與介面裡的另一個東西，並排除要譯的概念本身。

這一問要在寫的當下做，因為審查端看不出來：作者與同源審查者都知道那個詞在這裡是什麼意思，讀到「游標」時自動補上作者的定義，讀起來完全通順。

英文詞有好幾個意思時，先把這個情境裡的意思寫成一句話（「記錄下一頁從哪一筆接續的字串」），再替這一句找譯名。寫不出這句話，代表還沒弄清楚要譯的是哪一個意思；每個意思各自找譯名，不要讓一個譯名承擔全部。

## 反模式：沿用查得到的譯名就當成已經查證

「游標」不是憑空想出來的：某家資料庫廠商的繁體中文官方文件就用它當頁面標題，所以它看起來是有出處的譯名。但查得到不等於它在中文裡讀得通。

那份官方文件本身就有破綻：標題與多數段落用「游標」，同一頁裡也出現「資料指標」；頁面的中繼資料標示整頁是機器翻譯。所以查得到的譯名可能只是機器翻譯的產物。「官方文件這樣寫」要先看兩件事：同一頁裡用法一不一致，以及頁面是不是機器翻譯；任一項成立，先分辨哪一個譯法是人工翻譯、哪一個來自機器翻譯，不直接採信看起來比較正式的那一個。搜尋結果的摘要也不能當出處：同一次查證裡，摘要說另一家廠商用「分頁標記」，回原文核對時正式譯名是「分頁符記」。

另一個來源是語料：簡體中文的技術文字普遍把 cursor 寫成「游标」，這讓這個譯名看起來約定俗成。目標讀者用的是繁體中文時，「簡中語料常見」不構成「這裡的讀者讀得通」。

## 選譯名的程序

1. **先查承載這個概念的知識卡或術語表有沒有已定案的寫法**，有就照用，到這裡結束。
2. **把英文詞在這個情境裡指的東西寫成一句話。**
3. **列出候選譯名**：既有的譯法（包括看起來可疑的那個）、其他廠商目標語言文件的用法、以及照「這個東西做什麼」那句話自己組的短語。
4. **用術語探針量測候選**：同一批混入至少兩個已知通用的術語當控制詞，問每個詞在這個情境裡指什麼、沒把握就寫沒把握，並要它指出哪一個最快讀懂、哪一個最容易誤解（設計條件見 [term-probe-measures-register-not-invention](term-probe-measures-register-not-invention.md)）。
5. **讀有把握那幾份寫的定義，不只看份數。** cursor 那一次的候選裡，「分頁標記」有一份把頁碼與 offset 也算進去，會模糊「用接續標記而不用頁碼」這個對照；「接續標記」三份都讀成「從這裡接續往下拿」。
6. **選定的譯名再過一次同一個問句。** 替代譯名也可能讓讀者先想到別的東西：一次探針實測裡，替「書籤」找替代時提出的候選之一是「分頁遊標」，又回到同一個錯誤。
7. **寫回時第一次出現加英文附註**，之後以中文為主，程式識別字與討論英文詞本身時用英文；同一個英文詞的其他意思不要一起被替換掉，替換按義項走，不一條指令掃全部。既有譯名在其他中文資料裡流通時，附一句「其他中文資料常寫作 X」，讓讀者拿舊譯名也對得上。
8. **把定案的譯名寫回知識卡**，下一位作者照用，同一個概念才不會有兩個名字。

候選量過之後仍全部分歧、找不到可靠中文名詞的詞（例如 test oracle），第一次出現寫一句中文描述再附英文原詞，之後可以沿用英文。這和只寫英文不同：讀者第一次讀到時手上有中文說明。

## 探針結果要扣掉的偏差

cursor 那一批的三份探針裡，有兩份對「游標」的判斷相反：一份認為它最快讀懂，理由是它在分頁情境「高度約定俗成」；另一份認為它最容易誤解，第一反應是滑鼠游標。兩份相反的結論來自同一個模型。模型覺得「約定俗成」，反映的是它在訓練語料裡常看到這個用法，而那些語料多半是簡體中文（推測，沒有對照組能排除其他解釋）。

推廣成判讀規則：**探針報告某個譯名「很常見、很快讀懂」時，先問它常見在哪一種中文的語料（繁中或簡中）。** 只要有一份探針在技術文件的情境裡第一個想到的是軟體或介面裡的另一個東西，就照讀錯處理——真人讀者若第一個聯想到那個東西，只會比模型更吃力。

## 判讀徵兆

- 讀者問「這是不是翻錯了」，或者讀完之後用日常意思複述那個術語。
- 譯名在軟體或介面裡已經是另一個東西的名字（只看字典第一個意思跟技術概念無不無關會誤判：那樣「交易」「旗標」也會被判違規）。
- 某個譯名只在少數教材或官方文件裡出現，而同一頁裡還有另一個譯法。
- 討論中出現「那就都寫英文吧」，作為避開爭議譯名的方法。

## 跟其他原則的關係

- `compositional-writing` 的 `terminology-keeps-original-anchor` principle：規定第一次出現寫「中文（original term）」。本卡說明為什麼不能退回只寫英文，以及中文譯名要怎麼選。
- `compositional-writing` 的 `translation-must-preserve-concept-role` principle：管的是譯名的名詞頭要對得上概念角色。「游標」的名詞頭沒有錯在角色，錯在它已經是另一個東西的名字，兩條檢查彼此獨立。
- [term-probe-measures-register-not-invention](term-probe-measures-register-not-invention.md)：提供量測的設計條件；本卡補上一個它沒處理的偏差——模型對某個譯名的熟悉度可能來自另一種中文（簡中）的語料。
- `compositional-writing` 的 `regional-terminology-alignment` principle：管繁中與簡中的詞彙對照（螢幕與屏幕）；本卡處理的偏差落在量測工具裡，而不是落在作者的用詞裡。
