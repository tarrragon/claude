# 一次修法會對同一件事寫出兩種形式，而兩種都不命中舊 pattern

> **角色**：本卡是 `multi-round-review` 的支撐型原則（principle）、被「整合 finding 跟 fix 工作流」的收尾清單引用。
>
> **何時讀**：一批修法完成、準備收尾時。

## 核心原則

**修法會在同一批之內對同一件事寫出兩種形式，而正確的那一種通常就在旁邊。** 一個檔內嵌了數字、另一個檔對同一件事寫了具名路由；某一節套了標註習慣、另外幾列沒套；某處寫了間接指涉，而直接形式就在同一個檔頭幾行之後。

**缺的不是知識。** 寫的人知道正確的形式，他在同一批裡已經用過它。缺的是回頭比對的動作。

**類別掃描對它無鑑別力，理由可以指認：兩種形式都是新寫的，都不命中任何舊 pattern。** 類別掃描的輸入是 pattern，它問「舊問題還在不在」；這一類問的是「我剛寫的東西彼此一致嗎」。

## 承重的證據是「抓出者」的分佈

| 抓出者   | 數 | 缺陷性質                                                       |
| -------- | -- | -------------------------------------------------------------- |
| 獨立審查 |  5 | 形式不一致——同一件事兩種寫法，兩種都是新寫的、不命中舊 pattern |
| 作者自查 |  2 | 機械可驗——行數跨過門檻、新增的段落沒進路由表，有 pattern 可比對 |

**分界就是這條線**：作者自查抓得到的恰好都有 pattern 可比對，抓不到的恰好都沒有。這個分佈是「必須是獨立的一道 pass、不能折進作者既有的掃描」的論據。

## 這道檢查

每批修法完成後，把本批改動過的所有位置放在一起讀一次，只問：**同一件事我寫了幾種形式。**

兩個限制讓它便宜：**範圍限本批的改動**（不是整個成品）、**問題限形式一致性**（不重新判斷內容對不對）。窄下來之後它是一次線性通讀。

## 合併規則是 AND，並各自標明負責範圍

| 檢查                     | 抓得到              | 抓不到                         |
| ------------------------ | ------------------- | ------------------------------ |
| 類別掃描（既有）         | 有 pattern 可比對者 | 同一件事的兩種寫法             |
| 本批改動的形式一致性通讀 | 同源修法的形式分歧  | 需要重新量測或比對清單才成立的 |

**寫成「用新的取代舊的」或「跑其中一個就好」會製造一個特定的失效**：兩個判準被 OR 起來時，不量測任何東西的那一個會成為主導閘門——它永遠先通過，於是另一個永遠不必跑。

## 限制

分母是一個 skill、一個工作階段、一位作者、三個連續批次、七個缺陷。**三批皆出現，未觀察到隨批次遞減**——三批推不出趨勢，所以這裡沒有比率宣稱。新步驟本身只跑過一次。

## 判讀徵兆

- 同一批改動裡，同一件事在兩個位置上的寫法不同。
- 正確的那一種形式在同一份檔案或同一批次裡已經出現過。
- 這一類缺陷由獨立的審查者抓到，而作者自己的掃描回報乾淨。
- 收尾的動作只有「跑一次類別掃描」。
