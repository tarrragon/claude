# 要理解探針列出「有兩種讀法的位置」是審查題：同一份檔案兩批的總數差得比輪與輪之間還大，改用封閉案例題加預期答案

> **角色**：本卡是 `multi-round-review` 的支撐型原則（principle）、被 `round-2-probes.md`〈探針的處置門檻〉與 `integrating-findings.md`〈修完拿任務重走一次，再派下一輪〉引用。
>
> **何時讀**：設計理解探針的題目、拿每一輪的歧義總數判斷有沒有收斂、或決定什麼時候可以停止審查的時候。

## 核心原則

**「列出有兩種讀法的位置」要探針自己判斷文字哪裡有問題，是審查題，不是理解題。** 理解探針的設計條件是不給審查框架、問理解不問評價；給了審查框架，低階模型會退化成品質較差的審查者。審查題的回答是開放式的生成，每一份從一組可能的位置裡取一部分。

一次實測：一組規則檔跑了五輪，每輪三份探針、題目逐字相同，最後一題要探針列出有兩種讀法的位置。五輪的總數依序是 18、25、11、14、20，前後兩次被判成「沒有收斂」。對最後一輪的同一份檔案再派三份、題目不變，三份合計 13 處，原批是 20 處；單份從 3 到 8，六份的聯集約 18 個位置。五輪之間的差距沒有超過同一份檔案兩批之間的差距，所以總數判不出收斂或沒收斂。而那五輪裡沒有一份探針讀錯。

**總數判不出來，重複出現的位置判得出來。** 同一份檔案六份探針裡至少三份指出的位置有四個，都是要執行者判語意的分界，或是總則與例外分在兩處而沒有優先順序。

**規則類文件的探針要量讀錯，不量歧義數。** 規則類文件的讀者是照著執行的模型，探針讀錯就是將來的執行會做錯。封閉的案例題配上作者事先寫好的預期答案，探針的答案與預期不同就是讀錯：預期答案是作者的意圖，探針的答案是文字實際傳到的意思。同一組案例每一輪修完重跑一次，就是規則檔的回歸測試。

## 修法

- **題目只問理解與動作**：封閉的案例題，每一題有預期答案；要審查就派 reviewer。
- **換題目之後先量雜訊**：同一份檔案、同一組題目派兩批，兩批讀錯的位置一致，才拿它比輪。
- **停止條件看讀錯，不看數量**：同一組案例題連續兩批零讀錯（同一份檔案重測），工具的測試全過，就停。
- **預期答案本身也會錯**：三份探針一致給出另一個答案時，先查預期答案與條文。
- **案例集要補**：每一輪從實際工作碰到的情形補一兩題。

## 判讀徵兆

| 徵兆 | 判讀 |
| --- | --- |
| 每一輪的歧義數在一個範圍裡上下跳，修了很多處而數字沒有下降 | 量到的是取樣，先做同檔重測 |
| 探針回報很多「兩種讀法」，而沒有一份把動作做錯 | 題目是審查題；規則檔要量的是讀錯 |
| 同一個位置在同一份檔案的多份探針裡反覆出現 | 這是訊號，總數不是 |
| 修完之後某一題的答案跟上一輪不同 | 修法動到了那一題經過的規則 |
