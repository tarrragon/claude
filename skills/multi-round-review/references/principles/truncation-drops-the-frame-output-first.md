# 報告被長度上限截斷時，先丟掉的是設計在尾端的那個產出

> **角色**：本卡是 `multi-round-review` 的支撐型原則（principle）、被「Reviewer prompt 結構」與「每個 frame 的產出契約」引用。
>
> **何時讀**：派 reviewer 或探針之前，決定它的回報格式時；以及回收報告、準備讀結果之前。

## 核心原則

訊息長度上限的截斷從尾端切，方向固定。**一份報告缺什麼因此由它的排版順序決定，與哪一段重要無關。**

有些 frame 的實際產出排在尾端而材料排在前面。翻譯探針是清楚的一例：派它的理由是那一欄「翻譯時我必須自己決定、而原文沒有明確給出的東西」，譯文是副產品；回報的自然順序是先附譯文再列決策，於是超長時被切掉的正是產出。逐格表與逐跳表同型——彙整那一列排在所有格子之後。

**截斷之後的報告讀起來是完整的。** 留下來的副產品有頭有尾、份量可觀，缺席的那一欄不留任何痕跡：沒有省略號，也沒有「以下略」。判斷「這份報告可以用了」的人看到的是一份有內容的報告。

## 實例

一次翻譯探針的指令沒有約定切分方式。兩份逐字相同指令的回報裡，譯文完整送達，決策清單被截斷，而決策清單是那個 frame 的全部價值。

同一批的另一個發現說明損失為什麼難補：兩份譯文並排後找出四處分歧，其中一處語意相反（一份譯成 does not require、另一份譯成 does not cut，原意是仍須填），而該處未出現在任何一份決策清單裡——譯者當下沒有意識到自己在決定。決策清單與譯文因此是兩個不可互相取代的產出，而截斷剛好只留下其中一個。

## 修法

**派發之前問一句：這個 frame 的產出排在報告的哪個位置。** 排在尾端的有兩個處置，反轉順序比切分便宜。

**反轉輸出順序。** 指令明寫產出先寫、材料後附。這一個不依賴執行者遵守任何約定，被切掉的一定是材料。

**約定切分維度與標號。** 材料本身也要完整送達時用這個：指定切分的維度（逐份、逐段、逐題）與標號方式，並要求每一則自報「第幾則、共幾則」。少了這個自報，收件的一方分不出「送完了」與「送了一半」。

**回收時先查尾端。** 讀報告之前看最後一段有沒有在句中斷開、最後一項的編號對不對得上前文宣告的項數。

## 反模式

- **用報告的長度判斷它完不完整。** 被截斷的報告通常正好是最長的那幾份。
- **把副產品的完整度當成整份的完整度。** 譯文齊全、逐格表填滿、原始摘錄一條不缺，這些與產出在不在無關。

## 判讀徵兆

- 報告的某一欄從缺，而那一欄正是派這個 frame 的理由。
- 副產品齊全而彙整欄短或消失。
- 報告最後一段在句中斷開，或最後一項的編號小於前文宣告的項數。
- 指令裡沒有約定切分，而預期的回報包含逐項的清單。

## 跟相鄰原則的關係

- [理解要取樣、不要靠判斷](comprehension-sampled-not-judged.md)：那張卡的證據單位是「份」——派了 N 份就要等 N 份到齊才讀收斂度。本卡補的是一份之內的完整度：份數到齊而每一份都缺了尾端那一欄時，收斂度讀在不完整的樣本上，而報告上看不出來。
- [finding 清單列的是抽樣位置](fix-the-class-not-the-cited-instances.md)：兩者都讓一份看起來完整的報告少掉東西，而責任端相反——那裡是偵測端只給了抽樣，本卡是傳輸端切掉了已經產出的東西。
