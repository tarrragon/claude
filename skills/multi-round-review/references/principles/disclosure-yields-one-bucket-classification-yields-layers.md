# 要求揭露只擋得住省略，要分層得改成要求分類

> **角色**：本卡是 `multi-round-review` 的支撐型原則（principle）、被「每個 frame 的產出契約」的零 finding 那一條引用。
>
> **何時讀**：寫 reviewer prompt 的產出契約時；以及收到一份回報大量零命中的報告、要決定採不採信時。

## 核心原則

**要求揭露擋掉的是省略，擋不住一鍋端。** 契約寫「零命中要明寫，不可省略不提」，得到的回報會是一句涵蓋全部的話——它完全合規，而它把證據力不同的東西壓成同一個粒度。

**一鍋端比省略難察覺，因為它已經照契約寫了。** 省略留下一個空白，讀的人看得見；一鍋端交出一份完整的報告，讀的人沒有理由停下來。

**分類這個動作在報告者那一側原本不存在，所以那不是隱瞞。** 他沒有把條目分成兩堆再選一堆寫出來——他從頭到尾只有一堆。要他分堆，得由問句把分堆這件事本身帶進來。

**判別問句：這個欄位要求的是「說出來」，還是「分好類」。** 只要求說出來的，回報會落在最省力的那個粒度。

## 實例：三十四條零命中裡有十六條不是證據

一個 reviewer 跑完六十六條判準，回報三十四條零命中，格式完全符合當時的契約。

被追問「這些是逐條造過候選情境才判的，還是讀過覺得清楚就放行」之後，那三十四條拆成三類：

| 這個零從哪來                                     | 條數 | 該怎麼讀                   |
| ------------------------------------------------ | ---- | -------------------------- |
| 造過候選情境、判定不成立                         |   17 | 是證據                     |
| 判準只有二元事實（大小寫、引號閉合），造不出情境 |   16 | 不適用本 frame，不可當證據 |
| 沒查                                             |    0 | 未知                       |

中間那一類被讀成第一類時，讀者會以為那十六條判準經過了檢驗，而它們根本不在那個 frame 的射程內——那個零證明的是判準與 frame 不匹配，不是判準通過了。

**因果比現象值錢：那三十四條原本是一鍋端的，分類是被問句逼出來的。** 報告者是在被要求交代採信依據的當下，才不得不去分「我試過」與「我看過覺得不用試」。

## 修法

**契約的措辭從揭露改成分類，成本是一句話。** 兩種寫法要的是同一份資料，差別只在誰做分堆：

| 寫法                                                      | 得到什麼 |
| --------------------------------------------------------- | -------- |
| 零命中須明寫                                              | 一鍋端   |
| 零命中須註明是造過情境判定通過、還是判準不在本 frame 射程 | 分層     |

**分類的選項要由契約列出來，不要問開放題。** 「請說明你的依據」得到的是自由敘述，而自由敘述會回到報告者原本的粒度；給定的類別把分堆變成填空。

**類別要窮盡到「未知」為止。** 少了「沒查」這一格，沒查的那些會被歸進最接近的一格，而最接近的那一格是「判定通過」。

## 第二個軸：這個零是缺陷，還是就是我要的結果

前面那三格回答「這個零可不可信」。還有一個獨立的軸——**這個零是什麼**——而兩個軸在報告的措辭上同樣會被壓成一句「零命中」。

一次收尾階段的自我盤點列出六個回報過的零，落在三種意義上：

| 這個零的意義       | 實例                                                       |
| ------------------ | ---------------------------------------------------------- |
| 沒發現問題         | 死名歸零、已修計數零殘留、某個目錄零使用                   |
| 零本身就是 finding | 某一類誤用在十二處全部沒有檢查點——零個檢查點是缺陷         |
| 零是正面結果       | 某個詞在全文零命中，因而證明它是自造的；探針答「完全不知道」 |

**「我沒找到問題」與「我找到了『沒有』這件事」在報告上同形。** 前者不帶資訊、只是一次通過；後者是這一輪的產出。壓成同一句之後，讀的人拿不到後者，而後者通常是那一輪最值錢的東西。

所以零命中的回報要同時標兩件事：**這個零可不可信**（三格），以及**這個零是不是我要的結果**（三種意義）。兩個軸正交，各自都要窮盡到「未知」那一格。

**兩軸會被混成一維列表，成因就是它們的報告措辭相同**——列的人分不開「零本身就是 finding」與「假通過」，因為在報告上它們都寫成「零命中」。分類的動作要由欄位帶進來，不會由觀察自己長出來。

## 這一條適用在哪裡

任何要求執行者回報彙總狀態的欄位：零命中、已檢查、無發現、全部通過、不適用、不涉及。共同形狀是**一個字面相同的結論可以由幾條路徑抵達**，而那幾條路徑的證據力差很多。

## 判讀徵兆

- 報告用一句話交代一組零命中，而那組條目的性質並不一致。
- 契約裡的欄位動詞是「說明」「註明」「寫出」，而沒有給定的類別。
- 被追問依據之後，報告者當場拆出了原本沒有的分類。
- 零命中的條數佔比很高，而該 frame 的判準裡混著需要構造情境的與純二元事實的。
