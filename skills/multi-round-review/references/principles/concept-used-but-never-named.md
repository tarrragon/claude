# 從名字出發的術語檢查，抓不到被反覆使用而從未命名的概念

> **角色**：本卡是 `multi-round-review` 的支撐型原則（principle）、被 Round 3 的「Outbound impact audit」frame 引用。
>
> **何時讀**：規劃 outbound 的知識卡缺口檢查時；或外部讀者帶著一個標準術語來問，而剛審完的一批內容查不到那個詞、卻處處在做那件事時。

## 論述基礎與限制

本卡由一個語言層教材集合（二十餘篇加二十餘張術語卡）的一次外部提問抽出。那個集合在提問前跑過五輪審查，frame 涵蓋寫作規範、實測回歸、跨章一致、冷讀、steelman、outbound、個案實跑，另派過理解探針、術語探針與翻譯探針。提問者連問四題，前三題都有落點，第四題問一個術語是什麼意思，而那個術語在整個集合裡沒有住址。

個案一則，無對照組。附的一次全站掃描與一批三份反向探針，數字各有明寫的口徑，不當精確度用。

## 核心原則

**每一種術語檢查都以「文本裡出現的名字」為入口——給它一個名字，它去查定義、查卡、查通用度。** 一個概念以操作的形態在多篇裡反覆出現，而名字一次都沒有寫進正文時，沒有任何一條檢查會走到它。這是[承重術語漏定義](cross-links-eat-the-article-they-live-in.md)的另一端：那裡名字出現頻率最高、作者寫到失去陌生感；這裡名字頻率是零，作者用的是它的寫法而不是它的名字。兩端同一個成因（作者手上有讀者沒有的東西），而既有偵測只覆蓋高頻那一端。

外部讀者帶名字進來，內容帶用法出去——這個入射角的差異，是缺口由提問撞出而非由任何一輪 reviewer 找到的原因。

## 症狀

那個集合講「有沒有對應資料」的三種寫法，其中存在性子查詢那一種在關聯代數裡叫半連接（semi-join），否定式叫反連接（anti-join）。集合對這兩個運算的處理是：`semi-join` 寫在某篇的 tags 裡而正文零次；「半連接」在另一篇正文裸用一次、無定義、緊接著路由到一篇不含這個詞的目的地；關聯代數卡列運算時漏了它而它的兄弟（積）已有專卡；`anti-join` 全集合零命中而它的語法形態出現在五篇裡、其中一篇的結論就是它。

## 為什麼每一個 frame 都放行

理由各異而入口相同。**術語分級**的觸發條件是「文中出現關鍵術語」。**承重術語掃描**掃連續漢字的高頻詞，這個概念在正文裡是 ASCII 關鍵字、中文名詞頻一或零。**術語探針**的受測單位是文中的一個詞。**理解探針**問你讀到什麼，讀者回報不出不知道存在的名字。**冷讀的行話洩漏**該抓到那一處裸用，放行的兩個候選成因是：緊鄰的連結讓 reviewer 把有路由讀成有定義（路由承接查的是目的地承接主題、不查含這個詞），或探針自己認得這個詞、知道得比目標讀者多。**outbound 缺卡**這一輪抓到的三張候選全是正文裡的承重詞，它的入口也是名字。**共同前提盤點**抓重複的判斷，這裡重複的是動作。**枚舉窮盡**對照的是領域正典（正典本來不列導出運算），對照這個集合實際執行過的運算才會少一個。**tags** 是宣稱而無人驗證宣稱——frontmatter 檢查驗欄位存在、不驗 tag 說的話成不成立。

## 這個機制不限於術語：每一種檢查都有入口

本卡的形狀在術語之外一樣成立。**每一種檢查都從某個入口出發，而零命中只證明「從那個入口走不到」。**

路由檢查是同一個機制的另一個實例，兩個方向分得特別乾淨：**死名檢查**（指過去、目的地不存在）與**孤兒偵測**（內容存在、沒有任何地方指過來）。一次實測裡死名檢查全綠，而孤兒那一側從來沒有被驗過——兩者都是路由缺陷、回報也都是零命中，差別既不在作用域也不在指令或判準，只在**只驗了一個方向**。

處置是一句話：**雙向各驗一次，並在報告上分開寫。** 合成一句「路由檢查通過」會讓沒驗的那一側繼承已驗那一側的信用。

盤點入口的方法是問每一條檢查「它從什麼東西出發」，再問「反過來會走到什麼」：名字對用法、指過去對被指到、宣告對實作、輸入對輸出。反向那一側多數沒有現成工具，而它存在與否是可以先回答的。

## 修法：補一個方向相反的檢查

**從用法盤點到名字。** 列出這批稿件裡反覆出現的操作形態（程式碼區塊的語法構造、跨篇重複的查詢形狀、同一組步驟在多篇各走一次），對每一種問：這個領域叫它什麼；那個名字在集合裡有沒有住址。候選指標是同一構造出現在三篇以上的程式碼區塊而正文沒有給它任何名字。這是[共同前提盤點](shared-premise-has-no-home.md)的操作層版本——那個 frame 管被多篇當前提的判斷，這一條管被多篇執行的動作。

**反向術語探針。** [術語探針](term-probe-measures-register-not-invention.md)給名字問意思，這一種給形態問名字：把程式碼片段單獨餵給多份低階模型（不附正文、不附集合的用詞），問「這種形狀在教材裡的標準名稱是什麼」，明令沒把握就寫沒把握。收斂到同一個名字代表它在領域裡通用，回集合 grep 有沒有住址。設計條件沿用術語探針：同批混入至少一個集合已經命名的形態當控制，控制項收斂才採用；測試的名字要先查不在探針讀得到的規範檔裡。實測一批三份：存在性子查詢三份全回 semi-join，否定式與外連接加 NULL 篩選兩段三份全回 anti-join 並全部指出兩段同形，控制項自連接收斂。單批，證明的是這個方向問得出名字、不是漏報率。

**tag 當宣稱驗。** 對每篇的每個 tag 問正文有沒有承接。可機械產生候選而精確度低：一次全站掃描一萬兩千餘個 tag 近四千個在該篇正文字面零命中，該集合四十一個、收成「整個集合任何正文零命中」後二十二個、真缺口一個；噪音主要是英文 tag 對中文正文。候選生成器，判定要人做。

**枚舉卡對照集合的用法、不只對照正典。** 新文章用到清單外的運算時，枚舉卡是要回頭改的檔案之一。

**外部提問是最便宜的異源。** [規模買不到異源視角](review-scale-does-not-buy-independent-origin.md)在術語層的形態：同一個 session 出的搜尋落點問題會沿用集合自己的詞彙，出題人正是那個沒寫過那個詞的人。讀者實際提問要收進下一輪的問題清單，收的重點是他用了哪些集合沒用過的詞。

## 判讀徵兆

- 一個語法構造出現在多篇的程式碼區塊裡，正文沒有給它任何名字。
- tag 裡有一個詞，整個集合的正文零命中。
- 枚舉卡列了一組成員，而某篇在做清單外的那一個。
- 某個術語在正文只出現一次、緊跟一條連結，而目的地沒有那個詞。
- 外部提問用的名詞，集合裡查不到，而有一篇整篇在講它指的那件事。
