# 操作指引要帶環境專屬的工具路徑

> **角色**：本卡是 `multi-round-review` 的支撐型原則、被 Round 2-B″ 的 executable walkthrough 維度引用。
>
> **何時讀**：審查操作型內容時、或步驟被判定「邏輯正確、順序合理」但讀者仍照做不出來時。

## 結論

操作型內容的一個動作，在不同執行環境裡對應完全不同的工具路徑。只寫動作不寫工具，等於把「選工具」的認知負擔轉嫁給讀者——他知道該做什麼，但坐在電腦前不知道該打開什麼。

同一個動作跨環境的差異幅度：

| 動作       | 容器環境              | 有完整登入權限的機器     | 只有受限存取的託管環境      |
| ---------- | --------------------- | ------------------------ | --------------------------- |
| 保存現況   | 映像檔提交與標記      | 機器映像 + 套件清單      | 檔案同步 + 環境資訊頁面截圖 |
| 匯出資料   | 在容器內執行匯出工具  | 直接執行匯出工具         | 網頁管理介面匯出（有時限）  |
| 定期備份   | 磁碟區快照 / 倉庫推送 | 排程 + 匯出 + 物件儲存   | 本機排程 + 檔案鏡像工具     |
| 查執行設定 | 容器檢視指令          | 服務管理與連線埠查詢指令 | 環境資訊頁面 + 主機控制面板 |

四種動作在三種環境下是十二條不同的路徑，沒有一條能代表其他條。

## 為什麼審查抓不到

邏輯層的審查（步驟順序對不對、前後有沒有矛盾）與可執行性是兩件事。步驟可以完全正確而仍然無法照做，因為正確性檢查的對象是「這樣做對不對」，可執行性的對象是「這樣做的下一個動作是什麼」。

這個缺口的實測特徵是**同根因被指出兩次**：第一次補了工具名稱（「用什麼做」），第二次才補環境替代路徑（「其他環境怎麼做」）。第一次修完會產生已經補齊的錯覺，因為文中確實已經出現具體工具了——只是那些工具只適用於一種環境。

## 理想做法

假裝讀者從零照做，每一步問「下一個動作是打開什麼軟體、輸入什麼指令」。任何一步答不出來就是缺口。

接著問環境分支：這一步在另外兩種常見環境下怎麼做。文章若涵蓋多種環境，每一步要按環境分列工具；若只涵蓋一種，要在開頭明確標示適用環境，讓其他環境的讀者及早知道這篇不適合他。

## 判讀徵兆

- 步驟用動詞描述動作（「拍下現況」「建立備份」），但整段沒有任何工具名稱或指令。
- 文中的工具全部屬於同一種執行環境，而文章的適用範圍沒有相應限縮。
- 修過一次工具缺口之後，仍有讀者回報照做不出來。
