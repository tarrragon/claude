# 代理比本體便宜，所以成本壓力最高的階段一定伸手拿代理

> **角色**：本卡是 `multi-round-review` 的支撐型原則（principle）、被「整合 finding 跟 fix 工作流」的收尾清單引用。
>
> **何時讀**：收尾階段反覆出現表面不同的失效，而處置一律寫成「下次更仔細」時。

## 核心原則

**檢查一件事的時候，手邊通常有兩個東西：本體，與一個站在它前面的代理。** 規則的 regex 是本體，錯誤訊息對它的描述是代理；自己跑一次是本體，別人量過的那個數字是代理；成品的全部是本體，這一輪改動過的檔是代理；不加豁免時會失敗的位置是本體，自己寫的豁免條款是代理。

**代理比本體便宜，而且它們的產物在報告上同形。** 兩條路徑走完都得到一個零、一次通過、一句「已檢查」。

**收尾階段的成本壓力最高，所以在那個結構下伸手拿代理是理性的。** 這是本卡的重點：**「下次更仔細一點」對它無效**，因為問題不在注意力的總量，在那個時點的成本結構剛好指向代理。

## 四個實例的差價都很小

| 代理             | 本體                       | 差價               |
| ---------------- | -------------------------- | ------------------ |
| 錯誤訊息的描述   | 規則的 regex               | 打開一個檔         |
| 別人量過的數字   | 自己跑一次那條指令         | 一條指令           |
| 這一輪改動過的檔 | 成品的全部                 | 改一個路徑參數     |
| 自己寫的豁免條款 | 不加豁免時會失敗的那些位置 | 跑一次不帶豁免的版 |

**每一個差價都小到「就用代理吧」不像一個決定。** 這是它難防的地方——沒有一個時刻可以指認為「我在這裡選擇了走捷徑」，於是事後回看也找不到那個決定點。

## 套用之前先驗那個差價是真的

本卡的三條修法都預設「代理確實比較便宜」，而那個前提要驗過才算數。打開一個檔、跑一條指令這類差價是真的，看得見也算得出來；**有些看起來像成本的東西一量就翻轉**——[審查只問效力不問代價](review-frames-ask-efficacy-never-cost.md)裡的「找誤報會減少產出」就是一例，實測顯示撤回換來的是更準的 finding，那個成本差並不存在。

**「這是理性的成本選擇」是一個可以被驗的宣稱，不是一個解釋。** 沒驗就套用它，等於把一個未經檢驗的假設寫成了經濟學，而它會讓一個該修的偏斜看起來合理。

## 修法：改成本結構，不改注意力

- **降低本體的取用成本。** 把 regex 印進錯誤訊息、把「自己跑一次」做成一行可複製的指令、給檢查器一個「不帶豁免」的旗標。差價降到零，代理就沒有優勢。
- **讓兩者的產物長得不一樣。** 回報要附「這個結論來自本體還是代理」——查核責任的五欄分類與零命中的兩軸做的正是這件事。
- **在收尾清單上明列這一項。** 每一步旁邊寫「我用的是本體還是代理」，把那個不像決定的動作變成一個要填的欄位。

## 限制

四個實例出自同一段連續的工作，所以成立的是它們共用同一個結構，而不是這個機制的頻率。修法方向（降低本體的取用成本）尚未實測。

## 判讀徵兆

- 同一個階段反覆出現表面不同的失效，而處置一律寫成「下次更仔細」。
- 某個檢查的產物是一個零或一句「已檢查」，而說不出它是從哪一條路徑得到的。
- 一件事有兩個可用的來源，而兩者的差價是一條指令或一個檔案。
- 事後回看找不到「決定走捷徑」的那個時點。
