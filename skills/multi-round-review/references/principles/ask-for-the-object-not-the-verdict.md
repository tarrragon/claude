# 要交出物件，不要交出關於物件的判斷

> **角色**：本卡是 `multi-round-review` 的支撐型原則（principle）、被「整合 finding 跟 fix 工作流」的質疑步驟引用。
>
> **何時讀**：一個 finding 宣稱某件事不可能、超標或不成立，而要決定該追問什麼時。

## 核心原則

**一個關於物件的斷言可以在抽象層完全合理，而它的證偽要靠構造出那個物件。** 「這兩條判準不可同時滿足」是一個判斷；那個同時滿足兩條判準的東西存不存在，要寫出來才知道。

**沒有人要求構造時，回報者沒有理由去做。** 他的主張在他自己的推理裡是自洽的，而推翻它要離開抽象層——在抽象層再讀一次只會再確認一次，因為它在那一層本來就自洽。

**所以追問的形態決定了那個宣稱會不會被驗證。** 「請確認 X」得到的是同一個判斷再說一次；「請把 X 寫出來、算出來，我要能自己驗證」得到的是物件，而物件會自己說話。

**追問的成本落在追問者這一側**——他要先知道那個宣稱需要什麼物件才成立。所以這一條寫不成回報者的自律規則，它住在追問的那一側。

## 兩個實例

**構造一個宣稱不存在的東西。** 回報主張兩條判準不可同時滿足，理由是一串會累加的要求（觸發詞要窮盡列舉、負面觸發也要寫、還要第三人稱，聽起來確實塞不下）。追問寫的是「請把那個 description 寫出來給我看，我要能自己驗證它確實兩邊都達不到」。它去構造，構造出來兩百零六字元，低於門檻的兩百五十，主張當場不成立。

**把已經在手上的數字代進判準。** 另一個回報說某個檔案超標。追問要求算出那份內容的 ASCII 佔比——七成七，據此內插出的門檻是一萬六千九百零八，該檔通過。而**同一個回報者在更早一輪自己量過那個佔比**（八成二），卻仍拿另一組係數判它超標。

兩例的形態一致：**資訊一直在場，缺的是把它代進判準的那一步。**

## 修法

- **追問的動詞用「寫出來」「算出來」「構造一個」，不用「確認」「說明」「檢查」。** 前一組要求一個新產物，後一組容許把原本的判斷換句話說。
- **加上「我要能自己驗證」。** 這一句把產物的接收者從回報者換成追問者，交出來的東西因此必須獨立於它的推理而可檢驗。
- **回報者已經量過的數字，明確要求代入並印出過程。** 「把你量到的那個值代進這條判準、寫出計算」比「請確認判定正確」多一步，而那一步正是失效的位置。
- **判別問句：這個宣稱要成立，需要一個什麼樣的物件。** 一個字串、一個數字、一組走得完的步驟——說得出來就去要它；說不出來，那個宣稱可能還沒有可驗證的形式。

## 限制

兩個實例同一批、同一個要求者與回報者，所以「換一個回報者是否同樣有效」在證據範圍之外；「不追問時這一類宣稱有多少會倒」也沒有量測。

## 判讀徵兆

- 回報的關鍵宣稱是一個否定式的可能性判斷（不可能同時、塞不下、達不到、無法兼顧）。
- 宣稱附的理由是一串會累加的要求，而沒有實際把它們加起來。
- 回報者在更早的輪次量過相關的數字，而本輪的判斷沒有用到它。
- 追問用的動詞是「確認」「說明」「檢查」。

## 跟相鄰原則的關係

- [要求揭露只擋得住省略，要分層得改成要求分類](disclosure-yields-one-bucket-classification-yields-layers.md)：姊妹卡。兩者都是問句的形態決定回報的內容，受詞不同——那裡問同一批東西怎麼分堆，本卡問交的是判斷還是物件。共用的推論是回報者不會做問句沒要求的工作，而那不是隱瞞。
- [判定型規則要規定判定的痕跡](judgment-rules-must-specify-their-trace.md)：本卡是它在追問端的形態。那張卡規定產物要存在，本卡指定產物的形態。
- [從名字出發的檢查抓不到沒有名字的東西](concept-used-but-never-named.md)：兩者都靠換一個入射角才看得見——那裡換的是檢查的方向，本卡換的是追問的動詞。
