> **何時讀**：每一輪的 finding 整合完、派下一輪之前，查〈大綱稽核〉的觸發（審查對象是規則類文件時查〈設計稽核〉；任何一輪都可能成立）；Round 3 跑完、判定要不要 Round 4 時讀〈停止訊號〉；規劃任何一輪之前對照〈反模式〉。**亦由此進入**：`principles/cross-round-stopping-signal.md` 的角色段寫明它被〈Round N 規劃判讀〉引用，讀那張卡的人會回到這裡。

## Round N 規劃判讀

Round 1-3 是硬底線、直接跑不問。Round 3 結束後才進入「是否需要 Round 4」的判讀（〈停止訊號〉）。〈大綱稽核〉與規則類文件的〈設計稽核〉跟停止訊號不同：這兩項決定的是下一輪派什麼、還是先重組或重寫，每一輪整合完都要查一次觸發。重寫之後從 Round 1 重新起算時，Round 1-3 的硬底線照樣適用。兩項稽核共用一個停點：「同一批」指使用者交辦的這一次審查，重組或重寫之後從 Round 1 重新起算仍算同一批；「第二次」數的是兩項稽核的結構事實成立的次數，兩項合計。第一次成立時照該稽核的做法重組或重寫；第二次成立時不重組也不重寫，停下來把兩次稽核的痕跡交給使用者決定。這一停不受「Round 3 跑完之前不問」限制。一批同時有教學文章與規則類文件時，兩項都查，各自只看自己那一類的檔，成立的次數照兩項合計。

### 大綱稽核

審查對象是教學文章或文章集合時，主 session 在派下一輪之前做大綱稽核；它屬於 `SKILL.md`〈誰做哪一段〉底下〈主 session 不外包的四項〉裡的停止判讀，稽核與它導致的重組算觸發它的那一輪的處置，不另計一輪。審查對象是規則類文件時不做大綱稽核：每一輪照 `integrating-findings.md`〈修完拿任務重走一次，再派下一輪〉修，派下一輪之前查下面的〈設計稽核〉的觸發。

**觸發**（任一項，任何一輪都可能成立；越早做，前幾輪打磨過、之後被重組改掉的句子越少）：

- 題目範圍審查（2-C）判定某一節比標題泛、要移出去獨立成篇（只刪段標裡推導連接詞的那一種不算）。2-C 的移出成篇就是一次重組，照本節的做法與〈重組之後〉處理。
- 任一 reviewer 回報同一個機制或同一份清單在兩處展開而成員或說法不同。
- 同一段在這次審查裡被修法改過兩次以上：審查對象有逐輪提交時用 `git log -L <起>,<止>:<檔案> <受審版本的 hash>` 查；各輪之間沒有提交時，拿各輪的快照 diff 對照。finding 只給節名時，先回受審版本定位到行。
- Round 3 結束時仍有必修 finding，而且不全是事實錯誤。

**做法**，每一步寫一行痕跡（查了什麼、結果）：

1. 逐篇寫出讀者讀完要做的決定與要理解的機制，對照每一節為哪一個而存在。對不上任何一個的節列為重排的候選；節的題目來自素材裡的說法時，照 compositional-writing 的 `references/source-to-teaching-analysis.md`〈重建之後說法放在哪裡〉處理。
2. 查三項結構事實：
   - **同一個機制或同一份清單在兩處以上各自展開**（各自寫出成員或推導）。一處展開、別處一句話加連結的不算。關鍵詞取自本輪必修 finding 指向的機制與清單，以及各篇列出的條列清單的成員詞，交叉掃全集合。
   - **題目範圍審查判定某一節要移出獨立成篇**（觸發條件的第一項；由它觸發時這一項必然成立，處置照第 3 步）。
   - **一篇裡有兩條以上互相獨立的推導線**：兩條線的結論不共用前提，刪掉其中一條，另一條仍然完整。
3. 前兩項成立時重排大綱或拆篇，每個機制只在一處展開，其他位置寫連結；第三項成立時派理解探針量閱讀負擔（`round-2-probes.md`），拆不拆依回報，作者自認讀得通不改變這一步。三項都不成立、或只有第三項成立而探針回報不必拆時，回到原本的輪次規劃：Round 3 之前派下一輪，Round 3 之後照〈停止訊號〉判讀。

**稽核與重組期間的其他 frame**：事實核對、斷言支撐與題目範圍照常規劃；句子層的打磨（1-A、2-A 這類）延到重組之後，因為重組會改寫那些句子。

**重組之後**：下一輪跑〈重組後遺症 frame〉（`round-3-self-application.md`），它的 finding 照常處置；重組發生在 Round 3 之前時，後遺症 frame 跟那一輪原本的 frame 一起跑，不頂替 Round 1–3 的硬底線；七軸從重組後那一輪重新盤點，舊輪次涵蓋的是重組前的文字。稽核的結構事實是同一批裡第二次成立時，不重組，照〈Round N 規劃判讀〉開頭的停點處理。

理由：一篇同時討論好幾個主題時，同一個機制會在兩個主題的段落各展開一份，每一個新 frame 抓到的都是這個缺陷在句子上的投影，照 finding 修句子不收斂；而重組的 diff 大、再修一輪句子的 diff 小，所以觸發寫成查得到的事實，不靠執行者感覺稿件快收斂了。「句子層打磨延後」與「第二次重組交給使用者」是推論，還沒有實測過。實例與證據範圍見 [review-nonconvergence-points-to-outline](principles/review-nonconvergence-points-to-outline.md)。

### 設計稽核

審查對象是規則類文件（規則檔、規範、agent 指令、skill）時，主 session 在每一輪整合完、派下一輪之前查觸發；它跟大綱稽核一樣屬於主 session 不外包的停止判讀。

**觸發**（任一項）：

- 這一輪至少有一則必修，而且其中一半以上（含剛好一半），指出的缺陷是上一輪之後的修改造成的：逐則拿去上一輪的凍結版本找，上一輪在同一個位置已經有同一個缺陷的（措辭不同也算）是既有的；這個缺陷成立所依賴的句子（兩條規則互撞時是兩邊的句子）有任一句是上一輪之後新增、改寫或刪除的，就是新的，修法在新的位置寫出同一類缺陷也算新的。逐則寫出判定與上一輪的凍結版本對應的行（沒有就寫「無」）；各 reviewer 指向同一個缺陷的必修算一則。判的是缺陷，不是句子的字面：用 diff 的行來判，一段一行的規則檔裡改過的段落任何 finding 都會位於新增行上；只照字面 grep，措辭改過一個字而缺陷相同的舊缺陷會被誤算成新的。某一輪的審查範圍刻意只包含上一輪之後新加的句子時，那一輪不用這一項，但連續第二輪也這樣限縮時照常查；Round 1 沒有上一輪的凍結版本，也只查下一項。
- 同一段在最近一次重組或重寫之後（沒有就從 Round 1 起算）被修法改過兩次以上，重寫本身不算一次修法（查法同〈大綱稽核〉的同一項）。

**做法**，每一步寫一行痕跡：

1. 不派下一輪，也不再照 finding 補句子。
2. 查三項結構事實：
   - **同一條規則在兩份以上的檔裡各有一份完整寫法，而兩份沒有工具比對**（原則卡與它在 skill 的副本、skill 與它的公開鏡像這類有工具比對的刻意副本不算；一處完整、別處一句話加連結的不算）。
   - **一節裡同時寫「怎麼寫」與「既有文字怎麼處理」**：後者帶時間範圍（新寫與既有、改到與沒改到、批量替換），跟前者放在同一段時，同一個句子會從兩條規則得到不同的處置。
   - **範圍是用例外上的例外切出來的**：某條規則的例外底下還有例外，或適用對象在每條規則裡各自界定。
3. 第 2 步成立的事實各自照對應的寫法重寫：同一條規則有多份完整寫法時，只留一份，其他位置連過去；一節裡混寫既有文字的處理時，規則只寫怎麼寫，既有文字一次處理完，或記進專案的待辦；範圍是例外上的例外時，用正面的方式在一處定義，其他規則引用。三項都不成立時，照 finding 修完這一輪，回到原本的輪次規劃：Round 3 之前派下一輪，Round 3 之後照〈停止訊號〉判讀。
4. 重寫的版本從 Round 1 開始審：前幾輪審的是重寫前的文字。稽核的結構事實是同一批裡第二次成立時，不重寫，照〈Round N 規劃判讀〉開頭的停點處理。

理由：規則類文件每補一條邊界句，就多一條邊界；規則有多份完整寫法時，還多一處要同步。下一輪的 reviewer 在新邊界上找到新的互撞，照 finding 修不收斂。缺陷是否在上一輪之後才出現，逐則對照凍結版本查得到；把它讀成修法本身在產生缺陷，是從一批審查推論的，「一半以上」的門檻沒有校準，重寫的處置也還沒有實測過。觸發寫成逐則可查的判定，是為了不靠執行者感覺稿件快收斂了。實例見 [review-nonconvergence-points-to-outline](principles/review-nonconvergence-points-to-outline.md)〈修法〉的「規則類文件的設計稽核」那一項。

### 停止訊號

大綱稽核（規則類文件是設計稽核）沒有觸發，或稽核的三項事實都不成立時，照下面的停止訊號判讀。停止訊號齊備、停：

1. **七軸動完**：frame / instance / surface / scope / cadence / timing / granularity 七軸都用過。**判定這一條之前打開 [七軸盤點](principles/review-seven-axes.md)**——七個名字不含程序，而第四條降級之後 quorum 的重量壓在這一條上。那張卡給填法（逐 reviewer 對帳、不憑印象）、判定（不適用不計入分母、只有最弱切換的軸記為未動）、以及未動之後的處置，另附一份填好的盤點
2. **Finding 性質退化**：新 frame catch 到的 finding 又退回 surface 層（surface 層指 Round 1 預期 finding 那一類：編號、連結、規範違反）。**痕跡**：列出被判為 surface 的那幾則與它們佔本輪 finding 的比例，沒列的宣告不算
3. **修法成本反轉**：修一個 finding 成本超過讀者實際感受價值。**痕跡**：列出被判為成本反轉的那幾則，各寫一行估法（修要動哪幾處、讀者在哪個位置感受到差別），沒列的宣告不算
4. **新 frame 想不出來**（最弱的一條、不作必要條件）：腦力激盪後想不出「能 catch 新東西」的 frame——這一條隨經驗反向移動，見同節〈第四條量的是判斷者、不是稿件〉段

任二齊備、可以判定「真的夠了」，而**分母是前三條**。任一齊備、繼續但要主動規劃 frame 切換。

**第四條量的是判斷者、不是稿件**，所以它在實務上永遠不成立——想得出多少 frame 由執行者的經驗決定，跑過越多輪的人庫存越大，四次實跑零次成立（第四次停在四輪時仍想得出術語探針）。把它與前三條平鋪並列有兩個代價：quorum 的分母悄悄縮水（沒有人做過這個決定），以及執行者以為自己還沒做完、而「還可以再跑一輪」這個念頭沒有終點。判別新增訊號時問一句——這一條量的是被判斷的對象、還是判斷者自己；答案是一個以能力為條件的否定式（想不出、找不到、看不出）就多半量的是判斷者。詳見 [跨輪 review 停止訊號](principles/cross-round-stopping-signal.md)。

**未動的軸不一定是下一輪買得到的。** 七軸盤點的每一格要多填一欄「這一軸靠什麼補上」：五個軸填「下一輪」，timing 填「時間」，instance 填「另一個執行者」。填時間或另一個執行者的軸，第五輪補不到——照「未動的軸就是下一輪的價值來源」排下去，跑出來的那一輪在七軸上補不了任何一格，產出只能來自把 frame 軸再細分，正是「缺軸不缺深度」（`principles/review-seven-axes.md` 的結論）要防的加輪數。處置是建票綁觸發條件（異源交換的觸發是有另一個執行者可用，而票要指定交換的形式——兩邊各自量同一件事、各自報數，不是一邊做另一邊審；驗收寫「有幾個約定因為這次並排而被寫明」，不寫「取得對方的 N 則 finding」——那一類的產出沒有歸屬，按來源歸帳會固定漏掉它、冷讀的觸發是下次有人要動這份內容），並把停止判定寫成兩句話：哪幾軸判定為已覆蓋、哪幾軸判定為取不到。**「停在資源用完」與「停在證據齊備」在文字上同形**，不分開寫就消失。詳見 [缺口的處置看它需要哪一種資源](principles/gap-remedy-depends-on-the-resource-it-needs.md)

## 收尾清單

整批審查結束前的動作，每一輪修完的分層掃描在 `integrating-findings.md`；這裡是整批只做一次的：

1. **整體通讀**——所有 frame 跑過、finding 修完，不等於這份內容現在是好的；判斷標準是「讀起來像一個人一次寫完的嗎」，逐條檢查修法產物不能取代它
2. **重讀共用產物**——入口頁（路線還通嗎）、待辦清單（每列真的都還沒做、做完的都刪了嗎）、索引。它們被每一輪修改而不在任何一輪的射程裡
3. **列出被改過而不屬於任何一輪的產物**與這一批用過的工具版本——起跑前列過一次的那份清單，收尾再對一次
4. **finding 的方向分佈**——逐則標「漏抓／多抓」，一欄全空代表缺 frame 不是缺缺陷
5. **停止判定寫成兩句**——哪幾軸判定為已覆蓋、哪幾軸判定為取不到已建票

**停止之前還要看 finding 的方向分佈。** 把所有 finding 逐則標一個方向欄，只有兩個值：這一則說規則**漏掉了**什麼，還是說規則**多抓了**什麼。一欄全滿、另一欄全空時缺的是 frame 而不是缺陷——**零 finding 與零 frame 在報告上同形**，代價那一側交白卷讀起來像那一側沒有問題。成因兩端同向：找到漏抓是產出（多一則 finding），找到誤報是否定產出（少一則，且要撤回別人寫下的），而規劃者在找「還有什麼沒被檢查」、執行者的價值由 finding 數體現。修法是 frame 清單成對排（判斷標準漏了哪些情境／判斷標準會把哪些合規個案判成違規；這一類還有哪些位置／這一類的命中有哪幾處其實合規；涵蓋範圍夠不夠／成本由誰承擔）。「找誤報會減少產出」這個估計本身是錯的——實測兩次撤回之後的替代 finding 都比原本那一則強。詳見 [審查的 frame 全部在問效力](principles/review-frames-ask-efficacy-never-cost.md)

**停止訊號之外還有一個前置條件：整體通讀。** 所有 frame 跑過、所有 finding 修完，不等於這份內容現在是好的——修法本身改變了被審查的對象，而兩次各自正確的修法可以合成一個對兩個 frame 都不可見的缺陷（per [多次修法會合成缺陷](principles/sequential-fixes-compose-into-defects.md)）。停止之前要有一次以整體為對象的通讀，判斷標準是「這份內容現在讀起來像一個人一次寫完的嗎」。逐條檢查修法產物不能取代它——合成缺陷在那些條目之間。

同一輪還要重讀**共用產物**：入口頁（路線敘述）、待辦清單、索引。它們被每一輪修改、卻不在任何一輪的審查範圍裡，因為每輪的 frame 都是對著內容設計的。入口頁看「這幾條路線現在還通嗎」，待辦清單看「這幾列還沒做嗎、做完的都刪了嗎」。

**共用產物只是三類射程外項目的其中一類。** 每個 frame 都要有一個審查對象，所以不在審查對象裡的項目沒有任何 frame 會碰到——除了共用產物，還有**審查所用的工具**（方法論、規範檔、腳本，以及它們的版本）與**審查自己的產物**（finding 清單、覆蓋盤點表、停止判定）。一次四輪、二十餘個 reviewer 的審查全程沒有一步會發現所用的方法論落後十一個 minor 版，而那些版本差裡有一版正好改掉了該次停止判定所依據的規則。這一類靠清單補、不靠加 frame 補（新 frame 也要先有對象），所以起跑前列一次工具與版本、收尾前列一次被改過而不屬於任何一輪的產物。詳見 [審查的射程只涵蓋被審查的對象](principles/review-scope-never-includes-the-instrument.md)

## 反模式

規劃層的反模式。「用 finding 數遞減當停止訊號」與「同 reviewer 跑多輪」已寫成 `SKILL.md`〈基本原則〉第 1、3 條的正向形式，不重複；修法層的反模式在 `integrating-findings.md`〈修法的反模式〉。

- **跳過 frame 規劃直接派 reviewer**：「再來一輪 audit」沒指定 frame 切換、reviewer 用同方向掃同類問題、是 frame 顆粒度盲點的具體實例
- **跑臨時子集卻當成跑完整框架**：只派幾個臨時擬的 reviewer frame + 一次 grep、就回報「review 完成 / clean」—— 漏抓後容易誤判成「框架不足」（design gap）而去加 frame / keyword、實際是「沒跑完該跑的輪」（execution gap）。漏抓先分 design gap（改框架）vs execution gap（改執行、別只加 keyword）；register/stance 類（喊話 / 誇飾 / 必然）尤其要靠 reader simulation + external cold-read、不是加 keyword（per compositional-writing 的 multi-pass-review-frame-granularity 原則）
- **把「多輪全過」當成「知識類型對」**：歷輪 finding 全部落在字句與結構層時、「三輪全過」的語意只是「已覆蓋層全過」——斷言支撐與知識類型層若沒有 frame 負責、錯的知識類型（披著教學結構的經驗談）會全數通過。finding 類型分佈本身是訊號：全部集中表面層 = 深層無人在看、下一輪排斷言支撐 frame（per [claim-support frame](principles/review-needs-claim-support-frame.md)）。一次乾淨的實例：某份文件跑完三輪八個 reviewer、報告寫「三輪全過」，一天後另一批審查在同一份文件上找出五項嚴重的既有缺陷，全部來自上一次唯一沒有派人負責的維度——其中一項是判斷標準自身前後矛盾（起點欄宣告兩個維度、判定訊號欄只實作其中一個）。**「多輪全過」的作用域是跑過的那幾個 frame，而報告上不會出現那個限定詞**，因為列出跑了哪些 frame 的責任沒有人承擔——收尾時要自己把跑過的 frame 列出來，並問哪些維度整批沒有人負責
