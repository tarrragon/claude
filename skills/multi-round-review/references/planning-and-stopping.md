## Round N 規劃判讀

Round 1-3 是硬底線、直接跑不問。Round 3 結束後才進入「是否需要 Round 4」的判讀（〈停止訊號〉）。〈大綱稽核〉與規則類文件的〈設計稽核〉跟停止訊號不同：這兩項決定的是下一輪派什麼、還是先重組或重寫，每一輪都要查一次觸發，時機寫在各自那一節。重寫之後從 Round 1 重新起算時，Round 1-3 的硬底線照樣適用。

下列任一個停點成立時，這一批不重組也不重寫，停下來把材料交給使用者決定方向，不受「Round 3 跑完之前不問」限制。

- **同一批裡結構事實第二次以後的每一次成立**（大綱稽核與設計稽核都有這個停點）：「同一批」指使用者交辦的這一次審查，重組或重寫之後從 Round 1 重新起算仍算同一批；次數數的是兩項稽核有結構事實成立的次數，兩項合計；一次稽核裡幾項結構事實同時成立，都算一次。使用者在停點看過而決定不重寫、不重組的那一項事實，之後還在同一個位置（同一條規則的同幾份檔、同幾段）時，稽核把它當成不成立，痕跡寫明「使用者在第幾輪的停點決定保留」；換了位置或另一項成立時才算。**當成不成立**的事實不計次，該稽核的第 3 步不重組也不重寫它，判「同一段改兩次」那個停點的「三項結構事實都不成立」時也算不成立；〈設計稽核〉第 2 步範圍外的事實也用這一組後果。第一次成立不是停點，照該稽核的做法重組或重寫。材料是歷次成立的稽核痕跡；歷次成立裡有設計稽核時，另附停下之前做的兩層反省（〈設計稽核〉做法的第 5 步）。
- **設計稽核由「同一段被修法改過兩次以上」觸發，而三項結構事實都不成立**（只有設計稽核有這個停點）：材料是這一次稽核的痕跡與兩層反省。設計稽核只由必修的比例觸發、三項結構事實都不成立時，不是停點，依〈設計稽核〉第 3 步照 finding 修。

一批同時有教學文章與規則類文件時，兩項都查，各自只看自己那一類的檔。任一項到了停點，整批都停下，另一項這一輪該做的重組或重寫也等使用者決定。

使用者在停點做了決定之後，照決定的內容往下，決定可以依檔案分項（文章重組、規則照 finding 修），各項照對應的走法：決定重寫時，重寫的版本照〈設計稽核〉第 4 步從 Round 1 審；決定重組時，照〈大綱稽核〉的〈重組之後〉；決定照 finding 修下去時，停在 Round 3 之前的那一輪就修完派下一輪，停在 Round 3 或之後的那一輪就修完照〈停止訊號〉判讀；決定結束審查時就結束。決定不在這幾種裡時，照使用者的原話做。結構事實成立的次數不因使用者的決定歸零。

### 大綱稽核

審查對象是教學文章或文章集合時，主 session 在派下一輪之前做大綱稽核；它屬於 `SKILL.md`〈誰做哪一段〉底下〈主 session 不外包的四項〉裡的停止判讀，稽核與它導致的重組算觸發它的那一輪的處置，不另計一輪。審查對象是規則類文件時不做大綱稽核，改查下面的〈設計稽核〉（時機寫在那一節），每一輪照 `integrating-findings.md`〈修完拿任務重走一次，再派下一輪〉修。

**觸發**（任一項，任何一輪都可能成立；越早做，前幾輪打磨過、之後被重組改掉的句子越少）：

- 題目範圍審查（2-C）判定某一節比標題泛、要移出去獨立成篇（只刪段標裡推導連接詞的那一種不算）。2-C 的移出成篇就是一次重組，照本節的做法與〈重組之後〉處理。
- 任一 reviewer 回報同一個機制或同一份清單在兩處展開而成員或說法不同。
- 同一段被修法改過兩次以上：次數照〈設計稽核〉同一項的算法，只是大綱稽核排在這一輪的整合之後，所以這一輪的整合也算一次。審查對象有逐輪提交時用 `git log -L <起>,<止>:<檔案> <受審版本的 hash>` 查；各輪之間沒有提交時，拿各輪的快照 diff 對照。finding 只給節名時，先回受審版本定位到行。
- Round 3 結束時仍有必修 finding，而且不全是事實錯誤。

**做法**，每一步寫一行痕跡（查了什麼、結果）：

1. 逐篇寫出讀者讀完要做的決定與要理解的機制，對照每一節為哪一個而存在。對不上任何一個的節列為重排的候選；節的題目來自素材裡的說法時，照 compositional-writing 的 `references/source-to-teaching-analysis.md`〈重建之後說法放在哪裡〉處理。
2. 查三項結構事實：
   - **同一個機制或同一份清單在兩處以上各自展開**（各自寫出成員或推導）。一處展開、別處一句話加連結的不算。關鍵詞取自本輪必修 finding 指向的機制與清單，以及各篇列出的條列清單的成員詞，交叉掃全集合。
   - **題目範圍審查判定某一節要移出獨立成篇**（觸發條件的第一項；由它觸發時這一項必然成立，處置照第 3 步）。
   - **一篇裡有兩條以上互相獨立的推導線**：兩條線的結論不共用前提，刪掉其中一條，另一條仍然完整。
3. 前兩項成立時重排大綱或拆篇，每個機制只在一處展開，其他位置寫連結；第三項成立時派理解探針量閱讀負擔（`round-2-probes.md`），拆不拆依回報，作者自認讀得通不改變這一步。三項都不成立、或只有第三項成立而探針回報不必拆時，回到原本的輪次規劃：Round 3 之前派下一輪，Round 3 之後照〈停止訊號〉判讀。

**稽核與重組期間的其他 frame**：事實核對、斷言支撐與題目範圍照常規劃；句子層的打磨（1-A、2-A 這類）延到重組之後，因為重組會改寫那些句子。

**重組之後**：下一輪跑〈重組後遺症 frame〉（`round-3-self-application.md`），它的 finding 照常處置；重組發生在 Round 3 之前時，後遺症 frame 跟那一輪原本的 frame 一起跑，不頂替 Round 1–3 的硬底線；七軸從重組後那一輪重新盤點，舊輪次涵蓋的是重組前的文字。到了〈Round N 規劃判讀〉開頭的停點時，不重組，照那裡的處置。

理由：一篇同時討論好幾個主題時，同一個機制會在兩個主題的段落各展開一份，每一個新 frame 抓到的都是這個缺陷在句子上的投影，照 finding 修句子不收斂；而重組的 diff 大、再修一輪句子的 diff 小，所以觸發寫成查得到的事實，不靠執行者感覺稿件快收斂了。「句子層打磨延後」與「第二次重組交給使用者」是推論，還沒有實測過。實例與證據範圍見 [review-nonconvergence-points-to-outline](principles/review-nonconvergence-points-to-outline.md)。

### 設計稽核

審查對象是規則類文件（規則檔、規範、agent 指令、skill）時，主 session 在每一輪的 finding 收齊之後、照 finding 修之前查觸發；它跟大綱稽核一樣屬於主 session 不外包的停止判讀。

**觸發**（任一項）：

- 這一輪至少有一則必修，而且其中一半以上（含剛好一半），指出的缺陷是上一輪之後的修改造成的：逐則拿去上一輪的凍結版本找，上一輪在同一個位置已經有同一個缺陷的（措辭不同也算）是既有的；這個缺陷成立所依賴的句子（兩條規則互撞時是兩邊的句子）有任一句是上一輪之後新增、改寫或刪除的，就是新的，修法在新的位置寫出同一類缺陷也算新的。逐則寫出判定與上一輪的凍結版本對應的行（沒有就寫「無」）；各 reviewer 指向同一個缺陷的必修算一則。判的是缺陷，不是句子的字面：用 diff 的行來判，一段一行的規則檔裡改過的段落任何 finding 都會位於新增行上；只照字面 grep，措辭改過一個字而缺陷相同的舊缺陷會被誤算成新的。某一輪的審查範圍刻意只包含上一輪之後新加的句子時，那一輪不用這一項，但連續第二輪也這樣限縮時照常查；Round 1（重寫或重組之後的 Round 1 也算）不查這一項，只查下一項。
- 同一段被修法改過兩次以上，重寫本身不算一次修法。次數以輪計：一輪的整合裡改到那一段，不論改了幾處、提交了幾次，都算一次。數的是之前各輪的整合，這一輪的 finding 還沒修，不算。從起算點之後算，起算點取 Round 1 的受審版本、最近一次重組或重寫（照第 3 步做的，或使用者在停點決定的）的版本、最近一次停下的那一輪這三者之中最晚的一個；起算點是停下的那一輪時，那一輪的整合（停下之前或使用者決定之後做的）算在起算點之前。段落被拆開、搬動或併進別段時，沿用原段落在起算點之後的次數。查法同〈大綱稽核〉的同一項。

**做法**，每一步寫一行痕跡：

1. 稽核做完之前，不派下一輪，也不照 finding 修。
2. 查三項結構事實：
   - **同一條規則在兩份以上的檔裡各有一份完整寫法，而兩份沒有工具比對**（原則卡與它在 skill 的副本、skill 與它的公開鏡像這類有工具比對的刻意副本不算；一處完整、別處一句話加連結的不算）。
   - **一節裡同時寫「怎麼寫」與「既有文字怎麼處理」**：後者帶時間範圍（新寫與既有、改到與沒改到、批量替換），跟前者放在同一段時，同一個句子會從兩條規則得到不同的處置。
   - **範圍是用例外上的例外切出來的**：某條規則的例外底下還有例外，或適用對象在每條規則裡各自界定。

   只算有一部分在這一批改到的文字（含各輪的整合與重寫）或這一輪必修指向的段落裡的事實；其餘的事實照〈Round N 規劃判讀〉開頭「結構事實第二次以後的每一次成立」那一項的**當成不成立**處理；痕跡寫出這幾項事實的位置，並記進專案的待辦，不寫使用者決定保留的那種痕跡。
3. 這次稽核的結果是〈Round N 規劃判讀〉開頭的停點時，跳到第 5 步，不在這一步重寫。第 2 步成立的事實各自照對應的寫法重寫：同一條規則有多份完整寫法時，只留一份，其他位置連過去；一節裡混寫既有文字的處理時，規則只寫怎麼寫，既有文字一次處理完，或記進專案的待辦；範圍是例外上的例外時，用正面的方式在一處定義，其他規則引用。三項都不成立而不是停點時，照 finding 修完這一輪，回到原本的輪次規劃：Round 3 之前派下一輪，Round 3 之後照〈停止訊號〉判讀。
4. 重寫的版本從 Round 1 開始審：前幾輪審的是重寫前的文字。派 Round 1 之前，拿重寫的版本對照要求這一批改動的那幾則指示（含停點上的決定）的原話一次（取哪一份、怎麼逐字列出，照第 5 步「理解」那一層的取法），做完不停下：痕跡逐處寫出重寫的版本裡這一批改到的文字（含各輪的整合與重寫）對到原話或個案裡的哪幾個詞，或標成原話沒有要求；標成沒有要求的留或拿掉，由執行者判斷，痕跡寫出理由。
5. 到了〈Round N 規劃判讀〉開頭的停點時，不重寫，停下；停下之前依序做兩層反省。反省的對象依停點取：結構事實成立而停下時，是歷次成立裡設計稽核那幾次的那幾輪的全部必修，歷次成立都是大綱稽核時不做反省；由「同一段改兩次」觸發而停下時，是改到那一段的那幾輪裡修法改到那一段的必修，加上這一輪指向那一段的必修（一則必修的修法或指向有一處在那一段就算；幾段同時成立時逐段取）。取出來是 0 則時，痕跡寫「沒有可反省的必修」，照樣停下交材料。這些必修指向幾條規則就各做一次（一條規則指必修指向的那一款或那一段，每一則必修寫出它指向哪一段），結論連同稽核的痕跡一起交給使用者：
   - **寫法**：寫出這條規則要求的判斷，確認它有沒有固定的判定條件；沒有而規則把答案寫成了條件、類別或帶分支的測試，寫出是哪幾句，並寫出反省對象的那幾輪有多少必修指向那幾句的邊界。「固定的判定條件」的定義在 compositional-writing 的 `references/reference-authoring-standards.md`〈要靠判斷的條文寫成留意項〉第二段，這種規則的改寫方向也在同一節。
   - **理解**：把使用者點名的原始個案與使用者在要求寫這條規則的那則指示裡的原話逐字列出（那則指示在更早的工作階段時，從當時的紀錄抄；找不到紀錄時，寫出找過的位置與「找不到原話」，不用轉述代替原話），用一句話寫出它們的共同點，再列出規則用到的核心概念，逐個寫出它出現在原話或個案的哪裡；找不到的概念標出來，那是寫規則的人自己加進來的模型。共同點用原話或個案裡的詞寫，不用作者的轉述。兩種材料可以疊加：有要求寫這條規則的指示，就列指示的原話（沒有點名個案時只列這一份）；規則起於審查的 finding、事後檢討或執行者自己發現的缺口時，另外列那份來源的原文（finding 的報告、事件的 commit message 或檢討紀錄），它也算這一層的「原話」與「個案」。兩種都沒有使用者的話時，痕跡寫明「沒有使用者的原話」與來源。另外逐個查這些概念在既有規則裡有沒有住址，有的話寫出位置：新規則是那條規則的偵測工具，不另立判法。
   - 兩層都寫完才提簡化；兩層都判成沒有問題時，寫出依據（哪幾句、對照了哪一段原話或來源），不只寫「沒有問題」。找不到原話而判斷不出理解有沒有問題時，照實寫「判斷不出來」與缺的材料，不寫成「沒有問題」。

理由：規則類文件每補一條邊界句，就多一條邊界；規則有多份完整寫法時，還多一處要同步。下一輪的 reviewer 在新邊界上找到新的互撞，照 finding 修不收斂。缺陷是否在上一輪之後才出現，逐則對照凍結版本查得到；把它讀成修法本身在產生缺陷，是從一批審查推論的（之後的兩批顯示，規則剛寫好的那幾輪它多半只反映稿件還新，見下文比例觸發不停的理由），「一半以上」的門檻沒有校準，重寫的處置有本段末那兩批與 [rule-nonconvergence-reflect-form-then-understanding](principles/rule-nonconvergence-reflect-form-then-understanding.md) 經過段那一批的經過，三批都只重寫過一次。觸發寫成逐則可查的判定，是為了不靠執行者感覺稿件快收斂了。實例見 [review-nonconvergence-points-to-outline](principles/review-nonconvergence-points-to-outline.md)〈論述基礎與限制〉。主 session 查三項結構事實時看的是規則的形式；停下之前的兩層反省看的是規則的模型：形式修好了而模型偏掉時，冷讀者照樣會在新的邊界讀出兩種處置，稽核會再觸發。兩層反省放在停點（重寫之後、派 Round 1 之前另有一問拿原話對照重寫的版本，見本段末），而不寫成第四項結構事實：「模型有沒有偏」沒有固定的判定條件，寫成結構事實的條件、豁免與門檻之後，每一輪 reviewer 的必修都指向那幾條的邊界，這一點在把反省加進這一節的那一批實測過。「同一段被改兩次以上」觸發而三項結構事實都不成立時也停下：同一段改了兩輪還在改，是照 finding 修不收斂的訊號，形式又查不出成因，剩下的候選是模型，而模型有沒有偏要對照使用者的原話，由使用者判斷；照 finding 修下去，修的是偏掉的模型的邊界。只靠結構事實成立的話，這種情形永遠到不了停點，反省也不會做。只由必修的比例觸發時不停：規則剛寫好的那幾輪，必修指向的多半是上一輪改過的句子，比例觸發幾乎每一輪都成立，它量到的是稿件還新，不是修不收斂；把比例觸發也算進停點的版本，拿兩批實際的經過重走時幾乎每一輪都停（經過在 [rule-nonconvergence-reflect-form-then-understanding](principles/rule-nonconvergence-reflect-form-then-understanding.md) 的限制段）。「同一段改兩次」在規則批次的 Round 3 多半會成立：規則檔的理由段一段一行，每一輪的修法都會補一句理由進去，Round 1、Round 2 的整合各改它一次。手上的三個 Round 3 都停了，其中至少兩次停下之後由使用者改了方向，所以接受這個頻率：規則批次大約在 Round 3 問使用者一次，換到的是偏掉的模型不會被打磨到 Round 4 以後。稽核排在照 finding 修之前，是因為比例觸發要用這一輪的 finding、兩項觸發用同一個時機，而且停下時這一輪的修法還沒做，使用者的決定不會被已經做完的修法搶先；代價是「同一段改兩次」比排在修完之後晚一輪成立。結構事實持續存在而使用者看過、決定不處理時不再計次，否則同一項事實會在之後每一次觸發都再算一次，比例觸發又幾乎每一輪都成立，等於每一輪都停。大綱稽核沒有這一停：兩層反省拿規則的條文對照要求寫這條規則的原話，而文章的大綱不是照一則指示寫成的一組條件，沒有可以對照的原話；文章不收斂而大綱的結構事實都不成立時，照〈大綱稽核〉原本的做法回到輪次規劃，這一點沒有另外量過。「同一段被改兩次以上」從停下的那一輪之後重新算，因為它成立之後每一輪都還成立，不重新算的話之後每一輪都會停。結構事實的次數不歸零：歸零的話，停過一次之後再成立的結構事實會被當成第一次而直接重寫、不先問，而使用者在停點選的若是照 finding 修下去，那次重寫沒有方向；停點也可以一再把次數歸零，第二次以後成立的停點就永遠到不了。所以第二次以後每一次成立都停。結構事實只算有一部分在這一批改到的文字或這一輪必修指向的段落裡的那幾項：稽核要找的是這一批的修法不收斂的成因，既不在這一批改到的文字、也不在這一輪必修指向的段落裡的結構缺陷，跟這一批的 finding 無關；主 session 整份查時，規則檔有好幾節，每一批都可能查到一項，重寫就改到這一批的修法沒有改到的段落（這是推論，沒有量過）。代價是範圍外的結構缺陷只記進待辦，使用者交辦的是審查一份既有的檔時也一樣；「同一段改兩次」觸發而結構事實都不成立時，成因可能在範圍外的結構，反省卻只對照模型；哪些事實算數也跟著這一輪的必修指到哪裡（兩項都是推論）。大綱稽核的結構事實不限範圍，照〈大綱稽核〉第 2 步掃全集合；寫進這個範圍的那一批沒有量過文章那一邊。已知還沒寫的邊角：一批同時有文章與規則檔、其中一項停下時，另一類的檔這一輪怎麼整合與計數，以及一類的重組換不換另一類的起算點；段落拆開或合併的那一輪算不算一次；多份完整寫法要留哪一份；第 4 步對照原話時，使用者只回一句同意（「補」）時要不要連同被同意的那段提議一起當原話，一批裡有好幾則指示（含停點上的決定）時取哪幾則，原話指向一份文件（一張卡）時文件的內容算不算原話。這幾項寫成分支時，必修集中在分支的邊界（補上計數與範圍的那一批實測過），所以先不寫，遇到時照實寫進痕跡。兩層反省來自一條規則的一次審查；實例與反省的順序見 [rule-nonconvergence-reflect-form-then-understanding](principles/rule-nonconvergence-reflect-form-then-understanding.md)。第 4 步在重寫之後、派 Round 1 之前拿重寫的版本對照原話一次，是因為第 3 步的重寫只照結構事實改規則的形式，沒有一步檢查重寫加進的內容有沒有超過原話，而超出原話的內容在下面兩批都是重寫時加進去的。multi-round-review 2.45.0 那一批的原話只要求把一張原則卡（判斷標準漏掉元件所在的環境）寫進審查流程，第一次成立後的重寫版加了原話沒提的觸發條件、表格欄位與計帳規則；把一句射程說明同步進寫作 skill 一張原則卡副本的那一批，原話只要在 `criteria-fold-away-the-condition-that-produces-the-symptom` 的副本同步一句說明它的適用範圍，設計稽核第一次成立後的重寫卻把 3-H 那一段的程序搬進寫作 skill、另立一張原則卡。這一步加進來之前，兩批都到第二次成立的停點才對照原話。這一次對照只寫成一問加痕跡，判完之後怎麼改留給執行者：2.46.0 的初稿把「原話沒要求的不搬」「拿掉之後怎麼走」寫成條件，三輪審查的必修集中在這些條件的邊界，第三輪停下時由使用者縮成一項檢查加痕跡。這一項檢查不停下，而做這一項檢查的主 session 就是寫出那些文字的人（同源），這一項檢查能不能讓重寫的版本不留原話沒要求的內容，還沒有量過。

### 停止訊號

這一輪沒有走到重組、重寫或〈Round N 規劃判讀〉開頭的停點時（例如稽核沒有觸發、大綱稽核的結構事實都不成立，或設計稽核只由必修的比例觸發而結構事實都不成立），照下面的停止訊號判讀；停在 Round 3 或之後的那一輪、使用者在停點決定照 finding 修下去時也一樣。停止訊號齊備、停：

1. **七軸動完**：frame / instance / surface / scope / cadence / timing / granularity 七軸都用過。**判定這一條之前打開 [七軸盤點](principles/review-seven-axes.md)**——七個名字不含程序，而第四條降級之後 quorum 的重量壓在這一條上。那張卡給填法（逐 reviewer 對帳、不憑印象）、判定（不適用不計入分母、只有最弱切換的軸記為未動）、以及未動之後的處置，另附一份填好的盤點
2. **Finding 性質退化**：新 frame catch 到的 finding 又退回 surface 層（surface 層指 Round 1 預期 finding 那一類：編號、連結、規範違反）。**痕跡**：列出被判為 surface 的那幾則與它們佔本輪 finding 的比例，沒列的宣告不算
3. **修法成本反轉**：修一個 finding 成本超過讀者實際感受價值。**痕跡**：列出被判為成本反轉的那幾則，各寫一行估法（修要動哪幾處、讀者在哪個位置感受到差別），沒列的宣告不算
4. **新 frame 想不出來**（最弱的一條、不作必要條件）：腦力激盪後想不出「能 catch 新東西」的 frame——這一條隨經驗反向移動，見同節〈第四條量的是判斷者、不是稿件〉段

任二齊備、可以判定「真的夠了」，而**分母是前三條**。任一齊備、繼續但要主動規劃 frame 切換。

**第四條量的是判斷者、不是稿件**，所以它在實務上永遠不成立——想得出多少 frame 由執行者的經驗決定，跑過越多輪的人庫存越大，四次實跑零次成立（第四次停在四輪時仍想得出術語探針）。把它與前三條平鋪並列有兩個代價：quorum 的分母悄悄縮水（沒有人做過這個決定），以及執行者以為自己還沒做完、而「還可以再跑一輪」這個念頭沒有終點。判別新增訊號時問一句——這一條量的是被判斷的對象、還是判斷者自己；答案是一個以能力為條件的否定式（想不出、找不到、看不出）就多半量的是判斷者。詳見 [跨輪 review 停止訊號](principles/cross-round-stopping-signal.md)。

**未動的軸不一定是下一輪買得到的。** 七軸盤點的每一格要多填一欄「這一軸靠什麼補上」：五個軸填「下一輪」，timing 填「時間」，instance 填「另一個執行者」。填時間或另一個執行者的軸，第五輪補不到——照「未動的軸就是下一輪的價值來源」排下去，跑出來的那一輪在七軸上補不了任何一格，產出只能來自把 frame 軸再細分，正是「缺軸不缺深度」（`principles/review-seven-axes.md` 的結論）要防的加輪數。處置是建票綁觸發條件（異源交換的觸發是有另一個執行者可用，而票要指定交換的形式——兩邊各自量同一件事、各自報數，不是一邊做另一邊審；驗收寫「有幾個約定因為這次並排而被寫明」，不寫「取得對方的 N 則 finding」——那一類的產出沒有歸屬，按來源歸帳會固定漏掉它、冷讀的觸發是下次有人要動這份內容），並把停止判定寫成兩句話：哪幾軸判定為已覆蓋、哪幾軸判定為取不到。**「停在資源用完」與「停在證據齊備」在文字上同形**，不分開寫就消失。詳見 [缺口的處置看它需要哪一種資源](principles/gap-remedy-depends-on-the-resource-it-needs.md)

## 收尾清單

整批審查結束前的動作，每一輪修完的分層掃描在 `integrating-findings.md`；這裡是整批只做一次的：

1. **整體通讀**——所有 frame 跑過、finding 修完，不等於這份內容現在是好的；判斷標準是「讀起來像一個人一次寫完的嗎」，逐條檢查修法產物不能取代它
2. **重讀共用產物**——入口頁（路線還通嗎）、待辦清單（每列真的都還沒做、做完的都刪了嗎）、索引。它們被每一輪修改而不在任何一輪的射程裡
3. **列出被改過而不屬於任何一輪的產物**與這一批用過的工具版本——起跑前列過一次的那份清單，收尾再對一次
4. **finding 的方向分佈**——逐則標「漏抓／多抓」，一欄全空代表缺 frame 不是缺缺陷
5. **停止判定寫成兩句**——哪幾軸判定為已覆蓋、哪幾軸判定為取不到已建票

**停止之前還要看 finding 的方向分佈。** 把所有 finding 逐則標一個方向欄，只有兩個值：這一則說規則**漏掉了**什麼，還是說規則**多抓了**什麼。一欄全滿、另一欄全空時缺的是 frame 而不是缺陷——**零 finding 與零 frame 在報告上同形**，代價那一側交白卷讀起來像那一側沒有問題。成因兩端同向：找到漏抓是產出（多一則 finding），找到誤報是否定產出（少一則，且要撤回別人寫下的），而規劃者在找「還有什麼沒被檢查」、執行者的價值由 finding 數體現。修法是 frame 清單成對排（判斷標準漏了哪些情境／判斷標準會把哪些合規個案判成違規；這一類還有哪些位置／這一類的命中有哪幾處其實合規；涵蓋範圍夠不夠／成本由誰承擔）。「找誤報會減少產出」這個估計本身是錯的——實測兩次撤回之後的替代 finding 都比原本那一則強。詳見 [審查的 frame 全部在問效力](principles/review-frames-ask-efficacy-never-cost.md)

**停止訊號之外還有一個前置條件：整體通讀。** 所有 frame 跑過、所有 finding 修完，不等於這份內容現在是好的——修法本身改變了被審查的對象，而兩次各自正確的修法可以合成一個對兩個 frame 都不可見的缺陷（per [多次修法會合成缺陷](principles/sequential-fixes-compose-into-defects.md)）。停止之前要有一次以整體為對象的通讀，判斷標準是「這份內容現在讀起來像一個人一次寫完的嗎」。逐條檢查修法產物不能取代它——合成缺陷在那些條目之間。

同一輪還要重讀**共用產物**：入口頁（路線敘述）、待辦清單、索引。它們被每一輪修改、卻不在任何一輪的審查範圍裡，因為每輪的 frame 都是對著內容設計的。入口頁看「這幾條路線現在還通嗎」，待辦清單看「這幾列還沒做嗎、做完的都刪了嗎」。

**共用產物只是三類射程外項目的其中一類。** 每個 frame 都要有一個審查對象，所以不在審查對象裡的項目沒有任何 frame 會碰到——除了共用產物，還有**審查所用的工具**（方法論、規範檔、腳本，以及它們的版本）與**審查自己的產物**（finding 清單、覆蓋盤點表、停止判定）。一次四輪、二十餘個 reviewer 的審查全程沒有一步會發現所用的方法論落後十一個 minor 版，而那些版本差裡有一版正好改掉了該次停止判定所依據的規則。這一類靠清單補、不靠加 frame 補（新 frame 也要先有對象），所以起跑前列一次工具與版本、收尾前列一次被改過而不屬於任何一輪的產物。詳見 [審查的射程只涵蓋被審查的對象](principles/review-scope-never-includes-the-instrument.md)

## 反模式

規劃層的反模式。「用 finding 數遞減當停止訊號」與「同 reviewer 跑多輪」已寫成 `SKILL.md`〈基本原則〉第 1、3 條的正向形式，不重複；修法層的反模式在 `integrating-findings.md`〈修法的反模式〉。

- **跳過 frame 規劃直接派 reviewer**：「再來一輪 audit」沒指定 frame 切換、reviewer 用同方向掃同類問題、是 frame 顆粒度盲點的具體實例
- **跑臨時子集卻當成跑完整框架**：只派幾個臨時擬的 reviewer frame + 一次 grep、就回報「review 完成 / clean」—— 漏抓後容易誤判成「框架不足」（design gap）而去加 frame / keyword、實際是「沒跑完該跑的輪」（execution gap）。漏抓先分 design gap（改框架）vs execution gap（改執行、別只加 keyword）；register/stance 類（喊話 / 誇飾 / 必然）尤其要靠 reader simulation + external cold-read、不是加 keyword（per compositional-writing 的 multi-pass-review-frame-granularity 原則）
- **把「多輪全過」當成「知識類型對」**：歷輪 finding 全部落在字句與結構層時、「三輪全過」的語意只是「已覆蓋層全過」——斷言支撐與知識類型層若沒有 frame 負責、錯的知識類型（披著教學結構的經驗談）會全數通過。finding 類型分佈本身是訊號：全部集中表面層 = 深層無人在看、下一輪排斷言支撐 frame（per [claim-support frame](principles/review-needs-claim-support-frame.md)）。一次乾淨的實例：某份文件跑完三輪八個 reviewer、報告寫「三輪全過」，一天後另一批審查在同一份文件上找出五項嚴重的既有缺陷，全部來自上一次唯一沒有派人負責的維度——其中一項是判斷標準自身前後矛盾（起點欄宣告兩個維度、判定訊號欄只實作其中一個）。**「多輪全過」的作用域是跑過的那幾個 frame，而報告上不會出現那個限定詞**，因為列出跑了哪些 frame 的責任沒有人承擔——收尾時要自己把跑過的 frame 列出來，並問哪些維度整批沒有人負責
