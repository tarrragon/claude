# multi-round-review 版本紀錄

新到舊。版號規則與兩個住址（本檔與 `SKILL.md` frontmatter 的 `metadata.version`）見專案的 skill 同步規範。

**Version**: 1.63.2 — 三份翻譯探針對 `description-as-recall-trigger` 裡「沒有問就不知道的斷點」給了三種不同的意思（沒人問／缺了那個問題／讀者不知道該問什麼）。那句話把誰沒問、不知道什麼都省略了，中文允許、英文強制決定，所以這一類要靠翻譯才現形。就地展開成「讀者不曾遇到那個問題，就永遠不會知道有那件事」。

**Version**: 1.63.1 — `description-as-recall-trigger` principle 卡的 H1 停在被自己推翻的版本（「Description 是 Recall Trigger、不是文章摘要」），而同一次改動已把結論改成體例由內容定位決定。slug 不動、只改 H1。

**Version**: 1.63.0 — description 的體例改成依內容定位分兩種。查閱型內容維持觸發條件式（使用者帶著症狀或術語來），教材改成說這一篇涵蓋什麼——觸發條件式在教材上是缺陷，因為那句話寫成「遇到 X 時」之後文章就得是 X 的答案，而照問題組織的教材會產生沒有問就不知道的斷點。1-C 的檢查多一個前置判定（這一批是教材還是查閱型），並加一條整批訊號：一個分類的 description 幾乎每一篇都以「時」收尾，那是規範長出來的形狀、要回頭改規範。principle 卡 description-as-recall-trigger 同步

**Version**: 1.62.0 — B⁶ 術語探針的回答改成分四類讀，並在 prompt 要求裡加上「有把握的那些，寫出它指的東西」。第四類是收斂度看不到的一種：少數份有把握、而它們一致指向一個與作者用法不同的東西，代表這個詞在同一個領域裡已經有主人。它與非通用詞在收斂度上同區（多數份沒把握），只看數字會判成邊緣而換個同義詞了事，可是兩者的代價方向相反——無主的詞讓讀者查不到於是他停下來，有主人的詞讓他查得到另一個東西於是他不停下來。principle 卡 term-probe-measures-register-not-invention 同步

**Version**: 1.61.0 — 產出契約新增一條「探針的自評欄不是結果欄」，並在 2-B⁗ 那一列標註。探針回報的「有把握 / 看不出來」答的是這段文字有沒有給它材料，不是它答得對不對——後者它答不了，因為它看不到答案而那正是設計條件。一次二十六條路由的三份獨立量測裡三份自評欄幾乎一致（各二十四條有把握），逐條比對後才出現一條三份全錯、兩份方向答反的路由，而那一條的自評欄與答對的十七條無法區分。同批更新 principle 卡的「組成」方向維度。

**Version**: 1.60.0 — 同批 principle 卡的修正（條件分支降級為五種關係之一、判準補射程、新增「每一條判定都要附它的輸入」段）。另記一則方法論：本輪的 3-B steelman 回查原文推翻了該卡核心資料點的編碼，而 3-H 個案實跑顯示判準的兩個軸各只有一個分支而實際有五種——**兩者都在 Round 1-2 的十二個 frame 下結構性不可見**，因為前兩輪只檢查已寫的內容對不對，不檢查那個編碼是怎麼來的、也不拿極端個案走一遍。

**Version**: 1.59.0 — 修正 1.58.0 引入的判定條件與量測範圍。2-B′ 的路由承諾原本寫成句法規則，多輪審查找出假陰性，改成內容測試（遮住目的地能不能預測那一篇會給什麼），並註明用關鍵詞比對會高估、用句法規則會漏。版本紀錄另修一處量測範圍漂移：冷讀量測是二十七篇，三十九篇是後來那次承重術語掃描的範圍，1.58.0 把兩次併成了一次。

**Version**: 1.58.0 — Round 2-B′ 冷讀 frame 的篇章層加一題「這一篇讓你具備什麼能力」。冷讀預設「讀得懂」等於「有內容」，而互相引用的集合裡有一種稿件讀得懂而說不出要交付什麼——一次二十七篇的冷讀量測裡，內容段全部在講鄰居的短文，冷讀把每一段的內容都答對而最後一題寫「看不出來」並自列三種互斥的可能。同一題另外驗路由承諾：判斷標準是遮住目的地之後預測不預測得出那一篇會給什麼，句型只影響命中率，所以這一維用關鍵詞比對會高估、用句法規則會漏。新增 `cross-links-eat-the-article-they-live-in` principle 卡。

**Version**: 1.57.0 — 套新的取捨門檻回頭修剪本輪加進來的內容。定位閘門刪掉「規範裡的每一條規則都誕生自某一個定位」整段（那是為什麼會發生，屬歸納層）與微案例那個實例；2-D 刪掉「為什麼其餘 frame 全數通過」的說明與量測數字，留判斷標準、七種裝置、產出契約、處置；2-B⁷ 刪掉分離度數字與判讀說明，留設計條件與操作。刪掉的全部在對應的歸納卡裡查得到，skill 這一側改成一句話帶過並指過去。門檻是「一個沒讀過那張卡的 agent，照這一段做不做得出動作」——做得出就夠了，多的是說明

**Version**: 1.56.3 — 定位例外的措辭修正：一份歸納問題與解法的記錄兩邊都不是——讀者不是來理解一個主題的，而可執行的那一半住在另一個位置。上一版寫成「落在手冊那一側」，那個歸類會讓人以為處理方式該寫進那份記錄裡

**Version**: 1.56.2 — 定位的例外從「目錄頁」擴成「整個子集合也可能落在手冊那一側」：一份規則語料的消費者是即將動手而要查一條規則的人，它解釋理由是為了讓規則套得準、不是為了讓人讀懂一個主題。2-D 掃體例時要排除的因此不只目錄頁

**Version**: 1.56.1 — 定位閘門與 principle 卡補一條例外：同一個目錄底下可能兩種定位並存。一個內容分類裡的文章是教材，而它的目錄頁是那個分類的操作手冊（成員表、路由、待辦），使用者的動作是照著它走到某一篇——目錄頁該有的正是文章不該有的。所以定位按稿件要讀者做什麼判、不按目錄判，而 2-D 掃體例時要排除目錄頁，否則會把它正確的形式報成違規

**Version**: 1.56.0 — 定位成為 frame 之前的閘門，而不是清單裡的另一項。新增「派發之前先定這一批的定位」節，放在 frame 表之前：寫下一句話（誰讀、讀完要做什麼），並用它重新過一次 frame 的觸發條件。理由是這一輪量到的機制——規則的觸發條件會先於它自己的判斷標準生效：要求補微案例的那一條觸發於「判讀 / 選型型內容」，於是一篇讓人理解某個現象的文章形狀對上了就照樣被要求補一則演示判錯代價的短敘事，而那條規則自己明寫著要挑後果最不直觀的。定位判定為人類教材時，2-B‴ 的微案例、2-B″ 的可執行走查、1-D 的下游任務三個 frame 的預設都來自 agent 指令或工程決策內容，要重判。

新增 **2-D 體例與定位一致**（一律跑）。它抓的東西每一條規則都遵守了，所以其餘 frame 全部通過——它們問「這一條遵守了嗎」，而失配的稿件確實遵守了。判斷標準可機械執行：**讀者讀完之後那個動作落在哪裡**，在世界上動手是手冊、在腦中重新歸類是教材。掃的是裝置不是語氣，七種形態列在 frame 裡，其中序列連接詞（先、之後、最後）最容易漏——把步驟編號換成它只改掉一半。處置不刪資訊，改的是框架。

新增 **2-B⁷ 類型探針**：受測單位從一段文字或一個詞擴到整篇的定位。問法不能點名類型，五個問題沒有一個提到手冊或教材；第五題要求逐字抄出判斷依據，直接交出裝置清單。設計條件同 B⁶ 的控制詞——同批混入一份無疑義的手冊與一份無疑義的教材且不標示，控制項在「隨時翻」軸上分開，測試項才可歸因，實測分離度五比零對五比零。判讀時「會照著做」與「會放在手邊」是兩條軸，只翻一條要當成沒改完。

**Version**: 1.55.0 — 新增 principle 卡 article-writes-the-topic-not-the-authors-path-to-it 並接進三處。**frame 表補 2-C 列**（一律跑）——這個 frame 本來只存在於 Round 2 的內文而不進派發判定表，缺列等於它永遠不會被明確判定要不要跑，與 v1.48.0 補 2-B⁵ 列同一個成因。**Round 2-C 擴成題目範圍檢查**：把標題與各段標並排、逐個問這一節在不在標題的範圍內，產出是逐段標表；抓的兩種形態是段標帶推導的連接詞（把連接詞之後刪掉，前半通常就是完整的段標）與整節在講比標題更泛的東西（移出去獨立成篇、待辦條目要寫出實際內容）。**Round 1-A 新增可信度斷言 grep**，與物理化錯配共用一組關鍵詞而問的是不同的問題：那條問動詞對不對（證據「撐得住」寫成證據「可靠」），這條問這句話該不該寫——可信度是讀者讀完之後產生的感想、作者寫出來等於替讀者下結論而讀者手上的材料沒有變多；兩條互補不互相取代，順序是先問該不該寫、決定要寫之後再問動詞。實測是三篇短文跑過三輪十三個 reviewer 與十六份探針、全部通過，隨後由作者以外的眼睛一次指出三個同源缺陷——這一類在既有 frame 下不落空，因為每一句都合規

**Version**: 1.54.0 — 新增兩張 principle 卡並接進三處。**criteria-fold-away-the-condition-that-produces-the-symptom** 接進 Round 3-H：個案實跑的產出價值集中在把停頓點並排，而最高頻的形態是判斷標準只收「表徵」一個輸入、把產生表徵的那個條件從輸入端折疊掉（處置句寫著只有某一種執行環境才有的操作名詞）；派發前先數一個便宜的指標——分支數少於正文列出的種類數時就有種類落在所有分支之外，個案要刻意挑落在那些種類上的。實測是三篇短文的末節判斷標準通過了字句層、冷讀逐格、情境可想像性與 steelman 四種 frame，而九個具體個案只有兩個走通。**fix-the-class-not-the-cited-instances** 接進整合工作流（新增第 6 步）與 reviewer prompt 的產出契約（新增一欄）：finding 清單列的是抽樣位置，而清單的形式在暗示完整性，於是照著逐處修會留下同一類在沒被點名的地方——留下的舊實例比新引入的變體難抓，因為這一類已經回報過、後續輪次不再掃它。實測是同一個動詞的同一處論元結構歧義散在三個位置，四份理解探針一致指向其中一行、修好並經驗證翻轉，另外兩處由後續的翻譯探針換一個角度才撞見

**Version**: 1.53.0 — 新增基本原則「規模與來源是兩件事」與 principle 卡 review-scale-does-not-buy-independent-origin：一個 session 派出的所有 reviewer 與探針構成單一來源，增加數量提高的是覆蓋的面而不是視角的來源數。實測為兩個併行執行者各自跑完四輪、各自字句層掃描回報乾淨，交換檢視時各自一眼看到對方一處違規；其中一處的判斷標準可機械執行（問這個動詞照字面成立需要什麼物理條件），寫的人套在自己的小節標題上判定通過、另一個來源套同一標準當場判定不通過——差別在寫的人讀到標題時取回的是意圖而不是字面。Round 1-A 的同源上限段補上「同源的範圍包含整棵派發樹」。段名「四大基本原則」內嵌成員數、加第五條即失真，改為「基本原則」
