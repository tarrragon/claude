# 以同檔競爭判斷拆分：何時拆、如何拆

**核心主張**：不同主題的票反覆修改同一個檔案，代表這個檔案承載了不只一種職責（違反單一職責原則）。只排程讓各票輪流等待，等於每張票都付一次等待與衝突成本；先拆分，讓各票改不同的檔案，就能平行實作、各自合併，也能合成同一批送合併閘門。

本檔適用於文字規則（rules、references、SKILL、範本）與程式碼（Python 為主，原則通用）。

---

## 1. 訊號：怎麼量同檔競爭

| 訊號 | 量法 | 何時看 |
|------|------|--------|
| 不同票樹的修改次數 | 一段期間內 `git log --no-merges --name-only`，依 commit 訊息的票號取票樹根（同一棵父子票樹算一個主題），計每檔被幾棵票樹改過 | 版本中期、或並行線開始互等時 |
| 派發前衝突命中 | `ticket track conflicts` 命中同檔、且雙方不同票樹 | 每次派發前 |
| 因同檔而等待或衝突 | 票的 blockedBy 理由為「改同一檔」、批次合併因同檔被排除、閘門拿到名額後才撞上文字衝突 | 收到各線回報時 |

**Why**：「行數 > 300」只說明檔案大，不說明是否混了多種職責；高內聚的大檔可以只因單一主題而長。票樹數量直接反映「有幾種不同理由要改這個檔」，即職責數的可觀測代理。

**Consequence**：只看行數會漏掉「不大但被多個主題搶改」的檔（例如 200 行的骨架產生器被 6 棵票樹改過），也會誤拆「大但只屬一個主題」的檔。

### 1.1 計票樹前先看 commit 主旨

票樹根是主題的代理，不是主題本身。同一個功能經多輪審查時，每一輪的追修常另開新的根票：票號不同，主題相同。先讀 commit 主旨，把屬於同一功能的票樹合併為一個主題，再計數。

**Why**：只依票號取根，會把「一個功能被反覆修」計成「多個主題搶改」。實測：某覆蓋率檢查腳本在一段期間內計得 11 棵票樹，讀主旨後，多數是同一項檢查功能的多輪審查追修。

**Consequence**：計數膨脹的檔會排到熱點清單前段，拆分評估的排序依據失真；同一功能的連續追修本屬 §2 的「同主題演進」反例，不應推高觸發訊號。

**Action**：

1. 依票號取根計數，得候選清單。
2. 對達門檻的檔列出主旨（`git log --no-merges --since=<起點> --format='%h %s' -- <檔>`，排除 chore 類提交），把屬於同一功能的票樹合併。
3. 以合併後的主題數對照 §2 門檻；仍達門檻才觸發拆分評估。

## 2. 觸發門檻與反例

| 狀況 | 判定 |
|------|------|
| 同一段期間（例如一個版本內）有 **3 棵以上不同票樹**改同一檔，或並行中的兩張不同票樹的票因同檔互等 | 觸發拆分評估 |
| 同一棵票樹的連續子票改同一檔 | **不算**：同主題的演進本該集中在同一處，這是內聚 |
| 不同根票，但 commit 主旨屬同一功能（例如同一項檢查的多輪審查追修各開新票） | **合併為一個主題計數**：等同同一票樹的連續演進，見 §1.1 |
| 聚合檔：設定與註冊表（settings、registry）、CHANGELOG、索引表、版本日誌 | **不以職責拆分處理**：這類檔的競爭是結構性的，改用「一項一檔」或只追加的格式降低衝突（見 §4） |
| 被改的只是測試檔，對應的產品檔沒有同等競爭 | 先看產品檔：測試檔通常隨產品檔一起拆 |

**Action**：觸發時建一張拆分評估票，排在等待中的那些票之前；不要在等待中的票裡順手拆。

## 3. 拆分流程

### 3.1 共同前置

1. 列出近期改過此檔的各票，逐張寫出「它改的是哪一種職責」（例如：解析命令、判定並行期、產生提示訊息）。
2. 把職責分群，每一群是一個候選檔；若只分出一群，代表競爭來自聚合或連續同主題，回到 §2 的反例。
3. 決定排序：拆分票先做、先合併；等待中的票改為以拆分後的 main 為基準，各自只改自己職責所在的新檔。
4. 派發前把範圍宣告完整：拆分票的 where.files 要列出預計新增的模組路徑，以及會鎖住被搬移邏輯的測試檔；提交範圍以 where.files 為界，漏列的檔在提交時才會被擋下。
5. 拆完後比對同類職責的兄弟模組。原本散在同一檔內、各自實作同一種判定的兩段邏輯（例如兩處各自推導操作目標），拆開並列後常會發現一方已修、另一方沒修的既有缺口。這類發現記進拆分票的 Solution 並另開票，不在拆分票內修：拆分票只做純搬移，閘門紅燈時才分辨得出是搬移造成還是修改造成。

### 3.2 文字規則（rules / references / SKILL / 範本）

| 步驟 | 做法 |
|------|------|
| 依職責切，不依長度切 | 每個新檔回答一種問題（何時觸發／怎麼做／為什麼），原檔保留路由表指向各檔 |
| 自動載入層 | 依 `.claude/references/auto-load-stub-conventions.md` 的外移 SOP：原檔留禁令速查與路由，細節外移 |
| 引用不斷鏈 | 以標題錨點與檔名引用；`grep -rl` 原檔名與被移走的標題，逐一更新引用 |
| 單一定義 | 同一條規則只在一個檔定義，其他檔路由過去，避免拆完變成兩份各自更新 |
| 先盤點引用再拆 | 拆前 grep 全倉庫對本檔的段標引用（〈X〉「X」兩種括號，含 .py 註解與字串），列成清單；連結檢查只驗路徑、不驗段標，錨點失效不會報錯。被引用的段標在原檔留同名標題加一行路由；引用寫法與標題字面不同的近似引用也要能對上 |
| 被逐字對照的權威文字不搬 | 程式常數或其他文件宣告「與本檔某段逐字一致」的段落留在原位，只搬沒有對照關係的段落 |
| 程式碼圍欄內的標題不算切點 | 範例裡的 `## 標題` 會被誤認為段落邊界，掃描段標時要排除圍欄 |
| 用拆分前後的差值驗證 | 行守恆（原檔所有非空白行在「原檔加新檔」中計數不減）與錨點對照都在拆分前後各跑一次，看新增的缺失數；只看拆分後的絕對數字，會把既有的不精確引用誤算成拆分造成的 |

### 3.3 Python 程式碼

| 步驟 | 做法 |
|------|------|
| 先鎖行為 | 拆分前補齊或確認對外行為的測試（含正向對照：應擋者仍擋、應放者仍放）；拆分後同一組測試必須逐項通過 |
| 分辨鎖行為與鎖位置的測試 | patch 原模組內部函式的測試，鎖住的是「邏輯在這個模組裡」而非行為；邏輯搬走後即使行為不變也會紅。拆分前先找出這類測試，改成 patch 新位置或走真實輸入；並把這些測試檔列入票的 where.files，否則範圍檢查會擋下對它們的修改 |
| 萃取模組 | 依 §3.1 的職責分群，把各群函式移到新模組；原模組保留同名匯入（re-export）一段過渡期，呼叫端不需同步修改。re-export 只保住 import，保不住 patch。要 patch 哪個模組，看呼叫端在哪個命名空間查這個名稱：呼叫端仍留在原模組的名稱，patch 原模組有效；搬到新模組、由新模組內部呼叫的名稱，要 patch 新模組。名稱還在、也有 re-export，不代表 patch 有效。可變的注入點（時鐘、全域狀態、可替換的依賴）不要 re-export，只留在單一模組，否則 patch 其中一份、另一份照舊 |
| 移除會靜默失效的 patch | `monkeypatch.setattr(目標, "名稱", 值, raising=False)` 在名稱因搬移而不存在時照樣成功：patch 沒生效，測試仍綠。拆分時移除 `raising=False`，或改指新位置；不帶 `raising=False` 時，名稱不存在會直接報錯，問題一眼可見 |
| 盤點以「單一檔案」為前提的工具 | 依賴宣告檢查、行數或體量守衛、以檔名比對的 hook 等，常假設一個功能就是一個檔；拆成套件後要確認它們是否改掃整個套件，否則會漏報或誤報 |
| 共用邏輯進 lib | 兩個以上的檔案各自實作同一判定（例如命令解析、取票號）時，收斂成 lib 的單一函式，兩邊改呼叫它 |
| 巨型分支改分派 | 以「判斷是哪一種情況」為主的長 if/elif 鏈，改為 registry 或分派表，每種情況一個處理函式；新增情況時只加一筆登記，不改共用分支 |
| 避免循環匯入 | 新模組只依賴更底層的模組；兩個新模組需要互相引用時，把共用部分再往下抽一層 |
| 新模組不與標準庫同名 | 例如不取名 `types.py`、`logging.py`；直接執行該目錄內的腳本時，同名檔會遮蔽標準庫模組，錯誤訊息與拆分無明顯關聯，很難追查 |
| 拆分 portable skill 時，搬移來源記在 commit 訊息 | frontmatter 宣告 `metadata.portable: true` 的 skill，新模組的 docstring 不寫「自某檔搬移」的路徑與票號。本地守衛接受搬移豁免標記，推發佈庫時的可攜性檢查不接受：拆分當下提交得過，推送時才被擋，還得回頭再開一張票清理 |
| 一次只做一種改變 | 純搬移的 commit 不同時改行為；行為修改放在後續 commit，閘門紅燈時才能分辨是哪一步造成的 |

## 4. 聚合檔的處理

聚合檔被多個主題改是它的本職，拆成多個聚合檔只會把競爭換個位置。改用以下方式降低衝突：

| 檔案類型 | 做法 |
|------|------|
| 註冊表、設定 | 每個項目一個片段檔，由載入端合併；或固定排序並一項一行，讓合併時只動到相鄰行 |
| CHANGELOG、版本日誌 | 只在固定位置追加；需要時由工具產生，不手寫 |
| 索引表 | 由工具掃描產生，不手動維護 |

## 5. 驗收

- [ ] 拆分前後，對外行為的測試逐項一致（程式碼），或所有引用都已更新且 grep 無殘留（文字）
- [ ] 原檔與新檔各自只回答一種職責；路由表或 re-export 已就位
- [ ] 等待中的票已改以拆分後的 main 為基準，且各自只改一個新檔
- [ ] 下一段期間重新量 §1 的訊號，確認該檔的主題數（依 §1.1 合併後）下降
