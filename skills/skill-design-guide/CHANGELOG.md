# skill-design-guide 版本紀錄

新到舊。版號規則與兩個住址（本檔與 `SKILL.md` frontmatter 的 `metadata.version`）見專案的 skill 同步規範。

**本檔只記變更本身**：版號、改了什麼、落在哪一節。多輪審查的 finding 分類、逐 frame 敘事、
被推翻的判定與其推導過程屬設計過程紀錄，依 `writing-the-body.md`〈嚴禁清單〉該列的處置放在
**專案的 worklog 系統**，不放這裡。

**寫每一條之前先問**：這句話裡的**每個數字與每個完成式，是同一個時點的嗎**？壓縮舊條目時，
數字取自當時、項目清單取自現在，兩者會被併進同一句而不再可分；宣告「已回溯套用」時，
做了一部分與做完在文字上同形。實測本檔在同一批修法內犯過這兩種各一次——而那一批正是在修
前三次的同型缺陷。**這一問是壓縮專用的**：既有的「同一件事寫了幾種形式」對展開有鑑別力，
對壓縮沒有——壓縮的產物只有一種形式，它只是錯的。

**Version**: 1.9.0 — v1.8.0 暫緩的兩組判準補完，並依其中一組執行外移。(a) 「超標時該外移什麼」與「SKILL.md 該留什麼」原以互斥性當外移訊號，而互斥性對每張判準表都成立，兩個半句對同一批內容給相反處置；改為**四問依序，每一格都要求指名入口檔路由表的具體某一列**（是某列的觸發條件 → 留；每列讀者都用 → 留；指得出少數列 → 外移到那些目標檔；指不出任何列 → 沒有讀者情境，壓縮成主張句），落在 `splitting-an-existing-skill.md` 新增的〈外移什麼、留什麼〉。(g) 位置性指涉的「目標可能移動即失效」要求對未來下斷言，而同段實證是四處同型缺陷中三次由修法自身引入、當時都判過不會動；改為兩條打開檔案就看得到的條件——**跨檔**、**目標帶識別字**（`##` 標題、粗體引導句或檔名），合規只剩同檔緊接且目標無識別字一種，落在 `splitting-an-existing-skill.md`〈拆分特有的高頻缺陷〉。

同批依 (a) 判準外移三節：〈Degrees of Freedom — 自由度匹配脆弱性〉與〈Opinionated Defaults — 預設路徑引導正確做法〉移入 `patterns-and-troubleshooting.md`，〈三類 bundled resource 的分工〉移入 `creating-and-adopting-skills.md`，`SKILL.md` 各留一列路由；兩個目標檔的檔頭三段式與「本檔章節」清單、入口檔路由表的「涵蓋章節」欄同步更新，`writing-the-body.md` 與 `frontmatter-and-description.md` 的檔頭「同目錄」段與一處死名一併改指新住址。`SKILL.md` 由 4,670 tokens 降至 3,601（5k 預算的 93% → 72%）、153 行。**新 (g) 判準在本批內對自身生效四次**——「上述實證」「上面那行指令」「單檔見下」「上例三段套上面兩問」皆指向帶標題或帶粗體引導句的目標，已改具名。

**Version**: 1.8.0 — 五組判準重新設計，每組改為可由第三方跑出同一個答案的形式。(b) 引用規則由「只一層深，禁止 A → B → C」改為**一跳可達**——禁的是「只能經由另一份 reference 才被發現的內容」，reference 之間互相指路不算違規；落在 `writing-the-body.md`〈Body 寫作〉，機械檢查（`comm` 列出「在 reference 裡出現、但入口路由表沒有」的檔名）落在 `SKILL.md`〈發布前檢查清單〉Body 組。(c)「Claude 真的不知道這個嗎」改為**刪除測試**（拿掉該段，乾淨 session 重跑同一任務比對產出）。(d) 自由度判準的「走錯一步會壞掉嗎」改為兩問：產物有機械消費者或動作不可逆嗎、多次執行的產物要互相比對或彙總嗎。(e) 體量主判準改為**分段估算直接比 5k**，行數降為官方合規項；第 3 層「無上限」界定為目錄總量，單檔判準改以讀取方式定；落在〈Progressive Disclosure — 三層載入〉，該節的「語言換算表」同時改名為**分段估算表**。(f) description 三個口徑中**只有 250 字元是閘門**，另兩個降為官方硬上限與量級參考並附換算，落在 `frontmatter-and-description.md`。(a)(g) 兩組暫緩，由後續 ANA 承接。

同批把 (b)(e) 的措辭同步到三處：`seeing-like-an-agent.md` 反模式表（原列「巢狀引用（A→B→C）」，與一跳可達相反）、`creating-and-adopting-skills.md` 4d 與 `patterns-and-troubleshooting.md`〈Context 過大〉的「語言換算表」死名。**未改的兩處是歷史記述**：本檔 v1.5.0 條目與 `writing-the-body.md`〈一則完整走查〉的「改後設計（第一次）」都在敘述當時的設計，改名會讓它們宣稱當時產出了現在才有的東西。

**Version**: 1.7.3 — 修 Round 4 第四個 frame（修法自傷復跑）留下的三則。〈外部引用：指名身分，不用檔案路徑〉在全庫統一為全名（前次只改了正文兩處，CHANGELOG 兩處未動）；「亦由此進入」的擺放由要求獨立成段改為明訂兩種皆可（五份寫在「何時讀」句中、一份獨立成段，判準本就該卡在「與主路徑視覺上分得開」）；`splitting-an-existing-skill.md` 的「五份新檔」計數移除——該處與 CHANGELOG 舊條目的「八份」對同一次實測給出不同數字，而 v1.7.2 的壓縮已刪掉後者，改法依同檔〈拆分特有的高頻缺陷〉的既有條文取消計數而非改對數字。

**這一批的取樣單位是「事」不是「本批改動位置」**：前三則的復跑之所以還能找到殘留，是因為掃描範圍改為全庫的每一種形式，不限這批動過的檔。以改動位置取樣時，新形式的對照組必然在未改動處，該類永遠回報通過。

**Version**: 1.7.2 — 修 Round 4 三個 frame 的 finding。

**重組後遺症**（兩次各自正確的修法合成一個問題）：橫向入口查法的扣除規則補上「同目錄」段（該段被補成全互指之後成為最大宗的偽陽性來源，實測 5/9）；〈觸發測試〉的無程序標註由逐項改為整組（前三項的做法落在一個已被標為無管道的層，而原標註只掛在第四項）；〈Step 4：撰寫內容〉表格內編號改為 4a–4f 並修三處跨檔指涉（原有兩套 1–6 命名空間，「Step 5」同時指節與表列）；「有兩份漏列」等內嵌計數移除。

**形式分歧**（同一件事在六份之間有幾種形式）：六份「同目錄」段補齊為各列其餘五份（原有三種完整度，缺席者恆為同一份）；三處懸空 `---` 檔尾移除；「六步」計數四處全清；**「不涵蓋」的告示收斂為固定前綴 `**不涵蓋**：`**——該類是四批修法新增最多的一類內容而原有五種形式、無共同字串可掃，約定寫入〈內容品質規則〉。

**誤報**（拿判準審明顯良好的 skill）：三條判準補上缺的那句條件——TOC 加「且被選段查閱」（被整份執行的 reference 不適用，實測同一判準在兩支 skill 上判出 25 誤報 vs 8 真違規）；「時間敏感」限定為「效力有期限的內容，不是內容有時間戳」；〈外部引用：指名身分，不用檔案路徑〉的 Action 問句**提到例外清單之前**並改寫為「它要操作的東西 vs 讀者要去讀的東西」（該問句本就在條文內，被四類例外的枚舉蓋過；實測 24 個命中裡它一次判定 23 個）。

**未修**：`description < 250 字元` 的邊界問題不是加條件能解——16,000 ÷ 58 ≈ 276 顯示 250 的真身是均分配額而非單支截斷點，而「哪幾支值得多佔」的機制尚不存在，在它存在之前任何單支閘門都會把 43% 的庫判成違規。已入判準重設計票。
