**Version**: 2.6.0 — 三組獨立測試對〈修法時點分離〉與引導層收斂出的缺口落地（不重新設計，形狀取自統整分析）：(1) 三問表第一列「消費端已觀測」拆為「執行條件已觀測」與「使用者群已觀測」兩列並補合成規則（原詞在條文自身案例中可讀成兩種互不相容的粒度，同一輸入得出相反判定），第二問「反例已試」加強為「若修法或其前提為錯就會產生不同輸出」，第三問加註「本問只管數字來源，鑑別力由第二問管」（不在第三問下加分母子問——該方向會使前提驗證遞迴、三問恆答否）；(2) 擴散面判準由未操作化的「限本 consumer 且可逆」改為 `should_exclude()` 機械事實 + 本 consumer 內機械訊號兩軸組合（全樹實測：規則／references／agents／methodologies／pm-rules／error-patterns 六目錄排除比例皆 0.000，單靠排除規則會使這些目錄的第一檔恆空）；(3) 第二檔處置改為「待辦與來源」表待裁列 + 「問題與方案」區段回填，不再要求發現票降為分析票（ANA 票 `where.files` 預設唯讀、提交路徑比實作票更差），並依 `comment-as-section-protocol.md` 新補的「重複，射程不重疊／重疊」判準決定 `add` 或 `observe`；(4) 條文第 86 行原以 issue ref（`#81`）作延後 trigger，改寫為明確結論「候選方案 B 現不採用」+ 條件式操作規範（日後採用須先建 ticket）。`ticket-intake.md`〈步驟三〉補修法閘門段（未過三問的修法不得原樣寫進「當前結論」）與 owner 識別行的填寫紀律（範例格式、漏填後果）；`comment-as-section-protocol.md`〈init 前查重：三種關係處置〉的「重複」格拆為射程重疊／不重疊兩列並補覆寫條款、修正指向 `ticket-intake.md` 的跨檔斷裂錨點；`SKILL.md` 路由表觸發條件擴充涵蓋收束時點；`framework-issue-curator.md` 收束允許產出補一句路由指向修法時點分離判準（原路由 0 命中）。不改 CLI 與 hook。

**Version**: 2.4.0 — `add`／`init` 改為整塊處理手寫索引。原本只搬表格列：手寫索引寫成「標題＋導言＋表格」三件一組時，標題移除的條件是「表格正上方最多隔一個空行」，導言卡在中間即使表格被搬走標題仍留原處，於是 body 出現兩個「## 區段索引」而第一個底下沒有表格——`tarrragon/claude#82` 的手寫標題底下寫的正是「入口從此處進，不從 comment 列表找」，讀者照那句承諾進來看不到索引，而 `show` 與 `check` 全部通過（兩者只驗工具索引與區段的一致性）。修法三處：標題往上尋找不再要求緊貼表格（遇另一個 `## ` 標題才中止）、導言由新增的 `extract_index_preamble` 取出並遷至標記區塊的標題與表頭之間、`render_index_table` 接受 `preamble` 參數且每次重渲染時回讀寫回（不回讀的話 `upsert_section` 的整段替換會在下一次 `add` 靜默抹除導言，屬同族缺陷）。配方 `ticket-intake.md` 步驟二第三列的「不再產生第二張索引表」射程只到表格列，改寫為涵蓋標題與導言；`comment-as-section-protocol.md` 的索引表格式補導言的存放位置與回讀約定。139 測試（新增 3 則，其一為跑兩次 `add` 的往返對照）。**存量未處理**：其他曾以 `add`／`init` 併入手寫索引的 issue 可能留有同型孤兒標題，需一次掃描確認範圍，不在本次。

**Version**: 2.3.0 — 「待條件」加進入門檻。原本的自由文字轉列舉規則以「依語意就近歸入」收容無法分類的階段文字，把「待 <票號>」寫成待條件的示例而非門檻，使該值成為收容站。實測 193 列中 53 列標待條件，逐列讀後 50 列指不出等待對象，`todo --stage 可立即執行` 因此少報 46%（59 列 vs 實際 102 列）。配方改為：待條件的「做什麼」欄必須指名等待對象（票號／issue ref／明示前置項／可觀測觸發事件），指不出即依內容改標「可立即執行」或「本版」；附 Why/Consequence/Action 與「改寫舊資料時對每一列都要問」的明示。已依此判準校正 14 個區段共 52 列，留下的 4 列各自具名了指涉對象。CLI 與測試未變更。
